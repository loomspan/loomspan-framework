# PR 27.4 — Execute namespace calls with captured settings and source authority

## Outcome

Execute composed skills through their admitted snapshot, selecting each target's captured configuration while preserving one session, caller identity, entry budget, and correct source-to-target authorization.

## Requirements

- Extend existing execution bindings with the immutable captured snapshot, entry namespace/generation, and current namespace/generation. Derive or validate associations against the authoritative snapshot so a namespace cannot be paired with another generation. Resolve structured identities through selected generations and canonical capability keys, never the live registry.
- Before a child context switch, authorize the resolved target using the actual source namespace and authenticated caller. Enforce declared-call restrictions, same-namespace or captured Public target visibility, target RBAC through the existing role evaluator, and retained-snapshot resolution. Snapshot membership and qualification alone grant no authority. Discovery uses the same policy; every execution path independently enforces it. No new authorization subsystem or SPI.
- Preserve authenticated caller identity while current namespace follows the executing skill. Restore parent context on success/failure, including asynchronous and parallel branches; preserve session identity, snapshot, accumulated usage, and mission ancestry. A Public callee cannot call back into its Private caller merely because the caller was the entry namespace. Keep existing Java/REST security-context isolation and Spring lifecycle; arbitrary host Java code/unmanaged threads are not sandboxed by this boundary.
- Parse model-generated plan, step, and tool selections through the common parser, normalize only namespace case, then match against the exact bound tool surface. `Tax-calculateTax` may match bound `tax-calculateTax`, but `tax-CalculateTax` is different and unbound normalized targets fail. Enforce namespace/combined limits at model boundaries. Outgoing tools, plans, bindings, child-result matching, and provider adapters use canonical names unchanged, including underscores. No provider-name translations, hashes, truncation, aliases, or fallback formats. Preserve raw model output and authored prompt content.
- Current captured generation supplies skill definitions, model, provider connection/credentials, and mission timeout. Provider request timeout/retries retain existing connection behavior. Parent timeout/cancellation continues while the child uses its own mission timeout; do not add queue deadlines, remaining-time arithmetic, or a new cancellation model.
- Entry captured generation supplies session quotas, maximum depth, trace persistence policy, and recorded trace quota-limit snapshot. Keep existing shared usage counters and ancestry across namespace boundaries for all current usage categories. Do not reset counters, adopt child quotas, create per-namespace budgets, or change existing post-response checks into advance reservations.
- Attachment limits follow the current skill materializing input through existing materialization checks. A parent-accepted attachment may fail child materialization with a smaller limit. No session-wide attachment budget, minimum-limit composition, or extra materialization subsystem.
- Keep one session and trace setup. A child or publication after admission cannot change entry trace policy or configured quota snapshot. PR 27.5 owns serialized observation metadata and Console consumers; this ticket supplies accurate captured execution context.
- Preserve `RestSkillHandler` and existing `RestSkillInvocation` fields: `skillName` is canonical qualified target identity, `input` is unchanged, and `generationId` belongs to the captured executing target rather than the entry generation. Capture target identity/ID in the preparation-time REST invoker closure; retained dispatch after replacement/removal must not query current publication or trust invocation input for routing identity. No redundant namespace field or new routing subsystem.
- Preserve opaque globally unique IDs and their availability without resource acquisition after execution/failure/release/cutoff. Retirement callbacks still identify one generation under existing lease/physical-work and delivery semantics. No Java child-call API, new host-context API, namespace invocation view, or root-as-child behavior.
- Provider adapters retain validation of additional supported-provider naming constraints without renaming the canonical identity. Audit framework-authored planner prompts as well as plan outputs, step execution, bound callbacks, input/output bindings, and result correlation for obsolete local-name assumptions; authored user prompts and raw diagnostic outputs remain unchanged.
- Shared counters include skill invocations, tool invocations, model calls, provider attempts, linter retries, and usage units. For an entry limit of 20 model calls, six calls in orders plus three in pricing consume nine of 20; pricing's own session quota applies only when pricing is the entry. Add no budget transfers, minimum-limit composition, or aggregate namespace limit across callers. The trace configured-limits snapshot records entry session quota settings, not every configuration setting.
- Mission timeouts start under existing mission behavior, not at host admission, and exclude host queue time. A 60-second parent calling a 30-second child after 50 seconds still has its original timeout running; the child does not extend it. Timeout return does not prove arbitrary external work stopped or authorize premature resource release.
- Standard Spring Security APIs remain the supported way for Java skills to read propagated caller identity. Do not expose internal session/security objects, introduce a trusted app/environment context API, or equate caller propagation with database credential forwarding. No chosen Cloud JWT scheme, sidecar runtime dependency, or unmanaged-Java asynchronous propagation guarantee follows from this work.
- ID reads after release/retirement remain available but do not guarantee a host-owned generation mapping still exists. No durable cross-restart ID mapping or replacement retirement callback is implied. Public visibility does not override RBAC or declared-call restrictions, and RBAC never overrides a foreign Private boundary; Public targets do not automatically become model tools.

## Acceptance criteria

- [ ] Same-namespace Private calls and cross-namespace Public calls work subject to declared permissions/RBAC; cross-namespace Private calls and callbacks into a Private caller fail. Discovery and every supported ordinary/planned/bound dispatch path agree, with execution independently enforcing policy and no dynamic snapshot expansion.
- [ ] Cross-namespace children use captured target settings; success, exceptions, asynchronous work, and parallel branches restore/isolate parent contexts while preserving the authenticated caller and shared session. Publications/removals after admission do not alter execution.
- [ ] Model-generated plan/step/tool choices normalize namespace case before bound lookup, preserve skill-name case, reject malformed/oversized/unbound identities, and keep raw output intact. Tools, bindings, results, and adapters use identical canonical names without encoding.
- [ ] Parent/child namespaces with different quotas, depth limits, provider settings, timeouts, attachment limits, and trace policies demonstrate the specified entry/current split. Child usage accumulates into entry limits; parent timeout remains active; child attachment materialization applies its own limit; trace policy/recorded quotas remain entry-scoped.
- [ ] Equal local REST names from two namespaces deliver distinct qualified names. A cross-namespace retained REST call reports the old target generation ID after replacement/removal, while admitted-root ID remains entry-scoped. Retirement and ID reads preserve existing ownership semantics.
- [ ] Nested root rejection and security-context propagation remain correct. README and supported-surface tests explain qualified REST identity despite unchanged field types; run `LoomspanPublicSurfaceArchitectureTest`.
- [ ] Additional supported-provider naming checks remain enforced without alternate names; framework planner prompts and selections agree on canonical identities while raw/authored content is preserved. An undeclared skill in an already captured namespace is not callable merely because its generation is retained.
- [ ] Callback verification covers both early rejection of a declared reachable Private callback by admission and independent denial by the runtime guard using the actual source before switching context. Permissive RBAC does not bypass visibility, and Public visibility does not bypass required roles or declared bindings.
- [ ] Counter coverage preserves every existing usage category and entry settings for queued handoffs even if publication changes before execution starts. No admission-time deadline, host queue expiry, aggregate namespace budget, or expanded configured-limits payload is introduced.
