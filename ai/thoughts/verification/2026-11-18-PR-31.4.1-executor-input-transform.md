## Red test and corrections

`mvn '-Dtest=ExecutorDeclarationTests#executorInputTransformLoads' test` failed
as expected before production edits. One test ran and reported
`executor-fixture.yml`, `default-lookup`, field path `input_transform`, and
`unknown field`. The green suite reuses that same test method.

The first connected run exposed a direct generic Resource reaching existing
trace conversion before worker execution. This caused Jackson to access the
Resource's URI. The transform-only JSON admission check before opening the
mission frame gives this input a precise transform error and keeps resolved
`ref://` checking at the common handoff. The same run also corrected fixture
expectations for the public reload exception and internal catalog retrieval.
Subsequent fixture assertions check the projected planner schema and compare small
numeric values independently of Java wrapper width. Exact decimal and large
integer assertions remain in place.

The combined focused run passed all 307 tests, including all eight
`LoomspanPublicSurfaceArchitectureTest` checks, before the last lifecycle guard
refinement.

The cancellation-during-evaluation regression reproduced a late handler call
when the new executor preparation ran without a second lifecycle gate. A test
double delayed the prepared expression and ignored the worker interrupt before
returning a regular object. The caller interrupted during that delay, and the
single worker then finished physically before the test counted handler calls.
The red run counted one handler entry. The implementation now invokes the
existing lifecycle phase-entry guard between evaluation and handler dispatch.
The green run passed with zero handler entries.
