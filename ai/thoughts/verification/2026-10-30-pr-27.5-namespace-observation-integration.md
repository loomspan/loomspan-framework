## Implemented behavior

- Admission captures primitive `entryNamespace`, entry-scoped `generationId` and immutable `namespaceGenerationIds` before session construction/TRACE_STARTED. No observation object acquires a runtime lease or consults current publication to recover these identities.
- Java trace, active projection, finalized artifacts and existing HTTP DTOs carry the same facts. Known frame owners capture `executingNamespace`/`executingGenerationId` at opening; emission uses those stored facts through closure and cleanup. Skill-frame ownership uses exact capability lookup in the captured generations. Operation routes retain their operation meaning. Unknown owners omit both executing fields.
- Existing host inspection merges independently usable immutable metadata from a coherent active-generation registry capture. It includes Private/restricted namespaces and handles default withdrawal and an empty registry. Observation authentication/authorization and runtime permission-filtered discovery stay separate.
- Metric skill and tool identity tags preserve case. Other tag normalization and missing-value `unknown` behavior are retained.
- Console consumes the current Java contract across live observation, canonical analysis, acquisition/import, summaries, browser/MCP and TypeScript. Captured maps are copied at cache/artifact/query boundaries. Required capture metadata is validated even for development traces; optional owner facts must be a complete pair matching the captured mapping. There is no old-format reader or repair path.
- Existing summaries label entry generation explicitly and display captured associations/known record owners without namespace navigation, filters, reporting or new observation endpoints.
- The shared corpus includes `namespace-captured-context`: `orders-search` and `tax-search`, entry `orders-old`, retired target `tax-retired`, and captured but unexecuted `audit-unexecuted`. Java reference expectations and Go semantic comparisons include the full map and entry fields.
- README/routed authoring guidance covers canonical references, namespace-selected catalog acquisition, complete replacement, Private startup/Public sharing, fresh admission versus temporary validation, departmental fixed methods, restart, staged cycles, prospective removal and retained execution, entry/target IDs, and generic host responsibilities. Host controls remain necessary for credentials, database permissions, mutable Java state and resources.

## Material implementation decisions

`CapturedNamespaceMetadata` is an internal immutable primitive record used between existing internal execution/observation packages. It is deliberately included in the architecture test's internal-public rationale allowlist, not the Application API allowlist. No Application API/SPI or Spring bean replacement contract was added.

Existing no-metadata convenience constructors were moved into test factories so production construction always receives explicit captured metadata; synthetic test generations are not production fallbacks. Old test references, local-name catalog assumptions, fake model contracts and source-authority fixtures are updated directly. Local manifest/annotation declarations, task IDs and business content retain their distinct meanings. Tests that formerly authorized Java-root nested callback dispatch now assert the accepted callback denial; unit fixtures that test legitimate nested dispatch supply an actual captured YAML source with the declared edge.

Exact-release identity continues to come from filtered `META-INF/loomspan-release.properties` and `${project.version}`. No namespace marker, protocol counter, range, historical migration or development-build compatibility promise is introduced. Canonical prompt/input/output/tool/evidence/diagnostic payloads are unchanged. The existing derived `ExecutionJournalProjector` exception is unchanged.
