## Implemented behavior

`OrdinaryFinalOutputRepair` is an internal invocation-owned holder, passed by
reference through advisor context and tool context by `SpringAiModelInteraction`.
It retains only appended completed Message objects after successful canonical
manager delegation, the latest accepted raw provider AssistantMessage, and a
terminal repair flag. The holder is never cached on a client, manager, session
or thread local. Capture clears a missing reply rather than reusing stale raw
output. No provider history is reconstructed from composed application text.

All three ordinary advisors use the same request helper. Each immutable request
version owns its replay descriptor, with owner, bounds and original message
identity checks. Only that explicit span is removed when replay is replaced.
Schema retains its baseline/latest-only feedback policy; linter/evidence retain
their accumulated system hints. Baseline media and external feedback remain.
Typed options are copied; callbacks are explicitly empty, Responses hosted tools
are empty and Gemini search retrieval is false. Non-tool formatting/caps/effort
and tool context are retained. No arbitrary data/content fields are rewritten.

`CanonicalToolCallingManager` rejects terminal-repair dispatch before delegate
execution, including multi-call/control/unbound selections. Normal provider
status, canonical authorization and argument validation remain unchanged.
ProviderAttempt captures raw replies only after its existing status/accounting
path; no synthetic attempts or accounting were added. Old schema text-only
candidate rebuilding was deleted. Direct internal fixtures now explicitly
provide state/raw capture instead of a production composed-text fallback.

State allocation follows non-planning interaction calls, including direct
STEP_EXECUTION-mode ordinary-validator fixtures. Production step assembly removes
all three ordinary validators, so that holder never enters repair and changes no
step policy. Planning has no holder. This internal allocation detail and its
rationale are recorded in the implementation plan. Existing full factory step
and planning preservation tests ran.
