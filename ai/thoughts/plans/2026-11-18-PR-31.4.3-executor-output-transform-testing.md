# Executor output transform testing plan

## Change Summary

Verify executor-only prepared `output_transform`, strict JSON text admission, any-root JSON publication, one-time leaf evaluation and distinct canonical raw/published evidence. This is Step 3 of the developer-approved Full 5-Step Pipeline, continuing in the Step 2 planning context.

The controlling artifacts are the ticket `ai/thoughts/tickets/loomspan-pr-31.4.3-executor-output-transform.md`, research `ai/thoughts/research/2026-11-18-PR-31.4.3-executor-output-transform.md` and implementation plan `ai/thoughts/plans/2026-11-18-PR-31.4.3-executor-output-transform.md`.

## Impacted Areas

- Catalog validation and compilation, manifest declaration presence, definition copies and immutable generation capture.
- Prepared JSLT engine, strict JSON text parser, recursive finite JSON result conversion and serialization.
- Executor branch in `ExecutionCoordinator`, mission failure propagation and canonical completion evidence.
- Public direct invocation, ordinary model tool results, planned `output_from`, `child_result` input selection and declared output assembly.
- Executor and output-contract authoring topics, adjacent envelope wording and coverage routing.

## Risk Assessment

The primary risks are parsing only a JSON prefix, treating JSON null or empty JSON strings as absent input, unquoting JSON strings, dropping constructed nulls/empty containers, evaluating at multiple consumers, and replaying side-effecting work after a local failure. A captured call must hold its old expression across publication, while failed preparation leaves the active generation intact. Child diagnostics need the same raw/published distinction as root diagnostics.

Protected paths are existing allowlisted Java APIs, v1 executor handoff, manifest/input-transform behavior, exact omitted result text, public reload/handoff semantics and current-run diagnostic access/resource boundaries. Internal class/declaration names may change atomically. No obsolete supported path or migration is introduced. The plan adds arbitrary metadata DATA fields while retaining raw `executorOutput` and all typed envelopes, so synchronized Java/Go protocol changes and a compatibility-marker change are unnecessary.

Canonical tests preserve content, including keys such as `token`. Existing `ExecutionJournalProjector` behavior remains covered by its existing tests. No new sensitivity classification or content rewriting is part of these tests.

## Existing Test Coverage

- `ExecutorDeclarationTests` covers strict input transform syntax, model rejection, imports and executor form conflicts. It currently rejects the new root as an unknown field.
- `ExecutorInputTransformTest` covers JSON input fidelity, object construction, invalid handles, object-only result checks, evaluation errors, finite numbers and concurrent reuse.
- `ExecutorInputTransformIntegrationTest` supplies public direct/planned fixtures, explicit configurations, observer failures, failed preparation and retained `SkillInvocationHandoff` generation checks.
- `ExecutorDiagnosticsIntegrationTest` supplies real canonical records, best-effort write containment, raw root output and failure evidence.
- `DesignatedChildResultIntegrationTest`, `DeclaredChildInputBindingsIntegrationTest` and `DeclaredOutputBindingsPlanningIntegrationTest` protect the existing consumer paths.
- `ExecutorInvocationLifecycleIntegrationTest`, `ExecutorGenerationExecutionIntegrationTest`, `YamlSkillDefinitionTest`, `SkillGenerationManagerTest` and `LoomspanPublicSurfaceArchitectureTest` cover surrounding invariants.

The new tests must establish the output boundary and its connected consumer behavior. Existing tests alone establish no output-transform support.

## Bug Reproduction / Failing Test First

Add `ExecutorDeclarationTests#executorOutputTransformLoads` before production edits. Supply an executor leaf with `output_transform: {language: jslt, expression: '.'}` through `checkedSupplied`. Assert there are no issues and exactly one prepared definition. The baseline fails with an unknown `output_transform` field. Record the exact red command and expected diagnostic, then retain the test in the final suite.

This low-cost loader test demonstrates the missing feature without depending on a new production method. Subsequent execution tests establish semantics after the declaration exists. Planning has run no tests and makes no red/green claim.

## Tests to Add/Update

### 1. Declaration and prepared state

**Type — Unit/catalog**

**Location —** `src/test/java/ai/loomspan/internal/skill/ExecutorDeclarationTests.java` and `YamlSkillDefinitionTest.java` where its existing copy fixtures fit.

Prove output-only, input-only, both and neither load. For both, apply distinct input/output expressions to prove separate captured state. Parameterize existing declaration assertions where that keeps every field path explicit.

Reject model-backed presence for null, scalar, list, empty object and valid object values. Reject executor bare/null/scalar/list declarations, unknown nested fields, missing keys, wrong language types, wrong case/whitespace, absent/non-string/blank expressions and compile errors. Include successful block syntax/classpath import and unresolved import failure. Assert source, qualified skill and precise `output_transform`/`.language`/`.expression` paths. Confirm defensive manifest access cannot replace prepared state and original YAML remains exact.

Use existing `SkillDocument`, catalog and classpath module fixtures. No model or executor mock is needed. Affected surfaces are manifest behavior and internal prepared representation. Preserve existing input behavior while updating internal type names atomically.

### 2. Strict JSON boundary and result fidelity

**Type — Unit**

**Location —** `src/test/java/ai/loomspan/internal/skill/ExecutorOutputTransformTest.java` against the prepared internal transform, with existing input-transform tests updated for the internal rename.

Use identity `.` over objects, arrays, quoted strings, integers, decimals, booleans and JSON null. Include empty object/array, the JSON text `""`, surrounding JSON whitespace, nested ordered arrays, exact-case keys, large integers and precise decimals. Compare semantic JSON where whitespace is free, and exact strings where quotes, escaping or `null` matter.

Use object input with expressions returning each JSON root type. A missing lookup must equal the four characters `null`. A string lookup must equal `"returns"`. Values containing quotation marks and backslashes must decode to their original strings. Construct `{"nil": null, "object": {}, "array": []}` and assert every member survives. Verify a prepared expression can be reused concurrently with independent results.

Reject Java null text, empty and whitespace text, bare `returns`, incomplete/malformed JSON, trailing garbage and multiple values such as `{} {}`, `1 2` and `null true`. Use an expression that throws a distinctive sentinel to prove invalid text fails before evaluation. Valid JSON with that same expression must report the sentinel evaluation failure. Reject constructed nonfinite numeric values at root and nested positions using the engine's established division fixture.

No model/executor mocks are required. Affected surfaces are internal JSON processing and serialized skill results. Existing input transform JSON admission and object-only output must continue passing.

### 3. Direct and parent result publication

**Type — Public integration over loopback model fixtures**

**Location —** `src/test/java/ai/loomspan/integration/ExecutorOutputTransformIntegrationTest.java`, using `FixtureExecutor`, `ApplicationContextRunner`, `ResponsesFixtures` and existing plan/tool fixture builders.

Create a raw response with `answers.team.choice = "returns"`, `answers.repeat.noul = 0.95`, and `answers.impact.score = 0.8`. Apply the exact ticket expression and assert the public direct result contains exactly the three published fields and values. Use an expression whose reapplication to its own output yields a different result, making consumer reapplication detectable.

Exercise the same leaf through a planning parent with `output_from` and assert whole-text equality to direct publication with no final synthesis request. A dependent child binding from `/repeatContactProbability` must receive the numeric value `0.95` in executor input, retaining type and containing no raw `/answers` dependency. Include a fully bound parent output assembly selecting the published result or its probability, using the existing assembly fixture pattern. Exercise an ordinary tool call and inspect the provider's continuation/tool-result payload for the published String, never the raw envelope or an extra transform.

Record executor calls and model request counts. Give combined transforms a simple input projection and verify the executor receives it while callers receive the output projection. Consumers use the captured leaf result through their existing entry points. The tests require no real provider or TypeSafe pack.

Affected surfaces are public invocation, manifest behavior and serialized results. This preserves existing parent selection and decoding rules while changing the opted-in leaf output.

### 4. Failure, omission and canonical evidence

**Type — Public integration**

**Location —** `ExecutorOutputTransformIntegrationTest.java`, with reuse or focused additions to `ExecutorDiagnosticsIntegrationTest.java` when existing seams are needed.

For an opted-in leaf, return invalid JSON with an identity expression and valid JSON with an `error(...)` expression. Assert one executor entry per invocation, failed `SKILL_FINISHED` observer status, qualified `output_transform failed` context and the original cause/detail. Do this directly and for at least one child failure path so parent handling cannot silently accept the raw response or repeat the executor. The real ordinary/step failure path must produce a failed invocation without a second dispatch.

Make the executor throw its existing terminal or designated recoverable exception while the expression would throw a different sentinel. Assert original failure behavior and absence of transform sentinel/evidence. Preserve current executor failure classification and no successful-output metadata.

For omitted transforms, use a parameterized executor String set containing empty, whitespace, non-JSON, malformed JSON, JSON-looking text and quoted/escaped text. Assert exact public results byte-for-byte at the Java String boundary. Retain existing tests for non-string Java result conversion and Resource inputs.

Capture canonical logical records through `ExecutorDiagnosticTestSupport` from real sessions. For transformed direct and child success, assert a leaf `FRAME_METADATA_RECORDED` envelope has exact raw `executorOutput`, exact published `skillOutput` and `outputTransformStatus = succeeded`. For parse/evaluation failures, assert raw text, `outputTransformStatus = failed`, useful `outputTransformFailure`, no `skillOutput`, and the ordinary terminal failure linked to the leaf frame. Assert ordinary tool completion records contain the published text on success and no raw successful fallback on failure. Include keys such as `token` and literal prompt-like strings to verify fidelity. Test existing diagnostic failure seams still cannot change the actual success or replace the original failure.

Affected surfaces are current-run diagnostics, serialized results and invocation failures. Generic retained DATA readers already display these additive fields. Run existing canonical trace/Console fixture tests to retain envelope coherence, without inventing historical-format obligations.

### 5. Generation capture and failed preparation

**Type — Public reload/handoff integration**

**Location —** `ExecutorOutputTransformIntegrationTest.java`, following the existing input-transform retained-call test.

Publish a leaf with an expression returning `{"version":"old"}` from valid executor JSON and retain a public `SkillInvocationHandoff`. Publish an expression returning `{"version":"new"}`. Attempt malformed expression and invalid language preparations. Assert both fail before any executor call, active generation remains the new valid one, a fresh call returns new JSON, and retained invocation returns old JSON. Release the handoff in `finally`. Include output-only and both-transform capture where the same fixture can establish independence without duplicating the whole matrix.

Affected surfaces are supported reload/handoff and authoring generation semantics. Use actual generation publication and admission, not a substituted mutable catalog.

### 6. Authoring claim verification and supported surface

**Type — Focused behavioral evidence and review**

Use the tests above to support exact new claims in executor guidance. Inspect all changed authoring pages and routing/coverage entries for opt-in JSON requirements, post-executor side effects/failure, root types, null/missing behavior, string quotes and parent consumption. Qualify existing whole-envelope statements for transform omission. Keep stable named executable anchors and current product wording.

Run `LoomspanPublicSurfaceArchitectureTest` with no supported allowlist expansion. Internal renames may require updates to an internal technical inventory if the architecture test explicitly lists them. Such an update must preserve the closed application API and absence of internal/autoconfigure types in supported signatures.
