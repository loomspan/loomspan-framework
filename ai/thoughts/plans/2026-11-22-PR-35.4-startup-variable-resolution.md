## Desired End State

An active profile may override a connection API key and inherit its driver and headers from a base document. Only effective markers are validated and resolved. The winning executor section replaces lower sections as it does today. All effective uses of one name across connections, executor namespaces and configured skills share one normal `Environment.getProperty(name)` call. Fresh startup contexts have independent caches.

Authored `${region}` is terminal text in the three selected subtrees. A marker for the host property `report.label`, whose host value is `${region}`, receives the Environment's effective value. A value returned by Environment that itself contains placeholder characters is terminal too. Native duration, boolean, driver and numeric conversion and existing provider constraints run after substitution. Original YAML-looking multiline strings reach string consumers unchanged.

Actual configured executor invocations observe resolved owner, consumer and leaf settings through the existing invocation maps. Provider clients observe the resolved API key and exact headers. Failures identify authored resource/document and path plus a fixed reason. Missing, blank and failed variable lookups create diagnostic text from those facts without embedding returned values or callback causes. This does not introduce content classification or rewriting.

## Implementation Approach

Extend the existing YAML transport and fixed early binding integration. Retain per-document authored node slices with resource/document provenance alongside Boot's ordinary property source representation. Avoid encoding trees back to YAML, expanding placeholders and trying to reverse that expansion, or resolving documents when the loader first sees them.

Use Boot's selected ConfigData sources and native configuration-property naming to choose effective selected data. Retained authored connection fields participate in field inheritance. A higher-priority scalar at a field path replaces a lower marker map at that path as one setting. The winning executor section stays one replacement unit. A variable-authored nested key retains its original occurrence until the selected graph resolves it.

The fixed early binding integration owns a startup resolver instance associated with the application context/environment. It must run before connection conversion/validation and remain available through configured skill load. Register it through existing `ExecutorConfigurationBinding` infrastructure, which full Loomspan auto-configuration and the executor properties-only boot harness import. The bare `LoomspanPropertiesTest.TimeoutBinding` harness currently enables properties alone, so selected-marker tests there must import the fixed infrastructure explicitly or use the existing startup binding harness. An internal `StartupVariableResolution` collaborator can hold the effective authored slices and memoized normal Environment lookup. It is ordinary framework state scoped to one startup, with no consumer replacement contract.

Connection binding must receive terminal resolved values through an explicit placeholder-free Binder using Spring's normal conversion services and strict binding behavior. The existing published parser shows this native Binder pattern, but its restricted published schema is not the startup schema. Refactor the reusable connection-tree conversion/header handling where it already owns those rules. Keep startup's complete configuration model and other Spring binding intact.

Boot's `ConfigurationPropertiesBindHandlerAdvisor`, `AbstractBindHandler` and explicit Binder constructors were confirmed in the exact locally installed Boot 4.2.0-RC2 bytecode. Use a fixed early binding hook to intercept the selected properties before Boot expands strings, bind those properties through the terminal path, and let the ordinary outer binding finish other properties. Account for strict unbound-element tracking and validation ordering in the hook. An opaque raw transport/converter is also available in the existing integration. The first integration test must prove that the chosen hook actually prevents premature expansion, preserves unknown-field failures and applies values before validation. These mechanics may be simplified during implementation while preserving the selected design and all tests below.

## Implementation decisions and evidence

The early binding integration intercepts the existing `LoomspanProperties` binding, selects and resolves connections/executor settings, and delegates ordinary properties through a Binder using the original bind handler and normal Spring placeholder resolution. The selected provider tree reuses the existing parser's provider schema and terminal native conversion. Spring's native `ConfigurationPropertyName` matching handles relaxed field names. Connection identities, exact header names and executor data keys retain their distinct semantics. The fixed integration introduces one technically public internal startup collaborator and no supported API or SPI.

The configured foreign-startup test proposed by the testing plan assumed a foreign executor was selectable while preparing default startup definitions. Existing `initializeStartup` prepares default against no published external generations and preserves Private startup namespaces. An attempted configured foreign leaf fails with `Unknown executor 'infra-foreign'` before activation. The test now protects that existing boundary. Actual owner, consumer and leaf delivery across namespaces remains covered by PR 35.3's `ExecutorGenerationExecutionIntegrationTest#resolvedForeignOwnerConsumerAndLeafRemainCapturedAcrossRotation`. This corrects the test assumption while preserving the ticket's startup and compatibility scope.

Unknown startup provider fields retain full leaf paths. Their exception implementation now comes from the shared connection schema. The existing rejection test asserts the complete diagnostic path through this internal change.

The Windows editor writes classes to Maven's output directory, which can satisfy ordinary timestamp checks and can include error stubs while source edits are in progress. Final verification forces javac for all 350 production and 275 test sources using `-Dmaven.compiler.useIncrementalCompilation=false -DlastModGranularityMs=-1000000000`, with edits complete before the run. The explicit Mockito javaagent avoids the previously observed native runtime-attachment pipe denial.

Startup binds each connection under an internal fixed key before retaining the authored identity. This preserves application-owned case and punctuation while using native field conversion. Known optional null fields keep native absence/default semantics. Null header values still reach the existing header validator.
