## Current state analysis

- `SkillAdmissionSnapshot` is already the immutable authoritative association of namespace to retained generation. `ExecutionBinding` distinguishes entry and current context. `LoomspanSessionRunner.runAdmittedRoot` constructs the session before installing that binding, so trace initialization cannot discover the map through the current binding (`LoomspanSessionRunner.java:285–329`). Pass it explicitly before the first record.
- `DefaultExecutionTraceHandle.initialize` emits entry skill and entry `generationId`, but no namespace map. `ActiveExecutionSnapshot`, `ExecutionProjectionState`, finalized artifacts, HTTP DTOs, Go observation/artifact/analysis models and browser contracts share that omission.
- The host inspection supplier in `ObservabilityRouteRegistrar.createRuntime` reads only `generations.active("default")`. Removing default therefore also exposes a false assumption. `DefaultRegisteredSkillCatalog` already owns immutable inspection metadata and deterministic canonical ordering; reuse it.
- `MicrometerUsageMetricsRecorder.normalize` lowercases skill tags, merging case-sensitive local names. Driver/outcome normalization has separate semantics and should remain intact.
- Most name-bearing strings already pass through unchanged. Audit uses rather than indiscriminately retyping records or treating every route/string as a skill. `ExecutionFrame.route` also names planning/model/step operations. Known skill fields and captured bindings are authoritative; unknown diagnostic origins stay unavailable.
- Shared Console fixtures and many older Framework tests still use local/dotted references. PR 27.4 recorded 465 remaining baseline failing cases; Step 4 must reconstruct current failures, directly update obsolete expectations and fix actual namespace defects rather than exclude these cases.
- `NamespaceStartupIntegrationTest` demonstrates no-file managed publication but does not execute its model-backed caller. It also verifies embedded catalog composition rather than executing that parent. Extend these scenarios with deterministic provider fixtures.
- Exact release matching already derives from filtered `META-INF/loomspan-release.properties`, using `${project.version}`. Preserve this authority and development behavior.

## Desired end state and decisions

### Captured observation contract

Use these names consistently across Java, JSON, Go and TypeScript:

| Field | Meaning |
| --- | --- |
| `entrySkill` | Canonical qualified admitted entry identity. |
| `entryNamespace` | Canonical entry namespace from the admitted snapshot. |
| `generationId` | Captured **entry** generation ID, never a snapshot revision or current target ID. |
| `namespaceGenerationIds` | Immutable/copied map from every namespace selected by admission to its captured opaque generation ID. Includes entry and optional reachable namespaces, even when no branch executes them. |
| `executingNamespace`, `executingGenerationId` | Per-record/frame facts for a known executing owner, where execution context is represented. Kept separate from session entry metadata. |

Create the primitive immutable map once from the admitted snapshot before session/trace initialization; no observation object should retain generation runtimes or add resource leases. Validate entry membership and entry generation agreement at the owning construction boundary. Deep-copy maps at mutable language/API boundaries. Deterministic key order in canonical output/fixtures is desirable; map iteration order is not a new semantic contract.

Propagate entry namespace and the complete mapping through TRACE_STARTED, active projection snapshots, finalized artifact descriptors, HTTP active/trace DTOs, Console observation validation, validated analysis metadata, acquisition/import/list/detail/summary responses and browser contracts. Acquired/imported trace metadata comes from validated canonical bytes, following the existing acquire behavior, and remains usable after upstream expiry/removal. Do not reconstruct it from current publication or from acquisition response fields alone.

Record execution facts from the captured context owning the record. Known skill mission frames use their resolved skill identity; tool records distinguish a known target capability from their owning mission as their existing context does. Model/planning/step records use their owning execution context while retaining their operation route. When the lifecycle may append after context restoration, capture the owner facts in the existing frame/context at creation so terminal/cleanup records remain accurate. In particular, a child frame opened while the source binding is still installed must identify the resolved child, and a parent result/forwarding record must identify the parent. Never assume that a thread's current binding or a syntactically plausible arbitrary route proves ownership. Session/global records have entry metadata; unknown-skill diagnostics do not acquire invented executing fields. Existing identity fields continue as canonical strings.

The exact internal constructor grouping may be simplified while editing, but the fields, authority, timing and absence semantics above are settled. No new public identity/snapshot-map API is needed.

### Host inspection and runtime discovery

Expose all currently published skills through the **existing** host inspection list/detail/count routes. Capture active generation references coherently under the manager's existing registry monitor, then use their independently usable immutable registered metadata outside it. Merge into the existing internal inspection projection with canonical name ordering and exact lookup. Do not create a new application-facing aggregate catalog, cache, revision, namespace resource or enumeration endpoint. Public `SkillReloader.snapshot(namespace)` remains namespace-selected and immutable. Include Private and role-restricted skills in host metadata under existing observation authentication; runtime discovery remains execution-permission filtered. Support removal of default and an entirely empty active registry.

### Identity and metrics

Keep canonical skill strings whole in comparisons, indexes, sorting, correlations, lookup URLs and displays. Preserve local-name case for metric `skill` tags; retain `unknown` for existing missing/blank cases and keep other tag normalization. Fix specific producers still emitting local names rather than repairing arbitrary content downstream. Preserve raw model output and all canonical business/diagnostic payloads.

### Alternatives considered

Using current publication at observation/query time loses retained generation identity after replacement/removal. A single session generation ID cannot describe a cross-namespace snapshot. Treating every route as a skill corrupts non-skill operations and unknown failures. Retyping every DTO expands scope without improving the string contract. Namespace-specific observation APIs or an extra compatibility counter introduce unrequested features. Reusing the admitted snapshot's primitive metadata and existing projections gives complete accuracy with the smallest coherent contract change.

## What we're NOT doing

No new observation filters, queries, roles, reporting or namespace-enumeration features; no new supported API/SPI or internal bean replacement promise; no extra session/trace/event flow; no content rewriting outside the unchanged derived journal exception; no old-format readers, migrations, aliases or dual wire shapes; no compatibility counter/range. No Cloud implementation/authentication choice, tenant isolation guarantee, reserved shared namespace, publisher/membership role, bootstrap transactions, drainage, app migration gates, repository integration, provider sharing, benchmark/capacity work or optimization. Ordinary lifecycle cleanup/concurrency correctness remains in scope.
