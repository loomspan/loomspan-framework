## Performance and migration notes

### Implementation evidence: per-call option combination

The first Framework wire run showed that RC2 fresh schema-only typed builders
replace ChatClient defaults: the request lost MEDIUM, the configured cap and
temperature/stop settings. The option fixture now copies the effective defaults
with `defaults.mutate().outputSchema(schema)` before each call, matching the
existing native Anthropic copy-defaults approach. This explicitly preserves the
whole request-local options object rather than relying on implicit combination.
The ticket owns adapter/factory proof; no existing production Gemini schema caller
is migrated here. Ordinary and planner consumers remain owned by 30.3.1/30.3.2
and must copy the effective target defaults. The initial failing command and
captures remain in the implementation results. Raw-schema requirements remain
opt-in failures and are not repaired by this copy.

No production defaults, request limits, timeout behavior or retry ownership change.
The native enum avoids an unnecessary numeric budget for the exact fixture. No
persisted migration or compatibility reader is needed. Existing intermediate
schema-consumer build allowances do not excuse owned adapter failures.
