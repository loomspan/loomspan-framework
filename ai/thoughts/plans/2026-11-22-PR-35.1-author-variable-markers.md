# Authored variable markers implementation plan

## Overview

Implement the internal YAML facility required by `ai/thoughts/tickets/loomspan-pr-35.1-author-variable-markers.md`. It will preserve authored mapping entries before Java map construction, discover marker names with source paths without consulting values, and substitute marker nodes with strings. A reusable fixture corpus will define the same contract for independent Go extraction and Java preparation integration.

This is the approved Full 5-Step Pipeline, steps 2 and 3, following `ai/thoughts/research/2026-11-22-PR-35.1-author-variable-markers.md`. The developer approved the profile with `proceed`. The initial checkout has no tracked changes. The PR 35.1–35.4 tickets and the framework variable handoff are pre-existing untracked developer inputs to preserve.

## Current State Analysis

`YamlValues` constructs maps immediately through SnakeYAML Engine `Load`, using Core schema, textual timestamps and ordinary Java numeric kinds. `SkillDocumentValues` uses its separate exact-decimal mode for JSON-bound manifest fields. `YamlValues` rejects recursive containers and limits logical expansion to 1,000,000 values, counting repeated alias contents. These controls run before downstream consumers traverse the graph.

`ExecutionConfigurationParser`, `ExecutorConfiguration.from`, and `YamlSkillCatalog` subsequently require textual keys. The startup loader preserves the executor section through an opaque wrapper, while skill ingress carries its actual top-level config separately. The current representation carries neither authored tuple indices nor source filenames. A Java map cannot represent every authored mapping entry through deferred key substitution.

The installed SnakeYAML Engine 3.0.1 source provides `Compose.composeString` and `composeInputStream`, retaining `MappingNode.getValue()` tuples in authored order. `StandardConstructor.constructSingleDocument(Optional<Node>)` provides existing scalar/tag construction without parsing text again. Its settings override constructors after installing Core schema constructors. These APIs allow a composed tree and existing scalar rules to share one configuration.

## Desired End State

Framework packages can retain a parsed authored document, obtain ordered marker occurrences, and produce ordinary YAML values after applying a supplied string lookup. Public application API signatures and the current startup/preparation entry points retain their current behavior in this slice. The internal facility and its fixtures supply the semantics those entry points will consume in their assigned tickets.

## Implementation Approach

Add `ai.loomspan.internal.serialization.AuthoredYamlVariables` as the shared facade. Keep its authored tree opaque to callers. Nested value types may carry document/source, occurrence name/source/path and structured failure details. Retain SnakeYAML nodes or a compact ordered wrapper over those nodes so all tuples remain available before map construction. Avoid a second hand-written YAML scalar parser.

Factor the existing YAML settings creation in `YamlValues` into a package-private shared helper. The authored parser must retain Core schema, existing timestamp construction and ordinary scalar numeric kinds. Keep the existing exact-decimal skill-document API and its constructors intact. Existing `read`, stream and `documents` callers keep their behavior. Compose first, check cycles and logical expansion before constructing maps or walking occurrences, and retain authored tuple order. Centralize the resource-bound constant and bounded-count operation. A node graph check must count scalar keys and values and all sequence elements, memoizing completed alias subtree sizes and rejecting active ancestors.

Provide document factories for execution configuration and skill documents. Expose discovery without a lookup parameter. Expose substitution using a framework-supplied `Function<String, String>` or equivalently small internal callback. Source selection and distinct-name caching stay with the caller. The resolver must never infer Environment or map fallback. Output is ordinary YAML-domain values, suitable for later owning validators. The exact method names and placement of small private helpers can follow repository conventions while preserving this contract.

### Selection and grammar

For an execution document, navigate literal authored root keys `loomspan`, then `connections` or `executor-config`. Each immediate entry's value is the selected subtree. Its selector key is outside traversal. For a skill document, recognize the actual root `executor` field, require the actual root `config` value to be a map before selecting it, and traverse that config subtree. Owning validators retain responsibility for malformed declarations and section types. Nested schema fields named config create no boundary.

The selected value node and its descendants participate in whole-node recognition. Selector keys themselves never do. A selected config mapping is still subject to the owning map-root requirement after substitution. Traverse every key, value and sequence item under the selected boundary, including unknown fields and fields named prompt. All remaining document fields are carried through literally and trigger zero lookup calls.

A marker is a mapping with one authored tuple whose key is exactly a string-tagged `$var`. Its value must have YAML string type, be nonblank, and have no surrounding whitespace. Use `Character.isWhitespace` or `Character.isSpaceChar` over code points as the shared whitespace predicate for blank names, name edges and blank returned values, and cover representative Unicode whitespace in tests. The name is otherwise opaque and case-sensitive. Quoted `"123"` works. A multi-key mapping containing `$var` is ordinary data, and all of its descendants are walked normally. Strings containing placeholders or marker-looking text are ordinary strings.

Discover in document order, with depth-first authored tuple order, key before paired value, and sequence index order. Keep every occurrence, including repeated aliases at distinct authored use paths. The distinct-name projection preserves first occurrence order. Discovery validates marker syntax without accessing a value source. Substitution validates the document's marker shapes before lookup and replaces each marker with one nonblank string. Preserve the exact returned string, including leading/trailing whitespace around nonblank content, YAML punctuation, newlines and literal placeholder text. Returned strings are terminal scalar leaves.

### Paths and original locations

Use an empty root path internally. A string key matching `[A-Za-z_][A-Za-z0-9_-]*` uses dot notation, omitting the initial dot. This deliberately includes hyphens so `api-key`, `base-url` and `X-Region` agree with the ticket's examples. Every other string key uses a JSON-quoted bracket segment, including empty, dotted, Unicode, quote, backslash and control-character keys. Apply JSON string escaping, with tests for exact resulting characters. Sequences append `[i]`.

At authored entry index i, a key marker has `parent{key#i}`. Its paired value has `parent{value#i}` until the key is resolved. Preserve this authored path for discovery and diagnostics even if the resolved key has a readable name. For any other non-string key, use the same entry-index addressing for key descendants and paired values, avoiding stringification of complex keys. A literal string key's value uses its normal named path. Key traversal occurs even for composite keys.

Keep original tuple metadata until the full map has resolved. Before inserting an effective key, detect equality against earlier keys in that map. For a string collision involving a resolved key, report both original locations, including the literal sibling's authored value path or the other key's `{key#i}` path. Never insert first and discover the overwrite afterward. Distinguish unresolved discovery from materialization so keys that require values remain available for staged validation. Duplicate literal-key behavior must agree with the current YAML reader when values are materialized.

### Materialization and failure fidelity

Build fresh ordinary maps/lists from resolved nodes, preserving scalar construction through the shared SnakeYAML constructors. A copied node tree with string-tagged replacement nodes followed by standard construction is acceptable if collision checks run before constructor overwrite and raw document nodes remain reusable. A direct ordered materializer may use standard scalar constructors. Preserve aliases where practical and ensure bounded processing for all supported inputs. Handle existing supported tags consistently with `YamlValues`; add focused tests if construction ownership changes.

Missing or blank lookup results and callback failures produce structured exceptions with filename, authored path and a fixed reason. Catch callback failures without retaining a cause whose message can include supplied values. Collision exceptions carry two authored locations and a fixed reason. Keep supplied values out of custom record `toString` output used by these error paths. This is construction of resolution diagnostics under the ticket contract, with no field-name heuristics or general content rewriting. Existing journal projection behavior remains governed by AGENTS.md.
