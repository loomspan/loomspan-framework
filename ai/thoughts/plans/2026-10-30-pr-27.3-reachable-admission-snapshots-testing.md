# PR 27.3 Reachable Admission Snapshots Testing Plan

## Change Summary

Root invocation/handoff capture and retain reachable namespace generations, rerun existing dependency policy against that immutable view, and preserve prepared derived contracts. Temporary root validation performs the same checks without reserving execution. All root overloads parse canonical qualified identity and retain existing input, authentication, observer and ownership behavior.

Profile: full, developer approved. This plan accompanies `2026-10-30-pr-27.3-reachable-admission-snapshots.md` and its contract classification. No tests were run during planning; all commands below are planned verification, not claimed passes.

## Impacted Areas and Risk Assessment

High-risk changes are coherent selection/lease acquisition, partial failure cleanup, transitive contract comparison, admission versus publication semantics, and ownership through physical work after a logical timeout. Root operation risks include normalization inconsistency, accidental child role prechecks, stale catalogs pinning execution, authentication leakage, nested-root cleanup, and accidental provider construction during validation.

Application API protection applies to existing signature set, qualified semantics, descriptor use, observers, admission ID and temporary validation. Manifest policy remains existing policy rechecked against current captured targets. Internal Capture/runner/binding signatures are updated directly with no compatibility bridges. No persisted format or new diagnostic shape is introduced; preserve existing observer/journal behavior, including the documented journal redaction exception, without extending content rewriting.

- **Names:** `capturesEveryReachableSkillOnceAndOnlyReachedNamespaces`, `checksRepeatedTargetEdgesAndTerminatesOrdinaryCycles`, `javaSkillsAreLeaves`.
- **Proves:** two different reached skills in one namespace are both visited; optional and denied-role branches count; shared descendants/ordinary cycles terminate; an invalid second edge is not suppressed by visited target; captured association includes each reached generation exactly once and excludes a namespace referenced only by an unrelated skill in a retained generation.
- **Fixtures:** staged Public a/b/c publications with local multiple children and shared/cyclic edges; independent spare namespace; unrelated skill made broken by later external removal. Publish valid intermediate cyclic graphs rather than stubs/unresolved references. Compare generation IDs, immutable map behavior, retirement counts and no duplicate owner retention.

Remove selected generations after capture and verify zero retirement until release, then exactly one event per ID. For failure, arrange early reached namespaces then missing later target; replace/remove earlier generations after failure and assert immediate retirement.
- **Deterministic blocked validation seam:** inject/spy the existing SkillInputContractResolver through manager fixture and block resolving a reached YAML contract with latches; after validation has entered, bounded Future publication/removal must complete before releasing resolver. Use a retirement callback that launches a bounded independent registry operation to prove callbacks occur outside monitor, reusing existing tests. ### 6) Temporary validation versus reserved handoff

- **Type/location:** integration, `SkillReachableAdmissionTest`/`DefaultSkillTemplateTest`.
- **Names:** `validationAndAdmissionAgreeOnUnchangedDependencyState`, `validationChecksOnlyEntryRolesButTraversesRestrictedOptionalChildren`, `successfulValidationDoesNotReserveViewOrAuthentication`, `validationAndAdmissionLeaseWithoutConstructingRuntime`.
- **Proves:** valid input/RBAC with broken reachable missing/Private/incompatible target rejects both; broken unreachable target permits both. Valid reachable restricted optional child does not fail merely because caller lacks child role; make its dependency broken and both fail, proving no role pruning. Invalid input/root denial closes temporary leases and creates no root. Validate succeeds then dependency removal/visibility/schema, changed root authentication, or framework shutdown makes later invoke fail.
- **Side effects:** counted runtimeFactory/registry construction unchanged during validate/handoff/admission; zero handler/model/router invocation during validate/handoff; no root registration, fresh session, trace, observer, provider attempt or reusable return. Remove all selected generations after each success/failure and assert retirement, including conversion/error/authentication failure paths. Use lifecycle spy for validation no-admit proof without mocking dependency policy.
- **Surface:** Application API validation; preserve existing AccessDeniedException/null-map/error behavior and child execution authorization boundaries.
