## Implementation Approach

Reuse the model-detail semantic loader pattern rather than raw-envelope parsing. Add a small attachment-specific detail/parser/component within the existing record-detail mechanism (extract a focused component only if it materially simplifies the already large file). Validate JSON collection/object shapes for reliable display without implementing attachment/schema business validation in the browser. Render recorded keys/values faithfully, including arbitrary nested metadata; never classify or rewrite content. Preserve zero, null, empty values and unknown recorded metadata. Optional absent fields should be described as unavailable/unspecified without inventing values.

Offer the action for `FRAME_METADATA_RECORDED` records; the payload is authoritative for whether a collection exists. An absent collection is a valid no-attachments state, not a successful attachment inferred from the type. Malformed present collections report a display error. Distinguish an empty collection from unavailable content. Prefer complete inline semantic content; otherwise read the complete `contentRef` with `verifyScope` on every range. Do not parse a partial capture as a complete collection. Preserve artifact-expiry reporting and reset/hide detail with existing scope-generation behavior; ensure old scoped results cannot be exposed under a new scope.

### Implementation decisions

The view validates only JSON object/descriptor-collection shape, then renders the
original complete semantic JSON text. It deliberately does not stringify parsed
descriptor numbers: that would round metadata such as `9007199254740993` or long
decimals. A focused regression retains numeric lexemes and string whitespace.
This is a display check, not an attachment business/schema validator. Missing
and empty collections have separate messages; unavailable/incomplete capture and
malformed content have errors. Recorded descriptors need no Java/Go/TypeScript
DTO expansion or compatibility-version change.

The attachment detail is a scoped, mounted component rather than another durable
cache. Hiding it releases detail state; reopening deliberately reads again.
Trace/source/generation changes and record removal unmount it and discard pending
results and callbacks. The existing complete semantic loader still verifies each
ranged response and joins bytes before UTF-8 decoding. Existing raw inspection is
unchanged. This keeps lifetime local and prevents reuse across evidence scopes.

Documentation comparison is **aligned** after updating the obsolete Console
attachment-rendering limitation. The repository-local `loomspan-docs` router and
topics match this checkout. Guidance identifies the action, source channel,
absence/capture distinctions, preserved content, evidence anchors and independent
provider/public-invocation limits; the index routes directly to it. A reader needs
no ticket history to use the view. No existing provider/public invocation limit
was turned into an acceptance claim.
