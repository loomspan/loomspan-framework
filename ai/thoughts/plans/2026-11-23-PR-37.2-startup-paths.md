# PR 37.2 startup path spelling implementation plan

## Overview

Make startup YAML loading reject uppercase spelling in the relative definition path, including candidates that a case-sensitive configured glob would omit. Keep the caller's supplied filename check ahead of literal lookup. Supplied `SkillDocument.sourceName` remains an exact diagnostic label through public validation and preparation.

The selected route is the Full 5-Step Pipeline. The developer approved that route, breaking changes without compatibility shims, sequential local commits, and current-state product documentation. Planning starts from PR 37.1 commit `b88e24e`. The proposal, research and later tickets are developer inputs. This stage writes only the implementation and testing plans.

## Desired end state

For `classpath:/skills/**/*.yaml`, both `Orders/lookup.yaml` and `orders/lookup.YAML` produce an error identifying the relative path and offending directory or filename. The behavior is deterministic for real filesystem, exploded classpath and packaged JAR resources. It holds when the host's normal glob would omit the candidate.

For literal `classpath:/skills/Orders/lookup.yaml`, the checked relative path is `lookup.yaml`. The uppercase fixed directory is allowed. A caller-supplied uppercase literal filename fails before lookup, including on a case-sensitive host where that filename would be absent. A literal resource found through a case-insensitive filesystem must also report uppercase actual filename spelling.

The two supplied labels `Orders import #42` and `Orders/lookup.yaml` succeed through both public `validate` and `prepare`, with exact labels available in diagnostics and source metadata. Invalid namespace or manifest names still fail identity validation independently of the label.

## Implementation approach

Use a loader-owned `PathMatchingResourcePatternResolver` with an `AntPathMatcher` configured case-insensitive for candidate discovery. Continue using each original configured location. Validate exact relative spelling of every returned candidate before loading bytes. This discovers `lookup.YAML` and uppercase wildcard-matched directories without changing which valid lowercase definitions the pattern selects.

Narrow internal resolver constructor parameters to the concrete Spring resolver where that makes ownership explicit, and update checked-in callers directly. Every current caller creates a fresh resolver. Configure that supplied resolver in place before discovery so its existing ResourceLoader, classloader and protocol delegation remain intact. Keep it private to catalog loading. Do not reconstruct it against the default classloader or mutate application-wide Spring resource infrastructure. The alternative of enumerating every resource beneath the fixed prefix and filtering in Loomspan adds work and duplicate matching and is unnecessary with the verified dependency and internal wiring.

Relocate `SkillSourcePathResolver` to `ai.loomspan.internal.skill` as the shared authority for fixed-prefix/literal path derivation. Update the observation catalog and test imports. Keep label handling first in `resolve`, so labels never enter structural or case validation. Give startup discovery an explicit path validation operation. Avoid coupling the YAML loader to observation or retaining two root/prefix algorithms.

## Phase 1 — Discover and validate exact startup paths

1. Add a minimal failing startup test for `orders/lookup.YAML` under lowercase `**/*.yaml`. The baseline silently omits it, so assert an error naming that path and `lookup.YAML`.
2. Configure the catalog-owned resolver as described above. Preserve configured pattern semantics, resource existence checks, absent-root handling, error wrapping and deterministic resource ordering.
3. Reuse the relative-path helper from the skill package. Interpret a pattern relative to the directory before the first wildcard, excluding protocol prefix markers. Interpret literal locations relative to their filename. Fixed prefix spelling is outside the checked relative path.
4. Validate caller-supplied relative spelling before `getResources(location)`. For literal locations check only the supplied filename, even when absent. For patterns check uppercase in the relative pattern's literal text and components while retaining wildcard syntax. Include the original relative spelling and offending component in errors.
5. Validate actual candidate spellings before opening YAML. Case-insensitive matching serves candidate enumeration only. Compare each exact decoded directory/filename component against its lowercase spelling using `Locale.ROOT`. Do not lowercase any resource path, label or YAML content to make it pass. Preserve existing structural-path checks.
6. Derive relative names from actual returned resources. For file-backed resources use actual filesystem name spelling, including case-insensitive literal resolution. Keep the configured fixed root separate from the checked relative path. Avoid following a symlink merely to change the diagnostic filename. For archive resources use exact decoded entry spelling. URI escape hex digits must not be treated as path letter casing, and roots containing spaces must work. Preserve existing descriptive source-path semantics.
7. Route errors through the existing configured-resource feedback and startup failure path. A clear discovery error may stop discovery as it does today. Its message must identify the offending directory or filename and the full checked relative path. No malformed definition may be silently skipped or loaded under a changed spelling.

## Implementation decisions

- Caller classpath locations retain literal percent characters because Spring classpath lookup treats them verbatim. File/JAR URI paths decode escapes before spelling validation. Focused tests cover lowercase percent filenames, uppercase literal percent text rejected before lookup, and encoded lowercase Unicode filenames.
- Temporary-JAR test resolvers use `setUseCaches(false)` so Windows can close/delete test archives. Production resolver caching keeps its existing setting.
- The existing observation catalog test contained `Alpha` and `FetchDns` declaration fixtures rejected by PR 37.1. Their declaration names and exact assertions use valid lowercase names so the required source-path regression test executes. Console identity contract conversion remains assigned to PR 37.6.
