## Risk Assessment

- Boot-first management could select transitives different from AI's build platform. Resolve the root tree rather than equating a published module POM with root acceptance.
- SDKs use Jackson 2 while Framework/NetworkNT use Jackson 3. Verify both families, exact versions and dependency paths without excluding a required SDK library or introducing broad version overrides.
- New builder signatures, tool-manager defaults, metadata/usage/error shapes or timeout/retry behavior could break the current runtime despite compilation. Exercise existing local adapter and startup tests.
- Preserve one Spring AI tool loop, complete callback authorization/validation before execution, exact physical attempt ownership and existing stream closure.
- Preserve canonical prompt/input/output/tool/trace fidelity; keep current journal projection exception. No classification or content-rewriting assertions are introduced.
- Protected paths: allowlisted application API, documented connection/model/manifest behavior and current diagnostic coherence. Supported SPI: none. Persisted/serialized behavior and Java-to-Go protocol: no change planned.
- Intentionally removed obsolete paths: none in this ticket. A mechanical internal signature update replaces its old call sites atomically, without compatibility overloads. Responses/Ollama removal and reconstruction changes remain 30.1.2 work.
- Skill-authoring claims: none change. Routed current model/connection guidance is **aligned** with retained executable behavior; its coverage table requires no change. README platform statement must match actual resolution.
