## Desired end state

TypeSafe exposes one immutable compiled standard descriptive result schema through its existing internal accessor. Authored inputs use shared exact/no-coercion validation and reject attachment declarations everywhere supported, including map values. The native evaluator still accepts every object-valued answers value regardless of descriptive schema conformance.

Evidence compiles recognized annotations from root properties using the existing parser and exact property keys. Source/canonical text remains untouched; final presence includes explicit null. Effective catalog schema strings use a structural copy that preserves every accepted standard keyword and excludes only recognized execution annotations at schema-node locations. Forwarding never adopts producer-local evidence contracts. Public descriptor signatures and Console text rendering stay unchanged.

Completion requires the companion testing plan's acceptance matrix, verified ticket-owned boundaries, appropriate deterministic Console checks and a fresh independent clean Step 5. ## Implementation approach and settled decisions

1. Build standard JSON result nodes in TypeSafeDeclaration and compile once with StandardSchemaCompiler Role.OUTPUT/Origin.GENERATED. Store/return CanonicalSchema through the existing internal accessor; its tree() supplies detached copies. Do not invoke validate() on native responses. Keep every current shape, required list, enum, description and boolean openness, including explicit empty properties/required where represented. No numeric bounds or typed dynamic maps.
2. Replace TypeSafe attachment traversal with schema-node JSON traversal after shared input-schema validation. Reject x-loomspan-attachment on properties, items and schema-valued additionalProperties with the full declaration path. Ignore matching ordinary data property names as annotations. Shared validation owns malformed annotation shapes.
3. Extract evidence from canonical root properties and their textual x-loomspan-evidence. Reuse the parser/direct-child checks unchanged; preserve source text and token columns. Shared compilation owns placement and scalar shape. Use x-loomspan-evidence in expression error paths.
4. Simplify EvidenceContract to one immutable insertion-ordered expressionsByClaim map and a one-map internal factory. Exact map membership drives expressionForClaim and presentClaims. Remove the normalized index, Locale dependency and normalization helper; migrate all internal factory callers. Do not alter skill identity parsing, expression operator normalization or native TypeSafe question/candidate collision rules.
5. Add an explicit CanonicalSchema.structuralTree() detached-copy operation using the existing schema-node annotation-removal walker. providerTree() can delegate to this common operation; its existing API remains useful for provider request callers. SkillDependencyValidator must use structuralTree(), so catalog meaning is independent of provider request adaptation. Do not duplicate walkers or reconstruct a keyword whitelist. Strip recognized execution annotations only at schema nodes, retaining arbitrary matching property names, descriptions and all standard assertions.
6. Keep already-correct schema-tree decimal decoding. The implementation may need no request/response parsing change if focused tests confirm it. Any actual TypeSafe-specific precision gap is fixed locally without changing response acceptance or shared application mapper settings.
