Reachable execution snapshots remain downstream work.

## Desired End State

One canonical namespace maps to one active immutable generation containing visibility, supplied declarations, assigned fixed Java capabilities, execution configuration/runtime, and prepared contracts. Capture a target base (nullable for strict absence) and coherent external metadata once before expensive work. Every later reference into the target namespace uses the candidate. Publication compares only that target base plus ownership/state/lifecycle. Removal compares expected active ID and withdraws without waiting for owners. Existing owners determine physical cleanup after replacement, removal, and shutdown.

### Public API choice

Add the deliberately supported `ai.loomspan.api.NamespaceVisibility` enum with `PRIVATE` and `PUBLIC`. A named two-state value makes authorizing foreign calls reviewable without introducing a publication/configuration facade. Add it to the exact public allowlist and README/Java API type inventory. Keep visibility authoritative on the immutable generation; no second independently mutable registry property or visibility-update API.

Use these namespace-first complete management signatures (types abbreviated):

```java
SkillValidationResult validate(String namespace, Collection<SkillDocument> documents,
        ExecutionConfiguration configuration);
SkillValidationResult validate(String namespace, Collection<SkillDocument> documents,
```

Overloads omitting visibility always select `PRIVATE`, including replacing a Public generation. Explicit null visibility/configuration is invalid. Existing validation does not resolve credential values, so do not add credential-map validation overloads. Preparation keeps Environment resolution or explicit copied-map resolution; the explicit map has no Environment fallback. Remove all public default-only, no-input, and document-only preparation/validation overloads. No public base accessor, revision type, namespace view, visibility annotation, enumeration API, or alternate configuration type.

Normalize namespace at every management boundary with `SkillIdentity.normalizeNamespace`, retaining independent 32-character and combined-identity limits. IDs retain the existing manager prefix plus atomic counter, never reused across namespaces/removal/recreation. Catalogs and validation feedback remain target-local, immutable, and qualified; an empty namespace identifies itself.

## Implementation Approach

### Registry, synchronization and lifecycle

Replace `active` with a namespace map guarded by the existing `generationMonitor`; retain `published` ID ownership states. Manager operations perform target comparison and activation/removal atomically under that monitor. A preparation capture returns a small immutable internal receipt with target base ID and a copy of the external namespace associations. Validation uses its own coherent capture but allocates no ID. No later refresh of preparation base or metadata is permitted.

All registry capture, selected-generation lease acquisition, activation, removal, and destruction selection use this same monitor. Publication/capture admission check ordering remains lifecycle admission monitor before registry monitor. Candidate state is additionally guarded by the candidate monitor; never acquire a candidate lock from registry/retirement paths. Snapshot metadata selection needs the registry monitor only. No expensive parser/schema validation, provider/handler construction, resource close, or callback runs under registry or lifecycle locks. Return retirement selections and dispatch after leaving every such boundary. Removal does not wait for drainage; a synchronously eligible close/callback can follow withdrawal outside the monitor using the existing mechanism.

Candidate state remains framework-owned, one-shot, and separate from registry state. Hold candidate synchronization through publication ownership transfer; concurrent close either wins before publication or becomes inert after transfer. Rejection closes only an unpublished owned candidate, once. Mark detached close state under candidate synchronization and perform actual resource close outside registry/lifecycle locks. Foreign candidates are rejected without closing another framework's object. Preserve checks before preparation, after successful construction, and at publication; a post-construction shutdown rejection disposes of the completed candidate. Slow construction is not forcibly interrupted.

### Metadata and reusable contract policy

Factor manager's current contract/resolution helpers into a focused internal validator (for example `SkillDependencyValidator`) usable later with a supplied captured namespace view. Do not invent a transaction or general overlay framework. The resolver has exactly one overlay rule: target namespace uses candidate definitions and fixed registrations; every other namespace uses the once-captured immutable view. Metadata view may retain immutable generation references but validation must only read the audited fields: namespace/visibility, immutable definitions/constraints, input contracts, kind and schema/tool metadata. Never read clients, invoke callbacks, resolve live providers, or use REST/application invokers.

Current audited reads are independently usable after runtime close; therefore this implementation needs no executable lease for metadata-only preparation. Record that audit in implementation results and keep it true. If an implementation adds a retirement-sensitive read, acquire existing temporary ownership atomically during capture and release it on every success/error path immediately after validation, before provider construction. Do not hold external dependencies while a candidate waits for publication.

Validate every candidate skill and each outgoing edge required by existing rules. Follow reachable external declaration edges/contract resolution when needed, including paths returning to the candidate; do not scan incoming/unreachable external skills. A per-skill visited set terminates ordinary reference cycles, while edge checks occur even when a target was visited. A separate forwarding/schema recursion stack preserves existing forwarding-cycle errors. Selecting a namespace does not mark all its skills visited. Cross-namespace edges require Public target visibility, even when the target is Java, and source-to-target checks use the actual edge source. Same-namespace calls work Private. A path from an external namespace back into the candidate requires the candidate's proposed visibility.

Resolve external input contracts for child binding validation and recursively compute effective output schemas from definitions through the overlay. Do not simply reuse old external derived schema when its forwarding path returns into the candidate. Preserve TypeSafe schemas, REST/Java unspecified schema behavior, output openness rules, binding producer counts/paths/type checks, missing-name diagnostic suppression for failed candidate documents, and existing contract/cycle validation. Derived candidate contracts remain stored in its generation/capabilities. Errors reject preparation before providers are built, not warnings deferred to admission. Validation feedback includes only target supplied/fixed skills.

### Configuration and isolation

Each complete preparation uses fresh `ExecutionConfigurationParser` properties, fresh `YamlSkillCatalog`, local definitions/contracts/diagnostics/derived schema maps, copied document collection and copied credential map. Do not copy startup `skills` paths into parsed publication properties. Parse/check declarations without credential resolution, then resolve authored references by the selected credential path and build an independent runtime/registry. Omitted supported scalars use parser built-in defaults; models/connections have no fallback. Retain the exact accepted nested fields and rejection of host/unknown settings. Publishing cannot mutate startup/host properties.

Internal startup loading may retain a clearly named configured-resource path; remove generic `current*` inheritance and incomplete publication helpers. Update internal test factories to accept complete inputs; do not retain internal overloads for compatibility. Catalog suppliers must return fresh mutable instances, including tests. Reuse only completed immutable Java metadata and the existing fixed REST handler identity. Do not invoke a Java skill or REST handler implementation during preparation.

### Startup and removal

Track startup completion independently of active-map emptiness. Explicit one-time initialization can still be requested by early auto-configuration wiring and the singleton callback, using existing narrow startup/fixed-discovery synchronization; this is startup-only, never a lock around ordinary publication preparation. Build startup generations outside the registry lock, then install initial associations under it. On startup failure close any already constructed detached startup runtimes once. Do not infer restart/initialization from a missing `default` or Java namespace.

Group fixed registrations by canonical namespace. Create Private `default` from configured declarations plus its Java methods, and Private other Java namespaces from their assigned methods only. Each runtime snapshots the same startup settings independently. Startup default same-namespace qualified references validate normally; all foreign Private references fail ordinary source-to-target validation, including Java targets. No delayed or exempt validation. A coherent fixed-only startup metadata view can establish other Private namespaces for useful errors without a dependency-aware coordinator.

Adapt early registry bean wiring to explicit one-time startup initialization and `default` selection. Adapt direct entry to parse the requested root identity and capture the owning namespace's generation/lease. It must permit ordinary direct Java entry immediately after startup and fail while that namespace is removed; no implicit recreation. Do not add full reachable dependency snapshots here. Replace no-argument active lookups in remaining internal consumers with their explicit existing default scope or record the exact downstream blocker rather than adding a global aggregate/fallback.

Removal normalizes namespace, requires nonblank expected generation ID, checks lifecycle and exact active ID, removes that association, and marks its ownership state superseded. Missing/wrong-ID removals fail without modifying state. An old-base candidate stays stale after removal/recreation; an absence candidate can publish when the target is absent again. Leave fixed bindings/beans intact; recreation includes them automatically and allocates a fresh ID. Existing owners can finish and trigger retirement later. Restart is a new manager rebuilt from startup state, Private again, with no adoption of runtime removals/publications.
