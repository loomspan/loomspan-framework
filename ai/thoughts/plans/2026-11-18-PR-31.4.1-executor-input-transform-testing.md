# Executor input transform testing plan

## Change Summary

Executor YAML optionally compiles `input_transform` as JSLT at preparation and
evaluates it at the common Java handoff after ordinary assembly, validation and
reference resolution. The expression receives business JSON and returns the
complete v1 invocation input object. Constructed nulls and empty containers survive.

This is Step 3 of the approved Full 5-Step Pipeline and follows the companion
`2026-11-18-PR-31.4.1-executor-input-transform.md` implementation plan. This stage
designed verification and ran no tests. Actual outcomes belong to Step 4 and the
fresh Step 5 review.

## Impacted Areas and Risks

| Area | Principal risk | Required evidence |
| --- | --- | --- |
| Raw manifest ingress and binding | Coercion accepts invalid declaration values, or field presence escapes form checks | Raw shape/type matrix and contextual issue paths |
| Definition copying and preparation | Recompilation/mutation changes captured execution or a failed candidate replaces active state | Defensive copies, failed preparation and retained-handoff tests |
| Common Java route | Direct/child drift, duplicate application or config contamination | Public direct/planned equivalence with exact ticket expression and separate config assertions |
| JSON conversion | Handles stringify, keys change, null/empty values disappear, or numbers lose content | Strict helper tests and handler exclusion after reference resolution |
| Lifecycle and authorization | Transform route bypasses caller checks or original deadlines | Existing boundaries plus a transformed denial and lifecycle assertion |
| Diagnostics | Native executor shape displaces caller input/schema/source | Catalog/source and canonical mission-input assertions |
| Dependency delivery | Hidden preinstalled JAR requirement or incompatible Jackson selection | Fresh-source bootstrap, empty local-repository resolution and actual dependency tree |

Application API protection comes from AGENTS.md and the architecture allowlist.
The exact v1 invocation remains the executor author's supported boundary. Internal
helper signatures may change atomically. Manifest omission, config separation and
ordinary handles are explicit protected ticket requirements. No obsolete public
path is being removed. No Console wire shape or compatibility-marker change is
planned. Derived journal behavior retains the existing documented exception.

## Tests to Add or Update

### 1. Declaration matrix

Unit cases in `src/test/java/ai/loomspan/internal/skill/ExecutorDeclarationTests.java`.
Use checked supplied documents with source/skill assertions. Cover valid block
and inline expressions, omitted transform, and model-form rejection for every
present value. Transform values include null/bare field, scalar, array and empty
object. Cover missing fields, null/boolean/numeric/container language/expression,
blank expression, exact unsupported language, and unknown nested fields.
Invalid syntax must report `input_transform.expression` and fail before any
handler exists. Unknown top-level fields remain errors. Built-in JSLT syntax and
default classpath import compilation keep ordinary parser behavior, with a
missing-import case failing preparation. No framework-specific import registry is
introduced.

Affected surface is manifest behavior. No mocks are needed.

### 2. Compiled expression and strict JSON behavior

Add `src/test/java/ai/loomspan/internal/skill/ExecutorInputTransformTest.java` for
the package-private helper, adapting the name to the final helper if necessary.

- Evaluate the exact acceptance expression with the business fixture below.
- Assert an object with null-valued keys, nested empty objects/arrays, empty root
  `{}`, empty input, scalar/null elements in arrays, exact case/dot/slash/tilde
  keys and literal `${/input/notResolved}` strings. Use `LinkedHashMap` or
  `Arrays.asList` where null is intentional.
- Pass a finite decimal and a large integer through an identity/nested transform
  and verify content without double conversion. Include ordinary finite scalar
  kinds accepted by `SkillInputValidator`.
- Reject Resource, InputStream, byte[], arbitrary object, Java array, nested
  non-string map keys and non-finite numbers before Jackson conversion. Include
  a handle whose serialization/getters or `toString()` throws to establish that
  the conversion boundary never inspects it. Failure text identifies the path
  and type, without invoking arbitrary value formatting.
- Reject runtime scalar/string/boolean/array/null results with a root-object
  error. Use a known JSLT runtime error such as `error("fixture failure")` to
  preserve an evaluation cause. Constructed non-finite numbers must fail if the
  parser can emit them. Establish the precise expression against pinned source.
- Apply one prepared expression concurrently to distinct business objects and
  assert every output matches its own input. This checks the fresh-scope property.

Affected surface is internal implementation supporting manifest/runtime claims.
Use the real pinned parser and Framework mapper, with no mocked expression.

### 3. Direct and planned child equivalence

Add `src/test/java/ai/loomspan/integration/ExecutorInputTransformIntegrationTest.java`.
Use `ApplicationContextRunner`, `FixtureExecutor`, temporary YAML and
MockWebServer with deterministic accepted flight-plan output. Exercise public
`SkillTemplate.invoke` for the direct leaf and explicit planning parent. Use a
closed child business schema with required `context`, `policy`, `candidates` and
`parameters`, and bind each whole field from its parent's input. This supports
the existing automatic assigned dispatch after a real accepted plan. Assert the
planner/child contract has business fields and the handler receives equal objects
for both calls.

The leaf uses the ticket expression verbatim. Use input equivalent to the following.

```json
{
  "context": {
    "a/b": "slash value",
    "a~b": {"KeepCase": "tilde value"},
    "message": "Acme",
    "repeat": true,
    "count": 3,
    "history": ["First history item", "Second history item"]
  },
  "policy": {"requireReview": true, "nullable": null},
  "candidates": {"sales": {"description": "Sales team"}},
  "parameters": {"levels": {"low": 0, "high": 10}}
}
```

Assert the full expected object, including `model`, copied `contact`, selected
slash/tilde values, exact literal, `Repeat=true; count=3`, computed question,
structured policy and criteria, first history item and explicit
`questions.repeat.criteria.true` null. Independent expected values make duplicate
application visible because the transformed object lacks original business fields.
Count handler calls and assert input immutability. Add distinct skill/executor
config sentinel values and prove they stay in their existing accessors, with no
automatic merge into expression input.

Affected surfaces are manifest behavior and supported public invocation. Use the
real router, generation and worker machinery. The provider is the only local fake.

### 4. Failures exclude handler execution

In the same integration fixture, test invalid direct business input and invalid
assembled child input. Handler count remains zero for each failure. Add generic
or runtime-ref-capable transformed leaves that accept a Resource directly and
resolve an actual `ref://` to a Resource, then fail JSON admission at the handoff.
Cover scalar/non-object output and `error(...)` evaluation failure with unchanged
handler counts and ordinary terminal failure behavior.

Exercise a transformed executor leaf with denied YAML/composed executor policy
using the existing authenticated context fixture. Access denial must precede
handler entry. A failing expression in a denied leaf can establish that denied
calls also do not evaluate the expression. Reuse the existing declarative access
tests for policy composition breadth.

Affected surfaces are runtime failure and existing authorization boundaries.

### 5. Captured expression, preparation isolation and diagnostics

Extend `ExecutorGenerationExecutionIntegrationTest` or use a focused generation
test in the new integration class. Publish a leaf whose transform emits version
`old`, retain a public `SkillInvocationHandoff`, publish version `new`, and invoke
both fresh and retained work. Outputs must prove captured old/new expression
selection from the leaf generation, independently of the executor namespace.
Attempt preparation with invalid syntax/shape, assert the active generation ID
and fresh behavior stay at `new`. No application invocation occurs in preparation.

Assert the public descriptor/catalog ordinary input schema still contains the
business contract and retained YAML equals authored YAML including expression

`missionInput` persists for the transformed call. Validate failure visibility via
the existing execution event/trace path without changing wire fields. Include a
live cancellation/remaining-time read inside a transformed executor or extend an
existing lifecycle fixture, then run the surrounding lifecycle suite. Delay

Verify that the mission worker returns without entering the executor.

Affected surfaces are supported reload/handoff, manifest behavior and current-run
diagnostics. Reuse actual namespace publication and admission.

### 6. Omission and v1-only consumer

Existing direct, standard-child and explicit-child executor tests must continue

omitted-transform case only where existing coverage does not cover the new

## How to Run

JDK 21 and Maven 3.9+ are required. In this environment Maven uses JAVA_HOME
`c:/hamdev/jbrsdk21`; Java tools can be invoked by absolute JAVA_HOME path or a
command-local PATH adjustment. The bootstrap requires Git, network access to
upstream and its declared build repositories, and the upstream Gradle wrapper.

Use quoted Maven properties in PowerShell. Substitute the exact red-test method
name after creating it. These commands are required, and Step 4 records the exact
forms actually used.

```powershell
mvn '-Dtest=ExecutorDeclarationTests#executorInputTransformLoads' test
pwsh -File ai/scripts/install-jslt.ps1 -BuildDirectory target/jslt-clean-source -MavenRepository target/jslt-clean-m2
mvn '-Dmaven.repo.local=target/jslt-clean-m2' dependency:get '-Dartifact=ai.loomspan.thirdparty:jslt:0.1.15-jackson3-cf30e6d' '-Dtransitive=true'
mvn dependency:tree '-Dincludes=ai.loomspan.thirdparty:jslt,tools.jackson.core:jackson-databind'
mvn '-Dtest=ExecutorDeclarationTests,ExecutorInputTransformTest,YamlSkillDefinitionTest,YamlSkillCatalogTests,SkillGenerationManagerTest' test
mvn '-Dtest=ExecutorInputTransformIntegrationTest,DeclaredChildInputBindingsIntegrationTest,ExecutorGenerationExecutionTest,ExecutorGenerationExecutionIntegrationTest,ExecutorApplicationIntegrationTest,ExecutorInvocationLifecycleIntegrationTest,SharedDeclarativeAuthorizationIntegrationTest,SkillRoleEvaluatorTest,ConsoleRestFixtureCorpusTest,DefaultRegisteredSkillCatalogTest,LoomspanPublicSurfaceArchitectureTest' test
mvn test
mvn '-Dmaven.repo.local=target/jslt-clean-m2' '-DskipTests' install
git diff --check
```

The empty local repository resolves ordinary Maven dependencies from their
configured remote repositories and the interim artifact from the local install.
Use absolute local-repository paths for actual commands to avoid workdir ambiguity.
Do not seed the pinned artifact by copying an existing .m2 JAR. After installation,
run the temporary consumer's `mvn compile` with that same absolute repository.
Record Gradle test/build results, bootstrap and consumer outcomes separately.

The first red test must run before implementation. Bootstrap may precede it if
needed for dependency availability. Final implementation verification should run
focused suites before the full suite. A later fresh reviewer selects sufficient
independent verification under Step 5. No paid or live model provider is required.
