# Console/MCP executor inspection implementation plan

## Overview

Implement the existing generic executor diagnostic contract in Console's readers,
MCP inspection and chronological record UI. Explain that usage totals cover only
Framework-accounted native calls, and establish this with generic executor tests.
This is pipeline Steps 2/3 under the approved Full 5-Step Pipeline. Baseline is
`41113b440ae6cb112a46e99ebbd7f8963d3e1bd3`; only the Step 1 research document was
untracked at planning entry. This plan does not authorize a new provider integration.

## Current State Analysis

Java already emits `EXECUTOR_DIAGNOSTIC_RECORDED` and
`EXECUTOR_DIAGNOSTIC_SYSTEM_NOTICE_RECORDED`. The Go closed vocabulary omits them,
causing the previous ticket's reported `java-root-success` corpus failure with
`UNSUPPORTED_VALUE`. Data/content references, bounded pages and ranged reads already
exist. TypeScript canonical record types are strings; the separate live ActivityKind
union is not the trace vocabulary and needs no new event kinds.

The current record table already preserves sequence and lazily opens content, but
does not present executor diagnostic fields. Default visible types omit the two
events and frame boundaries. Existing failure styling uses Framework failure links,
not arbitrary payload severity. Native usage is updated through native provider
advisors and model response records, not executor JSON.

## Desired End State

Existing authenticated browser inspection and `LOOMSPAN_query_trace_records` /
`LOOMSPAN_read_trace_content` accept and expose mixed ordinary, developer and system
records without changing query semantics, content references, cursor format or
summary shape. Each record remains an individual chronological item in its recorded
frame. Opening a diagnostic shows authored severity, exact retained message and JSON,
explicit states and recorded reasons. Notices have no authored severity. Frame
boundaries, generation, input, output and Framework failures can be inspected in the
same selected-frame record context.

Authored ERROR does not imply failed execution; caught request failures/retries and
negative business results remain opaque authored evidence. Missing events or fields
produce no capture-cause explanation. Totals use the label **Framework-accounted
usage** and retain current values/fields and unknown semantics. Matching compatibility
markers remain `1.0.0-beta.10-SNAPSHOT` as supplied by current release machinery.

- No historical readers, migrations, negotiation, aliases or compatibility shims.
- No changes to prompt/input/output/evidence content or sensitivity classification.

## Implementation Approach

Reuse the existing canonical record/content model. Do not project a second copy of
the diagnostic payload into DTO summary fields: the producer owns its facts and
ordinary DATA descriptors already retain/retrieve them, including chunked envelopes.
In React, add small typed local detail variants and runtime shape checks for the two
payloads rather than a new closed global trace enum or presentation system. Unknown
arbitrary JSON remains inspectable inert content; runtime UI checks protect rendering
and do not rewrite the recorded data or invent producer states.

Reuse frame selection to group records; preserve canonical global order when no frame
is selected. Include frame-open/close in ordinary default selection so automatic
boundary evidence is reachable alongside diagnostics. A selected-frame context can
show existing frame facts and link to/open those boundary records. Do not regroup
the global sequence into blocks that change order or merge items. Use recorded frame
identity, including ROOT_MISSION child frames, rather than route/type heuristics.

Alternatives rejected: eagerly embedding diagnostic payloads in every summary adds
duplicate authority and delivery work; a separate diagnostic viewer loses existing
filters/cursors; treating severity as failure fabricates semantics. No producer
rewrite is needed. Existing accounting calculations already implement the intended
scope, so tests and explanatory text are preferred to a new accounting abstraction.
No unrelated dead-code removal was established by investigation; do not expand scope.

## Implementation decisions and evidence

- The real mixed mission with a missing native usage report retains HEURISTIC
  estimates because ModelUsageExtractor sees ordinary prompt text. UNAVAILABLE is
  correctly selected only when no textual prompt/response or exact usage exists.
  The runtime test protects that existing distinction; ModelUsageExtractorTest and
  the unavailable-usage corpus protect UNAVAILABLE evidence. This is an evidence-
  backed test arrangement, with no change to native accounting semantics.
- Reused named java-root-success and nested-frame-usage fixtures and added
  executor-recoverable-failure / executor-terminal-failure. Eight joined concurrent
  producer events have identical payloads for deterministic byte-for-byte fixture
  generation; canonical sequence preserves each event's identity. Existing runtime
  concurrency coverage independently checks distinct worker payload identities.
- Existing MCP output schemas use compact strings for record type, rather than
  closed output enums. Preserve that shape; validate input enums and actual output
  tool calls for both event values. Tool prose was shortened to keep discovery at
  25,563 bytes under its existing 25 KiB ceiling; current snapshot updated atomically.
- Console details preserve exact retained DATA JSON, including large number lexemes,
  instead of parse/stringify rendering supplied JSON. Selected detail display/read
  is bounded to 1 MiB; the existing Read content action handles further ranges.
- Fixed a hardcoded duplicate-frame-close invalid-fixture sequence to derive the
  next sequence from its selected record when the parent fixture inventory grew.
- Skill-authoring final assessment: Affected, documentation drift resolved. Capture
  guidance remains aligned; Console/MCP inspection and accounting scope now link
  current named tests. No supported signature, Spring extension point, API allowlist,
  usage field/calculation, route/tool or compatibility marker changed.
- Per orchestrator handoff, local commit is deferred until fresh independent review;
  implementation agent does not stage/commit/push. No Extensions files changed.
