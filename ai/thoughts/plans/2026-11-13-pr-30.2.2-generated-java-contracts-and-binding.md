## Design decisions and implementation approach

1. **Canonical producer boundary:** change SkillInputContract's schema component to CanonicalSchema. Implement genericObject and allowsEmptyInput against its canonical tree. Java BPP constructs JAVA_REFLECTED contracts directly from the final compiled generated schema; it no longer depends on SkillInputContractResolver. Leave reduced resolver rewriting to 30.2.3. Remove BPP's resolver factory argument and update owned wiring/callers, rather than retain an unused compatibility dependency. No duplicate legacy schema field or projection.
2. **One effective type list:** resolve each canonical implementation method parameter against the concrete target class and the declaring class's generic bindings. Pass that immutable positional JavaType list to generation and capture it in the invoker for binding. Use Jackson's binding TypeFactory with resolved owner bindings (or equivalent Spring resolved Type, preserving nested arguments); never resolve each stage independently from Parameter alone. Do not replace interface contract selection or proxy method dispatch.
3. **Complete generation before compilation:** generator uses separate application binding mapper and schema-tree mapper. Build final properties/required names directly by parameter position using selected contract names and SkillParam fallback rules; do not mutate/reuse a names map during renaming. Generator returns a compiled canonical contract after names, requiredness, descriptions and runtime metadata are final. BPP uses canonical tree serialization for tool schema, retaining runtime markers internally; provider-copy stripping remains CanonicalSchema's responsibility.
4. **Effective introspection:** use application creation introspection for property names/types and effective annotations, including mixins. Resolve enum JsonProperty names with binding-side enum annotation introspection; ordinary constants use their Java names rather than toString overrides. This bounded correction does not attempt arbitrary custom serializer inference. Inspect custom key deserializer behavior in a focused fixture; prohibited resolved key types remain prohibited even if a deserializer is installed. Do not claim arbitrary custom-key transformations are modeled.
5. **Runtime leaves first:** place the existing Resource/InputStream/byte[] predicate and existing descriptions in one shared internal implementation used by generation/binding. Recognize these before arrays, bean properties and recursion; emit marked string leaves directly. Authored nonblank SkillParam descriptions override fallback guidance exactly, including whitespace/newlines. Absent/blank descriptions retain existing guidance. Remove BPP's now-duplicated post-generation rewrite traversal.
6. **Declaration restrictions:** allow map key JavaTypes String/Object (including raw maps), reject other resolved key types at every exposed location. Reject effective enabled JsonUnwrapped on relevant property members, including fields/getters/mixins and prefix/suffix forms; disabled remains valid. Add UUID to existing string scalar classification without a format assertion.
7. **Recursion:** use an active expansion stack containing resolved JavaType and input path, with removal on return. Reject exact resolved-type cycles, including cycles through containers/map values. Do not treat sibling/separate parameter repetition as active recursion. Finite nesting such as Box<Box<String>> is permitted because the repeated raw type is reached through a finite substituted argument. Include generic declarations whose recursive expansion changes bindings; recognize unbounded declaration expansion rather than relying solely on equal resolved types or imposing a depth cutoff. A repeated raw declaration may continue only when consuming a strictly smaller finite substituted type subtree; repeated/growing declaration expansion is a cycle. Diagnostics identify method, current path and resolved cycle. No open fallback, partial publication or truncation.
8. **Bounded Resource container correction:** establish List<Resource> failure with a read/serialization-detecting Resource, then bind supported container children to their declared types and pass an already type-correct assignable container through without whole-container conversion. Preserve Resource leaves unchanged. Probe map/array/nested-container cases against actual binding before extending the correction; apply the same bounded strategy only where reproduced. Do not use global serializers, read Resource contents to bind Resource targets, or bypass scalar conversion/declared container assignability. Preserve current mapper conversion for unaffected DTO/scalar targets and conversion failures. This phase must not grow into general Java object construction.
