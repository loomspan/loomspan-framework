# Standard planner inability implementation plan

## Overview

PR 29.1 lets standard YAML planners end the current invocation unsuccessfully with an explicit reason. A Java caller receives the supported failure subtype. An enclosing standard tool-calling planner can receive the reason at its existing failed-call boundary and continue within its existing authority. Canonical records preserve the decision and the model messages that led to it.

The developer selected the Full 5-Step Pipeline by replying `proceed` at the auto gate. Baseline `c68280d` has a documentation-only PR 28 cleanup commit ahead of `origin/main`. Preserve the existing modifications to the accepted design, the three untracked series tickets, and `.codex/config.toml`. The current ticket controls scope. The research and two plans under `ai/thoughts/` carry the pipeline context.

## Current state analysis

- `SpringAiModelInteractionFactory.java:34–38` chooses the assembler by mode and does not retain the mode on the returned interaction. `SpringAiModelInteraction.java:39–65` binds callbacks only when application tools exist. Initial planning and step model turns submit empty callback lists in `DefaultPlanningService.java:525–530` and `StepLoopMissionExecutionEngine.java:1089–1090`.
- `CanonicalToolCallingManager.java:23–43` validates all generations before application dispatch. The pinned tool advisor invokes it after the provider advisor returns. The delegate's recoverable exception processor runs inside callback execution, which is too late to stop the declaring planner cleanly.
- `LoomspanSession.java:147–208` owns one identity registry and the first canonical `ERROR_RECORDED` fact. `DefaultMissionExecutionEngine.java:107–157` opens the declaring model frame before the provider/dispatch cycle. Its attachment wrapper can mask recoverability or a lifecycle cutoff as a media error.
- `ProviderAttemptCallAdvisor.java:96–107, 150–169` already captures before dispatch and charges usage afterward. Requests carry only message type/text, with null converted to empty. Responses carry only selected text. `DefaultExecutionTraceRecorder.java:45–69` owns attempt/frame metadata and can receive the new payload unchanged.
- `ExecutionBinding.java:82–90` and `MissionLifecycle.java:399–438` distinguish writable cleanup from open admission. The latter can hold existing ancestry locks across the acceptance write. `MissionWorkExecutor.java:73–114` owns timeout and authoritative cancellation.

## Desired end state

- The unqualified `loomspan_cannot_complete` control is present for `STANDARD` non-planning requests, including a root or child with no application tools. A valid response has exactly one such call across every generation and a closed `reason` object. Dispatch validates the whole selection before any application callback. A valid call records and throws one inability and exits the declaring model loop. Invalid or unbound selections reject terminally without correction.
- `PlannerInabilityException(String reason)` is the sole new supported application API. Its inherited message is exact. Existing invocation, observer, accounting, and completion owners keep their existing semantics. An enclosing standard caller receives `status`, `kind`, `correctionPermitted`, and `message`, associated through the existing Spring AI tool response.
- The canonical failure carries `RECOVERABLE`, `kind: planner_inability`, and the exact exception message. A validated standard model declaration adds a bounded `PLANNER_INABILITY_SIGNAL` diagnostic after the stack and first records on the declaring model frame. Java-origin instances and rejected responses preserve their actual origin and evidence.
- Structured chat request/response payloads preserve exact decoded messages, ordered calls and responses, and every returned generation. TypeSafe remains on its evaluation payload. Verify these outcomes with the companion testing plan.

## Implementation approach

### Phase 1 — Shared public meaning and first failure recording

- Add `src/main/java/ai/loomspan/api/PlannerInabilityException.java` extending `RecoverableSkillException`. Use its single `String` constructor and existing null/blank check, with no additional accessor or mutable state. Add the type to the public allowlist and focused value/consumer tests. Preserve `SkillFailurePolicy` recognized wrapper behavior. Use one internal `planner_inability` constant for canonical kind and feedback.
- Extend `LoomspanSession.recordFailure` with a narrow internal overload for one optional `TraceDiagnostic` at first recording. Existing calls keep their current path and stack diagnostic. Compute kind from the effective subtype and omit it on other failures, independently of classification and completion linkage. Build the stack diagnostic first, append the optional signal, and leave identity deduplication and existing cause/attempt links in the same owner. Ensure callers cannot supply a competing canonical kind through context. Keep unrelated frame metadata and observer projection stable.
- Use a bounded opaque signal diagnostic with the same existing canonical diagnostic budget and content type. Apply UTF-8-safe truncation with explicit metadata, preserving decoded line endings. Keep the stack-only newline normalization confined to stack capture. A truncated diagnostic may be an incomplete JSON text prefix. The separately stored exact exception message and ordinary response evidence retain their normal capture paths.
- Expose a narrow internal bridge at the current `ExecutionBinding` to first record an accepted signal using the current physical branch leaf, session, and mission. Reuse `MissionLifecycle.runWhileOpen` via a package-level entry with the binding ownership check. Check interrupt/open authority before accepting and keep the first write within the existing ancestry fence. The scope guard for ordinary cleanup writes permits `CANCELLING` and is insufficient here. This bridge takes the already serialized signal text and shared failure so the later step producer can reuse it without importing Spring AI or creating a second representation.

Automated check — `mvn -q '-Dtest=LoomspanPublicSurfaceArchitectureTest,ApplicationApiValueTest,SkillFailurePolicyTest,LoomspanSessionTest,MissionLifecycleTest' test`.

### Phase 2 — Bind the control and exit at canonical dispatch

- Pass and retain `ModelInteractionMode` in the internal interaction constructor. Bind one package-private Framework tool callback marker when the mode is standard and `planning()` is false. Add it to the actual per-request options alongside the ordinary callback array. The marker owns the exact name and required closed string schema; it exposes a defensive failure if invoked as an ordinary callback. The manager accepts only that marker in the prompt's bound callbacks and its exact name in the response. Application identities still go through `SkillIdentity.parse`, including `loomspan-loomspan_cannot_complete`. When definition validation is used, grant the exact exception only for this actual bound marker.
- Extend `CanonicalToolCallingManager`'s pre-delegate scan to consider selections across all returned generations. With no accepted control, preserve the canonical application-only dispatch and original response evidence. One exact bound control and no other calls permits validation. Two controls, any mixed application selection, any unbound call, or malformed data is terminal before the delegate can execute. Use a control-local Jackson reader for one complete JSON object with one field, rejecting duplicate keys, trailing values, coercion, null, non-string and blank reasons. Preserve original argument text for evidence and reason text for the exception. Text accompanying the call never becomes the return candidate.
- On a valid selection, construct `PlannerInabilityException`, serialize only `id`, exact `name`, and original `arguments` into the bounded diagnostic input, then first-record on the bound model frame and throw the same instance from the manager. Keep provider response recording and post-response usage checks ahead of interception. Declaring child never enters its own callback recovery path. Existing outer callbacks remain the only recovery boundaries. An initial or explicit-step request that produces the control spelling is unbound.
- Append receiving guidance to the Framework's actual standard non-planning system instructions under the same mode predicate as exposure. Explain that failed-child feedback marks unsuccessful completion, the message is explanatory data, effects may have completed, and repeating the same request does not address the obstacle. Continue only with permitted actions addressing the obstacle, or use the control. Put the control's own call-alone, unsuccessful completion, no rollback, and objective/inputs/tools/authority wording in its description. Avoid adding guidance to every payload.
- Extend the assembler's existing designated-recoverable processor to add kind only for the effective subtype. Preserve the other fields, exact reason, and association, and preserve ordinary recoverable feedback without kind. Step action/synthesis turns have no ordinary bound callbacks. No new escalation route is required. In `DefaultMissionExecutionEngine` preserve designated recoverables and authoritative lifecycle/quota/authorization failures across attachment calls, avoiding media advice on these paths. Retain existing useful attachment/provider context for genuine model/media failures covered by `MissionExecutionEngineTest`. Keep validators outside dispatch so they only inspect a returned candidate.

## Testing strategy

The companion testing plan gives the red test, exact scenarios, and acceptance mapping. Deterministic tests use actual Spring AI adapters over loopback, production runtime integration for root/nested effects and accounting, and focused unit or trace fixtures for states the adapters cannot supply directly. Optional live-model observations can assess whether a parent treats a reason as data and chooses a permitted alternative. They supply no completion evidence for deterministic requirements.

## Performance and migration

One response scan validates selections and one capture pass maps returned messages. Store full ordinary payloads through existing trace content handling. The extra diagnostic is one deliberately bounded copy of the accepted control, with no new quota or attachment copy. No migration is needed for the ephemeral format. The series coordinates producer and readers under the existing exact marker policy.

## Step 4 implementation handoff

- The declaring invocation first records the canonical failure under its existing open ancestry fence on the active model frame. The same throwable reaches the caller through the existing runtime wrappers. The unqualified control name belongs to the actual bound callback marker. Existing application tool identities retain canonical validation.
- A focused trace round-trip exposed a UTF-8 write failure when the existing 4,096-character chunk boundary split a supplementary Unicode character. `DefaultExecutionTraceHandle` now counts and writes chunks at the same code-point-safe boundaries. The chunk size, storage format, and retrieval path are unchanged. `ExecutionTraceContractTest#structuredChatCapturePreservesOrderNullsEmptyValuesAndExactContent` verifies the correction using actual trace writes and reads.
- The real adapters serialize the Framework tool through their existing native shapes. Anthropic and Gemini retain the required `reason` field in their native schema. OpenAI and Ollama also serialize `additionalProperties: false`. Framework runtime validation enforces closure for every driver.
- The existing embedded OpenRouter timeout fixture originally queued the throttled response. MockWebServer 4.12.0 uses the queued response's throttle for incoming request reads as well as for outgoing response writes. The larger standard request then consumed a material part of the test deadline before response delivery. The fixture now dispatches the throttled response after reading the request. The test keeps its one-second and four-second configured deadlines, one-request assertion, and response-body timeout check. Production transport is unchanged.
- The Framework writer intentionally replaces chat response `data.content` with `data.generations`. The current Console model detail reader in `TraceRecords.tsx` expects `data.content` and string request text. PR 29.3 owns the Console reader, Go failure DTO and shared fixture work. This is a verified source-level integration mismatch. No Console integration test failure is inferred from it. The separate TypeSafe payload, observer journal, and exact compatibility marker retain their existing contracts.
- PR 29.2 owns explicit-step declarations and parallel folding. A standard child declaration already propagates through an explicit-step ancestor to a higher standard caller under existing boundaries, as exercised by `ExplicitJavaFailureHandlingIntegrationTest#standardChildInabilityPropagatesThroughAnExplicitStepAncestor`.
- Bundled `loomspan-docs` matches the checked-out artifact version. The baseline documentation was aligned for existing designated recoverability. The updated Java and skill-authoring topics now describe the implemented subtype, continuation limits, output validation boundary, and canonical model evidence. The release-facing references describe only current behavior.

Optional developer observation — a representative live model can be observed treating the reason as explanatory data and selecting a permitted action that addresses the obstacle. The deterministic checks cover the runtime contract.
