# PR 27.2 TypeSafe Authoring Contract Testing Plan

## Change Summary

Complete bounded acceptance evidence for the native authoring contract already
implemented. New tests exercise uncovered walkthrough boundaries without adding
provider-response checks or changing shared schemas/bindings. Implementation
plan: `2026-10-10-PR-27.2-typesafe-authoring-contract.md`.

Execution uses approved **Full 5-Step Pipeline** (`full`), with Steps 2 and 3 in
the same context. Tests have not been run during planning. No credentials or live
service verification are required.

## Impacted Areas

- `src/test/java/ai/loomspan/internal/skill/TypeSafeDeclarationTests.java`: strict

- `src/test/java/ai/loomspan/integration/TypeSafeSkillIntegrationTest.java`: public

## Risk Assessment

- YAML text must remain its parsed value: folding/chomping, Unicode and whitespace
  cannot be reconstructed from raw-source expectations or trimmed by resolution.
- Absent and null fields must remain distinguishable. Null instructions and
  partial/empty Noul criteria have primitive-specific acceptance requirements.
- Strict unknown/duplicate parsing must reject before type conversion and preserve
  the existing parser authority; exact parser error wording is incidental.
- Ordinary input may normalize, but author-bound subtrees are exact. Parent input
  normalization must not accidentally erase the invalid-child test condition.
- Dynamic Score levels/order/nulls must stay per-call. Latch-backed overlap must
  prove concurrency, with bounded waits and cleanup on assertion failure.
- Schemas remain descriptive. Assert the roadmap table's full structure without
  turning output ranges, membership or legend prose into response checks.
- Protected paths are supported `SkillTemplate` invocation/catalog contracts and
  ticket/roadmap-defined manifest/request behavior. Internal constructor/public
  modifiers establish no separate compatibility promise. No obsolete contract
  removal or new API/SPI is presently planned.
- Canonical data fidelity and access boundaries remain protected. Existing derived
  journal behavior stays at its projector; this change does not extend it.

`LoomspanPublicSurfaceArchitectureTest` is the executable authority for supported

## Tests to Add/Update

### 1) `strictNativeManifestParsingRejectsDuplicateAndUnknownFields`

- **Type/location:** Unit, `TypeSafeDeclarationTests.java`.
- **Proves:** Supplied manifest parsing preserves existing duplicate rejection at
  manifest root, native block, question IDs, question fields and Choice keys;
  an unknown manifest field and native unknown fields fail. Ensure a valid control
  manifest loads with configured fixture connection/model, so missing model setup
  cannot be mistaken for the expected parser rejection.
- **Fixtures:** Complete valid leaf with fixture model; mutations repeat `name`,
  `state`, question ID, `instructions` or candidate key. Unknown-field mutation
  is separate from duplicates. Keep existing twelve incompatible-presence cases.
- **Mocks:** None; production `YamlSkillCatalog#checkedSupplied` and strict codec.
- **Surface/compatibility:** Configuration/manifest behavior; preserve deliberate
  strict parsing, assert failure and applicable location without brittle complete
  parser-message matching.

### 2) `parsedYamlScalarFidelityAndResolvedCopiesRemainExact`

- **Type/location:** Unit, `TypeSafeDeclarationTests.java`.
- **Proves:** `>` versus `>-`, and literal `|`/`|-` when useful, retain the exact
  parsed trailing newline; Unicode, quotes, backslashes and surrounding whitespace
  survive. Embedded finite number/Boolean text uses the existing JSON codec.
  Whole-value nested null/number/object/array stays typed, inserted markers remain
  literal, and changing input or one `ResolvedRequest#json()` result cannot affect
  a later read or another resolution.
- **Fixtures:** Compact structured state and question descriptions, supplied marker
  strings containing `${...}`, a finite decimal and integer, nested nullable data.
  Derive number interpolation expectation from the public JSON codec behavior,
  not from a new decimal formatter. JSON spelling/order is not promised.
- **Mocks:** None; YAML codec, declaration compile and resolve.
- **Surface/compatibility:** Manifest/external serialized request; preserve content,
  exact JSON value types and detached immutable capture.

### 3) `optionalPrimitiveFieldsPreserveOmissionNullAndPartialCriteria`

- **Type/location:** Unit, `TypeSafeDeclarationTests.java`.
- **Proves:** Choice and Score accept valid singleton criteria with omitted or
  null instructions and do not generate instructions. Noul with instructions
  accepts omitted/null/empty criteria and independently partial `true` or `false`
  criteria, including null descriptions; no opposite outcome is inserted. Noul
  without/null instructions accepts a described outcome and rejects omitted/null/
  empty/all-null criteria. Whole-value dynamic instructions/criteria undergo the
  same complete validation after resolution. Dynamic Score null levels retain
  their positions and are not removed.
- **Fixtures:** A compact case set, not an exhaustive cross-product. Use explicit
  key-presence plus null assertions, singleton Choice/Score, partial Noul object
  and whole-input criteria references. Include invalid dynamic instructions as a
  scalar to show no request coercion.
- **Mocks:** None.
- **Surface/compatibility:** Configuration/manifest and serialized request; preserve
  ticket-defined forms and registration-versus-invocation failure boundaries.

### 4) `exactGrammarAndCollisionScopeRemainBounded`

- **Type/location:** Unit, extend existing pointer, grammar and collision tests in
  `TypeSafeDeclarationTests.java`.
- **Proves:** First `}` closes an expression; escaped openers can retain otherwise
  malformed literal text without reparse; `~01` decodes once to literal `~1`;
  object key `01` is looked up exactly while array `01`, signs, `-` and overflow
  fail. Traversal through null/scalar and missing optional referenced values fail
  at resolution, with no registration-time input-schema proof. Collision errors
  include both names and location for fixed question IDs, fixed/dynamic Choice
  keys, while case siblings in arbitrary state/description objects remain valid
  and preserve spelling. Existing type/question-map rejection remains covered.
- **Fixtures:** Small exact-key objects, one-element arrays, a key containing `}`
  supplied through its containing object, `~1` literal key, scalar and explicit null.
  Keep question IDs/types literal even when marker-like keys appear in state.
- **Mocks:** None.
- **Surface/compatibility:** Manifest and request semantics; preserve exact grammar
  and the explicitly scoped Locale.ROOT name restriction.

### 5) `mixedFixedAndDynamicSchemasMatchTheDescriptiveTable`

- **Type/location:** Unit, strengthen existing descriptive-schema test in
  `TypeSafeDeclarationTests.java`.
- **Proves:** All declared root names required with closed root; every answer open
  with singleton string type enum. Noul requires exactly type/noul and numeric
  noul with `Probability of yes, from 0 to 1.` description. Choice requires
  type/choice/confidence/probabilities; fixed criteria preserve candidate enum,
  required numeric probability keys and closed map; dynamic criteria omit enum
  and keep map open. Score requires type/score/confidence/probabilities/legend;
  fixed levels expose numeric zero-based keys and range, dynamic levels retain
  broad range/map, every legend stays open. Descriptions convey 0–1 ranges and
  zero-based level range; no minimum/maximum or new vocabulary appears.
- **Fixtures:** Existing mixed five-question fixed/dynamic block with singleton or
  two fixed Score levels and templated fixed descriptions; independent explicit
  expected fields/required lists/openness/enums. Compare the roadmap's schema
  table semantics and mixed-batch structure, not incidental illustrative wording
  or absent/default serialized DTO fields.
- **Mocks:** None; inspect `OutputSchemaManifest`/existing codec conversion.
- **Surface/compatibility:** Published descriptive metadata consumed by catalog,
  tools, bindings and forwarding. Preserve existing schema representation and
  defensive copies; no returned-answer validation added.

### 6) `acceptedNormalizedAndExactBoundInputsProduceEqualNativeRequests`

- **Type/location:** Integration, `TypeSafeSkillIntegrationTest.java`.
- **Proves:** Ordinary direct numeric string input normalizes to the declared
  numeric/integer value before substitution. A fully author-bound numeric value
  accepted exactly produces an equal complete native request. Bound string input
  into that same numeric destination fails receiver validation before native HTTP
  and provider-attempt reservation. Do not assert the parent makes zero planner
  requests: distinguish chat planner requests from native `/v1/systemone` sends.
- **Fixtures:** One complete numeric leaf; a planning/forwarding parent with
  compatible binding topology whose input accepts raw number/string in an open
  subtree; a deterministic one-child flight-plan response. Reuse the documented
  parent local chat fixture and runner. Capture native bodies and attempt records
  separately for each session; compare trees, not serialization whitespace.
- **Mocks:** Local MockWebServer for chat planning and System One; production
  `SkillTemplate`, reload/generation, bindings and input validation.
- **Surface/compatibility:** Application invocation plus manifest/input contracts;
  retain ordinary coercion versus exact-author-bound behavior without shared
  validator or binding redesign.

### 7) `concurrentDynamicScoreLevelsStayPrivateAndMetadataRemainsStable`

- **Type/location:** Integration, `TypeSafeSkillIntegrationTest.java`.
- **Proves:** Concurrent three- and five-level Score requests preserve their own
  arrays, structured/null descriptions, indices and per-call result markers.
  Captured catalog schema is unchanged during/after both calls; dynamic maps are
  still broad. Provider-returned fixture extensions pass through without schema
  validation. Existing dynamic Choice/reload test remains unchanged evidence of
  captured-generation semantics.
- **Fixtures:** Shared dynamic Score leaf, different level arrays with distinct
  markers, local dispatcher reflecting relevant request data in `answers`; two
  arrivals required before `finally` releases responses. Assert both complete
  captured criteria arrays and results, not only counts.
- **Mocks:** Local MockWebServer; bounded latches/futures, production runtime.
- **Surface/compatibility:** Serialized request and generation-local internal
  ownership supporting public catalog stability; preserve per-call isolation.

## How to Run

Use Java 21+ and the repository Maven wrapper. No special profile, external API
key or provider service is needed; local tests use fixture credentials.

```powershell
./mvnw.cmd '-Dtest=TypeSafeDeclarationTests' test
./mvnw.cmd '-Dtest=TypeSafeSkillIntegrationTest,SkillInputValidatorTest' test
./mvnw.cmd '-Dtest=TypeSafeDeclarationTests,TypeSafeSkillIntegrationTest,SkillInputValidatorTest,LoomspanPublicSurfaceArchitectureTest' test
git diff --check
```

The final combined invocation can replace repeated focused invocations if all
changes are ready together. Maven `test` compiles production/tests and runs these
JUnit/Surefire suites. If new assertions expose a defect, run the smallest test
first for red/green evidence, then the combined suite after the fix. Do not expand
testing merely to increase command count. Broaden owner/consumer suites only if
the final diff changes production responsibility outside the focused contract.
