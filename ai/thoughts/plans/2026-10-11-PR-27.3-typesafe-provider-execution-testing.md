# PR 27.3 TypeSafe provider execution testing plan

## Change Summary

Preserve existing native provider behavior, correct registry construction ownership
and diagnostic chains, and close acceptance-level assurance gaps. Pipeline mode,
selected profile `full`; baseline commit is
`4552dff89b6928089e829a58b0f24a504d99064f`. This planning stage runs no tests.

## Impacted Areas and Risk Assessment

- Registry: an allocation can precede runtime assignment; construction and cleanup
  errors currently disappear. Prevent leaks and preserve the primary exception.
- Native invocation: retries must match physical sends, attempts and reservations;
  errors/extraction must not manufacture successful results or usage.
- Accounting: precise integral conversion, exact zero, per-response cardinality,
  unusable native metadata and late-write gates must remain consistent.
- Real HTTP lifecycle: cancellation must abort Apache I/O independently of worker
  Future interruption, release sockets, stop backoff and reject late accounting.
- Trace consumers: native envelopes/raw text/failures must remain current-version
  coherent, with truthful unavailable/truncated evidence and no chat assumptions.
- Protected paths: existing public invocation, configuration/manifest semantics,
  RestSkillHandler SPI and exact portable-trace release marker. Internal no-cause
  diagnostics are intentionally replaced, without retaining a compatibility path.
  No new public surface, trace schema, reader migration or marker bump is planned.

## Existing Test Coverage

`TypeSafeClientTest` protects default/prefixed routes, header/configuration
validation, one physical send for redirects/529, bounded UTF-8 error capture,
non-draining reads, usage conversion, real cancellation, timeout defaults and
normal registry shutdown. `TypeSafeSkillIntegrationTest` protects public direct/
child invocation, complete mixed/extended/>1MiB results on both prefixes,
529-then-success, quota stops, terminal extraction/accounting, captured generations,
interruption/shutdown and HTTP/backoff mission cutoff. Existing chat tests protect
their original HTTP classification. Java/Go native success corpus and TS native
request/envelope/raw/chunk tests protect normal consumption. Shared trace/journal
tests protect current record mechanics and the existing journal exception.

These were source-inspected, not freshly executed in this planning context. Add
the missing native status/retry matrix, end-to-end usage matrix, construction-
failure resource observation, and native failure/capture reader assertions.

## Bug Reproduction / Failing Test First

1. **genericConstructionFailurePreservesOriginalCause** — unit,
   `src/test/java/ai/loomspan/internal/autoconfigure/NamedAiConnectionRegistryTests.java`.
   Arrange a mocked integration that throws a distinctive RuntimeException; build
   the registry; assert contextual exception `getCause()` is the exact original
   instance, retaining its message. Current code reliably fails because it has
   no cause. Replace the existing obsolete no-cause assertion, preserving its
   useful assertions that only applicable configuration paths appear in context.
2. **constructionFailureRetainsCleanupFailuresAndContinuesClosing** — unit in the
   same class. Ordered connections include several disposable chat resources;
   one/two cleanup operations throw and a later construction fails. Assert every
   disposable was closed once; primary cause remains the construction exception;
   suppressed chain retains cleanup exceptions (including multiple failures).
   Repeat for the SafeAiConnectionConfigurationException branch, preserving that
   exact primary instance. Current helpers discard cleanup errors and fail.
3. **nativeConstructionOwnershipClosesAcquiredResources** — integration/unit as
   appropriate in registry tests/TypeSafeClientTest. Force failure after a native
   resource has been acquired and after an earlier native connection was built.
   Observe closure using existing Mockito construction/static interception where
   suitable and the actual Apache manager/client for a pooled resource fixture;
   verify a closed real client refuses send. A fake close assertion alone is not
   sufficient evidence that the native resource type is actually closeable.
   Pure failing retry settings should be resolved before native allocation.
   No supported factory/bean override surface is introduced for testing.

Run red tests before editing production. Persist actual red failure outputs and
post-fix results in implementation evidence. The remainder is regression/assurance
of baseline behavior and need not be artificially made red.

## How to Run

From repository root in PowerShell. Quote Maven `-D` arguments to avoid shell
interpretation. Use Java 21 and the checked-in wrapper; node/npm follow web
package.json pinned toolchain. No provider credentials are needed for fixtures.

```powershell
.\mvnw.cmd test '-Dtest=NamedAiConnectionRegistryTests' '-DfailIfNoTests=false'
.\mvnw.cmd dependency:tree '-Dincludes=org.apache.httpcomponents.client5:httpclient5,org.apache.httpcomponents.core5:*'
.\mvnw.cmd test '-Dtest=TypeSafeClientTest,TypeSafeSkillIntegrationTest,TypeSafeDeclarationTests,LoomspanPropertiesTest,NamedAiConnectionRegistryTests,ProviderRetryDeciderTest,SpringAiProviderIntegrationTest,LoomspanPublicSurfaceArchitectureTest' '-DfailIfNoTests=false'
.\mvnw.cmd test '-Dtest=ConsoleTraceFixtureCorpusTest' '-Dloomspan.console.fixtures.regenerate=true' '-DfailIfNoTests=false'
.\mvnw.cmd test '-Dtest=ConsoleTraceFixtureCorpusTest,ExecutionTraceContractTest,ExecutionTraceHandleTest,ExecutionJournalProjectorTest,ExecutionJournalProjectionContractTest' '-DfailIfNoTests=false'
.\mvnw.cmd test
```

Only regenerate after intentional corpus changes; inspect changes for LF and
expected scenarios, then execute the non-regenerating corpus gate. Baseline log
files are historical evidence, not passes for this pipeline. Save actual commands,
results and failures for Step 4/5 receipts.

From `loomspan-console`:

```text
go test ./internal/traceanalysis/...
go test ./...
go run ./internal/buildtool verify
```

From `loomspan-console/web`:

```text
npm run test -- src/observability/TraceRecords.model.test.tsx
npm run typecheck
```

Also run the focused failure/content-view test files actually changed; buildtool
verification is the repository standard broader web/build gate. Race detection
is required if implementation changes Go concurrent resource/state behavior;
planned Go changes are assertions/fixtures, so routine race reruns are unnecessary.

Required external documentation recheck during implementation: official TypeSafe
System One API, official OpenRouter System One API, and Apache timeout/configuration
docs matching the effective dependency. Record direct URLs, date, and conclusions;
do not treat documentation as a credentialed acceptance/accuracy test. New material
contradiction requires evidence-backed escalation before changing accepted requests.

## Exit Criteria

- [x] Cause/suppressed-cleanup red tests fail on baseline for the expected reason.
- [x] Registry owns/closes acquired native/chat resources on construction failure;
  primary and cleanup evidence retained, normal destroy remains idempotent.
- [x] Every ticket acceptance criterion has executed evidence from the table above.
- [x] Focused suites and final root Maven suite pass; architecture test runs after
  production changes and no public surface/SPI leaks exist.
- [x] Changed native corpus and Java/Go/TS consumers pass, exact release rejection
  still holds, canonical content and existing journal exception remain correct.
- [x] Timeout documentation matches effective Apache dependency/settings and local
  observations; official live API documentation has been rechecked.
- [x] TypeSafe guide evidence anchors reflect tests/fixtures actually establishing
  their claims, and documentation drift is explicitly classified.
- [x] Obsolete internal no-cause assertions are replaced without dual behavior;
  no legacy reader, shim, new capture setting or response-validation path appears.
- [x] Required failed/unavailable checks are resolved or escalated, not silently
  marked pass. Optional provider smoke remains separate from fixture evidence.
