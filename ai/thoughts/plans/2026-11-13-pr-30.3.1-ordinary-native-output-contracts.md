# Ordinary native output contracts implementation plan

## Overview

Implement PR 30.3.1's ordinary generation boundary using the existing immutable
`CanonicalSchema`, NetworkNT validator, binding projection/composition, official
Spring AI adapters and bounded output-correction owner. This is Steps 2–3 of the
user-approved Full 5-Step Pipeline. Research is
`ai/thoughts/research/2026-11-13-pr-30.3.1-ordinary-native-output-contracts.md`.
The initial checkout was clean; only that research artifact exists before planning.

The author declares one standard contract. Framework sends its canonical or
binding-projected generation contract through native options, checks exact generated
values locally, composes binding-owned values, and accepts only a complete valid
output. Text-only calls remain text-only. No correction allowance or transport
retry policy changes.

## Current state and decisions

- `YamlSkillDefinition.outputSchema`, `OutputBindingProjection` and
  `OutputBindingComposition` already use canonical contracts. The ordinary advisor,
  validator and renderer still refer to the removed manifest type.
- `ModelInteractionRequest` has no output contract; `SpringAiModelInteraction`
  currently passes only prompts, attachments, tools and trace/planning context.
- Official native seams exist: Responses `outputSchema`, Anthropic
  `AnthropicNativeOptions.withOutputSchema`, Gemini `outputSchema`. Complete typed
  effective defaults must be copied, including native output config and caps.
- Canonical composition already validates projected and complete outputs but has
  a duplicate parser/error conversion. Replace that duplicate with the migrated
  ordinary validator so precision, parsing and verdict semantics have one owner.
- The default schema codec now enables BigDecimal. Still establish a private
  strict, lossless reader at ordinary output ingress; caller-supplied codecs must
  not weaken it. Do not change unrelated shared codecs.
- Preserve ordinary parser location/fragment diagnostics and explicit truncation.
  Remove hand-written structural validation and case-folding; exact names and
  NetworkNT assertions are authoritative. `propertyNamesMatch` has no production
  callers and can be deleted with its obsolete tests.
- Preserve raw provider diagnostics already recorded by ProviderAttemptCallAdvisor.
  Application composition replaces text parts only; it must retain other ordered
  parts, part attributes/payload, message metadata, tools/media, generation metadata,
  other generations and response metadata.

## Scope exclusions

Do not migrate planning/step native response protocols (30.3.2), completed-history
or tool-free repair rules (30.3.3), TypeSafe/evidence metadata (30.3.4), or implement
the later live suite. Minimal shared-renderer caller signature and fixture updates
are in scope to prove requested step-final guidance; they do not restore the step
protocol. Preserve retained probes, resource-stream closure, authorization and
journal-only redaction. No live calls, model downloads, submissions, copied
adapters, body rewriting, registry, fallback, route dispatch or new public API.

## Provider evidence and exact mapping decisions

Evidence checked November 13, 2026; documentation is an unversioned snapshot, not a
live endpoint test. Adapter is Spring AI 2.1.0-RC2, Anthropic SDK 3.4.0 and Google
GenAI 1.73.0 as retained in the probe README. Retain source URL, retrieval date,
selected API field and exact keyword rule near the implementation/tests.

1. [Claude structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs),
   sections “Using a raw JSON schema” and “JSON Schema limitations”, explicitly
   concern Messages `output_config.format`, list unsupported constraints and state
   that unsupported features produce HTTP 400. This confirms applicability of the
   ticket's six bounded assertion entries to the selected native format API.
2. [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
   supported-schema sections require object roots, every declared property required
   and `additionalProperties:false`. Use one shared strict mapping without guessing
   the selected upstream from URL/model. These are limitations of the chosen shared
   mapping; no claim of keyword parity across its four hosted/local routes.

| Driver / context | Exact rule | Action |
| --- | --- | --- |
| Anthropic native output/planning | minimum, maximum, minLength, maxLength, maxItems | Omit from detached request schema at actual schema nodes only; retain canonical/local checks |
| Anthropic native output/planning | minItems with value other than 0 or 1 | Omit only those values; preserve 0 and 1 |
| Anthropic native output/planning | Object additionalProperties omitted or not false | Fail before affected send with schema location; do not close object |
| Anthropic non-strict tools | All approved assertions | Preserve; no tool omission and no enabling strict tools |
| Shared OpenAI strict output/planning | Object openness or optional declared properties | Fail before affected send; no closure, all-required conversion or nullable insertion |
| Shared OpenAI output/planning/tools | Approved assertions | Preserve; no rejection-backed omission entry established |
| Gemini generateContent output/planning/tools | Approved assertions | Preserve; SDK narrowing is B04, not an omission rule |
| All drivers | format | Preserve every approved standard format; no exact rejection entry established |

Only walk root, `properties` values, `items`, and schema-valued
`additionalProperties` where applicable. A property named `minimum`, `maxItems` or
`format` is application data. Do not remove it. Native typed maps remain excluded.
Do not add descriptions containing constraints or import SDK helper transformations
that close objects/filter formats. Omitted assertions weaken native generation only;
canonical acceptance still enforces them and may require bounded correction.

Existing B01–B05 records remain unchanged requirements. B01 schema decimal wire
rounding and B04 Gemini raw-schema narrowing prevent complete wire fidelity claims;
B02/B03/B05 concern separate replay/tool/status boundaries. Their complete retained
assertions remain opt-in under existing authorization, not new skips. 30.4.3 owns
integrated reconciliation. This ticket's new ordinary behavior cannot receive new
assumption guards merely because root compilation is blocked.

fallback when preparation fails. Corrections retain the same canonical context and

continuations retain the same contract/options under the official ToolCallingAdvisor.
If provider-attempt placement repeats preparation for continuations, it must be
idempotent and leave canonical/default snapshots unchanged. Null contract makes no
format changes and must not inherit a previous call's schema.

Extend existing request diagnostics with distinguishable canonical generation
schema and prepared native schema. Preserve complete original content. Where the
official adapter changes the schema further (B01/B04), label the preparation fact
