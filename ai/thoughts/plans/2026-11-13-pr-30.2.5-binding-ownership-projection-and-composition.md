### Key discoveries and decisions

1. Preserve two contracts: full canonical receiving/output schema and a detached projected model schema. Deep-copy accepted trees instead of enumerating their old fields, retaining all bounds, formats, descriptions, arrays, typed input extensions and annotations.
2. Child projection uses a GENERATED INPUT canonical tree with false reservations in the effective/advertised schema. Required lists exclude reserved destinations. Dispatch proof counts possible properties, excluding false reservations, rather than treating those structural prohibitions as model input space. This removes duplicate serialization authority while preserving the advertised contract and runtime override checks.
3. Keep dispatch conservative for nested destinations, generic/open roots, unconstrained/ambiguous trees and runtime/attachment shapes. Whole object/array bindings and explicit closed zero-input contracts may qualify. Unsupported authored shapes now fail compiler admission; do not retain tests requiring them to become accepted ambiguous nodes. Approved nullable types are valid standard declarations; assess the same closed whole-field proof and validate actual bound values.
4. Output projection continues removing whole bound properties and checking overrides explicitly, including in open objects. Do not expand output projection into a general transform. Binding-created ancestors become non-null object containers; required unbound siblings remain required, while all-bound ancestors may be omitted from the model contribution.
5. Move the existing bounded publication path/compatibility algorithm into a small binding-owned internal helper (for example `BindingSchemaCompatibility`), used by `SkillDependencyValidator` and actual-source unit tests. This is one authority extracted from the existing validator, not another compatibility engine. Do not infer producer shapes or implement implication solving.
6. Shared validation is the only instance-validation authority. Binding composition may have a private result adapter using existing `OutputSchemaValidationResult` records. Internal scalar/array destination checks use a private object wrapper with the selected schema as a property, as `SkillInputValidator` already does. The complete declaration root-object rule remains intact. Keep validation operational failures propagating; do not convert them into invalid candidates or success.
7. `SkillDependencyValidator` gets only the mechanical canonical-tree changes necessary for binding validation and its shared metadata seam: use canonical trees/provider trees as appropriate instead of legacy metadata reconstruction; do not insert closure. Broader structural effective-catalog semantics/assurance stay with 30.3.4.

### Phase 2: Canonical output projection and composition

Files: `OutputBindingProjection`, `OutputBindingComposition`, `OutputBindingCompositionTest`, `OutputBindingIsolationTest`, binding destination preparation in `YamlSkillDefinition`.

- Use CanonicalSchema and GENERATED OUTPUT projection. Preserve exact field spellings and whole-subtree binding ownership; remove legacy case canonicalization entirely.
- Standard omitted/true openness means residual model space at root and partial nested ancestors; explicit false plus all possible fields bound means no synthesis contribution. A wholly bound open subtree has no interior model space.
- Validate known selected destinations before a model call; validate model contribution before insertion and complete assembly against full original canonical contract. Build destination validators once per composition, preserving value snapshots and assertions.
- Retain mission identity, captured plan, all completed accepted work, producer/result identity, lifecycle and provenance controls. Keep complete-output policy ownership at existing engines.
- Replace only binding-owned schema lookups/copy calls in callers; general advisor/native request and step renderer work stays downstream. Record any resulting caller type mismatch precisely.
