# Ordinary native output contracts testing plan

## Change summary and boundaries

Prove canonical local acceptance, explicit ordinary contract propagation, native
request copies, prompt openness and complete binding composition. Controlling
artifacts are the PR 30.3.1 ticket, research, and companion implementation plan
`2026-11-13-pr-30.3.1-ordinary-native-output-contracts.md`. This is Step 3 in the
approved full pipeline; this stage changes no production or test code and runs no
tests. Initial checkout was clean apart from this run's process artifacts.

No live provider calls, model downloads or later suite implementation. Use local
MockWebServer/official SDK captures, real production algorithms and fresh builds.
Full application/build blocks are separately recorded, never treated as success.

## Impacted areas and risk assessment

- `internal/outputschema`: exact standard validation, numeric precision, shared
  recursive renderer, bounded advisor correction, complete assembly and raw versus
  accepted application text. Risk: false acceptance, changed budgets or lost parts.
- `ModelInteractionRequest`, ordinary mission engine and Spring AI interaction:
  selected canonical/projected contract identity and planning/text isolation.
- Existing provider boundary/native helper: detached request mapping, accurate
  diagnostic schema facts, incompatible structural contracts and no retries/fallback.
- Typed option copies: generation caps, thinking/effort, stops, route extensions,
  tools and target overrides must survive initial/correction/continuation calls.
- Existing authorization, source ownership, lifecycle fences, parser diagnostics,
  evidence/linter ordering and journal-only behavior are preservation controls.
- Application API remains protected by the real architecture check; no SPI.
  Internal removed-type constructors/helpers/tests have no compatibility promise.
  Manifest exact-name/open/null/format semantics intentionally replace old dialect.
  Current-run diagnostics preserve content, raw evidence and response structure.

## Existing coverage

`OutputSchemaValidatorTest`, `OutputSchemaPromptAugmentorTest` and
`OutputSchemaCallAdvisorTest` retain broad parser/guidance/retry controls but their
builders and several legacy semantics are obsolete. `OutputBindingCompositionTest`
and `OutputBindingIsolationTest` already test canonical contribution/full checks,
ownership, precision and fences through the actual-source binding harness.
`DeclaredOutputBindingsOrdinaryIntegrationTest` retains actual projected request
and full-assembly integration assertions, currently build-dependent. Three provider
protocol classes prove existing native option seams with explicit B01–B05 limits.
`StepPromptBuilderTest` retains final-only shared guidance coverage. Root
`LoomspanPublicSurfaceArchitectureTest` is the complete API authority.

## Bug reproduction / failing test first

1. **Standard omission/exact name:** migrate a minimal canonical fixture then show
   an omitted-openness object accepts an extra key while a required `name` is not
   satisfied by `Name`. Old custom walker fails one or both expectations.
2. **Lossless supplied mapper boundary:** construct validator with a default
   non-lossless mapper; maximum 1 must reject `1.0000000000000001`. The current
   validator constructor trusts that mapper. Use a canonical contract fixture;
   compilation failures from removed signatures are migration evidence, not a
   fabricated pre-fix assertion result.
3. **Native initial call:** invoke actual SpringAiModelInteraction with explicit
   canonical contract and local Responses server; outgoing text.format must exist.
   Current request record has no schema component, so preserve source/compile
   evidence until the contract can be wired; do not claim a runtime red test ran.

Prefer running one meaningful pre-fix failing assertion after minimal fixture
migration if practical, then implement; record exact outcomes. Do not restore
removed manifest types merely to run red tests.

## Tests to add/update

### 1. Canonical ordinary validator matrix

**Type:** unit. **Location:** `OutputSchemaValidatorTest`.
**Surface:** internal implementation and manifest semantics; intentional dialect
replacement. Compile real schemas with StandardSchemaCompiler, no validator mocks
for normal verdict tests.

- Root/nested additionalProperties omitted, true and false; exact keys including
  punctuation/Unicode, independent `name` and `Name`, required omissions and nullable
  presence. No aliases or case folding; no null insertion/coercion/defaults.
- Scalar enum types, numeric enum equality, nested arrays and every approved bound
  and standard format; valid controls alongside each violating instance.
- Maximum/minimum precise just-outside values, positive/negative long fractions,
  exponent forms and nested fields/array items. Pass caller-supplied default mapper
  and prove it cannot round the invalid instance into acceptance. Boundary values
  and large integers remain valid and original String remains unchanged.
- Blank/malformed JSON, trailing second JSON value, trailing garbage rejected;
  trailing whitespace accepted. Preserve meaningful parser reason/location/fragment,
  Unicode code-point bounds and existing INVALID_JSON versus completed verdict.
- A genuine operational validation exception escapes; never convert arbitrary
  runtime failure into a validation verdict or accepted partial result. A narrow
  mocked CanonicalSchema only for this failure test is acceptable if needed.

### 2. Recursive standard prompt and step-final consumer

**Type:** unit. **Locations:** `OutputSchemaPromptAugmentorTest`, focused cases in
`OutputSchemaCallAdvisorTest` and `StepPromptBuilderTest`.
**Surface:** manifest/prompt semantics; old closed-default behavior removed.

Parameterize root and nested omitted/true/false openness. Assert open for omitted
and true, closed for false, no blanket explicit-permission instruction. Preserve
requiredness, explicit nullable type arrays, scalar enum JSON values, descriptions,
format/bounds, array nesting, declared property order and exact paths. Ordinary
first request sees effective projected contract. Step renderer appears only in
final-response mode; intermediate step prompt retains existing behavior. Migrate
only shared renderer signatures/fixtures, not step protocol parsing/options.

### 3. Ordinary correction, outcomes and complete assembly

**Type:** unit/integration. **Locations:** `OutputSchemaCallAdvisorTest`,
`OutputBindingCompositionTest`, `OutputBindingIsolationTest`, retained
`DeclaredOutputBindingsOrdinaryIntegrationTest`.
**Surface:** internal execution plus manifest contract; budgets preserved.

- Precise out-of-range original candidate causes one correction then valid boundary
  succeeds; repeated invalid candidates exhaust exactly maxRetries+1 calls and
  cannot become accepted through rounding. Retry preserves complete latest candidate
  and existing bounded feedback/outcomes/trace facts.
- Every Anthropic omitted assertion still fails locally: minimum, maximum,
  minLength, maxLength, maxItems and minItems 2 or larger; include nested cases.
  Controls for retained minItems 0/1 and format remain enforced.
- Mixed binding sends projected model-only schema and composes untouched bound
  values; invalid projected contribution and invalid complete contract both prevent
  acceptance. Full binding assembly makes zero generation requests.
- Preserve source snapshots, exact keys/numbers/nulls, whole-subtree ownership,
  plan/lifecycle fences, accepted-child provenance and linter/evidence sequencing.
- Rich original response has reasoning, two text parts, media/tool parts, arbitrary
  payload/attributes and multiple generations. Composed application text appears
  once; every untouched non-text part stays ordered, metadata and other generations
  remain. Raw recorded provider candidate/parts remain unchanged and distinguishable
  from accepted assembled result. Include no-text/empty-text anchor behavior.

### 4. Request-copy mapping and known incompatibility

**Type:** unit plus wire integration. **Locations:** new focused native-schema test
in `internal/springai`, three provider protocol tests or new ordinary native test.
**Surface:** external serialized request and current diagnostics.

- Anthropic exact omission table at root and nested property/item schema nodes;
  minItems 0 and 1 preserved, 2 omitted. Property names `minimum`, `maximum`,
  `minLength`, `maxItems`, `format` survive. Canonical tree, required sets, types,
  enums, nullability and default option objects remain unchanged after repeated
  calls across different drivers and concurrent invocations.
- Anthropic non-strict tool constraints preserved; no tool-strict flag enabled.
- OpenAI/Gemini approved assertions and all standard formats preserved by Framework
  preparation; actual serialized equality checked where official adapter supports
  it. Unsupported/ignored/unknown is not an omission rule.
- Shared OpenAI open or optional object contracts and Anthropic open contracts
  fail before affected HTTP send, at root and nested nodes, with skill/driver/model/
  schema location. Assert zero request count; authored tree remains unchanged and
  no all-required/null/closure/wrapping/map conversion appears.
- Invalid declarations/unsupported roots/keywords/formats fail with real compiler
  identity/location and zero server requests. Preserve existing loading/registration
  controls; use full integration when buildable and disclose local-only compiler
  evidence otherwise.
- Schema context and prepared schema diagnostic facts are distinct. A pre-SDK
  prepared schema must not be falsely represented as actual wire evidence when
  B01/B04 causes further adapter changes.

### 5. Actual ordinary three-adapter initial/correction/continuation matrix

**Type:** deterministic integration. **Location:** new
`OrdinaryNativeOutputIntegrationTest` (or equally focused existing native classes).
Use real SpringAiModelInteraction/request propagation, real output advisor, native
option mapper and official ChatClient/ToolCallingAdvisor plus local HTTP server.
Do not prove ordinary wiring merely by calling options helpers directly.

| Driver fixtures | Initial and correction | Continuation / defaults | Exact blocked boundary |
| --- | --- | --- | --- |
| shared Responses: gpt-6.1-terra, openai/gpt-6.1-terra route extensions, muse-spark-1.3-contributor, qwen3.5:4b-q4_K_M | `/text/format/type=json_schema`, strict true, applicable projected/canonical schema on each attempt | One real tool callback and subsequent request retain schema/options; each identity passes same mapping, no URL/model schema dispatch | Only retained B01 long-decimal wire equality; B02 non-ciphertext reasoning replay remains separately blocked |
| Anthropic claude-sonnet-5-5 | `/output_config/format/type=json_schema`, exact approved omission tree on initial and correction | Real tool continuation retains same native format and medium native effort | B03 tool root fidelity only, not output omission or ordinary attachment |

On each driver: return an invalid simple candidate then a valid candidate to
exercise real output correction and inspect both physical request bodies. In
separate one-tool cases, inspect initial and continuation format rather than
substituting a synthetic option assertion. Distinguish tool continuation from
schema correction. Keep completed-history/tool-free repair policy unchanged.

Use 1024 small-result, 4096 tool-chain and 2048 attachment option controls as
applicable; verify caps never grow on correction, native and legacy thinking,
stops/tool defaults, effective model override and route extension preservation.
Ollama fixture uses enabled boolean thinking, not medium. OpenRouter fixture
retains standard endpoint tag openai, disabled fallback and require_parameters.
These names are accepted offline identities, not availability claims. Actual
attachments can use a local tiny Resource fixture for default/cap preservation;
native generated attachments remain excluded.

Also exercise schema A → text-only → schema B on one reused underlying model,
different skill/default snapshots and concurrent calls. No cross-call leakage;
text-only body contains no native format. A planned/step call with null ordinary
contract must not inherit the skill final-output schema.

Complete B01/B04 assertions remain in existing protocol classes and reproducible
with `loomspan.pr30.blockers=true`. Do not add a new skip for an ordinary case.
Where a rich ordinary schema hits the exact same B04 boundary, retain complete
assertion/evidence and identify B04/30.4.3 as its permitted block; keep simple
ordinary initial/correction/continuation controls actively passing. All other
ordinary attachment, mapping, correction and isolation behavior must execute.

### 6. Failure and retry preservation

**Type:** deterministic integration. **Locations:** ordinary native integration,
existing ModelAttemptCallAdvisorIntegrationTest/provider retry/status controls.
Return explicit HTTP 400 schema/support error with original detail: exactly one
physical request, no local correction/fallback or schema mutation. Unrecognized
permanent errors retain details without invented capability diagnosis. Return a
transient 429/503 followed by valid response: existing transport policy owns retry,
same schema/options retained, no correction allowance consumed. Operational local
validation failure escapes without new send/accepted result. Prior successful tool
counter stays one through a later rejection; no rollback claim. Preserve status
rejection-before-correction controls and existing journal exception tests.

## How to run

Prefer root commands where the graph is available; capture output to target logs
without printing secret/config environment content. Fresh compilation is mandatory.

```powershell
mvn -B clean '-DskipTests' compile
mvn -B '-Dtest=OutputSchemaValidatorTest,OutputSchemaPromptAugmentorTest,OutputSchemaCallAdvisorTest,OutputBindingCompositionTest,OutputBindingIsolationTest,StepPromptBuilderTest,OrdinaryNativeOutputIntegrationTest' test
mvn -B '-Dtest=SharedResponsesProtocolIntegrationTest,AnthropicProtocolIntegrationTest,GeminiProtocolIntegrationTest,ProviderResponseStatusIntegrationTest,ModelAttemptCallAdvisorIntegrationTest' test
mvn -B '-Dtest=DeclaredOutputBindingsOrdinaryIntegrationTest,ExecutionCoordinatorOutputSchemaIntegrationTest,MissionExecutionEngineTest,SpringAiChatClientAssemblerIntegrationTest' test
mvn -B '-Dtest=LoomspanPublicSurfaceArchitectureTest' test
```

If the root fails at downstream TypeSafe/evidence/step consumers, record its actual
errors and owners. Then run the exact-source harness created by implementation:

```powershell
pwsh -NoProfile -File ai/scripts/test-ordinary-output.ps1
pwsh -NoProfile -File ai/scripts/test-canonical-schemas.ps1
pwsh -NoProfile -File ai/scripts/test-bindings.ps1
pwsh -NoProfile -File ai/scripts/test-input-ingress.ps1
```

The ordinary harness must run actual production/native classes and the active
three-adapter matrix above. Publish exact source inventory and every unrelated
signature substitution. No stale target/classes, production rewrites or
substitution of tested algorithms. Extend existing harness lists for new shared
validator dependencies. Reuse existing blocker opt-in commands from
`ai/thoughts/phases/pr-30-blockers.md` to reproduce B01/B04 as needed; expected
failures are recorded failures, never green verification. A restricted harness
does not pass the full public-surface architecture check.

When root restored, run `mvn -B test` for integrated assurance; current blocked
integrated requirements remain owned by 30.3.2/30.3.4 and final 30.4.3 reconciliation.
No Console Go changes/checks are required unless implementation discovers an actual
consumed boundary change; do not infer one from generic diagnostic content.
