# Shared Responses Implementation Plan

## Overview

Replace the OpenAI Chat and native Ollama runtime paths with Spring AI Responses while preserving the existing factory, one tool loop, connection ownership, authorization and provider retry boundaries. Preserve ordered parts during ordinary canonicalization and capture faithful protocol evidence. Remove obsolete configuration and migrate active fixtures and documentation together.

Pipeline: full; the developer approved the Full 5-Step Pipeline with `proceed`. Steps 2 and 3 share this planning context. The initial checkout was clean; the only existing addition is the Step 1 research artifact. No production files or tests were changed or executed during planning.

4. SDK/adapter failures can lose fields from successful-HTTP failed Responses. Transport evidence can be retained narrowly, but lifecycle classification and accounting are owned by 30.1.5.

## Desired End State

All `openai` factory calls construct `OpenAiResponsesChatModel` with matching options, disabled SDK retries and existing credentials/headers/observation/timeout behavior. The three chat implementations are Responses, native Anthropic and native Gemini; TypeSafe remains separate. Native Ollama and Chat/profile runtime code and dependencies disappear. Ollama examples use explicit compatible `/v1` roots and `api-key: ollama` for local use.

Canonicalization preserves original messages when names are unchanged and replaces only changed tool-call parts with attributes and positions intact. Real second/third request captures prove encrypted reasoning/tool replay, statelessness and no duplicate effects. Exact schema and signed/plaintext fidelity remain required and explicitly blocked until an acceptable upstream artifact exists. **Independent implementation may finish, but this ticket and pipeline must not be reported complete while those required checks fail.**
