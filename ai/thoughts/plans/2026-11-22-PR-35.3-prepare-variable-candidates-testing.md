## Risk Assessment

The highest risks are a staging sentinel accepting an invalid literal sibling, stale definitions from the preliminary parse, effective key loss before collision checking, accidental host fallback in explicit mode, repeated lookup of one name and placeholder expansion after resolution. Other concrete risks include numeric changes caused by whole-skill rematerialization, skipping all dependency checks when one selector is unresolved, unused-map accounting omitting skill names, and retaining live resolution state in a published generation.

Protected paths are existing public overload descriptors, labels, complete replacement, visibility, target freshness, ownership, shutdown cleanup and captured owner/consumer semantics. The ticket intentionally removes the three published reference fields. Ordinary executor data whose key is `api-key-ref` stays application data. Normal startup source precedence is verified by its existing tests and receives its new semantics in PR 35.4.

## Tests to Add or Update

### 1. Staged candidate validation checks every decidable constraint

Use unit/manager tests in `ExecutionConfigurationParserTest` and `ExecutorConfigurationManagerTests`, with counting Environment and runtime factory fakes. Existing declaration/dependency harnesses supply registered executors and foreign namespace metadata.

Prove all the following.

- A valid candidate with unresolved key, header, namespace-data and skill-config markers validates without source lookup, provider construction or executor execution.
- Invalid names, padded/blank names, malformed marker names, invalid allowed sections, foreign target namespaces, malformed declarations, duplicate names and unknown executor references fail without values.
- A marked API key does not defer an invalid literal driver, `0ms` timeout, retry attempt range, invalid literal header name/null value or incompatible known driver option block.
- A marked driver, boolean Vertex mode or retry operand defers only the constraints requiring that input. Known malformed scalar shapes and unrelated literal violations still fail.
- A marker in a map/list-required position fails because resolution yields a string. Marker-looking ordinary multi-key maps retain their ordinary data meaning.
- A marker key that might supply an annotation path defers that missing selection. A wholly literal missing/non-map selector still fails. Unknown visibility or executor references never become deferred config checks.
- A literal-invalid peer document or unrelated dependency remains visible even if a different document contains unknown configuration keys.
- The retired `api-key-ref`, `header-refs` and `gemini.credentials-json-ref` provider fields fail during validation and preparation. Their spellings under ordinary executor domain maps remain data.

These tests cover configuration/manifest behavior and internal staging. They verify the explicit serialized break and existing protected dependency rules.

### 2. Every public overload selects and isolates its source

Extend `SkillReloaderTest` or the focused candidate test. Exercise each existing no-map and explicit-map overload, including visibility and publication-version variants. Use an Environment fake whose `getProperty` records exact names and returns a configured value, plus mutable `LinkedHashMap` sources and deterministic latches.

- No-map preparation uses normal `Environment.getProperty(name)`. Demonstrate normal host expansion using `report.label=${region}` with `region=west`, yielding `west` at a consumer.
- An explicit map is copied before preparation lookup. Mutating the caller's map after call admission cannot change the prepared data. Use a blocked preparation/lookup stage to make the ordering deterministic.
- Null map arguments reject at public boundaries. Empty maps accept reference-free candidates. A skill-only variable counts as used. Missing, blank and unused entries fail, and an entry with different case does not satisfy the exact name.
- A matching host property cannot rescue a missing explicit entry. Reject the candidate and assert zero host lookups.
- Distinct names are read once across repeated occurrences in all three sections. A second preparation of the same documents and version performs one fresh lookup per name and captures the new value.
- Concurrent `a` and `b` candidates resolve the same name from `first` and `second` explicit maps while Spring holds `third`. Assert all three source identities are independent. Keep an invalid concurrent peer to retain failure isolation coverage.
- Source-looking fields in a pack remain unknown published settings. The host's chosen overload exclusively determines the value source.

These are supported Application API behavior tests. Preserve descriptors, defaults and existing exact label behavior.

### 3. Returned strings reach typed and ordinary consumers intact

- Explicit `${region}` remains those exact characters in provider key/header, namespace settings and leaf config even when the Environment has `region=west`.
- Normal Environment lookup can return `west` from a host placeholder property. Also use an Environment fake returning text containing `${still.literal}` and prove that text reaches consumers without a second expansion.
- Include YAML-looking multiline `a: b\n- c\n`, a JSON string, Unicode, quoted/null-looking strings and trailing newline where the target string supports them. They remain strings rather than parsed nodes.
- Typed markers use ordinary conversion. Exercise valid/invalid driver enum, duration, Vertex boolean and retry numeric values. Assert errors at the owning property path and retain existing authentication-mode tests. Test valid and invalid resolved HTTP header names at provider validation.
- Keep native ordinary YAML numeric kinds in executor config. Keep high-precision schema/default/example numbers exact in a skill that also has a resolved config marker. Assert config immutability and original source YAML, source label and declaration executor reference provenance.

Resolution errors must contain authored source/path and fixed reason while excluding supplied values and callback exception text. Use a unique supplied string in missing/blank/collision/lookup-failure cases and assert captured messages/log records do not contain it. This checks the intentionally constructed resolution diagnostics and introduces no generic data rewriting.
