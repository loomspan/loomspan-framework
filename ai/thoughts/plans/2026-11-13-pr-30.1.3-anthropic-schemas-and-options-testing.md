## Risk Assessment

The main risks are losing default effort when attaching a per-call schema, leaking one call's format into another, silently stripping root entries through a convenience API, explicit rejected budgets or cap inflation on selected Sonnet, and changing legacy models globally. A unit assertion against an options object cannot establish SDK request behavior. A direct SDK schema fixture cannot establish Spring AI mapper fidelity. Do not substitute either for wire captures.

Protected behavior includes existing model/allowed-level configuration, legacy explicit budgets, unchanged tool-loop ownership, native retry disabling, request-timeout semantics, callback identity, access checks and canonical data. Contributor/helper signatures are internal and need no compatibility overload. No obsolete public surface is intentionally removed. Unknown model IDs retain current behavior without speculative inference; unsupported levels fail locally before request capture. No endpoint/model-family inference, fallback or cap repair is introduced.
