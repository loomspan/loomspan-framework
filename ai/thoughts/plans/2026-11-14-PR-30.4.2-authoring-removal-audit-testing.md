## Change Summary

Reconcile active guidance and examples with existing canonical/runtime behavior;
correct stale TypeSafe header documentation in configuration metadata; audit removed
provider/schema machinery. No new runtime behavior or supported API is planned.
Pipeline mode full, Steps 2+3. This plan contains proposed verification, not results.

- Root README, skill-authoring index/input/binding/executor/schema/connection topics;
  ticket-named output/evidence/TypeSafe guidance and active examples/generators.

- Optional concrete obsolete residue in active source/tests/resources if established

- Existing schema/declaration/input/example/configuration/removal/public-surface tests.

## Risk Assessment

1. Removing obsolete broad qualifiers can accidentally imply full framework/provider
   correctness. Every changed claim needs exact current proof; maintain real SDK limits.
2. Text searches confuse schema keywords with ordinary data keys, rejection tests and
   historical evidence. Classify matches instead of deleting them mechanically.
3. A loadable schema is not necessarily native-provider compatible. OpenAI requires
   all declared fields required and closed objects; Anthropic requires closure and
   omits documented assertions. Gemini narrowing/planning limits remain visible.
4. Published examples can drift from actual syntax or role semantics. Reuse current
   real Markdown/example and fixture loaders rather than checking prose strings.
5. Native TypeSafe and Console MCP/evaluation schemas are separate systems; no removal
   audit should count them as extra chat adapters or the legacy skill dialect.
6. Preserve the supported Java allowlist, configuration validation, exact content and
   access boundaries. No SPI, mask or canonical-data rewriting is authorized. Existing
   derived-journal rules remain unchanged.
