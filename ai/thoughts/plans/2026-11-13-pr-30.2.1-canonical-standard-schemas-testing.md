# Canonical standard schemas and lossless ingestion testing plan

## Change summary

Replace the internal schema declaration dialect with one Draft 2020-12/NetworkNT 3.0.9 foundation and lossless JSON-bound skill-document decoder. Test the supported role profile and standard semantics independently of downstream migrations. This is Step 3 in the approved full pipeline, continuing in the Step 2 planning context. No implementation or test commands have run during planning.

## Impacted areas and risk assessment

The changed production boundaries are the new internal schema compiler/snapshot, `LoomspanJacksonCodecs.schemaTree`, skill-specific raw YAML construction/JSON conversion, `YamlSkillManifest`, catalog registration and definition schema ownership. The greatest risks are hidden rounding before tree construction, accidentally retaining old coercion/name/closure rules, profile holes at nested nodes, annotation removal from ordinary data properties, mutable schema publication and treating operational failures as valid results.

The manifest contract intentionally changes. The supported Application API stays closed and unchanged; there is no Supported SPI. Executor configuration and ordinary Boot decoding are protected configuration behavior. Current diagnostic locations/messages/facts and generation immutability are protected. Removed schema DTOs and their catalog validators are internal implementation, not compatibility paths. The Java-to-Go protocol is unaffected.

Tests use root JUnit conventions and actual production classes. No provider transport mocks are necessary for compiler/decoder tests. Catalog integration uses `SkillDocument`/in-memory YAML and existing local configuration fixtures; it never contacts a model. No external suite, model download or live provider test is authorized.

- `YamlSkillCatalogTests` has input/output declarations, invalid fixtures, defensive schema copies and supplied-document diagnostics. Its old nested-array, case-folding, declared-required-name and closure assumptions must be updated rather than retained as new semantics.
- `TypeSafeDeclarationTests#parsedYamlScalarFidelityAndResolvedCopiesRemainExact` uses a programmatically constructed BigDecimal and is not literal YAML evidence. Existing duplicate YAML-key coverage does not detect numeric/string conversion collisions.
- `ExecutorConfigurationTests` covers aliases, expanded logical counts, immutable domain configuration and uninterpreted values. `ExecutorDeclarationTests` and `ExecutorConfigurationStartupTests` cover executor form/config separation and ordinary Boot property decoding.
- `SkillAdmissionSnapshotTest` and `SkillGenerationManagerTest` protect captured immutable generations. `SkillMethodBeanPostProcessorTest` already protects resource closure; retain it.
- Retained NetworkNT tests under `docs/maintainers/probes/tbd-06` demonstrate APIs/numeric/format/resource behavior. They remain intact; production foundation tests must call the new compiler, not copy the probe's implementation.
- `LoomspanPublicSurfaceArchitectureTest` is the required API/internal inventory authority. Its unchanged API allowlist and explicit technically-public internal entries are part of verification.

## Tests to add/update

### 1. Equivalent roles and standard instance semantics

**Location:** `src/test/java/ai/loomspan/internal/schema/StandardSchemaCompilerTest.java`. **Type:** parameterized unit. **Surface:** manifest contract/internal implementation. **Expectation:** intentional replacement of legacy semantics.

For INPUT, OUTPUT and PLANNING compile the same supported object contract, then test:

| Case | Required assertions |
| --- | --- |
| Exact property names | `name` does not satisfy required `Name`; distinct `name`, `Name`, ` name ` coexist; preserve empty/punctuation names permitted by standard schemas. A literal slash/tilde name gets correctly escaped diagnostic pointers. |
| Presence/null | Required missing fails; required nullable present null passes; optional absent passes; optional nonnullable null fails; nullable type-array order is immaterial. Inputs are unchanged after both valid and invalid runs. |
| Object openness | Omitted `additionalProperties` remains absent and open at every depth; explicit true remains open; false rejects unknown names. Never add required fields or null values. Required names without `properties` declarations retain standard behavior. |
| Types and coercion | Integer accepts numeric `1` and `1.0`, rejects fractional `1.1` and string `"1"`; number/boolean accept correct JSON kinds and reject numeric/boolean strings. Dates stay strings and are not normalized. |
| Enums | String, boolean, integer, finite decimal and null choices retain kinds and mathematical numeric equality (`1`/`1.0`); wrong case, numeric string and wrong scalars fail. No stringification. |
| Arrays | Homogeneous scalar/object and nested-array item schemas validate recursively, with indexed instance locations. |
| Bounds | Exact minimum/maximum at/below/above values beyond binary floating precision; long fractional and exponent bounds; Unicode code-point min/max length; empty/nonempty min/max items. All six assertions execute locally. |

No mocks. Preserve full diagnostic detail in internal assertions; do not add masking expectations.

### 2. Role-specific profile and meta-schema rejection

**Location:** same compiler test class or a focused profile test class in the same package. **Type:** parameterized unit. **Surface:** manifest contract/internal implementation.

- Accept object roots only, with optional exact Draft 2020-12 `$schema`. Reject missing/nullable/array/scalar roots and other declared dialects locally.
- Accept nested `{}` and schema-valued `additionalProperties` in INPUT, including nested values/arrays/objects; verify typed map entries are enforced. Reject those shapes for native OUTPUT/PLANNING as specified in the implementation plan.
- Accept generated false property schemas for ownership protection; evaluate forbidden override behavior. Reject authored false/true property schemas, generated true shapes and false schemas outside the permitted ownership-property location.
- Reject general type unions, invalid/null type declarations, object/array enums, unknown/legacy keywords, `default`, `pattern`, `$ref` (local and remote), `$defs`, anchors, `allOf`, `anyOf`, `oneOf`, conditionals, tuple/prefix items and other unsupported assertions. Exercise nested properties, items and typed map values, not only roots.
- Meta-schema cases cover malformed `properties`, `required`, duplicate required entries, negative/nonintegral min/max lengths/counts, wrong bounds/description/enum/format/additionalProperties shapes and malformed nullable type arrays. Assert schema locations and original reason; do not rely on compilation success as meta-schema validation.
- Literal ordinary property names `default`, `$ref`, `nullable`, `evidence`, `x-loomspan-evidence`, `x-loomspan-attachment`, `x-loomspan-runtime-ref-capable` remain legitimate. The walker interprets their schema values, not their data names.
- Demonstrate bundled meta-schema validation succeeds with external retrieval unavailable; rejected authored references never require a remote loader. Avoid live-network tests.

### 3. Pinned standard formats and settings

**Location:** `StandardSchemaCompilerTest` or `StandardSchemaFormatsTest`. **Type:** parameterized unit. **Surface:** manifest behavior/internal validation.

Create a table with at least one library-valid and one library-invalid value for each of the 19 documented standard names: date, date-time, duration, email, hostname, idn-email, idn-hostname, ipv4, ipv6, iri, iri-reference, json-pointer, regex, relative-json-pointer, time, uri, uri-reference, uri-template, uuid. Derive expected cases from the installed 3.0.9 validators rather than assuming stricter business rules. Include valid relative/empty values where a particular format permits them; choose invalid cases that the actual standard validator rejects.

Run formats through all roles, and representative nested item/map placements. Reject unknown names, differently cased names and the library's nonstandard `alpha`, `alphanumeric`, `color`, `ip-address`, `phone`, `style`, `utc-millisec` at declaration time. Plain strings with no format remain unconstrained, regardless of property name. Invalid date text is never rewritten.

Verify the production validation settings use `formatAssertionsEnabled(true)`, `maxEvaluationDepth(0)`, `maxEvaluationSteps(0)` and fresh contexts. Use behavior plus accessible internal configuration assertions rather than introducing public test hooks. A bounded moderately deep nested schema and a wide instance verify no incidental small limit was introduced; no stress/SLO claim is made.

### 4. Annotation placement, shape, fidelity and provider copies

**Location:** `src/test/java/ai/loomspan/internal/schema/CanonicalSchemaTest.java` / `StandardSchemaCompilerTest`. **Type:** parameterized unit. **Surface:** manifest contract and serialized schema copies.

Attachment matrix:

- Accept single, nested, array-string-item, array-object-property and typed-map string-value declarations; verify canonical metadata and surrounding nullable/required/bounds/openness constraints exactly.
- Cover all five supported media types and ordinary nonblank content-type values. Reject missing/null/nonobject metadata, unknown fields, missing/blank/unsupported media type, missing/null/empty/nonarray content-type lists, nonstring/blank entries, nonstring schema leaves and OUTPUT/PLANNING placements.
- Reject legacy `type: attachment`, old direct media fields and top-level `input_attachments` (the latter through catalog/manifest validation). Do not implement the downstream MIME grammar correction here.

Runtime marker matrix: accept boolean marker on generated INPUT string leaf only; reject authored use, wrong roles/locations/nonboolean values. No native generated attachment behavior is inferred from marker support.

Evidence matrix:

- Accept nonblank `x-loomspan-evidence` only on immediate root OUTPUT properties, including multiple exact case/whitespace-distinct property names. Preserve leading/trailing whitespace, multiline original expression text and punctuation.
- Reject root, nested property, array item, array-object property, INPUT/PLANNING placements, empty/blank strings and null/boolean/numeric/list/object values. Assert the diagnostic identifies the annotation path.
- Reject schema-node legacy `evidence`; accept ordinary data properties named `evidence` and `x-loomspan-evidence` at root/nested locations.

For every accepted annotation shape, compare canonical snapshots before/after provider extraction. Remove only recognized schema annotations; preserve descriptions, standard assertions and same-named data properties at every supported schema-node traversal edge. Unknown `x-*` declarations are rejected, not broadly stripped. Returned provider trees must be independent copies. Expression grammar/direct-child resolution and provider wire captures remain downstream checks, not claimed here.

### 5. Canonical ownership, diagnostics and operational failure

**Location:** `CanonicalSchemaTest`. **Type:** unit, with bounded parallel/repeated validations where useful. **Surface:** internal implementation and current diagnostics.

- Mutate original supplied schema after compilation, mutate trees returned by canonical/provider accessors, and verify subsequent validation and schema contents remain unchanged. Repeat across nested maps/lists/numeric values.
- Reuse one compiled schema for valid/invalid/repeated and independent concurrent executions; no errors, annotations or settings leak between calls.
- Assert validation diagnostics retain keyword, schema pointer/location, instance location and original library message/details for exact values containing whitespace/control escapes and key-like strings. Public input/output issue mapping is downstream, but the foundation must not lose the information it will need.
- Use an existing injectable/internal seam or a failing instance/parser path to show an operational error propagates separately from invalid-instance diagnostics. Never create an empty-error success or partial verdict after an exception. Avoid a new public failure-injection API and avoid modifying unlimited product settings for the test.

### 6. Literal YAML/JSON fidelity and pre-conversion rejection

**Location:** `src/test/java/ai/loomspan/internal/serialization/SkillDocumentValuesTest.java`, `YamlValuesTest.java`, and focused additions in `YamlSkillCatalogTests`/`TypeSafeDeclarationTests`. **Type:** unit plus catalog integration. **Surface:** manifest/configuration behavior.

- Literal long fractions, `9007199254740993.0`, finite exponents with positive/negative exponents and huge integers retain exact numeric values; feed literal schema minimum/maximum values directly into the production compiler and assert boundary verdicts. Confirm raw JSON parser equivalence without programmatic replacement of literals.
- Literal TypeSafe authored data has nested list/object finite decimals, booleans, null and quoted strings preserved through the decoder; catalog declaration/resolved-copy assertions are added but may have a recorded integration blocker.
- Reject numeric and boolean mapping keys at top-level, schema properties, nested list/object values and TypeSafe data. Reject numeric `1` alongside quoted `"1"` before conversion can collide. Accept quoted numeric/boolean-looking keys, exact casing and punctuation controls.
- Reject `.nan`, `.inf`, `-.inf` at nested schema enums/bounds and ordinary literal/TypeSafe data. Accept quoted `"NaN"`, `"Infinity"`, `"-Infinity"` unchanged. Reject other decoded non-JSON values rather than stringify them.
- Verify duplicate keys, recursive aliases and the existing one-million expanded-value bound still fail. Shared aliases below that bound preserve values; explicit timestamps remain strings. Do not add arbitrary smaller ingress limits.
- Config controls: top-level executor config retains the existing generic YAML numeric kinds and domain-value behavior, including nested maps/aliases and finite/nonfinite values permitted by that existing path; ordinary Boot properties retain delegated decoding. The exemption applies only to the actual config subtree, not any JSON-bound field named `config`. Invalid executor form/config shapes still fail under existing catalog rules.
- Diagnostics include source and the offending key/value path before `valueToTree`; assert the quoted-key controls survive as distinct JSON field names.

## How to run

Use Java 21+ and the repository Maven baseline; no credentials or model configuration are required for foundation unit tests.

1. `mvn -DskipTests compile` — establish actual root build state after production migration.
2. `mvn test -Dtest=StandardSchemaCompilerTest,CanonicalSchemaTest,StandardSchemaFormatsTest,SkillDocumentValuesTest,YamlValuesTest` — adjust exact test-class names to the implemented classes and record the resulting exact command.
3. If intentional root compile failures block (2), generate an isolated Maven descriptor under `target/` using root dependency management/dependencies and explicit includes of actual foundation production/test source. Execute those same normal unit tests from a clean separate output directory, with no fake downstream classes, stale root classes, copied implementation, normal-build exclusions or weakened assertions. A reproducible `ai/scripts/test-canonical-schemas.ps1` launcher may create this descriptor and report its deliberately restricted scope. Record its exact command and test counts. Do not call it a full project pass.
4. `mvn test -Dtest=YamlSkillCatalogTests,TypeSafeDeclarationTests` — catalog/literal TypeSafe integration and fixture expectations.
5. `mvn test -Dtest=ExecutorDeclarationTests,ExecutorConfigurationTests,ExecutorConfigurationStartupTests,SkillAdmissionSnapshotTest,SkillGenerationManagerTest,SkillMethodBeanPostProcessorTest` — preservation controls, run when buildable and otherwise record exact blockers.
6. `mvn test -Dtest=LoomspanPublicSurfaceArchitectureTest` — required after production edits; record blocked compilation if applicable. A source inventory is useful supporting evidence but cannot be called an architecture-test pass.
7. `git diff --check` and targeted searches for removed DTO definitions, old owned accepted declaration syntax and unintended public/conditional-bean surfaces.

No full historical resource microprobe rerun is required solely because a compiler is added; retain its files unchanged. If a concrete compiler setting change touches its behavior, select the relevant deterministic checks. No live provider or deployed suite check belongs in this ticket.
