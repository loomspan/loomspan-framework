## Change summary and impacted areas

One internal classifier rejects explicit refusal/incomplete responses in `ProviderAttemptCallAdvisor` and `CanonicalToolCallingManager`. Existing Responses interception retains actual failed-envelope usage. Usage/outcomes are recorded once; zero native counts remain exact. Current-version Java/Go attempt readers accept receipt-plus-failure without treating receipt as success. Documentation follows verified behavior.

Impacted components: provider advisor/integration/evidence carrier/classifier, canonical manager/assembler wiring, usage extractor, Java trace/attempt projections, Console `traceanalysis`, semantic corpus, routed authoring docs.

## Risk assessment and compatibility

- A valid JSON response can still be explicitly incomplete and must never enter schema/lint/evidence correction or planner parsing.
- An incomplete multi-call reply must execute zero callbacks across all generations.
- A complete tool turn can have no final text and must continue normally. Refusal-like prose is accepted under normal complete status.
- Returned and SDK-thrown evidence must link to the same actual attempt; usage and outcomes cannot be duplicated through success/failure or aggregated tool-loop paths.
- Quota enforcement can throw after usage mutation; cancellation fences suppress late writes. No accounting retry may create duplicate units or physical attempts.
- Missing usage, native zero usage and no HTTP response are distinct. Transport failures must not fabricate response tokens.
- Console currently rejects receipt then failure. Atomic current-version corpus/readers must be tested, including malformed lifecycle controls.
- No supported API/signature, configuration or durable format change is planned. Run the public-surface architecture check. Internal callers/fixtures change in place; no compatibility reader/shim.
