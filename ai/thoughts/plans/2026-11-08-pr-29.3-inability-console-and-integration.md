## Implementation Approach

### Phase 1 — Validate and project existing failure facts

1. In `internal/traceanalysis/failures.go`, use the existing reconstructed `ERROR_RECORDED.data` and member-presence check to reject a present kind unless it is exactly the string `planner_inability` and classification is `RECOVERABLE`. Accept an absent member for ordinary failures. Explicit null, empty, wrong types, unknown values and contradictions are invalid. Use the existing unsupported-value category. Keep `terminal` solely derived from completion and keep `failureId`, cause linkage, and frame provenance as recorded.
2. Carry optional kind through `failureResult`, persisted failure-index summary and `QueryFailures`, `FailureSummary`, and `RecordFacts.Failures`. Extend Browser `failureDTO` in `internal/browserapi/trace_analysis.go`, MCP `failureDTO` in `internal/mcpadapter/trace_contracts.go` and `mapFailure` in `traces.go`. Use an optional literal Browser contract, keep the invalidity guard at canonical ingestion, and apply the same shape to the Browser failure response boundary. In `output_schemas.go` expose the optional literal and its classification constraint within the existing open failure object, avoiding unrelated schema tightening. Omit absent kind in serialized output.
3. Reuse `TraceFailureFocus` for the selected inability in successful and failed traces. Key its labels, ID, and completion display to the selected failure and authoritative summary separately, so a child selected in a failed trace does not inherit the root failure's label or ID. Pass details only for the selected failure's matching origin frame. Present recorded context, route and skill evidence using existing source details and related actions. Display inherited task/plan/step data as the surrounding assignment if shown, and keep synthesis context explicit from the recorded summary. Keep the existing terminal loading state for completion-linked failures.
4. Add the named signal label in `TraceFailureDiagnostic` and reuse descriptor ordering, text/plain and truncation metadata, existing deliberate load, copy and download behavior, exact exception message, and range/authorization checks. Preserve opaque text including invalid/truncated JSON and CRLF. MCP continues to use failure-ID record filtering, detailed frames, ordinal diagnostic content references and the existing content reads.

**Automated success** — Failure kind validation, both Go projections and Browser/MCP DTOs, selection in both completion states, distinct selected versus completion IDs, exact diagnostic text, and unchanged ordinary recoverable and terminal/cause paths are covered by the testing plan.

### Phase 2 — Render the canonical model payload

1. In `TraceRecords.tsx`, replace the old chat readers with `messages` for requests and `generations` for responses. Use one local parser and renderer for messages, validating required text as string/null, assistant tool-call arrays, tool message response arrays, and exact nullable call/response fields. Accept empty generations and null output entries as defined by the producer. Use array position only as local presentation grouping and React keys. Render null and empty strings distinctly, without assigning identities or cross-record associations.
2. Show each generation in returned order and all message text, call IDs, names and raw argument strings, or response IDs, names and exact content strings in supplied order. Use plain inert text with whitespace-preserving styles. Replace chat response pretty-printing of the old field. Parent feedback is the content of the actual recorded tool-response message with its supplied identifiers. Existing provider-failure rendering still handles cases with no response captured. Keep `payloadType: evaluation` separate and use the same range/scope plumbing for inline and chunked payloads. Keep request/response disclosure and cache behavior intact.
3. Audit model record consumers, including `ExecutionJournalProjector`, record search/content paths, Java/Go fixtures and Browser mocks. Convert obsolete chat fixtures and assertions to the canonical payload. Keep TypeSafe `payloadType: evaluation`, tool/skill content and generic opaque record handling distinct. The journal's existing projection rules stay confined to that derived view.

**Automated success** — The model detail tests distinguish absence, empty strings and repeated IDs, assert exact multiline text, ordered multiple generations and calls/responses, demonstrate a later-generation protocol rejection with no later request, and keep range/TypeSafe tests green.

## Implementation notes

- The shared fixtures exercise the actual Java bounded diagnostic capture and failure ID reuse. The failed-root signal crosses the 1 MiB UTF-8 limit inside a multibyte character. The successful-root fixture records synthesis as the declaring step and separately retains its enclosing assignment.
- Current fixture updates also changed the derived artifact download length and the current finalized evaluation fixture digest. The transport metadata and current evaluation references were regenerated or updated. Historical replay results and their packaged skill snapshot are unchanged.
- The MCP record discovery schema exposes the optional discriminator and its required recoverable classification. A shorter existing record-tool description preserves the 25 KiB discovery budget. The live tool-list snapshot and exact response size were updated together.
- The model detail reader checks each continuation with the existing Console scope verifier before it joins the returned bytes. No Java production types or configuration keys were added in this step.
- Failure analysis validates the exact canonical members and retains the validated `exceptionMessage` JSON value. This preserves an isolated UTF-16 code unit escaped by the Java writer. The existing MCP record tool validates its structured output against both current schemas and publishes the validated bytes directly. Typed input validation, text fallback, and other tools keep their existing paths. Browser evidence reads reject a response whose source disagrees with the selected source.
