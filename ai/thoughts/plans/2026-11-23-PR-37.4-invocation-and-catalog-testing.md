# PR 37.4 Explicit invocation and catalog identities Testing Plan

## Change Summary

Require namespace/localName in every public root validation, invocation and handoff operation. Expose namespace/localName plus derived qualifiedName on both metadata records, and accept a local name in a namespace-scoped catalog. Verify exact target selection and existing capture, authorization, input, observer and lease semantics through normal entry points.

## Risk Assessment

1. A root method may accidentally keep default inference or parse a colon in one component. The signature reflection test and all-operation pair matrix must cover every shape.
2. Same-local declarations in distinct namespaces can expose a caller that captures the right metadata but later reconstructs a different target. Assert the typed snapshot entry, generation ID and actual executor/Java result.
3. Catalog input such as `warehouse-lookup` is a valid local name. It must stay local with foreign `warehouse:lookup` present. A local miss ends in empty, and invocation of that pair fails even with the foreign skill installed.
4. Exact grammar includes pair length, so a catalog miss must still validate the pair rather than validating only a local string. Use `order-support` with 49/50-character locals.
5. Changing Object/Map signatures can accidentally reroute overload resolution or move capture after Jackson conversion. Preserve and run the existing timing/null/error tests.
6. Handoff changes may release a lease twice, fail to release, read current generations when invoked, or lose authentication. Run the complete handoff/capture families.
7. API records may expose internal types through a new constructor/helper. Exact reflection and recursive architecture tests are both required.
8. Many tests call the facade even when their behavior is owned by later tickets. All checked-in tests must compile. Interpret root/canonical fixture changes by field and keep raw provider data exact.
