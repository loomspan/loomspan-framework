# PR 35.2 provider literals testing plan

## Change Summary

Published provider configuration accepts literal `api-key`, `headers` and `gemini.credentials-json`. Explicit credential URI syntax and the adapter resource-loading path are removed. Existing provider validation, ordinary scalar conversion, API-key authentication and Vertex construction remain covered through their normal entry points.

The implementation plan is `ai/thoughts/plans/2026-11-22-PR-35.2-provider-literals.md`. Full-profile pipeline testing begins from `3a02e941403117700db9a6c869af2e160ecc1f4b`. Planning itself runs no tests and claims no verification result.

## Impacted Areas

- `ExecutionConfigurationParser`, `DefaultSkillReloader` and `SkillGenerationManager` supply the parser and ordinary preparation route.
- `LoomspanProperties` supplies strict startup binding and provider validation.
- `SpringAiProviderIntegration` and `LoomspanAutoConfiguration` construct provider runtimes.
- `NamedAiConnectionRegistry` and `ProviderFailureGuidance` supply relevant current diagnostic paths.
- Spring configuration metadata and current model/publication authoring guidance describe the changed contract.

## Risk Assessment

1. Flattened header maps can lose punctuation, spaces, brackets or blank keys before validation. Tests must assert original names reach the shared HTTP-token rule and valid names retain exact spelling/value.
2. Literal strings or multiline JSON can change during scalar conversion or binding. Test exact captured values and use valid multiline service-account JSON at the adapter boundary.
3. Literal/reference pairs could overwrite each other according to YAML order. Test strict rejection for each pair in both authored orders.
4. URI support could survive in properties, parser aliases, adapter code, wiring, metadata or guidance. Verify strict unknown-field errors, zero credential reads and source absence.
5. Removing URI construction must preserve API-key and absent-explicit-JSON Vertex branches, provider retries and timeouts.

The protected Application API consists of the existing preparation/publication signatures. No supported SPI exists. Intentional removal of startup URI and published URI-reference contracts is authorized by the ticket. Internal adapter constructors change atomically. Ephemeral guidance uses current setting paths. There is no trace format or Java-to-Go transport change.
