# PR 37.5 model and worker dispatch testing plan

## Change summary

Native provider function definitions and returned calls use `namespace--local-name`. The adapter binds that name to the already resolved callback, and dispatch performs exact request membership. Plans and assigned worker actions use `namespace:local-name` with strict grammar, exact visibility and assignment validation. Raw model evidence retains exchanged names and content, while existing resolved identity fields use a colon.

This plan continues Step 2 directly into Step 3 in the Full 5-Step Pipeline. Its governing implementation plan is `2026-11-23-PR-37.5-model-and-worker-dispatch.md`. Planning ran no tests. Implementation must record actual commands, counts, failures and final results in the ticket completion record.

## Impact and risk

| Boundary | Risk and required evidence |
| --- | --- |
| Native adapter | Accidentally advertise colon spelling or derive the name from a parsed display string. Assert the exact definition from retained metadata components. |
| Request dispatch | Parse a returned name, retry globally, use another invocation's callback, or execute an early valid call before discovering a later unoffered call. Assert exact request membership and zero side effects on full-response failure. |
| Framework control | Permit a callback to impersonate `loomspan_cannot_complete`, weaken sole-control handling or change reason fidelity. Retain actual-type, collision and strict-envelope tests. |
| Plan acceptance | Normalize invalid names or alter accepted candidate data. Assert strict qualified grammar, exact root/visible membership and unchanged trees. |
| Assigned worker | Dispatch a different visible child, accept provider spelling or lose assignment/caller context. Assert prompt, structured action, actual execution, correction and authorization. |
| Evidence | Rewrite raw provider names, strings or rich parts while presenting a resolved target. Assert exact original response object passage, real trace payloads and distinct resolved fields. |
| Fixture conversion | Change a valid hyphenated local or arbitrary raw string according to its appearance. Interpret each field using target provenance and its protocol role. |

Application API signatures remain the supported explicit component API from PR 37.4. Internal wrapper/helper names can change directly. The serialized provider protocol replacement is approved by the ticket and developer. Current-run trace coherence and authorization remain required. The Java-to-Go/UI corpus coordination is assigned to PR 37.6, with combined builds and deferred-check reconciliation in PR 37.8. The existing exact release marker policy applies throughout.
