## Risk Assessment

- Losing interface-only annotations, registering bridges twice, allowing a mixed-role declaration, or checking only one interface can register the wrong contract or expose an executor as callable.
- Selecting a target instead of its proxy bypasses advice. Lazy/executor-only beans, JDK interface dispatch and CGLIB final/static/private methods need real Framework boundary tests.
- Output tests currently expect quoted Java strings and transformed exceptions. Updating these mechanically could accidentally change JSON object results, unrelated model results, input reference handling or cleanup.
- Broad cause-chain unwrapping could change application terminality. Only explicit reflection/proxy wrappers are transparent; an ordinary application wrapper is terminal even if a recoverable subtype exists below it.
- Null-preserving copying cannot use null-rejecting convenience copies. Arbitrary leaves/resources remain shared references; tests must not claim full object/resource immutability.
- This ticket does not deliver executor generation binding, root/child executor runtime routing, composed policy filtering or tool-manager correction. Test direct registrations internally and supported application declaration/value construction externally. Do not invent a temporary runtime route to create an end-to-end test.

### Protected and intentionally changed surfaces

The architecture allowlist, README, public API tests and ticket establish supported API. Preserve existing facade signatures and supported REST value/SPI behavior until PR 28.3. Add exactly the three authorized API types, without internal signature leaks or extra public extension contracts. `SkillMethod` text/null/failure semantics deliberately change under the Pipeline notes; do not retain both conversions. Transformer interfaces/beans/constructors are internal and must disappear atomically rather than acquire compatibility tests. No durable format or Console wire shape changes are planned. Existing current-run observation/control tests remain useful regression evidence; no historical-format or new content-masking tests are required.

## Bug Reproduction / Failing Test First

This work combines refactoring with deliberate new behavior. Establish small independent red tests, not a complete duplicate implementation:

1. **Exact string result:** in `SkillMethodBeanPostProcessorTest`, invoke an existing registered Java method returning `"  alpha\n"` and assert that exact value. It fails against baseline's JSON-quoted/escaped string. Add null/void to empty-text coverage alongside it.
2. **Thrown failure:** an ordinary application `IllegalStateException("wrapper", recoverable-or-ordinary-cause)` must be thrown, with the outer choice/cause intact. A version using an ordinary existing cause compiles on baseline and fails because the current transformer returns text. Once the new exception exists, add the designated nested-cause terminality case.
3. **Incompatible interfaces hidden by implementation:** create two mapped `@SkillMethod` interfaces with different annotation metadata and no `SkillParam`, plus directly annotated implementation. Registration must reject them before selecting a contract. Baseline's early return accepts them.
4. **New API/role tests:** new type/signature/default tests initially fail to compile because the types are absent. Record that as feature red evidence, then add the API and move to focused behavioral red/green checks. Do not run the entire suite merely to demonstrate missing types.

Step 4 should record the actual failing command and reason for at least the compiling output/contract regression before its fix. Planning has only established pre-change behavior from source and existing assertions; it does not claim an executed red test.

## Tests to Add/Update

Test names below express behavioral cases; reuse existing classes and parameterized/shared fixture helpers when clearer. Renaming or combining cases is acceptable if the resulting evidence covers each row.

### 1) Executor Annotation and Invocation Public Shape

- **Type/location:** unit, new `src/test/java/ai/loomspan/api/SkillExecutorTest.java` and expanded `ApplicationApiValueTest.java`.
- **What it proves:** `SkillExecutor` has exactly `name`, `namespace`, `config`, their defaults, runtime retention and method-only target. The record is public, is a record, has exactly five components in settled order/types, one public canonical constructor, ordinary record accessors and no extra builder/factory/runtime/authentication API. Constructor rejects each null map and null/blank metadata independently. Valid metadata remains exact; empty maps succeed.
- **Fixtures/data:** three different mutable top-level maps, nested mutable maps/lists containing null elements/values/keys where baseline copying accepts them, scalar leaves, `ByteArrayResource`, a mutable arbitrary leaf, array/set leaves. Mutate every source container after construction; attempt mutation through every output map/list. Assert copied maps/lists are detached/unmodifiable, while resource/arbitrary/array/set leaves retain identity. Mutating a leaf or its resource backing is outside container-copy guarantees.
- **Mocks:** none; no resource bytes should be read just to construct an invocation.
- **Affected surface:** Application API plus shared internal copying.
- **Compatibility expectation:** additive settled shape; existing REST value-copy tests continue passing through the same copier. Do not broaden `RestSkillInvocation` validation or change its three components.

### 2) Recoverable Exception Constructors

- **Type/location:** unit, `ApplicationApiValueTest.java` or focused `RecoverableSkillExceptionTest.java` in the API package.
- **What it proves:** extends `SkillException`; exposes only `(String)` and `(String, Throwable)` public constructors. Null, empty and whitespace-only messages fail for both constructors. A padded/newline valid message is byte-for-byte preserved. Omitted/null and non-null causes retain their expected values; cause message is never substituted as feedback.
- **Fixtures/data:** messages `null`, `""`, `" \t\n"`, `"  correct the account\n"`; distinct cause with a different message, including blank-message invalid construction with a nonblank cause.
- **Mocks:** none.
- **Affected surface:** Application API.
- **Compatibility expectation:** exact additive constructors, no no-arg/cause-only constructor, fallback message, trimming or extra wrapper return API.

### 3) Shared Discovery, Identity and Contract Matrix

- **Type/location:** unit/integration, expand `SkillMethodBeanPostProcessorTest.java` and `SkillMethodTargetDiscoveryIntegrationTests.java`, or a shared Java discovery test class in the same internal core test package.
- **What it proves:** one scan/lifecycle detects both roles on ordinary, JDK and CGLIB beans; interface-only annotations work; canonical generic bridges register once; equivalent interfaces are accepted; conflicting names/namespaces/config references or callable parameter metadata fail deterministically with useful bean/method/conflict diagnostics. Direct implementation annotation cannot hide incompatible interfaces.
- **Role-conflict cases:** both annotations on one physical declaration; callable interface/executor implementation; executor interface/callable implementation; separate interfaces assigning different roles; generic bridge mapping with a split role. Both scan orders produce the same failure category and useful declaration locations.
- **Identity cases:** fallback method name, default namespace, namespace lowercase normalization, local case, independent/combined length limits, invalid identities, duplicate role identities across beans/interfaces, same-name skill+executor across separate methods/beans, mixed-role bean. Existing explicitly named callable overloads remain valid and default-name overloads collide. Executor generic-interface fixtures use canonical `SkillExecutorInvocation` implementations; wrong canonical types still fail.
- **Fixtures/data:** real application-shaped beans and interface hierarchies; `ProxyFactory`; existing `StaticListableBeanFactory` for local invocation tests. Use a configurable real `AnnotationConfigApplicationContext` with a lazy executor-only bean to exercise `completeDiscovery()` relevance scanning and ensure application code is not executed by discovery. Call `capabilities()`/`executors()` repeatedly and in either order to check idempotence and shared completion.
- **Mocks:** none for proxy behavior; use counters for application method/advice calls.
- **Affected surface:** internal registration with supported annotation semantics.
- **Compatibility expectation:** existing valid callable schemas/binding remain intact; incompatible interfaces and split roles reject deterministically; no second scanner or lifecycle.

### 4) Executor-Specific Signature and Reference-Only Registration

- **Type/location:** unit/integration, same shared discovery suite; supported-surface catalog check where practical.
- **What it proves:** exactly one canonical invocation-record parameter is accepted. Zero, extra, map/Object/wrong parameter and varargs signatures reject at declaration registration with useful diagnostics. The exact config reference string remains registration metadata, without a duplicate semantic path/binding resolver. Non-string/void returns have the same support as callable methods.
- **Reference-only assertions:** executor-only bean yields one executor registration and no capabilities; mixed-role bean yields only callable methods in capabilities; same-name cross-role registration yields distinct entries. Executor has no generated `CapabilityToolDescriptor` or schema. Existing generation/catalog path receives only callable registrations. `SkillTemplate.invoke()` for an executor-only name fails as unknown without calling the executor; if a callable shares its name, invocation reaches only the callable.
- **Fixtures/data:** invocation record with distinct input/skillConfig/executorConfig maps and canonical metadata; invocation counter; same-name callable/executor methods. Internal tests can directly invoke the typed registration, but public fixtures must not import it.
- **Mocks:** no schema-generator mock required if absence is established by registration/catalog boundaries; a focused instrumentation fixture may prove no executor schema generation when helpful.
- **Affected surface:** supported declaration semantics/internal registration and public callability boundary.
- **Compatibility expectation:** no public executor route and no temporary generation subsystem. Full executor namespace startup/binding is PR 28.3, so do not claim that behavior from these tests.

### 5) Shared Result Conversion and Propagation

- **Type/location:** unit/integration, shared Java invocation tests alongside processor/proxy tests; update existing assertions in Java integration suites.
- **What it proves:** both role registrations invoke through the same managed-proxy boundary after argument construction. Results `null`, void, `""`, `" \t\n"`, ordinary String, number/boolean, map/list and DTO produce respectively empty text, exact text and expected JSON. Include strings that look like JSON or error messages to establish no content classification or reinterpretation. Actual serialization failure remains thrown and retains its cause; it cannot return error text.
- **Fixtures/data:** shared result-source collaborator used by callable/executor fixture methods; deterministic DTO/object whose accessor or configured serializer throws; use real application `ObjectMapper`, with a scoped mapper override only in an internal unit harness when needed to force failure. Count actual proxy advice invocations and assert the final bean (not captured target) supplies result/state.
- **Mocks:** none for real proxy/serialization paths. Avoid a mock converter whose expected values merely mirror implementation branches.
- **Additional regression:** callable typed ref binding, nested resources, input schemas and opened-stream cleanup still work when method invocation or serialization throws. Executor invocation retains resource/non-container leaves and distinct maps without typed coercion or merging.
- **Affected surface:** intentional Application API behavior change/internal implementation.
- **Compatibility expectation:** delete quoted-string/transformed-success assertions; preserve JSON object conversion and unrelated model/REST semantics.

### 6) Narrow Recoverability and Actual Infrastructure Wrappers

- **Type/location:** unit policy tests plus actual proxy invocation tests in internal core package.
- **What it proves:** direct `RecoverableSkillException` is recoverable and thrown; `InvocationTargetException` and `UndeclaredThrowableException` around it are transparent, including nested recognized wrappers. Application `IllegalStateException` or ordinary `SkillException` around it is terminal; recognized wrapper around that application wrapper remains terminal. Messages, causes and suppressed diagnostics remain available. Null/missing targets and terminal wrappers do not create feedback or loop.
- **Actual-boundary evidence:** invoke real annotated methods through reflection/shared invoker and JDK/CGLIB Spring proxies, including advice throwing an undeclared checked exception to establish the actual `UndeclaredThrowableException` behavior. Assert direct designated runtime failures retain their type through Spring reflection; contrast advice/application failures wrapping the subtype with `IllegalStateException`. Record the concrete wrappers observed; manually constructed policy cases supplement, not replace, these paths.
- **Terminal controls:** direct Spring AccessDenied/authentication exceptions, ordinary runtime errors, cancellation/control exceptions present at this boundary and JVM `Error` remain failures; shared policy never marks them recoverable merely because a deeper cause is designated. Old security cause-chain bypass expectations become assertions that the thrown application's outer failure is preserved, never successful text.
- **Mocks:** none for the actual reflection/proxy path; test advice supplies controlled throwables.
- **Affected surface:** Application API designated signal/internal policy.
- **Compatibility expectation:** no arbitrary cause scan or broad wrapper list. Worker `ExecutionException`/Spring AI tool wrapper integration is PR 28.5 and must reuse this policy there; it is not an excuse to add a second classifier or preemptively unwrap all causes here.

### 7) Real Spring Method Security and Proxyability for Both Roles

- **Type/location:** integration, extend `JavaSkillSecurityStartupTests.java`, authorization integration tests and/or shared role-specific proxy suite.
- **What it proves:** actual `@EnableMethodSecurity(jsr250Enabled=true)` advice is retained for executor as well as callable methods. Real `@RolesAllowed`, `@PermitAll` and `@DenyAll` are discovered and enforced on supported class/method/interface declarations. Authorized caller executes once; denied caller executes zero times and gets a failure. No advice/disabled advice/unrelated advice fails completed discovery for annotated declarations; unrestricted declarations need no JSR-250 advice.
- **Unsafe dispatch:** CGLIB private/final/static annotated methods fail completion; methods unavailable through a JDK proxy fail instead of target invocation. Interface-compatible JDK methods execute through advice. Use final Spring bean state/counters to catch unwrapped target execution.
- **Fixtures/data:** actual application context with security configuration, real authentication tokens, caller scope restoration in `finally`, invocation record for executors. Existing Java root/child authentication isolation and cutoff suites run unchanged except authorized result text updates.
- **Mocks:** no mocked access decision/advisor for the acceptance evidence.
- **Affected surface:** security boundary/internal shared discovery/invocation.
- **Compatibility expectation:** preserve existing supported Spring policy behavior. Do not add executor YAML policy composition/tool filtering assertions until the assigned runtime tickets.

### 8) Supported Surface, Wiring and Repository Regression

- **Type/location:** architecture and integration; `LoomspanPublicSurfaceArchitectureTest`, `LoomspanAutoConfigurationBoundaryTest`, `LoomspanAutoConfigurationTests`, `SupportedSurfaceIntegrationTest`.
- **What it proves:** exactly 27 supported types at this slice; public signatures leak no internal/autoconfigure types; internal helper visibility is deliberately classified. Application fixtures declare executor methods and construct invocation/exception values using public types only. No new handler interface or bean-replacement SPI is introduced. Transformer types and bean wiring are absent and there is one Java discovery owner. - **Fixtures/data:** reuse existing local protocol-compatible model server for supported consumer integration; no live external service. Executor method may coexist in the fixture but must be absent from public catalogs and callable name lookup.
- **Mocks:** supported application unit tests may fake `SkillTemplate`; Framework boundary evidence uses real autoconfiguration.
- **Affected surface:** supported Application API, preserved REST SPI, internal wiring, current-run diagnostics/control regression.
- **Compatibility expectation:** update inventories, remove obsolete transformer assertions/test, retain existing current Java/REST/model behavior outside the intentional break. The complete Java suite catches changed quoted-string expectations in roots/children/bindings/fixtures. Do not modify Go/Console contracts without concrete wire-impact evidence.
