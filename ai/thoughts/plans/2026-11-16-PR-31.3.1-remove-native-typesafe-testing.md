# Remove native TypeSafe — Testing Plan

## Change Summary

Remove Framework-native TypeSafe declarations, driver/configuration, dispatch, HTTP resources, public kind and current Console/MCP/trace assumptions. Retain ordinary JAVA executors and generic model execution. The approved profile is full; this testing plan accompanies `2026-11-16-PR-31.3.1-remove-native-typesafe.md` and the matching research artifact. No tests were executed during planning.

## Impacted Areas and Risks

- **Application API:** `SkillKind` removal and closed supported surface. Risk: an obsolete enum/type remains or new internal types leak through supported signatures.
- **Configuration and manifests:** unknown native syntax versus ordinary executor domain keys; startup and complete publication configuration. Risk: silently accepting/ignoring retired declarations or changing arbitrary executor keys/numbers.
- **Internal execution/resources:** generation/catalog classification, direct/child routes, registry failed-construction and retirement cleanup. Risk: removing shared provider cleanup or lifecycle machinery with the native client.
- **Bindings/authorization/publication:** native fixtures in generic tests. Risk: deleting meaningful coverage, fabricated output metadata, losing captured values or namespace authority.
- **Persisted/serialized and ephemeral diagnostics:** coordinated catalog kinds, REST/MCP schema snapshots, Java/Go trace corpus and TypeScript renderer. Risk: stale current shapes, removed generic content checks or compatibility-marker drift.
- **Consumer guidance:** obsolete recipes, deleted source anchors and unsupported claims. Risk: docs still prescribe removed grammar or imply parity not provided by executor packs.

Protected contracts remain generic namespace/reference-only visibility, authorization, captured config/publication/retirement, model-provider calls, executor JAVA provenance, live lifecycle observations, Framework-accounted usage and existing diagnostic inspection. Intentional removals have no compatibility paths. There is no supported Java SPI.

Before deleting production support, add a minimal rejection test in `YamlSkillCatalogTests` using a valid native leaf/configuration that currently loads. Include null/empty and executor-combination cases as post-removal negative coverage; exact generic error wording can follow the existing unknown-field mechanism, with field/source context and no translation.

Add configuration rejection tests in existing startup/parser tests for `driver: typesafe`. Current code accepts that enum, so the expectation must fail before removal and pass after the enum is removed. Record exact test selectors and observed pre/post results during implementation; do not report a source-only prediction as a test run.

## Tests to Add or Update

### 1. Unsupported native declarations and drivers

- **Type/location:** focused unit/startup tests in `YamlSkillCatalogTests`, `ExecutorDeclarationTests`, `LoomspanPropertiesTest`/configuration startup tests and `ExecutionConfigurationParserTest`.
- **Proves:** old native top-level field and driver fail; null/empty values and mixed forms do not evade validation; no fallback to model/executor route. Ordinary `config` keys named `typesafe`, `model`, request fields and literal strings remain domain data.
- **Fixtures/mocks:** in-memory YAML/current catalog fixtures and existing ApplicationContextRunner patterns; no external services.
- **Surface/expectation:** intentional Configuration and manifest contract removal; generic executor config protected.

### 2. Direct and parent-bound receiving input

- **Type/location:** `DeclaredChildInputBindingsIntegrationTest`.
- **Proves:** real annotated `FixtureExecutor` receives the same exact structured input through direct and parent binding routes; invalid direct input and assembled child input fail before callback; exact map key case and input contract stay enforced.
- **Fixtures/mocks:** ordinary local planner HTTP stub plus real public executor registration; remove System One/native connection. Keep request/callback counts meaningful for the changed route.
- **Surface/expectation:** protected generic execution, receiving schema and binding semantics. Do not assert native request substitutions or exact provider decimals here.

### 3. Complete-envelope result binding and forwarding

- **Type/location:** converted native scenarios in `DeclaredOutputBindingsPlanningIntegrationTest` and `DesignatedChildResultIntegrationTest`.
- **Proves:** real ordinary executor returns complete envelope; consuming pointers begin `/answers/...`; allowed/disallowed/missing/case-sensitive results retain runtime checks; parent selected-result forwarding preserves exact returned JSON, including outer data, and avoids synthesis/provider calls that should be skipped.
- **Fixtures/mocks:** existing `FixtureExecutor` returns deterministic envelope text, local planner stub only. It is a generic Framework test, not proof of pack transport implementation.
- **Surface/expectation:** protected runtime result assembly; intentional absence of generated executor output metadata and native answers extraction.

### 4. Captured provider and generation metadata

- **Type/location:** `NamespaceExecutionAuthorityIntegrationTest`, `SkillGenerationManagerTest`, shared `PublicationFixtures` users.
- **Proves:** ordinary OpenAI foreign child uses retained old endpoint/credential/model after replacement; replacement endpoint sees no request. Ordinary output schemas still support catalog forwarding and early binding compatibility. Executor metadata remains absent rather than generated; JAVA/YAML source provenance stays exact.
- **Fixtures/mocks:** deterministic local OpenAI response servers and existing public preparation/publication/handoff; annotated executor fixtures where needed. Remove native shared configuration aliases and update their actual consumers.
- **Surface/expectation:** protected namespace/publication/lifetime and generic metadata; native generated metadata deliberately removed.

### 5. Provider cleanup and public boundary

- **Type/location:** `NamedAiConnectionRegistryTests`, `NativeOutputContractTest`, provider/config tests, `ApplicationApiValueTest`, architecture/catalog tests.
- **Proves:** ordinary model initialization, retry ownership, failed-construction close and suppressed cleanup evidence, idempotent shutdown, remaining driver options and chat structured output work after runtime simplification. Enum has only YAML/JAVA; removed native internal classes leave no allowlist/classification debt; exact v1 invocation registration remains.
- **Fixtures/mocks:** existing closeable/disposable model fakes and mock provider collaborators; no native client replacement stub.
- **Surface/expectation:** internal signatures may change atomically; supported API remains deliberately closed with authorized enum removal.

### 6. Current catalog Java/Go/TypeScript/MCP coherence

- **Type/location:** `ConsoleRestFixtureCorpusTest`, Go observability DTO/service tests, MCP schema/parity tests, TypeScript typecheck and existing catalog UI tests.
- **Proves:** only YAML/JAVA classify callable skills; executor JAVA retains YAML source/executor identity; native REST fixture and list entry disappear; tools-list schema snapshot matches generated output. Exact matching release marker checks remain.
- **Fixtures/mocks:** existing `skill-executor-detail.json` and ordinary YAML/Java details; delete obsolete native detail fixture rather than retaining a legacy alias. Regenerate through existing fixture code where appropriate.
- **Surface/expectation:** coordinated current serialized boundary; same marker and no historical compatibility requirement.

### 7. Trace corpus and UI content semantics

- **Type/location:** `ConsoleTraceFixtureCorpusTest`, Go `traceanalysis/fixture_corpus_test.go`, `TraceRecords.model.test.tsx`, `TraceAttemptDiagnostics.test.tsx` and executor diagnostic tests.
- **Proves:** remaining current corpus matches Java/Go expectations; native-only scenarios/renderer branch are absent; ordinary supported content retains JSON/raw fidelity, chunks, Unicode, unavailable evidence and attempt diagnostics. Move uniquely generic assertions from deleted tests to supported fixture paths.
- **Fixtures/mocks:** remove all six native-evaluation trace/expected files and matching generator scenarios. Use existing ordinary failure/model/diagnostic fixtures; add only a minimal generic scenario if a distinct generic assertion otherwise has no evidence. Fixture files remain LF.
- **Surface/expectation:** current-run diagnostic coherence, not historical readability.

Diagnostics remain records within existing frames: `EXECUTOR_DIAGNOSTIC_RECORDED` and `EXECUTOR_DIAGNOSTIC_SYSTEM_NOTICE_RECORDED`, with existing `data` content. Existing `LOOMSPAN_query_trace_records` and `LOOMSPAN_read_trace_content` remain the retrieval contract. Java `TraceRecordType`/`TraceRecord`, Go `enums.go`/`parser.go`/`query_records.go` and MCP `traces.go`/`trace_contracts.go`/`output_schemas.go` are the inspection anchors. Existing tests must still establish type/frame filtering, ordered continuation without gaps/duplicates, bounded inline/reference reads, message/severity/JSON fidelity, explicit truncation/unavailability and no automatic failures from error diagnostics/notices. Absence establishes no cause; retained notices cannot recover discarded evidence. Add no tools/endpoints/stores/indexes/frames/severity filters/cursor formats/metadata query language or alternate content protocol.

### 8. Retained numeric, lifecycle, authorization and accounting regressions

- **Type/location:** existing suites in Existing Coverage.
- **Proves:** ordinary `config` decoding unchanged, generic exact schema numbers retained, reference-only visibility/auth boundaries intact; live lifecycle reads preserve no-deadline/expiry/original budget/cleanup-grace distinction, late writes fenced and resources retained; executor requests/retries/diagnostic usage do not reserve/add Framework model attempts/totals.
- **Fixtures/mocks:** existing real public-framework integration with local deterministic endpoints and controlled executor work. No live provider, Extensions consumer rerun or remote inference/billing cancellation assertion.
- **Surface/expectation:** all protected generic behavior; no native physical cancellation/accounting parity requirement.

## How to Run

Run from Framework root unless noted. PowerShell requires quoting comma-separated `-Dtest` arguments.

1. Focused red/post-removal parser check: `./mvnw.cmd '-Dtest=YamlSkillCatalogTests,ExecutorDeclarationTests,ExecutionConfigurationParserTest' test` (narrow to the actual new method if needed for red evidence).
2. Binding/publication regression: `./mvnw.cmd '-Dtest=DeclaredChildInputBindingsIntegrationTest,DeclaredOutputBindingsPlanningIntegrationTest,DesignatedChildResultIntegrationTest,NamespaceExecutionAuthorityIntegrationTest,SkillGenerationManagerTest' test`.
3. Boundary/provider/config check: `./mvnw.cmd '-Dtest=LoomspanPublicSurfaceArchitectureTest,NamedAiConnectionRegistryTests,LoomspanPropertiesTest,ConfigurationMetadataTest,NativeOutputContractTest,SkillDocumentValuesTest,ExecutorConfigurationTests,ExecutorConfigurationStartupTests' test`.
4. Generic executor behavior: `./mvnw.cmd '-Dtest=ExecutorDependencyResolutionTest,ExecutorGenerationExecutionIntegrationTest,ExecutorInvocationLifecycleIntegrationTest,ExecutorAccountingIntegrationTest,SharedDeclarativeAuthorizationIntegrationTest,MissionLifecycleTest,ExecutorDiagnosticsIntegrationTest' test`.
5. Intentional corpus regeneration: `./mvnw.cmd test -Dtest=ConsoleTraceFixtureCorpusTest -Dloomspan.console.fixtures.regenerate=true -DfailIfNoTests=false`. Inspect resulting changes; this is a mutation, not the final unchanged-corpus check.
6. **Required final Framework suite:** `./mvnw.cmd test`.
7. **Required explicit architecture:** `./mvnw.cmd -Dtest=LoomspanPublicSurfaceArchitectureTest test` after production changes.
8. **Required explicit Java/Go corpus:** `./mvnw.cmd -Dtest=ConsoleTraceFixtureCorpusTest -DfailIfNoTests=false test` without regeneration.
9. **Required Console checks**, from `loomspan-console`: `go test ./...` and `go run ./internal/buildtool verify`. The latter covers pinned tools, frontend typecheck/tests/coverage/build, skill checks and Go checks; do not replace it with Go tests alone.
10. If concurrent Go behavior actually changes, in Console PowerShell: `$env:PATH = 'C:\msys64\mingw64\bin;' + $env:PATH`, `$env:CGO_ENABLED = '1'`, then `go test -race ./...`. Current enum/schema/test plan alone does not trigger concurrency changes.
11. Produce local native-free artifact: `./mvnw.cmd -DskipTests install`; record `ai.loomspan:loomspan-spring-boot-starter:1.0.0-beta.10-SNAPSHOT`, source identity and `Get-FileHash target/loomspan-spring-boot-starter-1.0.0-beta.10-SNAPSHOT.jar -Algorithm SHA256`.
12. `git diff --check`; search current source/tests/docs/examples for retired native types, enums, declaration fields, driver syntax and evaluation payload assumptions. Classify remaining matches: negative tests, current external pack usage and historical planning evidence are valid; native production/current consumer claims are not.

Focused selectors may be split into smaller commands during implementation; record actual exact commands/results. Full suites and final corpus are mandatory even when focused checks pass. Race tests are conditional on actual concurrency modifications. All checks use local deterministic services; no real credentials/live inference are required.
