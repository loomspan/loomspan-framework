# PR 35.2 provider literals implementation plan

## Overview

Accept literal provider API keys, headers and Vertex service-account JSON in published configuration through the existing provider validation and binding machinery. Retire explicit credential URI loading throughout Framework. Run the Full 5-Step Pipeline approved by the developer, starting from clean revision `3a02e941403117700db9a6c869af2e160ecc1f4b`.

## Current State Analysis

`ExecutionConfigurationParser` accepts `api-key-ref`, `header-refs` and `gemini.credentials-json-ref`, resolving them to ordinary connection properties. Its connection and Gemini allowlists exclude literal equivalents. It also translates `gemini.credentials-ref` to startup `credentials-uri` (`src/main/java/ai/loomspan/internal/skill/ExecutionConfigurationParser.java:23,64–86`). The parser invokes the shared `LoomspanProperties.afterPropertiesSet()` validator after binding.

Startup already binds literal API keys, headers and JSON. `LoomspanProperties` validates driver applicability, authentication modes, HTTP-token header names and null header values (`src/main/java/ai/loomspan/autoconfigure/LoomspanProperties.java:216–267`). Its Gemini options additionally expose URI credentials and enforce the URI/JSON conflict.

`SpringAiProviderIntegration` consumes explicit JSON as UTF-8 service-account contents. Vertex mode also has a separate `ResourceLoader` path, and its constructor family and autoconfiguration receive that loader solely for credential URIs (`src/main/java/ai/loomspan/internal/springai/SpringAiProviderIntegration.java:58–99,153–168,460–485`, `src/main/java/ai/loomspan/autoconfigure/LoomspanAutoConfiguration.java:155–173`). Existing deterministic tests cover provider authentication, Gemini API-key mode and multiline service-account JSON construction.

## Desired End State

A complete reference-free pack prepares through `SkillReloader` with an explicit empty map, using literal `api-key`, `headers` and `gemini.credentials-json` in their applicable modes. Header names and converted values reach the common provider validator unchanged. Typed conversion, timeouts, driver options and authentication-mode checks remain authoritative at their existing boundaries.

Startup `gemini.credentials-uri` and published `gemini.credentials-ref` reject as unknown settings. The adapter contains one explicit credential path consuming JSON contents. Vertex construction with absent explicit JSON follows its existing client-builder behavior. Production wiring, metadata, diagnostics and current documentation describe that contract coherently.

## Implementation Approach

Extend the existing parser and common properties model. Keep the provider validator as the authority for header constraints and authentication modes. Remove the entire adapter resource dependency when removing its credential loader. Keep JSON parsing and provider construction on the existing implementation path.

When old reference and new literal fields target the same setting, reject simultaneous `api-key`/`api-key-ref`, `headers`/`header-refs`, or `credentials-json`/`credentials-json-ref` in the parser. This prevents YAML order from selecting the effective source during this ticket. These retained reference choices are explicitly assigned to PR 35.3 for retirement.

## Phase 1 — Published literal configuration

### Changes required

- Extend connection/Gemini allowed keys in `ExecutionConfigurationParser`. Flatten literal `api-key` and `credentials-json` as ordinary scalar strings using the existing conversion path. Remove published `credentials-ref` and its translation to `credentials-uri`.
- Parse literal header entries into a string map using existing scalar conversion for non-null values. Require string keys while preserving their exact contents, including blank names and punctuation, and preserve null literal values until `LoomspanProperties.validateHeaders` evaluates them. Spring map-key normalization must not turn an invalid authored header into a valid name or silently drop it. A straightforward implementation can retain the header maps and set them on the bound connections before `afterPropertiesSet`, using the existing `setHeaders` method. Apply equivalent name preservation to retained `header-refs`, whose values keep existing reference validation.
- Reject simultaneous sources targeting one setting before flattening. Retain all other reference lookup, explicit-map accounting and staged-validation behavior for this slice.
- Add the focused parser regressions and a normal `SkillReloader.prepare(..., Map.of())` test with a complete literal provider/model pack. Observe the runtime factory's actual prepared properties.

### Automated success criteria

- Parser tests prove literals, exact header names/values, ordinary conversion, invalid typed values and mode constraints.
- The public preparation entry point succeeds with a complete literal configuration and empty explicit map, and captured properties contain the authored settings.
- Existing retained reference and explicit-map isolation tests continue to pass.

## Phase 2 — Retire URI loading and verify adapter behavior

### Changes required

- Remove `credentialsUri` and its accessors from `LoomspanProperties.GeminiOptions`, and remove the URI/JSON conflict rule whose URI input no longer exists.
- Remove `SpringAiProviderIntegration.resourceLoader`, the URI loader and its imports. Replace internal constructors with the corresponding loader-free signatures and update every production/test caller. Remove the now-unused ResourceLoader argument from `LoomspanAutoConfiguration.skillGenerationManager` when confirmed unused by the method.
- Vertex mode conditionally supplies explicit credentials only for nonblank JSON. Preserve its builder project, location, HTTP settings and absent-JSON behavior. Preserve API-key construction.
- Use `gemini.credentials-json` in JSON parse failures and relevant provider guidance. Update `NamedAiConnectionRegistry`, `ProviderFailureGuidance` and tests.
- Replace URI configuration metadata with JSON metadata and update exact metadata assertions.
- Exercise rejected file/HTTP retired syntax at the strict startup and publication boundaries, proving failure precedes provider construction or resource access. Retain deterministic multiline service-account JSON construction and provider API-key wire tests.

### Automated success criteria

- Strict startup and published parsing reject retired URI fields with their authored paths. A counting/throwing credential resource observation and loopback request count demonstrate zero credential reads, as detailed by the testing plan.
- JSON contents, including multiline contents, reach the adapter and create a Vertex client without a model request. Malformed JSON reports the actual JSON setting.
- API-key authentication and existing no-explicit-credentials Vertex client construction tests pass.
- No production credential resource-loading path, field, alias or obsolete constructor parameter remains.
