# PR 30.2.3 Input Validation and Ordinary Tool Ingress Testing Plan

## Change Summary and execution context

Replace ordinary custom structural normalization with canonical standard validation,
retain narrow pre-tree runtime compatibility/marked-leaf gates, migrate reference
traversal, and decode complete ordinary callback object arguments losslessly.
This is Step 3 continuing Step 2 in the same pipeline context, selected profile
`full`, approved by the developer's “proceed”. No tests ran during planning.

## Impacted Areas and Risk Assessment

- `SkillInputContractResolver`: preserve canonical constraints/metadata rather than
  translating through a reduced legacy node; genuine generic classification must
  not grant explicit unconstrained nodes generic reference permissions.
- `SkillInputValidator`: no pre-check serialization, key identity loss, coercion,
  required-null-as-absent, unchecked open branches, shared-items bypass, mutated
  originals or private placeholder diagnostics. NetworkNT remains assertion owner.
- `RefResolver`: marker-aware traversal after validation, typed maps/nullable nodes,
  direct handle identity, generic recursive behavior and VFS authorization.
- `SpringAiToolCallbackAdapter`: exact decimal decoding before BoundCapability,
  actual object root before Map/null adaptation, complete-document parsing and
  existing Spring AI result conversion/exception behavior.
- `CanonicalToolCallingManager`: execute through actual adapter and real Spring
  manager; retain selection checks, planner-control rules and existing feedback.
- Public facade/router fixtures: no dispatch on rejection, unchanged map/key/value
  contents, validation/auth ordering, resolution only after validation.
- Binder preservation: existing stream cleanup after successful/failed conversion
  and body failure, and resource-container conversion remain protected controls.
- Documentation must not describe a restricted source slice as a working full
  application, complete provider integration or public invocation proof.

Application API signatures stay fixed; manifest and serialized schema behavior
intentionally adopts ticket-approved standard semantics. No Supported SPI exists.
Internal old-node APIs and normalization expectations have no compatibility shim.
Ephemeral diagnostics preserve original content and paths; journal redaction is
unchanged and not broadened. No Java-to-Go protocol change is involved.

## Existing Test Coverage

Canonical compiler/schema/format tests cover declarations, assertions, null and
presence, exact values and annotation provider copies. Generator/Java declaration/
BPP tests cover generated Object/maps/DTOs, registration, binding, direct handle
identity and stream cleanup. Validator/resolver/ref fixtures currently use the old
node/manifest representation; their source-level intent must be migrated, with
old coercion/date expectations replaced by the accepted standard rules. Callback
adapter tests currently check metadata only. Real-manager tests execute callbacks
but ordinary helpers bypass the adapter. Public facade/router fixtures exist but
their full production dependency graphs currently cannot compile.

## Bug Reproduction / Failing Test First

1. **Callback ingress unit red test** in `SpringAiToolCallbackAdapterTest`: use a
   mocked BoundCapability to capture the decoded map without constructing the
   downstream binding projection. Feed a long fractional decimal nested in an
   object/list, plus object-suffix/root-null controls. Assert exact BigDecimal,
   zero invocations for invalid complete text, and valid-object invocation. The
   current adapter rounds decimals and accepts null/empty-string/trailing content.
   This is reader ingress evidence only; mock capability is explicit.
2. **Runtime validator unit red tests** in `SkillInputValidatorTest`: use equivalent
   canonical generated/authored contracts for required `{}` value null, nested
   numeric/string key collision, and non-JSON undeclared open extras. Assert
   invalid input diagnostics/original preservation and null-presence rules.
   The baseline validator is not compilable with CanonicalSchema, so a runnable
   pre-fix validator red result may be unavailable. Record compile-blocked red
   evidence honestly; do not resurrect legacy source merely to run it.
3. **Shared item regression**: marked items `[Resource, invalidString]` where the
   string violates canonical minLength/format/enum. Every occurrence must be
   checked; a later invalid item cannot pass because an earlier handle caused
   the schema to be weakened.

Prefer running callback red cases before adapter edits if the actual-source slice
can compile them independently. Historical probes do not count as new red runs.

## Tests to Add/Update

Proposed names below describe cases; implementation may group them as parameterized
tests. Preserve equally meaningful existing names/fixtures where useful. All these
are deterministic framework JUnit tests, not neighboring live-suite implementation.

### 1) Canonical resolver and provider-copy fidelity

- **Type/location:** unit, `SkillInputContractResolverTest` and existing canonical
  schema tests under `src/test/java/ai/loomspan/internal/`.
- **Cases:** authored definition uses its canonical schema; reflected/tool schemas
  retain nullable type arrays, numeric/boolean/null enums, standard bounds/formats,
  descriptions, exact names and schema-valued additional properties. Generic absent
  schema remains generic; explicit closed empty object stays explicit; root `{}`
  rejects. Explicit unconstrained/described leaves remain unconstrained.
- **Provider controls:** canonical true runtime marker retained, only schema-node
  annotation removed in provider copy; string type/description/assertions retained.
  Same-named data property retained at root/nested/array/map locations. Serializing
  provider schema must not mutate canonical input.
- **Mocks:** YamlSkillDefinition may be mocked to return a real compiled schema
  while its unrelated catalog graph is blocked. No fake CanonicalSchema/compiler.
- **Surface/expectation:** manifest/serialized contracts protected; obsolete
  internal node parser intentionally removed, no legacy round-trip expectation.

### 2) Equivalent authored/generated JSON values and binding

- **Type/location:** unit/composition, `SkillInputValidatorTest`,
  `JavaInputDeclarationTest` and/or a focused `InputIngressBindingTest` beside it.
- **Fixtures:** real method generator/BPP declarations for Object parameter, DTO
  Object field, List<Object> and Map<String,Object>; equivalent authored schemas.
  JSON values: string, boolean, finite integer/BigInteger/BigDecimal/floating
  numeric controls, object, array, null and mixed nested values with literal refs.
- **Assertions:** standard validation succeeds without value change; real registered
  binder receives the successful input. Required absent fails, required present
  null passes at `{}`; optional absence stays absent, optional null stays null.
  Descriptions/requiredness/open objects/array bounds are unchanged. Reference text
  under explicit unconstrained leaves stays literal and no resolver is called.
- **Mocks:** none for generator/compiler/validator/binder; isolate registry or
  authentication dependencies using existing Java declaration test conventions.
  The direct composition is not full public invocation or full ordinary tool dispatch.
- **Surface/expectation:** accepted manifest/input behavior and existing Java
  binding preserved; required-null-as-missing intentionally replaced.

### 3) Recursive ordinary JSON compatibility and all open-property modes

- **Type/location:** unit and invocation composition, validator and input-binder tests.
- **Cases:** POJO with throwing serialization/getter sentinel, Resource whose content
  access throws/counts, InputStream counting/throwing on read, byte[], Float/Double
  NaN and positive/negative infinities. Put each directly, in nested objects, lists
  and map values under ordinary unconstrained, typed, boolean-open true, omitted
  openness and schema-valued `{}` locations. Generate equivalent open map contracts
  and author equivalent schemas. Unmarked typed string leaves receive no exception.
- **Assertions:** reject before conversion/Java handler; zero reads/open/getter
  calls and zero side effects; original maps/lists/values unchanged; useful exact
  input paths/rejectedValue. Valid null/finite numeric/ref-text controls preserved.
  Ordinary sibling type errors, requiredness, closed extras and array-bound failures
  remain effective around unconstrained leaves.
- **Mocks:** resource/stream/POJO sentinels only, real validator/compiler; handler
  counters in real binder composition. No serialization to construct acceptance.
- **Surface/expectation:** explicit ordinary input enforcement corrected; generic
  runtime-value/reference behavior remains a separate preservation fixture.

### 4) Runtime map keys and collision identity

- **Type/location:** unit plus public fixture, validator tests and
  `src/test/java/ai/loomspan/internal/skillapi/DefaultSkillTemplateTest.java`.
- **Fixtures:** maps with numeric/boolean/null keys; numeric `1` plus string `"1"`
  with distinct values. Root, typed-map, nested-map, list-item map and nested
  unconstrained/open occurrences. Include valid exact string keys with dots,
  slashes, tildes and whitespace.
- **Assertions:** reject before tree conversion/execution, useful path, both
  colliding entries still present and original values identical. String-key
  controls pass. Public validate and map invoke reject before coordinator/Java
  side effects; do not route through the unrelated DTO/object overload.
- **Mocks:** existing facade collaborators for public method-boundary tests; do
  not replace the real validator. Full public test execution may be compile-blocked
  and must be reported separately from passing validator tests.
- **Surface/expectation:** public map input behavior corrected; no public signature
  or object-overload redesign. Generic maps also cannot lose non-string keys.

### 5) Marked runtime Java leaves and private structural view

- **Type/location:** unit/composition, validator tests plus generator/BPP controls.
- **Fixtures:** true generated runtime marker on direct property, nested property,
  array items, typed-map values and nested array-object fields. Resource,
  InputStream and byte[] direct values; exact same objects must reach binder.
- **Assertions:** existing accepted runtime type gate, zero validation resource
  opens/reads/stream consumption and no object internals serialization. Unmarked
  equivalents reject. Marked false is not permission. Actual strings independently
  satisfy min/maxLength, enum and a supported format before resolution. Invalid
  string means zero resolution/invocation.
- **Occurrence matrix:** `[runtime, validString, invalidString]`,
  `[validString, runtime, invalidNull]`, runtime values in multiple map entries,
  nested arrays and a later invalid ordinary object. Check every occurrence before
  weakening shared schemas. For nullable marked schema, actual null passes; for
  non-nullable schema it fails even next to a runtime placeholder. Required
  nullable null is present; optional omission stays omitted. Repeat null controls
  for nested properties/array items/map values.
- **Parent/sibling matrix:** missing required, closed unknown field, invalid
  ordinary sibling, too few/too many array items and nested required child fail
  even alongside accepted direct handles. Generated false properties still reject.
- **Private-state controls:** canonical/provider tree before/after identical;
  input container contents unchanged; diagnostic rejected values come from original
  paths/objects, never private wrapper/null/schema text. Parent failures report
  caller data. Provider-copy tests contain no weakened leaves or inserted nulls.
- **Binding controls:** real BPP tests preserve Resource/container identity and
  supported conversion; incompatible target conversion still fails; opened streams
  close on success, conversion failure and Java body failure. Do not move conversion
  into the validator or duplicate the repaired cleanup implementation.
- **Mocks:** read/open sentinels and existing BPP collaborators only; no fake
  NetworkNT verdict. Tests may inspect public result/diagnostic behavior without
  exposing private validation data as a new diagnostic API.
- **Surface/expectation:** internal adaptation preserves supported Java invocation
  semantics while retaining standard parent validation; no authored marker feature.

### 6) Reference, generic, attachment and authorization preservation

- **Type/location:** unit, `RefResolverTest`; receiving boundary,
  `CapabilityExecutionRouterTest`; validator attachment controls.
- **Fixtures:** real DefaultRefResolver with existing mocked VFS/session authority;
  explicit marked/unmarked strings, nested properties, lists, typed maps, ANY and
  open extras. Separate generic contract with nested refs/arrays and direct values.
- **Assertions:** exact refs resolve only at permitted explicit leaves; ordinary
  strings and unconstrained/open refs remain literal. Generic behavior unchanged;
  failures/authorization remain enforced. Reject invalid canonical marked strings
  before VFS lookup. Preserve direct handles without conversion during resolution.
  Schema-valid unauthorized and unavailable tools never dispatch. Assembled router
  validation remains exact; no new retry/loop or authorization reordering.
- **Attachment seam:** metadata-annotated strict ref and Resource first-pass controls
  remain accepted; ordinary text and Java-only stream/byte[] attachment inputs do
  not acquire permission. Canonical nullable JSON controls and parent constraints
  remain effective. No MIME/filename/descriptor/read tests are implemented here;
  those belong to 30.2.4 and remain explicitly identified integration gaps.
- **Mocks/limits:** full coordinator/router compilation is downstream-blocked;
  keep its executable regression source but do not call ref-unit tests full dispatch.
- **Surface/expectation:** authorization and manifest/runtime resolution preserved;
  internal walker representation intentionally changes.

### 7) Actual ordinary callback and manager ingress

- **Type/location:** unit/integration, `SpringAiToolCallbackAdapterTest` and
  `CanonicalToolCallingManagerTest` in `src/test/java/ai/loomspan/internal/springai/`.
- **Exact values:** long fractional `0.12345678901234567890123456789`, large/small
  exponent forms, nested objects/lists and large integer controls. Assert exact
  BigDecimal/BigInteger numerical values received at capability boundary and
  real Java binding composition. Add maximum/minimum boundary where a tiny decimal
  excess would round to the accepted bound as Double; real validator rejects and
  Java side-effect count remains zero.
- **Invalid complete documents:** valid object followed by object, numeric/string/
  boolean/null scalar, or malformed garbage; incomplete JSON; empty/whitespace-only
  input; root null, empty/nonempty JSON strings, arrays, numbers and booleans.
  Direct callback and real Spring manager must invoke the target zero times.
- **Valid controls:** `{}` under permissive contract, ordinary object, permitted
  nested null and trailing whitespace. One valid selection invokes once. Keep
  existing planner-control rejection tests separate and intact.
- **Preservation:** exact schema/name/description, result conversion for string,
  null and structured results, existing error propagation; canonical name execution
  copy retains raw provider argument text/evidence. Real manager availability/name
  checks still reject unbound names before delegation. No batch rollback claim.
- **Mocks/limits:** BoundCapability may be a Mockito mock because its actual
  constructor enters unported ChildInputBindingProjection (30.2.5). Stub invocation
  through real validator/binder as a clearly labeled composition fixture; this
  proves real callback decoder + manager + those components, not real capability
  authorization/full DefaultCapabilityInvoker. Add/retain the full-dispatch test
  fixture separately and record compile-blocked execution with owners.
- **Surface/expectation:** raw serialized callback contract corrected; Spring AI
  result converter and tool loop preserved, no global mapper mutation.

### 8) Three integration request schemas and public surface

- **Type/location:** existing deterministic OpenAI Responses/Anthropic/Gemini
  request-capture tests and architecture tests, where source graph is buildable.
- **Cases:** unconstrained and description-only leaves, runtime marker annotation,
  similarly named property and ordinary standard assertions. Actual serialized
  requests must preserve unconstrained shape/description, omit only recognized
  metadata, not mutate canonical trees or contain private placeholders. Non-strict
  tools remain non-strict using each integration's actual supported behavior.
- **Limits:** a providerTree assertion is not an actual request capture. Identify
  exact fixture/production blockers; ordinary generation restoration is 30.3.1,
  planning 30.3.2, catalog 30.3.4; integrated rerun is 30.4.3. Selected deployed/live
  acceptance belongs to the neighboring live suite and is unauthorized here.
- **Architecture:** run actual LoomspanPublicSurfaceArchitectureTest; restricted
  classpaths cannot certify the full type inventory. No new supported API/SPI,
  internal signature leakage or replacement beans. When root test compilation is
  blocked, record it and retain 30.4.3 rerun ownership.

## How to Run

Implementation creates `ai/scripts/test-input-ingress.ps1` using the existing
focused actual-source launcher convention. No handwritten replacement production
classes or stale target output may be used. The fresh reviewer runs the same
commands independently and verifies source inclusion/mocking limits.

```powershell
./ai/scripts/test-input-ingress.ps1
./ai/scripts/test-canonical-schemas.ps1
./ai/scripts/test-java-declarations.ps1
mvn -o -DskipTests compile
mvn -o '-Dtest=SkillInputValidatorTest,SkillInputContractResolverTest,RefResolverTest,SpringAiToolCallbackAdapterTest,CanonicalToolCallingManagerTest,DefaultSkillTemplateTest,CapabilityExecutionRouterTest' test
mvn -o '-Dtest=LoomspanPublicSurfaceArchitectureTest' test
git diff --check
```

Run repository commands rather than constructing alternate dependency versions.
Focused launcher may be extended to include otherwise buildable actual request
tests; record exact include list and resulting test counts in implementation
verification. Attempt narrow callback red tests before edits if buildable. No
need to rerun unchanged checks repeatedly absent new changes/failures.
