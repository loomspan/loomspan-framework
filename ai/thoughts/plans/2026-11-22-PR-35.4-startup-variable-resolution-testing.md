# PR 35.4 startup variable resolution testing plan

## Change Summary

Effective startup connections, namespace executor settings and configured executor leaf config resolve whole-node markers through one startup-local Environment source. Boot source selection precedes discovery. Authored and returned placeholder text is terminal in those subtrees. Typed connection conversion and current validation remain authoritative.

This is pipeline mode, full profile, with baseline `2045545807c883025c8ecba92bdb9c53a64446a6`. The governing implementation plan is `ai/thoughts/plans/2026-11-22-PR-35.4-startup-variable-resolution.md`. No tests ran during planning. Names below are proposed new test names, and implementation may use equivalent descriptive names if it records the final mapping.

## Impacted Areas

- `AuthoredYamlVariables` multi-document/slice transport, graph bounds, occurrence paths and provenance.
- `ExecutorYamlPropertySourceLoader` source association and retention of authored selected nodes.
- `ExecutorConfigurationBinding` early terminal connection/executor binding and startup source lifetime.
- `LoomspanProperties` conversion, unknown fields, validation and authentication modes.
- `YamlSkillCatalog` configured resource ingress and original-byte/declaration handling.
- `LoomspanAutoConfiguration` and `SkillGenerationManager` wiring, all-or-fail boot and captured configurations.
- Provider adapter clients and real executor owner/consumer/skill settings.
- Current startup examples, fixture README, authoring topics and coordination handoff.

## Risk Assessment

The largest risks are resolving inactive/lower settings, replacing an entire connection when only one field was overridden, accidentally merging executor sections, expanding placeholder text twice, and validating connections before terminal values are bound. Tests must observe consumers and lookup counts through real ConfigData startup. Property-only harnesses alone cannot establish source selection.

Other risks include loss of marker-key positions while flattening headers, collision after a key resolves, loss of multiline strings, altered alias identity or scalar kinds, strict binding treating transport metadata as an unknown field, and configured skill source/provenance changing during resolved ingress. Native non-YAML higher sources need coverage because hosts supply command-line settings, test MapPropertySources and system environment data.

The protected paths are existing application invocation/configuration maps, profile/import/source precedence, normal typed/strict validation, executor section replacement, published preparation isolation and captured generations. The intentional obsolete behavior is provider placeholder expansion within selected startup connection fields. The ticket authorizes that change. There is no new Java SPI or application resolver type.

## Existing Test Coverage

- `ExecutorConfigurationStartupTests` has five real SpringApplication boot tests for source selection, executor section replacement, ordinary properties, malformed active shape, duplicate keys, leading empty documents, nulls and aliases.
- `ExecutorGenerationExecutionIntegrationTest` covers configured consumer settings and the worked fixture through real published preparation/invocation. It supplies a real Loomspan runtime/executor harness that can support startup consumer assertions.
- `PreparedCandidateVariablesTest` covers preparation's exact-map modes, concurrent source isolation, typed values, terminal strings and memoization. Startup must use its own source lifetime while preserving these tests.
- `AuthoredYamlVariablesTest`, `VariableMarkerFixtureTest`, `YamlValuesTest` and `SkillDocumentValuesTest` cover grammar, paths, complex keys, sizes, aliases, lossless declarations and the shared corpus.
- `LoomspanPropertiesTest`, `ExecutionConfigurationParserTest`, `ConnectionProtocolTest`, `SpringAiProviderIntegrationTest`, `GeminiProtocolIntegrationTest` and configuration metadata tests protect provider literals, strict schema, JSON contents, retired URI behavior and actual client construction.
- Catalog, startup namespace, generation, public reloader and dependency tests protect capture and validation boundaries.
- `LoomspanPublicSurfaceArchitectureTest` is required after production type changes.

The missing evidence is a connected startup resolution across all three selected sections after Boot effective selection, including terminal provider strings and marker-authored header keys.

### 2. Imported executor section replacement

Keep this independent from the connection example so per-field inheritance and whole executor replacement cannot accidentally mask one another.

### 3. Terminal strings and host placeholder semantics

Add `StartupVariableResolutionIntegrationTest#authoredAndReturnedPlaceholderTextReachesConsumersLiterally`.

Use literal `${region}` in a provider API key/header or string option, executor data and configured leaf config. With `region=west` in Environment, each authored string reaches its consumer exactly as `${region}`. Add a marker for host property `report.label=${region}` and verify that all three selected consumers receive `west` from one normal host lookup. Add a custom Environment result for another name equal to `${terminal.missing}` and assert that exact text reaches all consumers without another expansion or lookup for `terminal.missing`.

Read strings at the bound provider settings and through a real provider request where HTTP syntax permits, and at an actual executor invocation. Assertions only on a helper tree do not establish binding behavior.

Use a control property outside selected subtrees, such as `loomspan.models.primary.provider-model` and a normal host `copied` property, to verify ordinary Spring expansion still works. Retain the existing host timestamp and session conversion controls.

### 4. Environment and higher property-source behavior

Add source-selection tests in the startup binding suite, with one real boot test exercising non-YAML overrides.

- A high-priority `MapPropertySource` overrides only API key while lower YAML driver/header remain effective. Preserve original string whitespace and multiline content by using MapPropertySource directly instead of `TestPropertyValues`, which trims trailing newlines.
- Command-line overrides select only their authored fields and displace lower markers with zero lookup.
- A `SystemEnvironmentPropertySource` with `APP_REGION=west` supplies a marker named `app.region` through normal Environment lookup. Use an isolated environment map, preserving process state.
- An ordinary properties/config source can author a terminal connection placeholder string. It remains terminal under the same selected connection semantics.
- Start two contexts with identical marker names and distinct values. Each context observes its own value and one lookup, with no cache reuse between contexts. A later detached no-map preparation resolves freshly rather than consulting startup's cached value.

Mocks are limited to the value-source counter and loopback provider. Source precedence is exercised by actual Spring sources.

These tests qualify configuration and diagnostic behavior. They do not create a public binding extension contract.
