# Binding ownership projection and composition testing plan

## Change summary

Implement the accompanying PR 30.2.5 implementation plan under Full 5-Step Pipeline. Canonical schemas replace legacy binding representations. Exact names, omitted openness and exact numeric enum overlap are intentional contract changes; source identity, snapshots, ownership, values, validation order and required-work rules are preservation controls.

## Impacted areas and risk assessment

High-risk areas are reserved false schemas under open/typed input objects, ancestor requiredness/nullability, nested residual model space, static compatibility versus runtime obligations, exact-decimal preservation and lifecycle/source selection. A schema validation pass alone proves none of producer selection, override protection, work completion or provider request attachment.

Protected surfaces: manifest binding semantics and exact output content; supported Java API signatures remain unchanged. Internal legacy node/manifest constructors and case aliases are intentionally removed, with no simultaneous old/new behavior. There is no supported SPI or Console protocol delta. Current-run provenance must preserve source task/skill/frame and avoid duplicate selected payload. No sensitivity classification tests are added.

## Existing test coverage

Research inventories `ChildInputBindingProjectionTest`, `ChildInputBindingAssemblerTest`, `ChildInputBindingTest`, plan dependency/producer validators, `AcceptedResultDecoderTest`, `OutputBindingCompositionTest`, `OutputBindingIsolationTest`, `SkillGenerationManagerTest`, ordinary/planning output-binding integrations, child-binding/isolation integrations and public-surface tests. Old node accessors, removed output manifest builders, legacy `format: choice`, case aliases and permissive unsupported-schema fixtures need migration. Root/nested omitted openness, numeric enum spellings and all new bounds/formats are coverage gaps. Research ran no tests; its forced compile failed on authorized intermediate consumers.

## Bug reproduction / failing test first

This is an intentional migration with baseline compile failures, not a claim that new standard semantics were previously reachable legacy bugs. Add minimal unit regression cases while migrating fixtures:

1. `OutputBindingCompositionTest`: fully bind the only declared root field. Omit `additionalProperties`; expect model contribution required. Repeat nested partial object, explicit true and false. The old hasSpace algorithm treats omission as closed and fails the new expected behavior.
2. Focused compatibility test: numeric enum `[1]` versus `[1.0]` must overlap; `[1.0000000000000000000000000001]` versus `[1.0000000000000000000000000002]` must not. The old representation-based comparison rejects equivalent values.
3. Closed exact-case destination: declared `value` with binding `/VALUE` fails declaration; open destination treats `VALUE` as a distinct runtime key. Old normalization aliases them.

If old production cannot compile even with migration-independent unit fixtures, record pre-fix failure as compile-blocked plus concrete source evidence; do not claim an executed red test. Never restore deleted types merely to obtain a red run. After migration, demonstrate each regression with deterministic tests and record actual execution.
