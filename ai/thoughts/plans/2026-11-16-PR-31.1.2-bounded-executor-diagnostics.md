## Selected Capture Contract

### Budgets

Use named internal constants, not properties or supported API:

| Resource | Limit |
| --- | ---: |
| Authored message retained as UTF-8 | 8 KiB |
| Serialized supplied JSON | 32 KiB |
| Developer envelope serialized JSON | 48 KiB |
| Container nesting | 32 |
| Visited values plus object keys per call | 4,096 |
| Accepted diagnostic attempts per invocation, including rejected captures | 128 |
| Aggregate developer envelope bytes per invocation | 256 KiB |
| Ordinary capture/recording notices per invocation | 4 |
| Each fixed system-notice envelope | 2 KiB |
| Reserved invocation-limit notice | One additional 2 KiB envelope |
| Java fallback warning attempts per invocation | 4 |
| Numeric representation guard | BigInteger/unscaled BigDecimal bit length <= 4,096; absolute BigDecimal scale <= 4,096 |

Charge attempted events before capture so floods of invalid calls are bounded. Charge retained developer-envelope bytes before append even when append fails; do not refund failed writes. Ordinary notice bytes/counts are independent bounded reserve (at most 8 KiB); invocation-limit notice has its own reserve and is attempted at most once. Once either event or aggregate-byte limit is reached, attempt the reserved notice and suppress all subsequent calls before inspecting message/data. A single event too large is a per-event capture condition, not immediate aggregate exhaustion unless its bounded fallback envelope itself cannot fit.

Bound UTF-8/JSON escaped output before allocating unbounded representations. Do not call getBytes on a complete oversized source string. Walk only a bounded prefix to retain message text at a Unicode code-point boundary. Retain exact text whenever it fits; for a truncated message retain the prefix without an invented suffix and record the state. Preserve escaped controls, non-ASCII and original data keys. Null messages are invalid and use a fixed unavailable notice; do not invoke validation that escapes the method.

### JSON algorithm

Create a private instance-local Jackson factory with StreamWriteConstraints and bounded read constraints for any bounded-byte-to-tree conversion. Feed a streaming generator through a capped byte sink using a small exact-class value walker; do not call the application mapper or serialize arbitrary input objects. Jackson is already a dependency. Recognize the exact 31.1.1 contract before any traversal: null, String, Boolean, Byte/Short/Integer/Long, finite Float/Double, exact BigInteger/BigDecimal; exact HashMap/LinkedHashMap and actual JDK Map factory classes; exact ArrayList and JDK List factory classes; reference arrays and specified primitive arrays. Reject characters/char arrays, subclasses, custom collections/numbers, DTOs and JsonNodes. JDK class recognition can derive classes from safe empty/one/multiple-element factory instances rather than names alone.

Bound string and key scan length/escaped size before generator calls. Check exact numeric classes and representation guards before conversions. Use identity-based active-container cycle detection; repeated acyclic aliases are legal and charged each visit. Check depth/work/output before descending/iterating. Concurrent mutation of a supported mutable collection is unsupported caller behavior: contain any ordinary traversal failure, record an unavailable capture state when possible, and never retain references after return. A successful capture is a snapshot of observed traversal, not an atomic snapshot against concurrent mutation. Later mutation after the diagnostic method returns cannot affect retained data.

Abort rejected structured capture, discard its incomplete byte buffer, and never attempt to repair/parse incomplete JSON. Valid JSON data is preserved exactly within the contract; no partial malformed JSON is emitted. Partial retention applies to message prefixes. Structured data that cannot be wholly captured is explicitly unavailable with a reason; do not invent a partial object. Convert only complete, bounded generated JSON to a controlled JsonNode for the existing trace content path. Distinguish absent data on `(String)` from explicit JSON null on `(String,Object)`.

### Vocabulary and data envelopes

Add `EXECUTOR_DIAGNOSTIC_RECORDED` and `EXECUTOR_DIAGNOSTIC_SYSTEM_NOTICE_RECORDED`. Do not change TraceFrameType or use ERROR_RECORDED. Developer data envelope:

```json
{"severity":"INFO","message":"Sending request","messageState":"COMPLETE","dataState":"COMPLETE","data":{"provider":"typesafe"}}
```

Severity is exactly INFO/WARN/ERROR. messageState is COMPLETE/TRUNCATED/UNAVAILABLE; dataState is ABSENT/COMPLETE/UNAVAILABLE/CAPTURE_FAILED. Omit data except for COMPLETE (which may contain null). Include `reason` when capture is incomplete. Use stable reasons UNSUPPORTED_VALUE, CYCLE, MESSAGE_LIMIT, DATA_LIMIT, DEPTH_LIMIT, TRAVERSAL_LIMIT, NUMBER_LIMIT, CAPTURE_FAILURE, RECORDING_FAILURE, INVOCATION_EVENT_LIMIT and INVOCATION_BYTE_LIMIT. A too-large message produces one developer record with its prefix and TRUNCATED; rejected JSON produces one developer record with preserved bounded message and explicit unavailable/failure state when recording succeeds. Each such condition also attempts a separately capped system notice and warning. Never retry a failed developer append because delivery may already have occurred.

System-notice data contains reason, fixed explanatory message, and optional originalMessage with explicit originalMessageState. It has no severity and no rejected data, exception object, throwable message, caller class rendering or stack serialization. Original message prefix is capped so the complete envelope remains <=2 KiB. Use fixed reason-based Java warnings, at most four attempts, without passing rejected values or throwable rendering to the logger. Both notice and logger failures are caught independently; they do not trigger another notice/logging pass. Notices are best effort; absence establishes no reason.

Identity belongs to the existing record/frame envelope and bounded framework metadata (`skillName`, `executorName`, `executorConfigGenerationId`), not a duplicate diagnostic sequence. Frame identity is the invocation association. Canonical record timestamp is Framework supplied by the existing trace handle.

## Implementation Approach and Phases

### Phase 1 — Bounded capture and containment

Add internal capture implementation under `ai.loomspan.internal.core` (suggested `BoundedExecutorDiagnosticCapture` and `DefaultExecutorDiagnostics`). Keep helpers package-private unless cross-package runtime wiring actually requires public internal access. Use small package-private constructor-injected capture/append/warning collaborators for deterministic failure tests; do not add beans/properties solely for injection.

Each public method enters a synchronized invocation state, returns immediately if locally closed, suppressed or reentered, and catches ordinary RuntimeException/Exception at the method boundary. Do not catch JVM-wide fatal Errors. A reentrancy flag suppresses synchronous recorder/logger callback recursion before payload work. Keep event/byte/notice/warning state within the handle. Ensure validation, fallback envelope construction, record append and warning are all within containment. Fixed fallback serialization never touches rejected input again.

### Phase 2 — Invocation lifecycle and canonical trace integration

Existing session/trace synchronization assigns the canonical sequence. The close monitor serializes normal closure against calls; lifecycle cutoff can revoke a pending captured event before append. No separate diagnostic execution scope, thread executor, sequence or per-call frame.

A small internal recorder helper accepting captured binding/frame is appropriate; it must not derive the frame from the calling thread or introduce supported extension methods. This small new evidence append is best effort/contained. It introduces no output serialization of arbitrary application objects, no synthetic success on failure, no tool-success credit and no new result event vocabulary. ## Performance and Failure Boundaries

Capture memory is proportional to fixed per-call buffers, depth and visited values; aggregate retained diagnostic output and fallback work have explicit reserves. No unlimited copy/tree/string is constructed before limits. JVM memory exhaustion, other fatal JVM failures and caller argument evaluation remain outside the guarantee. Approved mutable containers cannot be atomically frozen against concurrent external writers. Ordinary diagnostic append failure may leave no delivered notice and must not be inferred by consumers. Existing automatic observations, business result conversion, auth and executor work retain their semantics.
