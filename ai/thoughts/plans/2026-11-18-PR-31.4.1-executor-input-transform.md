# Executor input transform implementation plan

## Overview

Add optional root `input_transform` to executor YAML leaves. Framework compiles
the JSLT expression during loading/preparation and evaluates it once at the
common executor handoff. The ordinary input schema remains the contract used by
callers, planners, bindings and validation. Java receives the complete transformed
object through the existing v1 invocation.

This plan is Step 2 of the approved Full 5-Step Pipeline. The developer approved
the route on 2026-11-18. The PR 31.4.2 ticket is separate untracked work to preserve.
Implementation will update the checkboxes below and record actual commands/results
in a verification artifact. No production change or test run occurred in planning.

## Desired End State

An executor declaration accepts exactly `language: jslt` and a nonblank textual
`expression` under `input_transform`. Structural errors and compilation errors
produce contextual authoring issues during startup/validation/preparation. A
failed candidate never replaces active state. The compiled immutable expression
belongs to its leaf definition and survives generation capture.

At invocation the validated and reference-resolved child input alone is bound to
JSLT `.`. One evaluation produces an object. Framework retains every authored JSON
key/string, constructed null and empty container. An empty root object succeeds.
Unsupported runtime values, evaluation errors and non-object results terminate
before the handler. Diagnostics continue to expose original business input,
ordinary schema and exact authored YAML. Authorization and live lifecycle remain
on the existing path.

Omission follows the existing reference-resolved handoff, including handle
identity. Skill and executor configuration remain separate invocation values.
The supported Java API has zero signature/type changes.

## Implementation Approach

Use a small package-private compiled transform helper in the skill package,
referenced by the immutable definition. The manifest carries the authored
declaration and its prepared compiled artifact using the existing compiled-schema
copy pattern. Catalog validation owns contextual errors. The definition exposes
an internal operation accepting and returning `Map<String, Object>` so JSLT types
never appear in supported APIs or cross-package signatures unnecessarily.

Compile with `new Parser(new StringReader(expression)).withSource(...)`
and `.withObjectFilter("true")`. Use JSLT's ordinary built-ins and parser semantics.
Its default resource resolver resolves classpath imports during compilation. Keep
that default, add no Framework module registry, filesystem/network resolver or
application extension functions. Missing/invalid imported resources fail the same
preparation boundary. A new import policy is outside the ticket's settled language
contract. Capturing the compiled expression also captures compiled imports.

Perform strict JSON admission before serializing or evaluating any input. Accept
maps with string keys, lists, null, strings, booleans, integral Java wrappers,
BigInteger/BigDecimal and finite Float/Double, consistent with ordinary declared
input validation. Reject Resources, InputStreams, byte arrays, arbitrary objects,
non-string keys and other runtime values with a path/type error. Do not call a
host mapper, coerce objects with `toString`, base64 bytes or serialize runtime
handles to discover their structure. Use the framework schema JSON mapper after
successful admission, or construct equivalent JSON nodes directly. Preserve exact
keys and numeric content through the boundary. Conversion of the output object
uses framework-owned JSON handling and retains nulls/empties. Verify finite JSON
numbers if an evaluation can construct non-finite values.

The helper is needed because document admission and schema-aware runtime admission
own different failure contracts. Keep its recursion local, with no general
conversion service or public extension hook. No dead/unused in-scope abstraction
requiring removal was identified.

### Implementation observations

- Connected verification exposed that a direct Resource in a generic input
  contract can reach canonical frame serialization before the worker. Jackson
  tries the Resource's URI getter and fails before the transform can identify
  the unsupported value. For transformed calls, check the original argument
  tree's JSON domain after ordinary validation and before handing it to trace
  recording. This check performs no conversion and preserves canonical input
  for admitted data. Check again after reference resolution so handles produced
  from `ref://` fail before evaluation. Evaluation remains once on the mission
  worker, and omitted transforms keep the existing path.
- Reuse the worker's existing lifecycle guard at the transition from JSLT
  evaluation to application handler entry. Evaluation may return after the
  caller has cancelled, so the handler starts only if the lifecycle still
  permits new work. This creates no new deadline or execution scheduler.
- The clean Console CI Java verification and Maven Central workflow verification
  jobs also need the local dependency bootstrap. They run the same pinned-source
  script as developers. Publication of the interim coordinate and remote
  repository delivery are outside the local-install scope.

## Performance and failure considerations

Compile once per definition and share the prepared expression across invocations.
Pinned `ExpressionImpl` creates a fresh scope on each apply. JSON tree allocation
occurs once per transformed handoff, and omitted transforms incur only the
presence checks. Exercise concurrent applications with distinct inputs to verify
isolation. Use the existing worker timeout/cancellation behavior. This work adds
no expression-specific execution scheduler or timeout promise.

Runtime failures carry the skill/transform stage and preserve their cause through
existing mission failure handling. No retry, repair or stringification is added.
Use normal authoring errors for syntax/shape failures. Static non-object
expressions may compile and then fail root-object enforcement at invocation.
