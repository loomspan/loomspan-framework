# PR 27.1 Canonical Namespace Identities — Testing Plan

## Change Summary

Introduce shared internal parsed identity, authoritative namespace-owned definitions/generations/catalogs, qualified reference parsing during preparation, Java namespace annotation, target-only feedback, and explicit namespace catalog acquisition. Local declaration syntax stays local; all actual references become qualified. Supported API breaks and direct removal are authorized; no legacy/local reference acceptance is protected.

Read with `2026-10-29-pr-27.1-canonical-namespace-identities.md` and the ticket/design. Selected profile is full, with independent Step 5 review required. This plan specifies tests; no test/source code or baseline build was run by planning.

## Impacted Areas

- New internal identity value; `CapabilityMetadata`, Java discovery and `SkillMethod`.
- `YamlSkillCatalog`, immutable definitions/allowed constraints/input-output bindings, compiled evidence expressions.
- `SkillGeneration`, manager validation/preparation/derived-schema maps, REST invoker closure.
- `DefaultSkillCatalog`, `SkillCatalog`, reloader snapshot method, startup bean wiring.
- Supported-surface tests, testkit generation builders, valid/invalid fixtures, samples and routed authoring/Java API guidance.

## Risk Assessment

- Confusing a local declaration with a reference, applying only the 64-character local grammar, omitting optional/unoffered checks, or enforcing namespace 32 only through the combined limit.
- Lowercasing skill names, using locale-sensitive lowercasing, accepting whitespace, extra hyphens, slash/colon syntax, aliases or fallback lookup.
- Comparing authored strings instead of identities in duplicate, direct-child, self-binding, forwarding and evidence checks.
- Giving a namespace generation foreign fixed Java registrations, local definition keys, contradictory metadata ownership or another generation's catalog.
- Mutating raw source/prompts/diagnostic evidence when normalizing semantic fields.
- Validation allocating IDs/resources or returning partial skills on error; candidate access accidentally reporting its base ID.
- Catalogs refreshing or retaining executable resources, and empty catalogs lacking ownership.
- Claiming deferred active-registry/removal, root/model dispatch or Console integration has passed in this slice.

Protected paths: Spring proxy/interface/lazy discovery, argument binding and method RBAC; the sole REST SPI shape; immutable schema-preserving unfiltered catalog metadata; candidate cleanup/publication ownership; validation side-effect and incomplete-proposal behavior; content fidelity and the existing journal exception. Intentionally obsolete: unqualified reference syntax, no-argument catalog snapshot, injected startup catalog, local map-key invariants. Update obsolete assertions rather than testing old/new behavior simultaneously.

## Bug Reproduction / Failing Test First

This is an intentional new contract, not a claim that the current local-name contract is defective. Start with the lowest-cost failing executable assertion using existing classes: in `DefaultSkillCatalogTest`, `catalog.skill("unqualified")` must throw `IllegalArgumentException` under the new contract (currently it returns empty). Record the exact focused command and expected failure. If Maven test compilation is already blocked by existing environment/downstream code, record that as blocked rather than claiming an assertion ran. Annotation reflection/default and new identity tests can then be added with implementation; a compile failure for a missing new symbol is not the preferred red-test proof.

## Tests to Add/Update

### 1. Shared parser/formatter boundary matrix

- Type: parameterized unit tests, no mocks; location `src/test/java/ai/loomspan/internal/core/SkillIdentityTest.java` (match final internal package).
- Proves: `Tax-calculateTax` equals `tax-calculateTax`; `tax-CalculateTax` differs; `a_b-c` differs from `a-b_c`. Namespace-only `Tax` canonicalizes to `tax`; local components preserve exact case. Underscore and ASCII first characters are valid. Round trip is deterministic.
- Reject: null/empty where appropriate, missing/extra separators, empty components, `/`, `:`, wildcard/import/encoding-like values, Unicode, leading/trailing/internal whitespace and digit-first components. No trim/repair behavior.
- Independent lengths: namespace 32/local 1 succeeds; namespace 33/local 1 fails despite combined length under 64. Namespace 32/local 31 totals 64 and succeeds; namespace 32/local 32 totals 65 and fails. Namespace 1/local 62 totals 64 succeeds; local 63 totals 65 fails. `default` local 56 succeeds, 57 fails. Standalone local grammar accepts 64 but identity construction rejects oversized result. Namespace-only length 32 succeeds/33 fails. Include a Turkish default-locale regression with restoration in `finally`, or an equivalent locale-independent proof without shared-locale test interference.
- Length diagnostics include offending input, actual length, limit. Boundary callers add source/field.
- Surface: internal implementation and manifest contract; intentional new grammar without old reference compatibility.

### 2. Java namespace annotation and fixed registration

- Type: unit plus existing Spring discovery tests; locations `api/SkillMethodTest`, `internal/core/SkillMethodBeanPostProcessorTest` and existing target discovery integration suite.
- Assert exact annotation elements/defaults; omitted namespace assigns `default`. Explicit `Tax` registers `tax-search`; separate `orders-search` coexists. `Tax-search` and `tax-search` collide with both method locations. `tax-Search` and `tax-search` coexist.
- Parameterized annotation fixture methods exercise namespace 32/33 and total 64/65, including a long otherwise valid local name; invalid startup errors identify method/source, field and limit. Avoid invoking application method bodies during discovery.
- Preserve existing proxies/bridge/interface/lazy/RBAC/argument schema assertions, updating only canonical identity expectations.
- Surface: Application API, Supported SPI unchanged, internal discovery; intentional annotation addition/name semantics.

### 3. Authored declaration and reference preparation

- Type: unit in `internal/skill/YamlSkillCatalogTests`; isolated catalogs per case, existing minimal model configuration/REST handler fixtures, no live providers.
- Run shared declaration limit cases through configured startup and supplied documents, with model-backed, REST and existing TypeSafe declaration paths. Verify long valid-local declarations fail combined limits even if never referenced/offered. Declaration `name` stays local and no namespace manifest field is invented.
- Run valid/invalid reference matrix through allowed-child (including optional), `output_from.skill`, input `child_result.skill`, output `child_result.skill`, and evidence-expression leaves. Qualification is mandatory for `default` and same namespace. Namespace-32/reference-total-64 succeeds; namespace-33 fails independently; total-65 fails. Include contextual source/field/length/limit diagnostics rather than only exception type.
- Mixed-case namespace references compare equal to canonical declarations for duplicates, direct-child membership, parent/self rejection and binding producer resolution; local case remains exact. Distinct underscore placement never collides.
- Raw supplied source labels containing arbitrary diagnostic text, YAML bytes/private prompt strings, and original expressions remain unchanged; canonical semantic skill fields normalize where identity is valid. Test field-specific evidence; no scanner, content masking or bulk prompt rewrite.
- Surface: Configuration and manifest contracts, ephemeral diagnostics, internal immutable preparation. No temporary local syntax.

### 4. Evidence expression identity leaves

- Type: unit in existing parser/compiler tests.
- Assert `Tax-search and (orders-load or default-fallback)` parses with canonical leaves and original source/columns retained; existing Boolean precedence/parentheses behavior persists. `and-search` is a valid identity; bare operators remain grammar operators. Malformed/unqualified/oversized leaves fail through shared identity validation with usable position/detail.
- Verify compiler direct-child membership uses canonical identities, without normalizing the raw expression source or interpreting a qualified hyphen as subtraction.
- Surface: manifest contract and diagnostics; obsolete unqualified leaf tests migrate to qualified leaves.

### 5. Generation ownership and immutable metadata

- Type: new focused `internal/skill/SkillGenerationTest` or existing manager generation tests; simple metadata/REST definitions, no runtime required.
- Construct `alpha` and `beta` generations each declaring local `search`, keyed/described `alpha-search`/`beta-search`. Assert opaque IDs independent of identity formatting.
- Reject local capability/definition keys, key/name mismatches, wrong-owner metadata/definition, mismatched catalog owner/ID if injectable, and missing/wrong-kind definition capability. Declaration owner/local composition must obey length checks.
- Empty generations/catalogs identify owner and ID. Maps, descriptors and schema strings remain immutable. Existing exact metadata-instance ownership behavior persists where applicable.
- Surface: internal implementation; intentionally remove local-key constructors/assumptions.

### 6. Catalog lookup contract and retention

- Type: `internal/skillapi/DefaultSkillCatalogTest`, existing reloader tests for replacement.
- Assert canonical namespace property even empty; all four kinds sorted by canonical names, unfiltered despite denied policy; exact schema strings unchanged.
- `catalog.skill("ALPHA-search")` returns `alpha-search`; `alpha-Search` differs. `alpha-missing`/`beta-search` return empty without accessing another catalog. Malformed/unqualified/oversized lookup fails. Duplicate canonical metadata and foreign ownership fail construction.
- Retain old catalog across replacement/candidate close and assert names, ID, namespace and schema unchanged. A closing fake runtime/retirement test shows catalog retention adds no resource lease. Do not invent a catalog close lifecycle.
- Removal and current-registry selection after removal require PR 27.2; preserve exact rerun coverage request there. Foundation tests can prove metadata detachment directly without implementing removal.
- Surface: Application API and internal metadata; no no-argument alias or injected bean.

### 7. Target-only proposal feedback and candidate IDs

- Type: `internal/skill/SkillGenerationManagerTest`, `SkillReloaderTest`; use explicit internal target preparation and mixed-owner fixed Java metadata until PR 27.2 public management integration.
- Target `alpha` supplied local search plus fixed alpha Java produces only alpha canonical feedback/catalog names. Foreign beta fixed methods are absent and cannot collide; supplied declarations cannot replace same-owner fixed Java. An empty target without assigned fixed methods is valid if existing validation permits it.
- Validate repeatedly: generation allocation count/next candidate sequence unchanged, no handler constructor/provider factory calls, publication/retirement state unchanged, no Java skill execution. Warning-only metadata remains complete and sorted; any error yields empty skills with existing named/nameless failed-document secondary suppression semantics.
- Prepared candidate ID differs from base ID; `snapshot().generationId()` equals candidate ID; snapshot namespace matches target; canonical REST closure uses its owning candidate ID/name and does not consult current catalog at invocation.
- Surface: Application API feedback/candidate semantics, sole SPI handoff strings and internal preparation. Full cross-namespace REST execution belongs to PR 27.4.

### 8. Acquisition and supported surface

- Type: existing reloader and supported-surface integration tests plus architecture.
- Reflection/API usage proves `snapshot(String)` and `SkillCatalog.namespace()` exist; no `snapshot()` and no injected startup `SkillCatalog` bean. Acquire explicit `default`; pass `descriptor.name()` as the canonical semantic argument in examples/tests without splitting it.
- Namespace snapshot operation accepts namespace-case variants, rejects malformed/33-character owner independently, selects generation once and rejects absent/mismatched ownership. Do not assert non-default startup grouping/removal before PR 27.2.
- Existing public API allowlist remains the same 23 types; only necessary internal classification addition. Public signatures expose no internal/autoconfigure types; `RestSkillHandler` remains sole SPI; no alias/local accessor/catalog lifecycle/revision/rename API.
- Surface: Application API intentional break; autoconfiguration bean removal is intentional integration behavior.

## How to Run

Use Windows Maven wrapper and quote comma-delimited selectors for PowerShell. No live network provider credentials/model service are needed. The wrapper may download build dependencies normally; no web research is required. Confirm Java 21 and wrapper Maven >=3.9 if environment fails.

1. Pre-change red assertion (after adding the single test, before production changes):

   `./mvnw.cmd '-Dtest=DefaultSkillCatalogTest' test`

2. Production compilation:

   `./mvnw.cmd -DskipTests compile`

3. Focused identity, annotation, preparation, catalog and ownership suite (omit no required existing test; add final new generation test name if introduced):

   `./mvnw.cmd '-Dtest=SkillIdentityTest,SkillMethodTest,SkillMethodBeanPostProcessorTest,YamlSkillCatalogTests,SkillGenerationManagerTest,DefaultSkillCatalogTest,EvidenceExpressionParserTest,EvidenceExpressionParserAdditionalTest' test`

4. Candidate/supported boundary suite (locate exact existing Java discovery integration class names and add those relevant to changed discovery):

   `./mvnw.cmd '-Dtest=SkillReloaderTest,PublicSkillReloadIntegrationTest,SupportedSurfaceIntegrationTest,SkillGenerationExecutionIntegrationTest' test`

5. Mandatory closed-surface check:

   `./mvnw.cmd '-Dtest=LoomspanPublicSurfaceArchitectureTest' test`

6. If focused checks pass and the checkout can execute the broader suite:

   `./mvnw.cmd test`

7. Whitespace/error check:

   `git diff --check`

Maven normally compiles all test sources even with a focused Surefire selector. A selector is not proof of execution when test compilation fails. Do not report a blocked architecture run as PASS. Record command, failing phase, concrete file/symbol or assertion, whether in-scope or downstream, responsible ticket, and exact rerun. Fix in-scope failures before handing to review. A documented downstream blocker may coexist with ticket completion under the explicit pipeline notes, but meaningful in-scope unit verification is still required; choose only a trustworthy focused execution method and disclose its limits. Never modify production API to make a temporary test bridge.
