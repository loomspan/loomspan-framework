# PR 30.2.2 — Generated Java contracts and binding testing plan

## Change summary and governing artifacts

Full pipeline Steps 2+3; developer confirmed profile. Governing implementation plan: `ai/thoughts/plans/2026-11-13-pr-30.2.2-generated-java-contracts-and-binding.md`. Ticket and research paths are recorded there. This plan creates no tests or implementation; Step 4 owns their execution.

Java generation will compile complete canonical input schemas using application binding introspection and concrete resolved types. Tests must prove the generated contract agrees with registered binding, reject unsupported declarations before publication, preserve resource identity/metadata/cleanup and keep executors YAML-owned. Runtime input adapter, reference traversal, provider capture and public dispatch checks remain assigned to their explicit restoration owners.

## Impacted areas and risks

- Generator: resolved generic/member types, effective property/enum names, interface names/requiredness, scalar classification, map keys, JsonUnwrapped, recursion and runtime-leaf ordering.
- BPP: capture effective types once, canonical contract publication, positional parameter metadata, binding/conversion and stream cleanup.
- SkillInputContract: canonical authority, generic kind and empty-input behavior. No parallel reduced representation.
- StandardSchemaCompiler: description-only unconstrained nested INPUT leaves, without broadening roots, roles or unsupported vocabulary.
- Production mapper wiring: custom binding mapper versus dedicated schema mapper.
- Documentation: current enforced declaration rules versus incomplete runtime integration.

Primary risks are silent metadata loss, raw-class generic false positives, growing generic recursion, property-name collisions, resource bean introspection/serialization, conversion bypass for ordinary container children, and reporting a narrow slice as an integrated pass.

Application API signatures and annotation/executor roles are protected. Generated serialized contracts intentionally change as specified. BPP factory and schema representation are internal and need no compatibility shim. No Console protocol boundary changes. No sensitivity classification or content rewriting tests outside the existing journal exception; existing exception behavior is untouched.

## Existing coverage and meaningful red cases

Existing `LoomspanMethodInputSchemaGeneratorTest` covers four broad paths but encodes recursive fallback and integer-string coercion. Replace those obsolete assertions rather than preserve both behaviors. `SkillMethodBeanPostProcessorTest` covers interface-independent registration, optional parameters, Object descriptions, direct/nested conversions and cleanup; it lacks swapped-name, annotated-enum, inherited generic, configured naming and Resource-list identity combinations. Existing `JavaSkillIntegrationTest` and `SharedJavaDiscoveryInvocationTest` cover proxies and executor roles but currently depend on the broken full runtime build.

Baseline `mvn -o clean compile` failed before tests with 43 removed-manifest diagnostics. Accordingly, a normal root red test cannot currently execute. Record this honestly. Establish pre-fix behavior with the existing code/probes and, where practical, a disposable real-source pre-fix slice or focused registration test before changing the relevant implementation. Do not revive a removed legacy DTO or use stale target classes to manufacture a red run.

Minimal regression fixtures:

1. Interface declares `(String left, Integer right)` with distinct descriptions and mixed requiredness; implementation names are `(String right, Integer left)`. Published properties currently collide. Assert final names/types and ordered invocation values.
2. `GenericBase<T>.increment(T value)` inherited by `IntegerBean extends GenericBase<Integer>`. Assert integer schema, successful value 4 reaches body as Integer, invalid string is rejected by canonical validation and never invokes the body.
3. `List<Resource>` receives the same read/serialization-detecting Resource. Assert identity inside the body and zero calls to content/URI/file access during binding. This proves the demonstrated correction and must fail the old whole-container conversion path.
4. Direct recursive DTO registration must throw instead of publishing an open child. Generator-level tests alone do not establish no capability publication.

## Test harness boundaries

Use the real BPP with a StaticListableBeanFactory and real JavaSkillInvoker, querying `processor.capabilities()` directly where TestCapabilityRegistry would pull in the entire broken catalog. Register actual bean instances in the factory and run `postProcessAfterInitialization`; do not mock generation or conversion. For proxy tests use actual Spring proxies.

Ordinary JSON composition helper: register -> obtain CapabilityMetadata -> obtain its canonical schema -> validate a genuine JSON tree using CanonicalSchema.validate -> invoke that metadata's registered invoker only on an empty verdict. Assert invalid-input fixtures leave method counters at zero. The helper must not claim to exercise production router ordering; the integrated router tests are separately blocked checks.

Do not pass arbitrary Java runtime handles to valueToTree to manufacture JSON acceptance. Resource/InputStream/byte[] binding fixtures operate on direct/already resolved values and are labeled as binder evidence. Full marked-runtime validation and reference resolution must use the existing production paths after 30.2.3 restores them; no placeholder adapter or resolver test stub is allowed here.

## Tests to add or update

### 1. Canonical publication and standard semantics

**Type/location:** unit and local registration integration; generator tests, BPP tests (or a dedicated `JavaInputDeclarationTest` in the same package), canonical compiler tests.

**Proves:** root object shape, complete canonical/tool-tree equality, no reduced reconstruction, stable immutable canonical tree and provider copy behavior. Authored/generated equivalent schemas have equivalent standard verdicts. INPUT `{}` and description-only leaves accept string/boolean/finite number/object/array/null. Required missing fails; required present null passes for unconstrained values; optional omission remains absent, optional null remains present. Cover Object parameters, DTO properties, collection items and map values. Literal ref:// strings remain unchanged through explicit unconstrained ordinary binding. Record whole runtime JSON-compatibility/rejection checks as downstream rather than serializing arbitrary Java objects in this helper.

**Negative controls:** integer numeric strings fail; malformed typed siblings fail; extra closed-record/root properties fail; missing required DTO properties fail. Preserve surrounding array bounds/requiredness in equivalent compiled authored/generated-shape contracts without inventing new Java annotations. Description-only root and OUTPUT/PLANNING leaves still fail; invalid description types and unsupported keywords fail.

**Surface:** serialized contract and internal implementation. No coercion/fallback compatibility path.

### 2. Effective generics, names and parameter metadata

**Type/location:** local BPP registration/validation/invocation; generator nested-type unit tests.

**Fixtures:** inherited T=Integer, inherited T=Resource/InputStream, inherited nested map/list/DTO generic members; finite Box<Box<String>>; swapped interface names with heterogeneous types and descriptions; mixed optional/required parameters; ordinary matching-name control.

**Asserts:** correct resolved leaf types/required lists/descriptions, correct argument positions, invalid strings rejected before test dispatch, runtime markers use the same effective types. Generic JDK proxy/concrete override control remains valid. Optional primitive rejection remains intact, including any resolved effective primitive case supported by Java reflection.

**Naming fixture:** BPP created with SNAKE_CASE application mapper and independently default schema mapper using production's two-mapper factory wiring. Nested firstName publishes first_name in canonical/tool trees and binds Ada; unadvertised firstName fails the closed schema. Include explicit JsonProperty and default naming controls and runtime-reference properties under effective names. Inspect production auto-configuration wiring to ensure its factory call supplies these distinct mappers; a shared-mapper test is insufficient.

**Surface:** configuration/serialized behavior; application declaration signatures unchanged.

### 3. Enum and UUID fidelity

**Type/location:** BPP registration/validation/invocation plus generator shape tests.

**Fixtures:** ordinary enum, enum READY annotated JsonProperty("wire-ready"), UUID as parameter/nested DTO/list/map value. Include enum toString override control so names are not inferred from String.valueOf.

**Asserts:** only advertised enum value validates and reaches intended constant; UUID advertises string without newly added format; valid UUID binds to expected value; malformed UUID fails conversion without method invocation; UUID objects fail string schema. Parameter description/requiredness and ordinary sibling rejection remain intact.

**Surface:** generated serialized contracts and binding; intended correction.

### 4. Declared map-key restrictions and typed-map controls

**Type/location:** parameterized generator/BPP registration tests plus ordinary map invocation controls.

**Reject fixtures:** Integer, Long/other numeric, enum and custom key classes at direct parameter, DTO property, collection item and map-value locations; inherited generic K resolved to a forbidden key. Check method, parameter/property/items/value path and unsupported key type. Ensure rejected capability is absent, its target side-effect counter is zero and no provider fixture is called.

**Allow fixtures:** Map<String,String>, Map<String,Integer>, raw Map, Map<Object,Object>, record-valued maps, maps in arrays/records and nested maps. Preserve distinct string keys "1" and "01", values/types/descriptions/requiredness and closed record nodes. Invalid entry reports its precise canonical validation location. Numeric strings do not satisfy integer entries. Runtime-reference map-value nodes retain markers. Whole-map binding transfer belongs to 30.2.5.

**Custom mapper inspection:** configure a key deserializer for a prohibited key type and prove declaration rejection remains based on resolved key type. Inspect/document whether application String-key customization can transform keys; do not introduce property-name features, global key conversion bypasses or arbitrary serializer inference. General custom-key mapping fidelity is outside the bounded supported correction.

**Surface:** configuration/serialized contract; explicit unsupported declarations now reject.

### 5. Effective JsonUnwrapped rejection

**Type/location:** parameterized BPP registration tests.

**Fixtures:** enabled field, getter, application mixin, prefix/suffix, nested property, collection item and typed-map value. Effective creation introspection must see relevant annotations rather than reflection on only the raw class. Disabled enabled=false and plain nested DTO controls remain valid and bind expected data.

**Asserts:** method and exact declaration path in registration error, no capability for rejected method, no invocation. This is rejection of the declared generated contract, not flattening support. Do not add restrictions for deferred Java edge cases.

### 6. Resolved recursion and runtime-leaf ordering

**Type/location:** generator and BPP registration tests.

**Reject matrix:** direct self-cycle, mutual DTO cycle, cycle through array/list/map values and nested combinations, generic Node<T> -> Node<T>, and expanding generic Node<T> -> Node<List<T>> (or equivalent genuine recursive declaration). Include genuine DTO recursion beside a Resource property to prove runtime-leaf handling does not suppress real errors.

**Accept matrix:** repeated DTO siblings, same DTO in separate parameters, acyclic nested DTOs, Box<Box<String>>, resolved inherited generic nesting. Assert all leaf constraints/requiredness/closed nodes survive. No depth limit, open fallback or partial contract may appear.

**Runtime fixtures:** direct Resource/InputStream/byte[], nested properties, collection/array items and map values, including concrete Resource subtypes with internally recursive implementation properties. Assert marked string leaves and no expansion into java.io.File or implementation internals. Combined finite generic/resource case retains both semantics.

**Asserts:** rejection before capability publication with method/input path/resolved cycle. Preserve other valid methods and executor declarations without inspecting recursive application data internal to executors. Preserve existing per-method registration semantics; do not require an unrequested all-bean transaction.

### 7. Runtime descriptions and provider-copy metadata

**Type/location:** parameterized BPP registration tests and canonical copy tests.

**Fixtures:** each of Resource, InputStream and byte[] with exact nonblank multiline/padded SkillParam text; absent and blank descriptions; required and optional variants. Include nested/item/map resources and a literal data property named x-loomspan-runtime-ref-capable.

**Asserts:** published tool and canonical schemas retain exact authored descriptions, string type, runtime marker and requiredness; fallback description equals existing generic guidance when absent/blank. Canonical marker survives providerTree generation, provider schema removes only schema-node annotations, standard assertions/descriptions/data properties stay intact, and original canonical trees remain unchanged. Tool publication here does not certify actual provider requests.

### 8. Resource container identity, conversion and cleanup

**Type/location:** real registered BPP invoker tests; existing cleanup tests updated to canonical assertion APIs.

**Fixtures:** Resource implementation whose stream/URI/file/metadata methods throw or count calls; direct Resource and List<Resource> with multiple handles and null where binding permits; already reference-resolved List<Resource> values. Do not describe the latter as actual RefResolver evidence.

**Asserts:** body sees identical handles, binding does zero reads/serialization and returned observable identity assertions pass without serializing the Resource as a result. Verify valid ordinary container scalar conversion still occurs as designed after validation. Probe Map<String,Resource>, Resource[] and nested lists locally before broadening the fix; retain tests for each additionally demonstrated shape and ensure declared raw container assignability is preserved. Do not silently return List for a different incompatible declared raw type.

**Preservation controls:** Resource-to-string, Resource-to-byte[], Resource-to-InputStream; nested records/items; direct streams; read failure, conversion failure of a later argument, method-body failure, nested binding failure and success. Assert expected streams close exactly as existing contract requires and Resource handles themselves are not consumed when their target remains Resource. Do not replace or remove existing failure/closure assertions.

**Deferred integration:** direct/runtime-ref validation plus real reference-resolved containers use 30.2.3's restored validator/RefResolver and later complete dispatch. Keep ready-to-run assertions in integrated tests when practical, but record their non-execution explicitly.

### 9. Executor, collision, proxy and security preservation

**Type/location:** focused BPP tests, existing SharedJavaDiscoveryInvocationTest / JavaSkillIntegrationTest / executor integration suites when buildable.

**Asserts:** executor-only bean produces executor registration and no callable contract; exactly one SkillExecutorInvocation required; recursive internal executor state is not reflected; duplicate callable names rejected, distinct callable/executor indexes retained; SkillExecutorInvocation configuration/input/metadata handoff unchanged. Test actual JDK/CGLIB proxy target invocation in the buildable slice where feasible. Preserve generic concrete override and ordinary annotation metadata controls.

Full YAML validation-before-executor dispatch, authorization enforcement, captured configuration generations and public SkillTemplate invocation are blocked integrated checks rather than inferred from direct invoker tests.

### 10. Public surface and documentation

**Type/location:** LoomspanPublicSurfaceArchitectureTest and deterministic source/doc review.

Run the real architecture test through normal build. If unavailable, record its compilation blocker and inspect changed API signatures/internal-public inventory without calling that inspection a passing architecture test. A partial classpath must not certify a full-surface inventory. New internal public helper types, if necessary, require documented inventory entries; supported API allowlist remains unchanged.

Review input-contracts.md, standard-schemas.md, skill-authoring/README.md and java-api/java-skills.md against the exact changed source/test claims. Confirm no recursive fallback/coercion claims survive as current supported behavior, canonical described Object semantics are stated accurately, and runtime/provider/public-dispatch gaps remain visible.
