# PR 28.2 executor declarations and configuration testing plan

## Change Summary

Verify one declaration-form authoring boundary, immutable executor skill config, removal of `rest:` syntax, shared namespace executor configuration, publication ownership/defaulting and real Spring YAML ingestion fidelity. This is pipeline Step 3 in the same context as Step 2, selected profile **full**. The implementation plan is `2026-11-01-PR-28.2-executor-declarations-and-configuration.md` in this directory.

## Impacted Areas

- `YamlSkillCatalog`, `YamlSkillManifest`, `YamlSkillDefinition` and declaration consumers.
- `ExecutionConfigurationParser`, `LoomspanProperties`, target-aware `SkillGenerationManager` calls.
- Ordered Boot YAML loading, internal raw carrier/binding conversion and `META-INF/spring.factories` discovery.
- Existing `ImmutableContainers`, relevant architecture allowlists, parser fixtures and routed authoring/configuration guidance.

## Risk Assessment

1. Repeating form matrices in raw checks, typed binding and definitions can produce precedence or null/empty loopholes. Check behavior and inspect source ownership.
2. Direct Java Map binding can pass while real YAML loading has already lost nulls, empty containers or exact keys. Real Config Data loading is mandatory.
3. A custom YAML loader could alter ordinary Spring properties, mishandle multiple documents/imports or validate inactive profile content too early.
4. Domain strings such as `${ENV_VALUE}` and `api-key-ref` can be unintentionally interpreted by normal binding/credential code. Assert literal values and scalar classes, not only serialized equality.
5. Target enforcement can be missed in one of preparation's two parse paths. Tests cover parser ownership and manager call handoff.
6. Defensive copies must freeze every map/list while retaining nested nulls and scalar leaf types; JSON conversion is insufficient evidence.
7. Existing runtime tests use obsolete REST syntax. That syntax is intentionally removed; preserve meaningful model/TypeSafe behavior, but do not add a compatibility reader, disable tests silently or pretend executor execution is supplied in this ticket.

Protected surfaces are existing supported Java signatures and unaffected configuration/model/TypeSafe behavior. The manifest/configuration contract changes are authorized by the ticket. Internal constructors/loader machinery are not supported SPI. No Console wire, persisted-history or current trace format change is selected.

## Tests to Add/Update

### 1. Executor declaration acceptance and immutable copy

- **Type/location:** unit, `YamlSkillCatalogTests` and `YamlSkillDefinitionTest`.
- **Names:** `executorLeafHasExplicitFormAndReference`, `executorConfigOmissionAndEmptyMapAreEquivalent`, `executorDataSurvivesManifestAndDefinitionCopies`.
- **Proves:** required identity/description, valid local/qualified executor textual identity, optional input schema/RBAC and generic input when absent; explicit executor form with no model settings. Omitted/empty config is immutable empty; nested map/list/null/scalar/key fidelity survives all public internal copy accessors.
- **Fixtures/mocks:** supplied YAML plus mutable nested Java source maps for definition copy tests; no executor bean/model/client mocks needed.
- **Surface:** configuration/manifest contract and internal representation. Existing supported schema semantics are protected; REST syntax is deliberately replaced.

### 2. Presence/type/conflict matrix

- **Type/location:** parameterized unit, `YamlSkillCatalogTests` with existing valid/invalid resource fixtures as appropriate.
- **Names:** `executorRejectsForbiddenFieldPresence`, `configRequiresExecutorAndMapValue`, `restIsAnUnsupportedManifestField`, `declarationFormsNeverChoosePrecedence`.
- **Proves:** forbidden `typesafe`, `model`, `thinking_level`, `prompt`, `planning_mode`, `concurrency`, `max_steps`, `allowed_skills`, `linter`, `output_schema`, `output_schema_max_retries`, `output_from`, `output_bindings` fail for ordinary/null/empty values. Test config `null`, bare field, strings/numbers/Booleans/lists; test empty/null config on model and TypeSafe forms. Executor reference null/bare/blank/whitespace/wrong-type and invalid identity fail. `rest` true/false/null/empty/map/list always fails normal unknown-field handling.
- **Assertions:** source label, skill where available, offending field and meaningful diagnostic rule. Do not couple to exact prose. With multiple simultaneous invalid fields, require a correct diagnostic rather than arbitrary field ordering.
- **Mocks:** none. This verifies structural validation does not need callable application code.

### 3. Model/TypeSafe/concurrency regressions and validator ownership

- **Type/location:** unit, `TypeSafeDeclarationTests`, `YamlSkillCatalogTests`, `YamlSkillDefinitionTest`.
- **Names:** retain existing meaningful tests and revise only obsolete direct constructor expectations.
- **Proves:** TypeSafe still requires its model/input contract and TypeSafe driver; ordinary model leaves retain execution/thinking/schema rules; concurrency is valid only under explicit planning with a non-null Boolean. Constructors check representation invariants and do not independently maintain authoring rules.
- **Source review:** one form matrix owner; no REST syntax support; no inference that absent execution configuration means REST; domain data excluded from Jackson manifest copy. No mirror-the-implementation test is required merely to count validators.

### 4. Namespace structure, immutable data and publication ownership

- **Type/location:** unit, new internal immutable-value tests and `ExecutionConfigurationParserTest`.
- **Names:** `executorConfigurationRetainsNestedValuesAndExactKeys`, `publicationRejectsForeignExecutorNamespace`, `omittedExecutorConfigurationNeverInherits`, `executorConfigurationRejectsInvalidOwnershipStructure`.
- **Proves:** startup-style structural factory accepts multiple namespaces; published parser accepts only its target, including rejection of a foreign empty namespace map. Section and namespace roots must be maps; namespace grammar/normalization follows existing identity rules and normalized duplicate namespaces reject. Nested null/scalar/list values remain allowed because only later path binding requires a selected map. Omission/empty section is empty; two parses never inherit values. Mutating input/returned nested containers cannot change held data.
- **Fixtures:** the fidelity fixture above, same target with case-normalized spelling, invalid roots/namespaces, sequential independent parses.
- **Mocks:** none; publication parses direct YAML, not Framework Binder-generated domain properties.
- **Surface:** configuration contract/internal representation; no lifecycle authority is added.

### 5. Uninterpreted domain configuration and target handoff

- **Type/location:** parser unit plus focused manager validation integration where needed.
- **Names:** `executorApiKeyRefIsOrdinaryData`, `executorStringsAreNotInterpolated`, `validationDoesNotInvokeApplicationCode`, `managerUsesTargetForEveryConfigurationParse`.
- **Proves:** missing external references inside executor data do not resolve or fail; supplying a credential map entry used only by executor content still counts as unused under existing connection credential rules. Existing connection reference tests remain meaningful. `validate` against empty documents with target configuration performs no application invocation; foreign namespace fails as a configuration issue. Preparation's metadata and credential-resolving parses both use the same target.
- **Mocks:** use invocation counters/throwing application beans only when an integration test exercises actual application wiring; avoid constructing an executor runtime or client just for structural parsing.

### 6. Loader registration, active source selection and ordinary Spring behavior

- **Type/location:** integration, `ExecutorConfigurationStartupTests`.
- **Names:** `configDataDiscoversExecutorAwareYamlLoader`, `profileDocumentsPreserveDataAndValidateOnlyActiveContent`, `ordinaryPropertiesKeepBootSemantics`, `importsAndDocumentOrderingKeepExecutorSubtreesCoherent`, `invalidActiveExecutorShapeFailsStartup`.
- **Proves:** factory registration is used by normal Boot loading; `.yml` and `.yaml`, multiple docs including empties, active/inactive profile metadata and imports associate the correct raw subtree. Invalid inactive structural executor data does not fail active binding. Selected root data remains intact; normal host/Framework values and placeholders outside executor data still follow Boot behavior. Duplicate YAML keys fail and invalid active section/namespace structure reports its field.
- **Fixtures/mocks:** temporary/classpath YAML and a minimal non-web Spring application; no external services. Use a small subset for import/precedence behavior, not a generic Boot compatibility suite.

### 7. Architecture and authoring guidance

- **Type/location:** existing architecture suite plus source/doc inspection.
- **Proves:** supported API allowlist stays unchanged; technically public loader/converter/data machinery is deliberately classified internal/integration and does not create a consumer SPI. Relevant guidance describes tested syntax, fidelity, target ownership and complete replacement. Runtime binding/path validation remains accurately identified as PR 28.3 work.
- **Evidence/claims:** new executor topic and routing correspond to tests 1–3; startup/publication guidance to tests 4–6. Existing relevant prose is baseline **aligned** and must be updated with the change. No new documentation-derived runtime expectation is introduced.
