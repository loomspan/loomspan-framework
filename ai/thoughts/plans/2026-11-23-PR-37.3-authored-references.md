## Current state analysis

`YamlSkillCatalog` validates each raw reference, then qualifies only structured semantic fields in `prepareReferences`. Executor selection is qualified separately during manifest construction. The source bytes, prompt, schema data, descriptions and raw evidence expression remain authored content (`YamlSkillCatalog.java:480`, `:697`, `:798`, `:804`). Evidence is compiled using the catalog's owner and original token columns (`:897`).

`SkillDependencyValidator` builds a callable metadata index and independent executor views. Its outgoing graph check chooses the exact owner, enforces namespace visibility, checks the selected index and ends on a miss (`SkillDependencyValidator.java:39`, `:163`, `:173`, `:282`). Generation capture and admission retain exact reachable ownership. Runtime visibility and `DefaultAccessGuard` separately enforce declared direct calls, retained generations, foreign Public visibility and caller authorization.

Bindings store their producer as `SkillIdentity`, match exact accepted-result names and retain provenance. Output forwarding selects the exact planned/accepted task identity. `EvidenceExpressionParser` treats an entire bare `and` or `or` token as an operator, while `orders:and` and `orders:or` are identifiers. These mechanisms can be verified without changing root invocation signatures or provider tool dispatch.

The pre-series codec at `c271b80` used one hyphen as the qualified separator. Original `warehouse-lookup` therefore selected `(warehouse, lookup)`. PR 37.1 also introduced legitimate hyphenated local declarations and converted some fields already. Current spelling alone is insufficient to decide which strings need rewriting.

The PR 37.1 completion record lists 20 failing authored-reference cases in `YamlSkillCatalogTests` and `ExecutorDeclarationTests`. Namespace, dependency, authorization, binding and evidence families contain further older canonical strings and normalization expectations. Those cases need coherent fixtures and assertions under the exact contract.
