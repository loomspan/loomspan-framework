# Authored variable markers testing plan

## Change Summary

Add a shared internal YAML facility that preserves authored mappings, discovers whole-node variable markers within the three selected boundaries, and substitutes those markers with terminal strings. A language-neutral fixture corpus supplies exact names and source/path occurrences to Java and independent Go implementations.

This is step 3 of the approved Full 5-Step Pipeline, continuing in the step 2 planning context. The controlling implementation plan is `ai/thoughts/plans/2026-11-22-PR-35.1-author-variable-markers.md`. This document designs verification. Planning has run no tests and has made no production or test-code edits.

## Impacted Areas

- `src/main/java/ai/loomspan/internal/serialization/YamlValues.java`, for shared settings and resource controls.
- New `AuthoredYamlVariables` internal facade and nested document, occurrence and failure types in the serialization package.
- `src/test/java/ai/loomspan/internal/serialization/AuthoredYamlVariablesTest.java`, for focused unit coverage.
- `src/test/java/ai/loomspan/internal/serialization/VariableMarkerFixtureTest.java`, for corpus conformance.
- `loomspan-variable-fixtures`, for language-neutral authored YAML and expected JSON files.
- `LoomspanPublicSurfaceArchitectureTest`, for the new framework-only type inventory.
- Existing scalar, skill-document, executor declaration, configuration and startup tests, because factoring YAML settings can affect these callers.

## Risk Assessment

1. Eager map construction can discard authored key markers, merge equivalent keys or lose entry indices before diagnostics can identify both locations.
2. Traversal can enter selector names, schemas or other excluded fields, or miss unknown fields, nested prompt fields and composite keys inside a selected boundary.
3. YAML scalar construction can treat quoted numeric names as numbers, change ordinary number kinds or timestamps, or accidentally parse a returned string as YAML.
4. Substitution can move paths to resolved key names, overwrite literal siblings, mutate the retained document or recursively expand returned placeholder text.
5. Composed-node work can bypass existing cycle and logical alias expansion limits or eagerly expand alias graphs before checking them.
6. Callback failures and duplicate-key exceptions can embed supplied values in message/cause text unless the facility owns those failures directly.
7. A fixture corpus can look reusable while tests only exercise a subset of its cases or use Java-only expected representations.

The protected Application API is the closed allowlist, verified by its architecture test. The shared fixture and marker/path contracts are Configuration and manifest contracts and Persisted or serialized contracts established by the ticket. Resolution diagnostics are Ephemeral diagnostic formats. The composed tree and lookup callback are Internal implementation. No Supported SPI is introduced. Current Console wire formats have no change.

The plan's intentional internal changes need no compatibility shim. Existing preparation and startup provider-reference rules belong to their integration tickets. Regression tests here protect behavior affected by the shared parser refactor.

## Tests to Add or Update

### 1. Boundary selection and traversal

Type is unit. Location is `AuthoredYamlVariablesTest`. Use hand-authored YAML and a lookup function that records names or fails if called unexpectedly.

- Select every immediate connection value and namespace executor value, preserving authored selector spelling in paths. Select actual top-level config only when the root executor declaration is present and config is a map.
- Traverse unknown fields, nested fields named prompt, map keys, map values and sequence elements at arbitrary depth inside selected values.
- Place markers in connection selector keys, namespace selector keys, models, session policy, unrelated root sections and invocation-shaped inputs. Assert zero discovery occurrences and zero lookup calls for those markers.
- For skill documents, put markers in prompt, model, executor, descriptions, roles, schemas, input/output transforms and nested schema config fields. Assert zero lookup calls there. Include a model-backed skill with a config-shaped subtree and confirm it creates no selected boundary.
- Include a selected container whose own exact one-key shape is a marker to cover the plan's whole-node rule. Owning type validation remains a later concern.
- Include a selected complex mapping key that contains nested markers in a map value and a sequence item. Assert traversal through `{key#i}` and ordinary nested path/index segments, followed by its paired `{value#i}` traversal. Assert original authored ordering.

Affected surfaces are Configuration and manifest behavior and Internal implementation. No provider, environment or application executor mock is required.

### 2. Marker shape, YAML type and exact name semantics

Type is parameterized unit. Location is `AuthoredYamlVariablesTest`, with portable variants in the fixture corpus.

| Input | Expected result |
| --- | --- |
| Flow `{ $var: app.region }` and equivalent block mapping | Same occurrence name and path |
| `{ $var: "123" }` | String name 123 |
| `{ $var: 123 }`, `{ $var: true }`, null, sequence or map name | Located discovery failure before lookup |
| Empty, spaces, line-break-only and representative Unicode blank strings | Located discovery failure before lookup |
| Leading/trailing whitespace or newline around nonblank name | Located discovery failure before lookup |
| Internal whitespace in a nonblank, unpadded string name | Exact unchanged name passed to lookup |
| `$Var` and `$VAR` keys | Ordinary map data |
| Two-key map containing `$var` | Ordinary map, with nested markers still discovered |
| `$var` text appearing inside literal scalar content | Literal scalar |
| Punctuation such as `name:default` in a valid string name | Exact opaque lookup name, with no expression/default processing |
| Names differing only in case | Distinct names and exact callback arguments |

For every invalid marker, assert source and node path. Add invalid markers under literal keys, sequence elements, marker keys and unresolved paired values. Discovery must have no value-source dependency. A record/list equality assertion must compare every occurrence rather than just counts.

Affected surfaces are Configuration and manifest behavior and the shared serialized fixture contract.

### 3. Authored path formatting

Type is parameterized unit. Location is `AuthoredYamlVariablesTest`; include representative escaping in corpus cases.

- Identifier and hyphen keys use dot segments, including api-key, base-url and X-Region.
- Dotted keys use JSON-quoted brackets, including `headers["X.Region"]`.
- Empty, numeric-looking, Unicode, quote, slash, backslash, tab and newline keys use valid JSON-quoted brackets with exact escaping.
- Sequence indices are zero-based, including nested sequences.
- Marker key indices count all authored entries, including preceding literals, and use `{key#i}`. Their paired values use `{value#i}` even when a later substitution resolves the key to a readable identifier.
- Nested markers inside complex keys retain the outer `{key#i}` path and nested addressing.
- Each occurrence carries the caller-provided filename unchanged. Identical paths in separate files remain distinct occurrences.

Affected surfaces are Ephemeral diagnostics and the serialized cross-language path contract. Use literal expected path strings that make a wrong escape visible.

### 4. Terminal string substitution and scalar preservation

Type is unit. Location is `AuthoredYamlVariablesTest`. Use a local Function with controlled returns and a call recorder.

- Preserve exact returned punctuation, YAML-looking strings, multiline strings, leading/trailing whitespace surrounding nonblank text, `${region}`, `{ $var: other }` text and embedded newlines.
- Verify replacement remains one Java String and never creates a map, sequence or second lookup.
- Preserve ordinary literals and their types, including Integer, large BigInteger, Double, boolean, null, explicit textual timestamps, quoted numbers, empty map and empty list. Compare with `YamlValues.read` for supported scalar/tag inputs.
- Retain the existing exact-decimal `SkillDocumentValues` regressions and verify ordinary config numeric kinds after settings factoring.
- Substitute keys and values in the header fixture and assert exact resulting map contents, including a literal Accept header.
- Reuse one parsed authored document for discovery and two substitutions with different callbacks. Assert fresh results, unchanged original occurrences, no stale values and independent nested output containers.
- A repeated variable used multiple times yields the same supplied value at all occurrences. Distinct-name lookup caching is a caller responsibility in this slice, so this test records only legal callback names and resulting values.
- Materialize an ordinary multi-key `$var` map and confirm its ordinary shape and nested substitution survive.

Affected surfaces are Configuration and manifest behavior and Internal implementation. No YAML dump/reparse round trip is used to assert scalar fidelity.

### 5. Resolution failures and collisions

Type is unit with corpus conformance cases. Location is `AuthoredYamlVariablesTest` and `VariableMarkerFixtureTest`.

- Return null, empty and whitespace-only values. Assert a located missing/blank resolution failure and no usable partial result.
- Throw an exception whose message and cause contain a distinctive sentinel string. Assert the resolver failure's message, retained cause chain and captured log text omit that supplied sentinel. Use fixed reasons and authored locations.
- Resolve a marker key to a literal sibling key with the marker authored before the literal. Repeat with the literal first. Assert failure reports both original locations before either entry is overwritten.
- Resolve two different marker keys to the same string. Assert both `{key#i}` paths, source and a collision reason.
- Include a collision after a nested marker inside a complex key is resolved. The materializer must enforce its map equality rules before overwrite while preserving the original outer entry locations.
- Include identical marker-shaped keys in two authored tuples. Discovery must retain both tuples. Substitution must diagnose their effective collision, using both authored indices.
- Include duplicate literal keys and compare rejection with the existing YAML reader when materializing.
- A marker key may resolve to a string containing punctuation or newline. On collision, assert the failure identifies authored paths and carries no resolved key/value content.

Affected surfaces are Ephemeral diagnostics and Configuration and manifest behavior. These assertions test intentionally constructed resolution diagnostics. They introduce no data-classification or masking mechanism.

### 6. Alias, cycle, input and resource controls

Type is unit. Location is `AuthoredYamlVariablesTest`, with existing regression tests retained.

- An aliased selected map or sequence contributes occurrences at each authored use path. Compare ordering and output values.
- Aliases used inside mapping keys and paired values retain entry-index addressing.
- A recursive map and recursive sequence fail before lookup and before materialization.
- Generate a small YAML alias DAG with exponentially repeated logical contents that exceeds 1,000,000 values. Assert the familiar limit and zero lookup calls. The test must not require an exponentially constructed Java graph.
- Include a bounded alias DAG under the limit and confirm successful discovery/materialization. Preserve shared container handling where supported by the chosen representation.
- Keep string, byte-stream/BOM and document-loading behavior aligned with the actual entry methods exposed by the facade. A single-document method must preserve existing rejection of multiple YAML documents. If multi-document ingress is added for this facility, test source identity and per-document selection explicitly.

Affected surfaces are Internal implementation and established Configuration resource controls. No external service or large static file is needed.

### 7. Complete fixture conformance

Type is corpus integration through the production internal facade. Location is `VariableMarkerFixtureTest`. Load expected JSON with the repository's existing Jackson codec and resolve fixture paths from the Maven project working directory.

The fixture README defines how to enumerate all cases and all documents. Every case must run, including its negative phase. For positive cases, compare exact ordered occurrences and distinct names, then compare JSON-compatible resolved output where provided. For failure cases, assert phase, source/path locations and reason category. Do not derive expected occurrences by scanning the input in the test.

The worked case contains two named source files, four distinct names and six occurrences. It asserts provider.key at primary.api-key, app.region at both X-Region headers and one nested sequence position, records.url at records base-url, and records.lookup-path at skill config.path. It also asserts literal Accept = application/json. Use demo-key, west, https://records.example.test and /v2/records/{recordId} as substitution values.

The separate header-key case introduces header.name and tests the paired app.region value. The separate collision case resolves header.name to the literal sibling X-Region and asserts both original locations. Portable fixtures also cover flow/block equivalence, multi-key maps, invalid names, escaping, unknown fields and boundary exclusions. Complex-key descent has at least one portable case for Go parity.

Affected surfaces are Configuration and manifest behavior and Persisted or serialized fixture contracts. Go extraction and actual Java preparation/executor observation are assigned to the integration owners. This ticket's tests establish the shared semantics they will consume.
