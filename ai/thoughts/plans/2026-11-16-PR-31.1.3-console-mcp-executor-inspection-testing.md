# Console/MCP executor inspection testing plan

## Change Summary

Restore current Java executor diagnostic event consumption in Go/MCP/browser,
present individual retained records and boundary evidence in existing frames, and
clarify/prove Framework-accounted usage scope. This is pipeline Step 3, continuing
in the Step 2 context under the approved Full 5-Step Pipeline. No implementation or
test execution occurred during planning; pre-fix failure below is established from
source plus the earlier ticket's explicitly reported failure, not a planning rerun.

## Impacted Areas

- Java producer fixture corpus/support, generic executor runtime accounting tests,
  existing provider usage/failure-containment checks and API documentation.
- Go `traceanalysis/enums.go`, parser/filter vocabulary, corpus/projection/content
  tests and `mcpadapter` enum schemas, tool descriptions and real semantic harness.

## Risk Assessment

- A parser-only fix could restore corpus acceptance while schemas or default UI
  selection still hide the records. Exercise outward discovery and actual calls.
- Authored ERROR or usage-shaped JSON must never feed Framework failure, attempt,
  retry or accounting projections. Test adversarially misleading ordinary JSON.
- Chunked envelope data, explicit null versus absent data, Unicode prefixes,
  unavailable capture and complete notice content have different meanings. Retained
  notice completeness must not imply recovery of discarded diagnostic content.
- Type/frame selection, pagination and physical/logical representations must not
  duplicate/omit events or leak notices across filters. Concurrent emission must be
  checked by canonical sequence and event identity, not expected worker order.
- UI promises/caches can outlive source/generation/artifact selection. Check stale
  response suppression and ordinary expiry/error handling, including imported traces.
- A fabricated corpus proves projection but cannot prove quota isolation; use a
  real mixed-mission executor/native runtime test for accounting enforcement.
- Protected paths: existing supported Java APIs/results, namespace/configuration,
  authentication/access boundaries, exact version rejection, query/cursor/content
  semantics and unknown native usage evidence. No intentionally removed public
  path. Update obsolete internal enum/schema expectations atomically, with no dual
  old/new reader or historical fixtures.

- **Act/assert:** successful mission; exactly two native sends/providerAttempts;

  numbers. Diagnostics preserve null and original JSON. A native over-quota control
  follows existing provider-advisor tests rather than treating executor HTTP as quota.
- **Additional cases:** executor-only operation succeeds with zero native accounting
  and unknown executor usage; mixed missing native reported usage retains the existing HEURISTIC

  extractor test and shared unavailable-usage corpus; executor HTTP 200 followed by local decoding failure records factual

  Existing native decode-after-success usage tests confirm captured native usage is

- **Surface:** protected application behavior, configuration quota semantics and

## How to Run

Commands below are required/planned checks, not claimed results. Use PowerShell
quoting for Maven comma-separated test patterns. All commands are from Framework
root unless another working directory is named.

1. Before the enum fix, from `loomspan-console`:
   `go test ./internal/traceanalysis -run '^TestFixtureCorpusMatchesJavaExpectedSemantics/java-root-success$' -count=1`.
2. After Go/test changes, from `loomspan-console`:
   `go test ./internal/traceanalysis ./internal/mcpadapter ./internal/browserapi -count=1`.
3. From `loomspan-console/web`:
   `npm run typecheck` and
   `npm test -- src/observability/TraceRecords.executorDiagnostics.test.tsx src/observability/TraceExplorer.test.tsx src/observability/TraceViews.test.tsx`.
   Run any additional affected TraceRecords/usage test files in the focused set.
4. Focused Java:
   `.\mvnw.cmd "-Dtest=ExecutorAccountingIntegrationTest,ExecutorApplicationIntegrationTest,ExecutorDiagnosticsIntegrationTest,ExecutorInvocationLifecycleIntegrationTest,SessionUsageServiceTest,ModelUsageExtractorTest,ModelAttemptCallAdvisorIntegrationTest" "-DfailIfNoTests=false" test`.
5. Intentional fixture regeneration:
   `.\mvnw.cmd "-Dtest=ConsoleTraceFixtureCorpusTest" "-Dloomspan.console.fixtures.regenerate=true" "-DfailIfNoTests=false" test`.
   Inspect output diff, then validate without regeneration:
   `.\mvnw.cmd "-Dtest=ConsoleTraceFixtureCorpusTest" "-DfailIfNoTests=false" test`.
6. After any production Java type edits:
   `.\mvnw.cmd "-Dtest=LoomspanPublicSurfaceArchitectureTest" test`.
7. Required complete Console checks, from `loomspan-console`:
   `go test ./...` and `go run ./internal/buildtool verify`.
   The wrapper includes pinned toolchain checks, npm ci, packaged skill/agent-eval,
   typecheck/coverage/build, generated frontend assets/manifests and Go tests.
8. If concurrent Go code changes (and recommended for the concurrent event test),
   from `loomspan-console`, prepend `C:\msys64\mingw64\bin` to `$env:PATH`, set
   `$env:CGO_ENABLED = '1'`, then `go test -race ./...`. Restore task-local environment
   changes afterward if the shell is reused. Record unavailable gcc/cgo as an actual
   blocked required check when concurrent code changed, never as a pass.
9. `git diff --check`; inspect fixture LF and unchanged matching release/version
   files. Record exact verification and restored prior-ticket debt in Execution notes.

Do not run live inference, Extensions tests or unrelated benchmark suites to satisfy
this ticket. If a command fails, resolve it or document exact cause/remaining owner
under the ticket's rules; do not suppress a relevant failing check.

## Implemented evidence and interpretation

`ExecutorAccountingIntegrationTest` has four real ApplicationContextRunner cases:
exact two-native-attempt quota around two executor HTTP requests; missing native
reported usage retains HEURISTIC estimates; executor-only zero-native accounting
with raw null executor usage; HTTP 200/local JSON decode failure retaining null usage
and the designated recoverable exception. Ordinary prompts make heuristic estimation
available, so missing reported usage is not mislabeled UNAVAILABLE. Existing
ModelUsageExtractorTest and unavailable-usage corpus protect explicit UNAVAILABLE.

using actual Framework failure recording, eight joined concurrent events in
java-root-success, and a child ROOT_MISSION with real local HTTP failure/retry and
adversarial usage/outcome JSON in nested-frame-usage. Shared totals remain 5/3/8
with two native attempts. Invalid derivative traces are regenerated, including a
sequence-safe duplicate-close mutation. Existing payload enums/shapes stay exact.

Go executor_diagnostics_test.go files exercise actual processor, MCP/browser tools,
filters, independent continuation pages, physical/logical inventory and exact ranged
content. Discovery input enums contain both events; output record types retain the
existing compact-string schema and actual returned values validate. No output enum
was introduced. Existing acquisition/authentication/expiry/version rejection remains
covered by the full module suite.

TraceRecords.executorDiagnostics.test.tsx adds 20 lazy/inert/state/source-safe detail
cases, including split UTF-8/BASE64, large numeric lexemes and explicit display bounds.
The full frontend coverage run exercises 608 tests in 49 files. Documentation claims
are grounded by these paths, ModelUsageExtractor and the existing native advisor,
producer containment and lifecycle tests. Coverage rows and Console playbook routing
were updated; current supported-surface and journal-only exception remain intact.
