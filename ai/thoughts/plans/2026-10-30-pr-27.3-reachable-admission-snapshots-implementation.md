## Implemented behavior

- `SkillGenerationManager.capture(SkillIdentity)` selects exactly the entry's transitive declared graph under `generationMonitor`. Selection tracks visited skill identities separately from namespaces and checks existence for every encountered reference. Optional/role-restricted children participate; Java capabilities are leaves.
- `SkillAdmissionSnapshot` is an immutable internal entry/namespace association. Visibility comes from immutable captured generations. A single aggregate `OwnerLease` holds each selected generation once.
- Capture completes graph selection and constructs its immutable result before incrementing any owners, all under the same monitor. A missing later dependency therefore fails without partial ownership to unwind. Contract validation failures close the complete aggregate in the facade. Closing collects retirement decisions under the monitor and dispatches resource close/listeners after leaving it.
- `SkillDependencyValidator.checkGraph` is shared by complete-candidate preparation and entry-rooted admission. Preparation still overlays the complete candidate and preserves duplicate/parse diagnostics. Admission visits only the entry graph, checks captured foreign visibility, resolves existing input contracts and binding rules, recomputes forwarding, and compares effective output JSON trees with published prepared metadata. No published metadata is changed; no dependency revision/history pin or general schema normalization was added.
- Every template/handoff root overload uses the shared qualified parser and canonical lookup, before conversion/validation. Authentication remains captured after preparation at the existing boundary. Entry RBAC now precedes admission/session creation, without eager child RBAC.
- `PreparedInput`, handoff payloads, runner and execution bindings carry the authoritative snapshot. `withMission` and `forkBranch` preserve it, and binding construction rejects a generation absent from that association. Existing child dispatch restrictions remain; PR 27.4 owns target context switching and independent dispatch authorization.
- Existing `AdmittedRoot`/`MissionLifecycle` own the aggregate. Pending abandonment, errors, completion, cutoff and rejected nested roots use existing cleanup. A logical timeout cannot release resources still owned by physical work. Entry `generationId()` is stored independently of consumable payload and remains side-effect-free after release.
- Validation uses the same capture/dependency/input/entry RBAC checks with temporary ownership; it creates no root/session/provider work and reserves nothing. Validation/handoff preparation remain allowed inside an active scope; nested fresh/admitted execution remains rejected.
- README, public Javadoc and routed `loomspan-docs` topics describe fresh admission, temporary validation, retained catalogs, all-branch reachability, prepared contracts and the later PR 27.4/27.5 boundaries. Internal signature changes update their test callers directly without production aliases or compatibility bridges.

## Material implementation decisions

1. Delay owner increments until the complete graph and immutable association have been selected under the monitor. This satisfies ownership-before-retirement while avoiding partial acquisition on ordinary capture failure; no close/callback is needed under synchronization.
2. Preserve candidate preparation's complete validation and diagnostics by passing its collected issue list into the shared graph checker. Admission uses captured published metadata and a singleton root definition rather than complete-candidate validation per namespace.
3. Reuse Jackson tree equality directly for prepared effective output schemas. Whitespace/property order changes pass; changed fully forwarded structures (including additive and multi-hop changes) require republication. Existing binding constraints, unknown/open-schema limitations and ordinary child evolution remain their own policy.
4. Preserve lifecycle authority rather than adding a snapshot-specific execution engine. No deadline, runtime construction, public dependency map, authorization SPI or new Spring replacement contract was introduced.
5. Internal runner/binding construction now takes snapshots. Test-only factories construct synthetic snapshots for pre-existing unit fixtures; they do not create a production fallback format or supported application API.
6. Entry denial now precedes session creation, so the supported-surface denial test expects no observer callback. Post-session execution/observer failure behavior remains covered separately.
