# PR 37.1 declaration identity testing plan

## Change summary

Declaration components become exact lowercase ASCII names with optional single hyphens, reserved-substring exclusions and a shared two-separator-character pair limit. Startup and supplied YAML retain their specified owners. Both Java annotations use an explicit nonempty name or the exact method name, with corrective startup errors. Role indexes remain independent and use an unambiguous colon-qualified key.

This plan continues pipeline Step 3 in the Step 2 context under the approved Full 5-Step Pipeline. It implements the acceptance criteria in `ai/thoughts/tickets/loomspan-pr-37.1-declarations.md` using the implementation plan `2026-11-23-PR-37.1-declarations.md`.

## Impacted areas and risks

- Shared `SkillIdentity` grammar, parser/rendering and namespace validation feed registration and later runtime consumers. Hyphens inside components must never collapse distinct pairs.
- Java annotation fallback, explicit names and defaults must remain verbatim. Existing camelCase fixtures need valid annotation names while preserving their unrelated test behavior.
- Configured YAML discovery and supplied validation/preparation must apply the right owner before computing the pair length.
- Callable uniqueness spans YAML/Java, executor uniqueness is independent, and cross-role reuse must stay valid.
- Namespace keys in executor configuration become exact validated identifiers. Nested business data remains arbitrary and unchanged.
- Shared colon rendering can expose failures in authored-field, API, provider, worker and Console suites before their owning tickets are implemented. Record exact deferred failures. PR 37.1 declaration gates must pass.

The allowlisted annotations and public reloader are Application API. YAML and executor owner keys are Configuration and manifest contracts. Registration records/maps and codecs are Internal or accidentally exposed implementation. There is no Supported SPI. Identity-bearing serialized and ephemeral diagnostic consumers receive their coordinated conversion under the later tickets specified in the implementation plan. The developer explicitly authorizes the behavioral replacement without compatibility shims. Existing `ExecutionJournalProjector` redaction coverage remains as scoped in `AGENTS.md`.

## Tests to add or update

### 1. Exact components, pair limits and key round trips

Type is unit. Location is `SkillIdentityTest`.

Use a parameterized matrix for both component positions. Accepted examples include `a`, `lookup`, `lookup-3pl`, `order-support`, `a0` and `a-0`. Rejected examples include null, empty, `3pl-lookup`, `Lookup`, `LOOKUP`, leading/trailing/internal whitespace, line terminators, `_lookup`, `lookup_name`, leading/trailing/repeated hyphens, slash, colon, double-hyphen, non-ASCII characters and components containing `anthropic` or `claude`, including substrings such as `myclaudeskill` and `anthropic-tools`. Check case as supplied and do not test case-folded success.

Component validation permits length 64 and rejects 65. Pair construction separately enforces the total cap. In namespace `order-support`, 49 lowercase characters succeed and 50 fail. Test both asymmetric extremes and the exact total of 64. Error assertions identify the invalid component or pair and the length constraint without depending on incidental punctuation.

Round-trip `(a-b, c)` and `(a, b-c)` through colon parse/render, asserting unequal identities and unequal keys. Reject malformed qualified references with zero/multiple colons, empty sides or invalid components. `resolve("lookup-3pl", "orders")` yields the local pair and `resolve("warehouse:lookup", "orders")` yields the explicit pair. This helper test establishes the registration foundation. Field-level resolution/access coverage is PR 37.3.

No mocks are needed. Affected surface is Internal implementation with intentional replacement of the obsolete codec.

### 2. Real Java declaration names, diagnostics and indexes

For both `@SkillMethod` and `@SkillExecutor`, cover omitted/empty name on a valid lowercase method, explicit hyphenated name on a camelCase method, default owner and explicit hyphenated owner. An explicit whitespace name must fail without falling back to the method. A camelCase method with omitted/empty name fails with the annotation role, bean, method, invalid selected name and advice to supply a valid annotation name or rename the method. Invalid explicit name and namespace representatives fail for both annotations. Unit identity cases supply the full grammar matrix.

For both registration kinds, annotation constants with a 49-character lowercase local name under `order-support` succeed and 50 fail. Use real annotations on fixture methods to establish the declaration boundary. Executor methods use exactly one `SkillExecutorInvocation` parameter.

Register duplicate callable pairs and duplicate executor pairs and assert that the error names both locations. Register equal locals under two owners and verify both exact records survive. Register one callable and one executor with the same pair and inspect each independent collection. Include `(a-b, c)` versus `(a, b-c)` to prove the string-backed index preserves distinct pairs.

Use the real processor and existing managed invocation fixture. Avoid models or network requests. Affected surfaces are Application API annotation behavior and Internal registration. The intentional break covers invalid old spellings. Existing method/proxy/security behavior keeps its prior assertions with portable explicit declaration names.
