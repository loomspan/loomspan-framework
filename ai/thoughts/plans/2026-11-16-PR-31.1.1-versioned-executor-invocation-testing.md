# Versioned executor invocation and lifecycle testing plan

## Change summary

Replace the unversioned record with the exact v1 Framework-created class, retain
captured values/generation identity, declare the diagnostic JSON capability, and
implement live cancellation/execution-budget reads. The implementation plan with
the same filename stem controls the settled declarations and staging decisions.
This is Step 3, continuing the approved full pipeline's planning context.

## Impacted areas

- API v1 types/package policy and architecture exact inventory/signature checks.
- Shared Java registration/proxy dispatch and coordinator invocation construction.
- MissionLifecycle, MissionWorkExecutor, explicit StepLoopMissionExecutionEngine,
  and existing Framework shutdown deadlines/physical retention.
- Executor/generation/namespace/access integration fixtures and supported facade.
- Current API/authoring docs and Console buildtool documentation assertions.

## Risk assessment

The main risks are a new public construction/SPI seam, overly broad package
acceptance, stale invocation imports/record assumptions, lost configuration or
generation capture, callbacks reading ambient rather than captured lifecycle,
cleanup grace being reported as execution time, renewed parent budget at child
entry, failure to arm explicit-step parent timeouts, blocked shutdown reads,
cleared interruption and premature resource retirement after logical completion.

Application API replacement is an intentional ticket-authorized break. Existing
configuration/manifest/namespace/access/result contracts remain protected. No
Supported SPI exists. No persisted/serialized or ephemeral trace payload changes
are planned. Preserve existing observation semantics/content and the derived
journal's existing exception; no automatic sensitivity rewriting is introduced.

## Tests to add/update

### 1. Exact supported v1 surface

- Type/location: unit, `architecture/LoomspanPublicSurfaceArchitectureTest` and
  `api/SkillExecutorTest` (new dedicated `api/VersionedExecutorInvocationTest`
  may hold the value/reflection checks).
- Proves: exact 25 direct API plus 2 v1 top-level types; no old class resource;
  final non-record invocation; exactly planned public accessors; no public or
  protected invocation constructor/mutator; no internal/autoconfigure signature
  leakage; capability has exactly six void methods with String/optional Object;
  no public custom level/version switch/cancellation controls.
- Fixtures/mocks: reflection/ArchUnit on actual production classes; internal
  factory only for isolated constructor validation, no mocked API class.
- Surface: Application API and internal classification. Expect intentional old
  API removal and exact new-class acceptance, never prefix-wide permission.

### 2. Registration and shared invocation

- Type/location: unit/integration, `internal/core/SharedJavaDiscoveryInvocationTest`.
- Proves: exact v1 succeeds; Object, unsupported lookalike, capability interface,
  wrong arity and varargs fail; generic/interface/JDK/CGLIB discovery and advice
  still apply; result String/null/structured conversion is unchanged; callable
  and executor roles remain distinct.
- Fixtures: actual annotated managed beans/proxies and existing setup.
- Mocks: retain only existing isolated framework collaborators; do not mock away
  registration or managed method invocation.
- Surface: Application API and internal execution; intentional parameter break.
  Verify old production class absence rather than adding legacy-class support.

### 3. Captured value behavior

- Type/location: unit API tests and `SupportedSurfaceIntegrationTest`.
- Proves: captured input, skillConfig, executorConfig, skill name and generation
  retain exact values; recursive map/list copies are unmodifiable; nulls and
  precise number leaves survive; Resource/other leaves retain existing identity;
  original mutable maps cannot alter snapshots. Null/blank identity validation
  stays internal to Framework construction.
- Fixtures: nested lists/maps/null, BigDecimal, a Resource handle, capture of real
  executor argument through supported public invoke.
- Mocks: none in public supported integration. Internal factory is acceptable for
  isolated invalid-construction cases, not consumer usage guidance.
- Surface: protected retained Application API behavior.

### 4. Deterministic execution-budget owner cases

- Type/location: unit, `internal/core/MissionLifecycleTest`.
- Proves: unarmed mission has no deadline; armed budget decreases; expiry is exact
  zero; advancing beyond expiry never yields negative; establishing/reading again
  does not renew time; earliest ancestor wins; cancellation grace differs from
  execution time; lifecycle cancellation remains true through cleanup; normal
  closure alone does not fabricate cancellation.
- Fixtures: existing injected LongSupplier/AtomicLong clock shared through parent
  and child; different parent/child budgets; explicit advance; values near signed
  and conversion boundaries including large supported durations.
- Mocks: existing minimal mission/session test setup; actual lifecycle owner.
- Surface: internal implementation establishing public observational semantics.
  Do not base expected remaining time on the cleanup deadline or a fresh entry
  timestamp. Avoid wall-clock sleeps for arithmetic.

### 5. Real public lifecycle wiring and decisions/non-AI examples

- Type/location: new `integration/ExecutorInvocationLifecycleIntegrationTest`,
  plus existing `ExecutorApplicationIntegrationTest` and supported-surface suite.
- Proves: real facade supplies live callbacks to the captured mission; reads
  from another controlled thread observe later cancellation/deadline changes;
  values are not captured snapshots or ambient ThreadLocal lookups.
- Cases: direct leaf, standard tool child and explicit-step child after parent
  work consumed part of its original budget. Make parent and child timeout
  configurations distinguishable. Verify child remaining time is bounded by
  parent remainder and decreases across repeated checks rather than resets.
- Cancellation/interruption: block an executor with latches, cancel via the
  existing caller-interruption path, observe changed cancellation and original
  interrupt flag behavior without calling Thread.interrupted(). A cooperative
  test executor checks cancellation/interruption/remaining time before simulated
  work and during a wait; after observation it does not start another operation.
  This proves generic cooperation, not packaged HTTP retry behavior.
- Data fixtures: a decisions-shaped application executor with ordinary question/
  data maps and precise JSON values; reuse the non-AI local HTTP fixture. Do not
  call/import native TypeSafe or implement provider logic in Framework fixtures.
- Mocks: local protocol-compatible planner server where needed; real framework
  dispatch/lifecycle, no replacement lifecycle/internal execution beans.
- Surface: Application API plus protected composition semantics.
- Empty/no-deadline is established by owner unit tests: configured public mission
  timeouts are always positive; do not introduce a no-timeout setting solely for
  testing. The real public test covers configured finite and expired observation.

### 6. Live shutdown and ancestor cancellation

- Type/location: unit/integration, `FrameworkExecutionLifecycleTest` and the new

- Proves: an already-captured invocation sees the later shared shutdown deadline,

- Fixtures: existing framework owner, admitted root, injected clock where supported,
  controlled latches and fake Future cancellation handles.
- Mocks: only existing test-supported time/executor collaborators.
- Surface: internal authority supporting public live observation; preserve all
  existing shutdown timing and first-cause behavior.

### 7. Retained generations, authorization and late physical work
