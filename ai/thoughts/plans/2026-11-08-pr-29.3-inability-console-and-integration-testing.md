# PR 29.3 Planner Inability in Console and MCP Testing Plan

## Change Summary

Verify explicit inability and structured chat evidence through Java emission, Go ingestion and both fact projections, Browser presentation, and MCP query/content tools. Preserve the existing separation of classification, failure origin, and completion. Use deterministic runtime evidence from `afde893`, then rerun the coordinated Framework and Console suites on the completed current checkout.

## Impacted Areas and Risks

- The analyzer can silently accept wrong `kind` types or discard the value from one projection. Exercise both inline and reconstructed payloads, both read projections, and both valid completion states. Cause navigation and ordinary recoverable omission remain covered.
- A selected child can be displayed with the root completion ID, or a nested synthesis can be mislabeled using its nearest ancestor assignment. Assert selected origin, recorded context, and root outcome independently. Java-thrown inability has the same kind and no accepted model diagnostic.
- Old model readers lose nulls, calls, feedback, later generations and whitespace. Exercise complete ordered payloads and interrupted/unavailable content, including current TypeSafe behavior. Treat adapter strings as supplied and avoid inferred associations.
- A truncated signal can be invalid JSON. Check raw text, copied/downloaded values, and continuation through the existing paths. Capture bounds and exact exception text have independent assertions. Use existing invalidity, authorization, and scope coverage.
- The deliberately supported contract is the closed Java API, including the one subtype. Exact compatibility-marker rejection, established configuration and business result serialization stay covered. Current chat diagnostic fixtures move to one canonical shape. No historical compatibility fixtures are required.

## How to Run

### PowerShell toolchain setup on this host

Run in a shell with JDK 21 and Maven available. The observed default Node 24.22.1 differs from the required 24.18.0. The root orchestration lookup found the exact `node-win-x64@24.18.0` tarball in the local npm cache. Provision the pinned executable in a task-specific temp directory. Set this PATH in every verification shell. Use the installed npm 12.0.2 CLI with that pinned executable, since the installed Windows npm launcher otherwise selects its sibling Node.

```powershell
$pr29NpmRoot = (npm.cmd root -g | Select-Object -Last 1).Trim()
$pr29NpmCli = Join-Path $pr29NpmRoot 'npm/bin/npm-cli.js'
if (!(Test-Path -LiteralPath $pr29NpmCli)) { throw 'Cannot locate the installed npm CLI' }
$pr29Node = Join-Path ([System.IO.Path]::GetTempPath()) 'loomspan-pr29.3-node-24.18.0'
New-Item -ItemType Directory -Force -Path $pr29Node | Out-Null
npm.cmd pack 'https://registry.npmjs.org/node-win-x64/-/node-win-x64-24.18.0.tgz' --offline --allow-remote=all --pack-destination $pr29Node
if ($LASTEXITCODE -ne 0) { throw 'Cannot unpack pinned Node from npm cache' }
tar -xf (Join-Path $pr29Node 'node-win-x64-24.18.0.tgz') -C $pr29Node package/bin/node.exe
if ($LASTEXITCODE -ne 0) { throw 'Cannot extract pinned Node' }
$pr29NodeBin = Join-Path $pr29Node 'package/bin'
@"
@echo off
"%~dp0node.exe" "$pr29NpmCli" %*
"@ | Set-Content -LiteralPath (Join-Path $pr29NodeBin 'npm.cmd') -Encoding ascii
$env:PATH = "$pr29NodeBin;$env:PATH"
node --version
npm.cmd --version
```

Planning verified `v24.18.0`, `12.0.2` through PowerShell and `cmd.exe`, and Go 1.26.5 in `loomspan-console`. The extracted executable and launcher are present in the temp location above. Subsequent shells on this host can prepend that `package/bin` directory directly. The exact tarball URL uses the cached archive without a registry metadata fetch. If the cache is unavailable, retry the pinned URL without `--offline` in the same task-local location. The cached Playwright Chromium 1234 and headless shell are available on the observed host. Use `npm.cmd --prefix web exec -- playwright install chromium` from `loomspan-console` if the browser runner reports a missing matching executable.
