### Anthropic static-header credential precedence

Preserve both authored `Authorization` and `X-Api-Key` headers case-insensitively when adapting static API-key authentication. `LoomspanProperties.validateHeaders` permits Anthropic Authorization headers; the matching prior SDK `anthropic-java-core:2.40.1` `StaticAuthHeaders.kt:15-25` returns the request unchanged when either header exists. The selected 3.4.0 implementation also honors either existing header. Therefore inject `x-api-key` only when neither is authored, preserving the previous wire behavior for custom-auth gateways as well as ordinary API-key connections. This is mechanical preservation under Phase 2, without a new auth mode or public configuration.

A local source-launch loopback request with a mixed-case authored Authorization header established that checking only X-Api-Key sends both the configured API key and the authored bearer token. The corrected predicate retains only the authored Authorization header in that case. Probe source and output live under ignored build paths (`target/Review3Auth.java`, `target-pr3011-review3-auth-before.log`, `target-pr3011-review3-auth-after.log`); no retained suite or assertion is changed. Ordinary API-key and explicit X-Api-Key precedence remain required preservation controls.
