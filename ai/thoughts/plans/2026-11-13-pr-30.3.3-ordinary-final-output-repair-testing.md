## Tests to Add/Update

Names below describe required test cases; implementations may group parameterized cases without changing the obligations.

### 1. `eachOrdinaryAdvisorReplaysCompletedWorkWithoutExecutableTools`

- **Type/location:** integration, OrdinaryFinalOutputRepairIntegrationTest.
- **Matrix:** schema, linter, evidence separately x Responses, Anthropic, Gemini. Combined advisors x each adapter in a separate scenario.
- **Fixtures:** real advisors and canonical manager, real ProviderAttempt, adapter-native local HTTP scripts; one canonical sentinel tool, unique result/IDs. Evidence uses a real EvidenceBackedOutputValidator/current mission successfulDirectSkills with an optional unsupported claim so omission can correct it, rather than a synthetic validator.
- **Proves:** original system/user content, completed exchange/result and latest raw candidate reach actual correction serialization; native contract/caps/effort preserved; zero repair tool definitions/functions; callback count remains one. Assert pairing and cardinality structurally, not only substring presence.
- **Mocks:** HTTP provider only; limited collaborator mocks permitted for this wire-focused family, disclosed. Stronger session tests below use real accounting.
- **Surface:** serialized provider behavior/internal implementation; intentional change authorized by ticket.

### 2. `repairToolSelectionsFailBeforeAnyDispatchIncludingDefaults`

- **Type/location:** same integration test; canonical manager focused tests for mixed responses.
- **Matrix:** each advisor x three adapters; model-default callbacks on each adapter, plus combined advisor guard scenario.
- **Fixtures:** initial authorized callback executes, invalid final triggers repair, repair emits that callback again. Include multiple selections/mixed authorized and unauthorized names and planner-control selection in focused manager tests.
- **Proves:** exception through existing failure path, no fallback or extra outgoing request, exactly one total effect (or zero when no initial execution), whole-response prohibition before delegate side effects. Actual repair request omits executable tools despite defaults. Normal authorization remains independently tested outside repair.
- **Mocks:** provider scripts; manager spy/callback counters only where necessary for before-delegate proof.
- **Surface:** internal execution boundary and serialized behavior, authorized repair-policy change.

### 3. `repeatedAndCombinedRepairsReplaceOwnedReplayAndLatestRawCandidate`

- **Type/location:** same integration test plus focused new helper tests in springai.
- **Fixtures:** two actual initial tool rounds with rich assistant parts, three distinct rejected schema candidates, final success; combined linter/schema/evidence phases requiring inner and outer corrections. Test both normal ordering and bound-schema ordering.
- **Proves:** every repair has exactly the two completed exchanges in order, correct ID associations and only the latest rejected raw reply. No duplicate calls/results or stale candidates; schema feedback follows baseline/latest policy, linter/evidence system feedback accumulates as before. User text intentionally resembling feedback/results cannot be removed by inference. Descriptor ownership is request-local, bounds checked; mismatched ownership cannot splice another interaction's history.
- **Mocks:** real integration advisors; helper unit fixtures may directly supply explicit raw Message objects.
- **Surface:** internal execution lifecycle/serialized behavior.

### 4. `repairRetainsProviderRequiredPartsAndMedia`

- **Type/location:** three-adapter repair integration; reuse rich protocol fixtures.
- **Fixtures:** Responses reasoning IDs/encrypted payload and call IDs; Anthropic signed thinking/tool_use/tool_result; Gemini thought signatures and function call/result parts, plus initial user attachment using accepted fixtures. Preserve unchanged canonical names and test normalization already supported by manager.
- **Proves:** native serialized replay retains provider-required metadata and exact call/result associations; raw candidate keeps its native fields; attachment bytes/MIME/reference representation remains present once in baseline media. Assert unchanged message parts/metadata identity in manager/helper unit tests as supporting evidence, never as replacement for wire checks. No native generated attachments or unsupported replay variants are invented.
- **Mocks:** only local provider response scripts.
- **Surface:** serialized protocol fidelity and current-run diagnostic content.

### 5. `outerRepairUsesRawModelContributionWithFixedBindingSnapshot`

- **Type/location:** real advisor integration with OutputBindingComposition under an actual mission; helper support tests in outputschema if needed.
- **Fixtures:** mixed output binding from input, stable captured definition/generation, raw contribution valid for its projection but outer linter/evidence requires repair. Change the external source/captured-candidate opportunity while repair is held with latches.
- **Proves:** outgoing replay is raw provider contribution with native metadata, never composed application output. Final result includes exact fixed bound value/provenance; full assembled schema is validated. Same invocation never recaptures source snapshots and another invocation uses its own values. A model attempt to supply bound fields is still rejected under existing policy.
- **Mocks:** no replacement of composition/source snapshot algorithms; direct prepared definitions avoid blocked catalog only.
- **Surface:** protected configuration semantics/internal lifecycle.

### 6. `sequentialConcurrentAndNestedCallsHaveIndependentRepairState`

- **Type/location:** integration, same or separate `OrdinaryFinalOutputRepairLifecycleTest` in springai using real production session/assembler sources.
- **Fixtures:** reuse same client/interaction sequentially; run two simultaneous calls with barriers and unique IDs/results/input/media; actual nested interaction invoked by an initial tool callback on the same thread while parent continuation awaits. Child may repair independently. Use real ExecutionBindingScope/session testkit and distinct missions/branches as production requires.
- **Proves:** completed work, raw candidates, repair flag and bound snapshots never leak. A parent's entry into repair cannot disable a separate child/next call's normal tools. Child history stays private; parent sees only its direct result. Concurrent correlation uses IDs, not arrival order. No callback or request is duplicated.
- **Mocks:** loopback HTTP scripted dispatcher; no fake shared-state/usage implementation.
- **Surface:** internal lifecycle and protected invocation isolation.

### 7. `repairPreservesUsageBudgetsCancellationAndExhaustion`

- **Type/location:** ModelAttemptCallAdvisorIntegrationTest and/or new lifecycle test, real SessionUsageService and production state/session collaborators through testkit.
- **Fixtures:** ordinary initial tool round plus repairs; nonzero distinct per-response token usage, transport 503 then success; low provider-call quota; cancelled/interrupted call before repair attempt and during retry backoff. Existing session/cancellation controls may be reused where unchanged.
- **Proves:** one request/response/usage account per physical attempt, distinct semantic attempts as existing contract requires, no synthetic attempt for replay, normal transport retry uses same request and independent allowance. Cancellation prevents further dispatch/request; reservations/quota exhaustion remain enforced. Schema/evidence exhaustion throws at existing count; linter exhaustion returns last response and failed outcome. Terminal repair flag remains active throughout repeated repairs even after an inner validator passes.
- **Mocks:** HTTP and permitted clocks, not accounting algorithms. Retain strong capture/count assertions when migrating legacy two-callback linter test to initial tool + direct repaired answer.
- **Surface:** protected budgets/exhaustion and current-run diagnostics.

### 8. `normalToolsPlanningAndStepPoliciesRemainUnchanged`

- **Type/location:** existing canonical/provider/protocol/planning/step suites listed above, migrate only fixture context necessities.
- **Proves:** initial normal tools and argument feedback still work, canonical authorization rejects unbound selections before effects, provider refusal/incompleteness does not enter repair or dispatch, planning correction keeps its policy, step-final CALL_TOOL remains rejected, resource closure controls remain untouched. Existing transport/status and quota tests pass.
- **Surface:** protected documented configuration/runtime behavior; no new ordinary policy is applied to planning/step.

### 9. `explicitReplaySegmentsAndTypedOptionsDoNotMutateBaselines`

- **Type/location:** focused new helper unit tests under springai plus migrated advisor tests.
- **Fixtures:** typed Responses/Anthropic/Gemini options including defaults, tools/names/native declarations as supported, caps/effort/response formats/tool context; immutable message lists with misleading repeated text; explicit owned spans; raw MessageParts and composed differing response.
- **Proves:** copies retain correct concrete type and non-tool fields, input options/messages untouched, terminal flag shared only within call, replay replacement preserves surrounding content. Direct internal fixtures supply holder/raw capture explicitly; absence cannot trigger fallback reconstruction from composed text. Unit tests supplement real serializer evidence.
- **Surface:** internal implementation, atomic fixture migration with no compatibility shim.
