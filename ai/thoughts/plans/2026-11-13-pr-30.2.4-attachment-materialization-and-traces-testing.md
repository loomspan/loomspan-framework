# PR 30.2.4 attachment materialization and traces testing plan

## Change Summary

Cover canonical attachment traversal, declared-leaf Resource validation, MIME syntax/case, bounded size/hash reads, null/name handling, accurate pointers, owning-frame recording, journal/observer propagation and factual generic failures. Full pipeline Steps 2–3 are complete with this plan; no tests were run during planning. This plan accompanies `2026-11-13-pr-30.2.4-attachment-materialization-and-traces.md` in this directory.

## Impacted Areas and Risk Assessment

- Compiler/canonical loading: malformed MIME must fail before runtime while authored annotation text and provider standard keywords remain intact.
- Input adapter/materializer/coordinator: avoid serialization of Resource handles, weakened parent assertions, manufactured null descriptors, lost map keys, ambiguous pointers and association/order changes.
- Reads: avoid contentLength consuming an unbounded stream; detect opening and mid-read failures with cause, retain repeatability and signatures, close all streams.
- Engines/recorder: exact mission frame ownership under nested/model frames, once-only timing before planning/no-model completion, and retained evidence on later failure.
- Journal/observer: isolate frame IDs even for same-route interleaved missions; preserve existing journal exception without mutating canonical payloads; list and streamed parity with no cross-projection state.
- Protected surfaces: unchanged closed application API, existing input semantics/access boundaries/max-size setting, faithful current trace/observer details. No supported SPI exists. Removed internal schema models and removed attachment dialect need no compatibility fixture/path.
- No REST/SSE or Go envelope change is planned. Console UI tests belong to PR 30.4.1; no live-provider tests are authorized.

## Existing Test Coverage

Materializer currently covers named reference success, MIME mismatch, invalid signature, already-open resource, missing reference and byte-array size rejection. Coordinator has ordinary null context and one declared attachment case. Standard engine covers media execution, descriptor planning, generic wrapper and cancellation; step engine covers media execution. These helpers still use the removed manifest model. Canonical/compiler tests cover declaration positions, malformed shape, provider stripping and removed dialect; they do not yet prove MIME parser rejection. Journal covers lifecycle and its existing exception, not attachment joins. Mapper tests cover existing journal-to-event mapping.

## Tests to Add/Update

All names below are proposed descriptive test names; implementation may combine related parameterized cases while preserving every assertion. Existing suite locations are under `src/test/java/ai/loomspan/`.

### 1. Declaration, loading and provider-copy controls

- **Type/location:** unit `internal/schema/StandardSchemaCompilerTest.java`, `CanonicalSchemaTest.java`; integration `internal/skill/YamlSkillCatalogTests.java`.
- **Names/proofs:** `rejectsMalformedMimeAmongValidDeclaredTypes` checks missing slash/invalid syntax nonblank entries, indexed path and offending text. `acceptsParsedMimeWithoutRewritingDeclaration` checks valid lower/upper/mixed type/subtype and case-sensitive parameter values remain authored. Catalog error retains skill/source/schema location. Single/nested/items/object-array/map annotations accepted; missing/nonempty/blank metadata, wrong placement/output and removed dialect reject. Retain TypeSafe rejection; where unrelated catalog/TypeSafe consumers block integration, record those exact owners rather than alter scope.
- **Fixtures/mocks:** real compiler/canonical tree, temporary local skill YAML catalog fixtures; no provider mock needed.
- **Surface/compatibility:** manifest supported syntax and provider-copy/current canonical contracts; removed dialect intentionally rejected. Assert private descriptor contracts never appear in `providerTree()` and similarly named data properties remain intact.

### 2. Validation adapter and original value preservation

- **Type/location:** unit/integration `internal/runtime/attachment/DefaultMissionInputMaterializerTest.java`; supporting `internal/runtime/input/SkillInputValidatorTest.java` where admission regressions belong.
- **Names/proofs:** `validatesReferenceAssertionsButNotResourceFilenameAgainstStringConstraints` checks valid/invalid actual `ref://` string min/max/enum/format as applicable and direct Resource with a filename that would fail string assertions still reaches resource checks. `retainsParentAndSiblingAssertionsInDescriptorView` rejects missing required field, invalid ordinary sibling, undeclared closed field, min/max array bounds and invalid parent type with an attachment alongside; no model calls or unnecessary reads on initial invalid structure. `descriptorValidationDoesNotMutateCallerOrProviderSchema` checks original maps/lists/keys, explicit nulls and canonical/provider trees unchanged, resource identity preserved, descriptor-only rendered text and valid private descriptor contract.
- **Fixtures/mocks:** real canonical schemas, validator, materializer; in-memory valid image/PDF bytes and local resolver/VFS. Use a counting Resource/throw-on-read resource to prove admission does not consume invalid input.
- **Surface/compatibility:** manifest behavior and internal adapter; ordinary Java marked Resource/InputStream/byte[] admission/closure controls remain distinct and preserved.

### 3. Traversal, null matrix, exact names and map precedence

- **Type/location:** unit `DefaultMissionInputMaterializerTest`; integration `internal/core/ExecutionCoordinatorTest.java`.
- **Names/proofs:** `materializesNestedTypedMapValuesWithNamedPropertyPrecedence` covers reference and direct repeatable Resource map values, nested typed maps, arrays of attachment strings, arrays of objects and nested arrays; named ordinary property wins over attachment-valued additionalProperties and ordinary siblings validate. Boolean openness/unmarked map values are not treated as attachments. Original key order/structure, resources and descriptor paths associate exactly.
- **Null matrix:** absent optional succeeds with no media/descriptor, absent required fails, required-nullable present null succeeds, required-nullable missing fails, prohibited null fails; repeat at nested property, typed-map value and array-item locations. Run through materialization and `RenderedMissionInput`, then assert immutable outer/nested containers preserve nulls and array positions.
- **`usesJsonPointersForDistinctAttachmentLocations`:** inputs include literal `a.b`, nested `a/b`, literal `files[0]`, array `files/0`, keys containing `/`, `~`, empty name and combinations. Expected examples `/a.b`, `/a/b`, `/files[0]`, `/files/0`, `/a~1b`, `/a~0b`, `/`. Assert both materializer and coordinator `FRAME_OPENED` descriptor trees, original keys and media identities. Do not resolve paths with dot syntax.
- **Coordinator assertions:** permitted null stays null in recorded mission input; unnamed direct repeatable Resource records source `resource`/name null and progresses; reference remains exact. No invented source for invalid value and no resource bytes/Resource serialization in declared attachment records.
- **Fixtures/mocks:** real coordinator/session/binding test patterns; fake executor/model captures progression without external I/O; real materializer for the null/resource integration cases, not a stub that manufactures expected descriptors.
- **Surface/compatibility:** author-facing inputs and current-run trace coherence; JSON Pointer spelling is the accepted intentional change.

### 4. MIME/signature/readability/repeatability and bounded size

- **Type/location:** unit `DefaultMissionInputMaterializerTest`.
- **`matchesEquivalentParsedMimeAcrossFilenameAndFallback`:** identical valid JPEG bytes with lower/upper/mixed allowed type/subtype; named `.jpg` and missing/unknown name single-MIME fallback; genuine MIME mismatch and invalid JPEG signature reject. Preserve parameter value case rather than globally lowercasing declarations. No wildcard/provider policy tests are added.
- **`supportsUnnamedRepeatableResource`:** valid JPEG, no filename, single allowed MIME; descriptor retains null name, media identity and actual size/hash. Named control retained.
- **`rejectsUnreadablePdfWithPathAndOriginalCause`:** opening and mid-read IOException variants using non-image named PDF so digest is reached, exact path/cause and closed stream assertions; readable unknown-length PDF control gets correct size/hash. Reference and direct paths both exercise checks.
- **`boundsReadsWithoutCallingContentLength`:** repeatable AbstractResource inheriting stream-reading contentLength; large body with 16-byte configured limit; unknown-length override too. Assert contentLength is not invoked, digest stream consumes at most limit+1 bytes, closes and rejects. Use PDF/file media to exclude signature pre-read; image variant can account separately for its existing maximum 16-byte header read.
- **`reportsActualSizeAndDigestAtAndBelowLimit`:** 0/at/below-limit fixtures with known SHA-256, inaccurate/reported-unknown lengths ignored in favor of actual stream bytes; captured limit behavior and no new aggregate/count limit.
- **Preservation controls:** already-open InputStreamResource fails repeatability; missing ref and non-Resource resolution fail with field location/cause; invalid signature, true MIME mismatch and oversized inputs reject. All resource failures prevent subsequent planning/model work in engine integration tests.
- **Fixtures/mocks:** custom repeatable counting/throwing resources with close counters; local resolver, exact known byte arrays. Never use hosted URLs.
- **Surface/compatibility:** configuration/resource behavior and diagnostics; original causes retained, byte limit unchanged.

### 5. Standard and step engine descriptor ownership/timing

- **Type/location:** integration `internal/skill/MissionExecutionEngineTest.java` and `internal/runtime/step/StepLoopMissionExecutionEngineTest.java`; recorder/state-focused tests under their existing core/runtime paths if useful.
- **`recordsAttachmentsOnceBeforePlanningOnOwningMissionFrame`:** both engines, valid reference/direct inputs and multiple nested attachments; capture actual canonical metadata records, count exactly one, correct root/child mission frame ID/route/type, ordering before planning/model. Include interleaved/nested same-skill missions or a recorder test with current model/plan frame to prove ownership is captured mission ID rather than leaf frame. Use real recorder/state binding for ownership assertions, not only Mockito call counts.
- **`recordsAttachmentsBeforeNoModelCompletion`:** local output-binding-only completion where supported; standard/step routes that complete without a model still record. If broader composition/step schema blocks compilation/execution, retain the actual test and record exact PR 30.2.5/30.3.2 blocker; do not fake the production branch or claim it passed.
- **`retainsAttachmentsWhenPlanningOrExecutionFails`:** successful materialization followed by planning/model failure yields same metadata then failed close. Assert original refs, pointer/name/contentType/mediaType/size/hash/metadata and association order, no Resource/file-byte payloads. Failed materialization (unreadable/oversized and validation cases) yields no metadata and zero planner/model invocations. No attachment input yields no successful attachment collection.
- **`planningUsesDescriptorsWhileExecutionUsesOriginalMedia`:** preserve existing behavior, including multiple associations/order; Resource identity reaches execution request, never planner text/schema. Trace input/descriptors avoid file bytes without content classification.
- **`genericAttachmentFailureRetainsContextAndCauseWithoutIncompatibilityAdvice`:** `IllegalStateException("boom")` wrapper retains factual skill/model/connection/driver/media and original cause; absent unconditional support advice; retain cancellation and designated-failure controls unchanged.
- **Fixtures/mocks:** deterministic model/planner/work-executor fakes and existing session/captured-binding scaffolding; no provider calls. Migrate only attachment-owned schema helpers to canonical annotations, preserving unrelated assertions.
- **Surface/compatibility:** internal lifecycle and current serialized diagnostics; unchanged public signatures and cancellation behavior.

### 6. Journal and observer projection fidelity

- **Type/location:** unit/integration `internal/runtime/trace/ExecutionJournalProjectorTest.java`, `internal/skillapi/SkillExecutionViewMapperTest.java`, and existing SkillTemplate observer tests where buildable.
- **`projectsAttachmentMetadataIntoFinishedFrameForListAndStream`:** construct real FRAME_OPENED → metadata → model/plan → FRAME_CLOSED traces, verify `SKILL_FINISHED.details.attachments` equality in list and actual streamed handle projections. Include failed/aborted close after successful materialization; no metadata/no collection control and failed-materialization trace.
- **`isolatesInterleavedSameRouteMissionAttachments`:** separate frame IDs, nested/interleaved records and different descriptor lists. Verify no child/parent or same-route contamination and separate repeated/concurrent calls to projector do not share state.
- **`observerRetainsAttachmentDetailsUnderExistingJournalException`:** canonical descriptor metadata includes an existing exception-triggering field name and a normal field. Canonical record stays exact; derived journal and mapped observer apply only current exception rules recursively. Do not add heuristics or change rules. JSON Pointer values and missing optional fields/names survive. Public invoke result remains original.
- **Fixtures/mocks:** actual trace records/handle, projector and mapper; real observer callback path when buildable. A standalone mapper test alone does not certify full public invocation.
- **Surface/compatibility:** journal/observer API details and current diagnostics; documented narrow exception preserved.
