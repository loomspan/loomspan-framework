## Implemented behavior

- Closed supported API now requires namespace, complete supplied declarations and ExecutionConfiguration. NamespaceVisibility is the sole deliberately added type; default visibility is Private on every replacement. Exact expected-ID removal is supported. Incomplete/file-only/inheriting overloads and unconditional internal activation were removed, without shims.
- One monitored namespace map owns coherent preparation capture, target-only base/absence publication, removal, lease acquisition and retirement selection. Parser/schema/client work and resource close/callback delivery stay outside registry/lifecycle locks. The reloader has no whole-preparation/publication lock; each private candidate has one-shot state and ownership transfer.
- SkillDependencyValidator reuses the former contract/binding/forwarding checks. Its sole overlay rule always selects candidate declarations when a path returns to the target namespace. It validates all candidate roots and reachable outgoing external edges, including visibility before revisiting a node, without scanning incoming/unreachable callers. Forwarding recursion still rejects schema cycles.
- Each candidate has fresh parsed properties/catalog/diagnostics/definitions/contracts/credentials/runtime. Publication compares no external revisions and never refreshes the captured target base. Null internal base means strict absence, including absence-again semantics.
- Explicit one-time startup is independent of registry emptiness. Private default contains configured declarations and assigned Java; other assigned Java namespaces contain only their fixed methods and have separate runtimes using the same startup settings. Root capture selects the requested namespace. Removal never recreates it, destroys no host beans, and retains existing physical-work ownership.
- README and routed Java/authoring guidance document complete inputs, reset semantics, visibility, concurrent preparation, startup, staged cycles, removal and callback limits. Documentation drift from obsolete incomplete/inheriting APIs was replaced. Package/project documentation versions match beta.9-SNAPSHOT.

## Material implementation details and audit

Metadata-only preparation reads namespace/visibility, immutable definitions and constraints,
input/tool schemas, kinds and source metadata. It never reads clients, runtime settings,
provider registries, REST invokers or application Java implementations from dependencies.
Generation.close only closes its runtime and does not mutate these metadata objects.
Therefore current validation needs no temporary executable leases. Captured metadata tests
retire dependency resources before using their metadata, and the candidate retains no
executable dependency ownership during its own construction or wait for publication.
If later policy reuse adds executable reads, those reads require existing temporary leases.

Fixed discovery publishes its Java list only after the REST-name list is complete;
only this narrow initialization and fixed REST handler construction synchronize on the
manager. Concurrent REST candidate tests establish one completed handler instance and no
handler/application implementation calls during preparation.

The actual built-in max-depth is 32; tests use startup 91/candidate 100/replacement omission
32 to establish default reset. The ticket's 100-to-64 illustration describes the rule,
not a change to the existing depth default. Quota defaults remain unchanged.

Configuration/credential failures retain their original cause and field-path diagnostic
in the reloader wrapper. No content classification, masking, redaction or sanitization
was introduced. Existing derived execution-journal behavior is untouched.

## Broad-suite blockers and attribution

The full suite is not a pristine-baseline comparison. No clean-checkout full-suite rerun
was performed, so a blanket claim that every failure predates this ticket is unsupported.
Concrete source attribution is available: SkillIdentity, CapabilityMetadata identity
construction, and existing catalog reference parsing are unchanged by this diff; many
failures construct unqualified/dotted identities before the changed publication path.
Examples include CapabilityExecutionRouterTest (`childLlmSkill`), ExecutionCoordinatorTest
(`allowedVisibleSkill`), TypeSafeSkillIntegrationTest (`judgment`), DefaultSkillTemplateTest
(`invoiceParser`), and ConsoleTraceFixtureCorpusTest (`root.skill`). Such fixtures cannot
pass the unchanged PR 27.1 parser and need the sequenced consumer/fixture migration.
Binding/planning startup failures similarly still author unqualified child references,
for example `consumer`; they reject in unchanged YAML parsing before publication.

Observation-side examples: TypeSafeRegisteredInspectionIntegrationTest expects `judgment`
where canonical metadata returns `default-judgment`; ExecutionTraceContractTest expects
`rootVisibleSkill#planning` where records contain `default-rootVisibleSkill#planning`;
ObservabilityRestIntegrationTest expects an old catalog fallback HTTP 200 but gets 404.
These belong to PR 27.5 consumer/observation closure, not a reason to add fallback aliases.
PR 27.3 owns reachable admission snapshot retention, and PR 27.4 owns cross-namespace
settings/dispatch/captured REST identity; those systems were not implemented or certified
here. The ticket expressly permits named downstream slice blockers without bridges.

Ticket-relevant old API/catalog shape assertions and PublicSkillReloadIntegrationTest
inheritance expectations found in the broad run were corrected and are included in the
final required selection. Java security, authentication propagation and generation
ownership are verified independently by that selection. A fresh reviewer must assess
whether the targeted evidence is sufficient under the ticket's slice allowance.
