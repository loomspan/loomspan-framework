## Implementation Approach

Extend the existing standalone example rather than add another consumer module.
Keep ordinary tests entirely on the public application API and installed JAR. Use
explicit, test-only invocation probes for conditions that cannot be placed reliably
at the HTTP server (before-send cancellation, diagnostic target faults and late
physical Java return). A probe is an application-owned annotated executor that
receives the real Framework-created v1 invocation and delegates to the discovered
pack executor's annotated method. Find the existing bean/method through the public
`SkillExecutor` annotation and ordinary Spring/Java reflection, unwrap reflection
exceptions, and retain the actual packaged executor and transport. No private
Framework types, internal bean replacement, production hooks or new API.

For diagnostic faults only, a test Mockito invocation delegate may forward every
live/config accessor to the real invocation while making `diagnostics()` or its
record methods fail. Clearly label this test instrumentation, not application
guidance. It proves pack containment through an actual SkillTemplate invocation;
existing Framework recorder fault tests separately prove capture/append/notice/
fallback containment. Do not count synthetic lifecycle overrides as proof of actual
Framework lifecycle. Ordinary uninstrumented leaf tests remain the primary path.

## Phase 2: Qualify lifecycle, resources, accounting and diagnostic faults

Add focused consumer classes such as `LifecycleConsumerTest.java`,
`AccountingConsumerTest.java`, `DiagnosticFaultConsumerTest.java` and test probe
support in the same example. Naming may follow implementation's natural grouping.

Lifecycle and resource checks:

- Use real Framework cancellation before first send via the probe's pre-delegate
  gate: interrupt the caller, observe live cancellation on the retained invocation,
  release the gate, and assert zero provider sends. Independently enter with the
  executing worker interrupted, recording that pack handling preserves interruption.
- Interrupt/cancel during a deterministic Retry-After wait after the first 503;
  prove no second send and preserved interrupt. Also exhaust remaining time during
  that wait. Use diagnostic retry-scheduled signals or a probe/observer latch rather
  than racing a fixed backoff.
- Delay parent planning, then send through the actual pack under the original
  execution budget. Stream a progressing body shorter than inactivity intervals but
  longer than remaining time; execution must stop before full body delivery and
  retries must not restart the budget. Distinguish mission execution time from a
  larger cleanup grace. Existing generic tests retain no-deadline/zero-expiry checks;
  add actual retained invocation zero-expiry assertion to consumer probe.
- For late physical Java return, let the real pack complete then hold its result in
  the test application probe while ignoring cancellation until explicit release.
  Register `onGenerationRetired` before publication, supersede the generation, let
  logical timeout settle, and assert failed terminal outcome, fenced late result/
  diagnostics and no retirement before physical release. After release, await
  retirement once. Do not equate a remote stub still running with local retained
  physical executor work; document this instrumentation boundary.
- Hold active real HTTP work, close application context, and assert callers settle,
  no retry sends occur after shutdown and pack-owned deadline threads terminate.
  Prove transport survives ordinary publication/retirement and is closed at application
  shutdown. Use bounded worker/thread completion, no untracked background I/O.

Accounting checks:

- Use the existing planner MockWebServer with a real standard parent that calls the
  packaged leaf then returns a final model response. Set native provider-attempt
  quota to exactly two while the leaf makes a retry plus success; mission succeeds
  with two native model calls and two pack HTTP sends.
- Read canonical usage records (and matching Console projection in Phase 3), not
  internal sessions. Native model usage supplies known totals; large/unfamiliar
  provider usage remains in complete result/diagnostic data without changing totals.
- Cover native missing reported usage through its existing heuristic accounting,
  pack missing usage remaining absent, executor-only zero Framework totals, and
  successful HTTP followed by malformed JSON failing once without fabricated usage.

Diagnostic checks:

- Probe-forward actual invocation with diagnostic-target access and INFO/WARN/ERROR
  recording faults; real pack success/retry result and original nonretryable HTTP
  failure survive. Ensure fault path was reached, not merely configured.
- Keep business request/result serialization and caller argument evaluation outside
  the guarantee. Existing automatic boundary semantics remain untouched.
- Use real bounded capture with large evidence to prove full business result and
  explicit unavailable/truncated capture notice; include authored severity checks
  without fabricating execution failures or usage.

Automated success criteria:

- [x] All advanced cases pass using the real installed pack and local fixtures.
- [x] Assertions establish no-send/cardinality, actual live budgets, late fencing,
  physical retention and shutdown rather than only elapsed time or absence of exceptions.
- [x] Accounting derives only from Framework model calls; missing provider usage is
