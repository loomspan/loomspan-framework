## Desired End State

Ordinary explicit inputs receive a recursive Java-value compatibility check before
tree conversion and standard validation without coercion or mutation. Every map
key remains a string; unconstrained/open leaves permit JSON values including null,
not arbitrary Java values. Marked Java leaves preserve direct Resource/InputStream/
byte[] support through separate checks and a private structural validation view.
Actual strings and actual nulls receive canonical assertions before any leaf is
weakened. Callback ingress accepts exactly one object and preserves decimal values.
Original input values, diagnostic evidence and provider schemas never contain the
private validation representation.

## Implementation Approach and settled decisions

Use canonical trees and the existing `StandardSchemaCompiler`; avoid a second
structural validator. A narrow pre-tree walk checks Java JSON compatibility and
runtime-leaf exceptions only. NetworkNT owns types, requiredness, openness, enum,
formats and bounds. A schema-guided walker is necessary to distinguish marked
leaves; it must still inspect undeclared/open values recursively.

For leaf assertions, wrap a canonical leaf as a property of a private object
schema and validate a corresponding object instance through the existing compiler.
This reuses object-root compilation without introducing general fragment APIs or
loosening the public declaration profile. Build private schema copies only when
adaptation is needed. Ordinary JSON-only validation uses the canonical validator.
Private schema/instance objects never leave the validation method/helper.

Preserve the separate generic-contract behavior: existing generic recursive
reference resolution and runtime-value permissions remain distinct from explicit
ordinary schemas. Reject non-string map keys before copying/conversion there too;
do not infer that an explicit unconstrained leaf grants generic resolution.

## Phase 1: Canonical input contract resolution and reference traversal

### Changes Required

- Replace `SkillInputContractResolver`'s old manifest parser, node model conversion,
  proof classifier and custom serializer with canonical contracts. YAML uses the
  already compiled `definition.inputSchema()` directly. Java/tool-schema ingress
  uses the shared schema codec/compiler with appropriate GENERATED input origin.
  Keep blank-schema/genuine generic-tool classification explicit; a supplied root

- `toJsonSchema` serializes the canonical provider copy, retaining exact standard
  keywords/descriptions and removing recognized annotations only at schema nodes.
  Internal resolution retains canonical metadata. Do not use the application
  conversion mapper to manufacture or normalize schema values.

  properties, schema-valued additional properties and array items. Resolve only
  true runtime markers and attachment annotations for explicit contracts. Empty
  and description-only leaves, unmarked strings and boolean-open extras stay
  literal, including nested `ref://` values. Generic resolution remains recursive.
  Preserve direct runtime handles and existing VFS authorization behavior.
- Remove obsolete owned methods rather than retaining old-node return paths.
  `SkillInputSchemaNode` itself still has downstream consumers; do not expand this
  ticket into their migration or add new usages.

## Phase 2: Ordinary JSON checks and private runtime adaptation

### Changes Required

- Replace `SkillInputValidator`'s type/coercion/date validation with the compatibility
  walk plus NetworkNT. Preserve `SkillInputValidationResult` and caller failure
  routing; `normalizedInput` now means a detached container snapshot with unchanged
  values. Preserve marked Resource/InputStream/byte[] identity, including byte[];
  do not change `DeepInputValues`'s unrelated binding snapshot policy globally.
- Before mapper/tree conversion, recursively reject non-string keys (including
  numeric 1 alongside string "1"), non-finite Float/Double, unsupported Number
  kinds/Java objects, byte arrays, resources and streams outside marked exceptions.
  Accept JSON string/boolean/null, supported finite numbers, string-keyed maps and
  lists. Report useful original paths and rejected values without reading streams,
  resources or serializing object internals. Check all open branches: true,
  omitted, and schema-valued `{}`; generated/authored contracts behave equivalently.
- At every non-attachment true runtime marker, accept direct Resource/InputStream/
  byte[] using the existing gate. Actual JSON values (including null) must satisfy
  the complete canonical leaf. Inspect every occurrence before changing a shared
  items/additional-properties schema. No earlier accepted runtime item permits a
  later invalid string/null/ordinary value.
- After successful leaf checks, substitute null only for accepted direct handles
  in a private instance and `{}` for corresponding marked leaf schemas in a private
  schema. Preserve property names, positions, absence and all parent constraints.
  NetworkNT validates ordinary siblings, closure, required fields and array bounds.
  Return original handles and values to downstream binding, never the private view.
- Preserve the existing attachment first-pass allowance separately: strict
  `ref://` strings and direct Resource at attachment-annotated string leaves.
  Apply actual JSON/null canonical assertions and parent constraints; do not open
  resources, validate MIME, create descriptors or admit InputStream/byte[] through
  the attachment exception. A narrowly checked private structural placeholder may
  preserve this Resource allowance, but it is not the Java marker gate and performs
  no materialization. Full attachment validation remains owned by 30.2.4.
- Translate standard errors to existing issues using original instance locations
  and original rejected values. Do not include private wrapped paths, placeholder
  values or weakened schema text in messages/evidence. Operational evaluation
  failures propagate rather than becoming ordinary invalid-input verdicts.

copies/leaf validators; reuse prepared leaf/structural validators where practical
without global unbounded caches or shared mutable per-call state. No network work
belongs in validation. All schema/input working copies are invocation-private.
