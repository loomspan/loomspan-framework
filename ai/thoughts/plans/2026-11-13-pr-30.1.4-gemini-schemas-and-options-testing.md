# PR 30.1.4 Gemini schemas and native options testing plan

## Change summary

Verify exact selected-model native Gemini levels and unchanged total output caps,
retain older-model numeric behavior, and add faithful actual-request schema checks.
RC2's lossy schema conversion is a concrete dependency blocker; the plan requires
complete opt-in correctness assertions and truthful failing/blocked results under
the developer's explicit November 13, 2026 B04 deferral recorded in the governing
implementation plan and results. Default iteration success is not blocker closure.

## Impacted areas and risk

- `SpringAiChatOptionsContributor`: native-vs-budget selection, omitted/unsupported
  level, no cap inflation, independent effective targets.
- Official factory/ChatClient request combination: changing request-local schemas,
  default preservation, no schema leakage, absent conflicting numeric budget.
- Tool/output wire fidelity: nullable arrays fail before HTTP; maps, `{}` and
  reserved false property may be narrowed/dropped; test failures must retain the
  canonical contract rather than weaken assertions.
- Configuration/manifest mapping is deliberate; Application API has no delta,
  Supported SPI none. Serialized wire content is protected by ticket requirements.
  Diagnostics retain raw evidence; internal mapping may change atomically.
- Scoped Google default-base-URL hooks must reset in `finally`; fixture calls must
  remain local. No paid network sends, external submissions or suite work.

## Existing coverage

## Tests to add or update

### 1. Selected native contributor mapping

Unit, existing `SpringAiChatOptionsContributorTest`: exact `gemini-3.8-flash`
low/medium/high -> native LOW/MEDIUM/HIGH; includeThoughts true, budget null,
maxOutputTokens unchanged from SDK defaults. Null thinking remains omitted;
unsupported level throws before sends. Legacy `gemini-2.5-pro` low/medium/high
retains 1024/4096/8192 numeric budget with native level absent. Build options in both
orders and assert no state leakage. Surface: Configuration mapping/Internal.

### 2. Native options survive changing per-call schemas

Loopback integration, new `GeminiProtocolIntegrationTest`: build official factory
model and ChatClient with contributor-derived selected defaults. Parameterize caps
1024,4096,2048. Submit schema A then B using currently serializable supported
schemas with different fields/bounds; assert exact per-request chosen schema
where representable, native MEDIUM, absent budget, unchanged cap/temperature/stop
controls. Third unformatted call proves defaults and previous call stay unchanged.
This proves option combination only; keep raw-schema fidelity cases independent.
If RC2 also changes these schema trees, preserve the fidelity failure and keep a
schema-free positive option case so native behavior can still be evaluated.
Surface: Serialized protocol/Internal; no network beyond MockWebServer.

### 3. Nullable output fidelity

Actual factory/ChatClient capture of two request-local object-root output schemas
with nullable type arrays, nested homogeneous arrays/records, scalar enums,
descriptions, required/optional fields, boolean openness and approved bounds.
Compare complete `/generationConfig/responseJsonSchema` JSON trees. Keep output
maps/composition/references excluded. Pre-HTTP failure must record exception and
zero physical requests, never be passed off as faithful request serialization.
Surface: Serialized protocol; required owned acceptance.

### 4. Ordinary-input raw tool fidelity

Actual factory/ChatClient tool capture. Use `FunctionToolCallback` with literal
standard schema to isolate transport from downstream schema generation. Cover
string-, integer- and closed-record-valued maps, nested maps, maps in arrays/records,
nullable fields, unconstrained leaf `{}`, reserved property `false`, descriptions,
requiredness, formats, bounds, root and nested openness. Split reserved-false and
nullable fixtures when necessary to make losses independently visible.
Assert raw `tools[].functionDeclarations[].parametersJsonSchema` equals the full
canonical schema and no narrowed `parameters` substitutes for it. Assert canonical
callback string/tree unchanged, exactly expected local sends, no tool side effects
when response is plain text. Inputs are not reshaped. Surface: Serialized protocol.

### 5. Independent effective model/legacy controls

Create fresh selected and legacy contributor defaults/ChatClients sharing the
official model where feasible. Wire captures must show native/no budget for exact
selected target and numeric budget/no native level for legacy, with unchanged
provided cap. Test order independence. Do not merge selected null budget into a
legacy default builder: RC2 does not clear inherited budget that way. Existing
assembler creates fresh target defaults; end-to-end mission/planner override and
continuation wiring belongs to downstream consumers listed below.

### 6. Preservation checks

Run canonical manager, provider names, connection protocol/factory, assembler and
transport-timeout controls, architecture check, and full local tests as buildable.
Retain existing approved skips accurately. The four Gemini correctness methods
are now explicitly approved default skips and must fail on opt-in until corrected.
Do not remove valid assertions or skip positive option/preservation controls.
