# PR 28.2 executor declarations and configuration implementation plan

## Overview

Implement the structural authoring and configuration portion of configured Java executors. A skill author gets an explicit executor leaf with immutable operation data; an application supplies immutable namespace-indexed executor data through startup YAML or complete published configuration. Framework validates structure and preserves content. It does not execute application validation or interpret executor settings.

Selected execution profile: **full**, approved by the developer with `proceed` after Step 0. The checkout was clean before pipeline artifacts. This plan and its testing plan are the governing handoff for Step 4; no further routine approval is required.

## Current State Analysis

- `YamlSkillCatalog#readManifest` applies raw TypeSafe, REST and concurrency restrictions, then typed binding. `loadDefinition` repeats REST and concurrency applicability checks (`YamlSkillCatalog.java:328,419`).
- `YamlSkillManifest` records presence through setters (`YamlSkillManifest.java:29`). `YamlSkillDefinition` reconstructs form from REST presence and nullable execution settings, repeats concurrency authoring checks, and Jackson-copies the manifest (`YamlSkillDefinition.java:37,236`).
- `ImmutableContainers#copyMap` already preserves nested maps/lists, nulls and scalar leaves without serialization. Use this PR 28.1 owner for executor data.
- `ExecutionConfigurationParser` accepts four Framework sections and binds their flattened scalar settings. `SkillGenerationManager#prepare/validate` already has the normalized publication target in `PreparationView` (`ExecutionConfigurationParser.java:29`, `SkillGenerationManager.java:160`).
- Spring Boot 4.1.0 `OriginTrackedYamlLoader` transforms null/empty containers before flattening. Literal dotted keys and case-sensitive nested data cannot be recovered reliably from normal property names. Pinned `Binder#bindObject` and `MapBinder#bindAggregate` also show that binding a Map property directly is insufficient when descendant properties exist.
- Generation storage, reference existence/visibility, annotation path binding, retained execution and remaining REST API/runtime deletion belong to PR 28.3. This ticket must produce their immutable inputs without a separate resolver or lifecycle.

## Desired End State

One authoring boundary validates declaration form before applicable-field checks and binding. Definitions carry an explicit internal form (`MODEL`, `TYPESAFE`, `EXECUTOR`, or equally clear names), resolved model settings only for model/TypeSafe forms, and executor reference plus immutable skill config for executor leaves. Form is not inferred from a null model configuration.

Startup and publication use one immutable internal namespace-indexed executor-configuration value and one structural validation/copy operation. Published parsing knows the target and rejects foreign namespace entries. Omission yields an empty value in each fresh parse. Domain values never enter Framework scalar flattening, placeholder substitution, credential reference resolution or JSON copy boundaries.

### Key discoveries and implementation choices

1. Keep the current manifest/catalog machinery. A small form enum and an authoring-validation method are sufficient; no generic manifest schema engine or public declaration API is justified.
2. Add an ordered internal `PropertySourceLoader` for YAML through `META-INF/spring.factories`, ahead of Boot's ordinary YAML loader. Delegate ordinary Spring properties and preserve their normal source order, activation metadata and origins. Preserve the raw `loomspan.executor-config` subtree as an opaque property value before Boot flattening loses distinctions; remove that section's flattened descendants from the delegated property source.
3. Use an internal raw carrier plus a configuration-binding converter to turn only the selected active source's raw subtree into the shared immutable representation. A typed opaque property avoids Binder's recursive Map binding and domain placeholder processing; conversion at binding time avoids rejecting inactive profile documents. Neither carrier nor converter is an application extension API. Collapse private/nested implementation details where practical rather than building a general configuration subsystem.
4. Parse raw YAML documents through the shared `YamlValues` ingress, backed by the existing SnakeYAML engine with Core scalar semantics and duplicate detection. Use it for startup, publication and manifest values so null spellings and aliased containers agree. Reject recursive containers before immutable copying. Memoize alias traversal and immutable container copies, and reject logical YAML expansion above 1,000,000 values before Jackson/Boot traversal so small alias graphs cannot cause exponential resource use. Retain raw skill config outside Jackson conversion; the manifest's existing typed schema validation still consumes its other fields. Tests must prove loader discovery, empty/null/sequence document association, multi-document activation, ordinary properties and source ordering. Do not match documents by fragile scalar values or reconstruct raw values from flattened keys.
5. Add the target namespace to internal parser calls rather than infer it from executor keys. Every `prepare` parse, including the credential-resolving second parse, and `validate` uses the same target. Update internal test callers atomically; no compatibility overload is needed.

## What We're NOT Doing

- PR 28.3 generation ownership, reference resolution, path binding, executor-only startup enumeration, executor invocation or REST public API deletion.
- Domain schemas, connection/resource validation, custom validation callbacks, typed application binding, interpolation, credential interpretation, merging of skill and executor config, resource factories or a second configuration registry.
- Planner recovery, Sidecar migration, Console protocol/provenance changes or repository-wide final examples assigned to later tickets.
- A `.properties`/environment syntax that can encode distinctions absent from those formats. This change establishes the accepted YAML contract and does not invent an encoding for nulls, literal dotted keys or empty containers in flat strings.

## Implementation Approach

Reuse the catalog's source diagnostics, existing schema validation, identity syntax, duplicate-detecting YAML decoding and shared container copying. Keep authoring semantics in one catalog-owned form-validation pass. The internal immutable representation contains namespace data and offers exact namespace access without annotation-path traversal. A separate source carrier transports undecoded structural input only until active startup binding; it is not a configuration authority.

## Phase 1: Explicit declarations and one authoring boundary

### Changes Required

- Add `executor` and `config` presence tracking/binding to `YamlSkillManifest`; remove `rest` as a recognized property and `Field.REST`.
- Determine form from authored `executor`/`typesafe` presence; reject conflicting forms without precedence. Executor references must be nonblank textual identities under existing identity syntax; reference existence and visibility remain later work.
- Centralize form-specific presence restrictions in one pass before typed binding/applicable-schema validation. Executor leaves allow identity, description, input schema, RBAC and optional config; reject model/thinking/prompt, TypeSafe, planning/max steps/concurrency, children, linter, output schema/retries/forwarding/bindings even when null/empty. TypeSafe retains its current required model/input and disallowed-field semantics, adding executor/config conflicts. `config` on model or TypeSafe forms always fails.
- Reject present skill config unless map-valued; omission and `{}` produce an empty immutable map. Preserve nested null values and exact keys using `ImmutableContainers`.
- Consolidate concurrency applicability to the same authoring owner. Raw malformed-type checks and typed schema checks remain but do not repeat the form matrix. Binding/copying must not run alternative form validators.
- Pass validated form explicitly into `YamlSkillDefinition`. Constructors protect only representation invariants, such as required model configuration for model/TypeSafe forms and absent model configuration for executor form. Remove REST inference and constructor copies of concurrency/form authoring rules.
- Copy executor-owned config outside Jackson manifest conversion, then restore it with shared copying (or replace the manifest copy with an explicit typed copy). Schema/other typed copying may retain existing conversion where it is unrelated to domain data. Keep authored presence exact and returned manifest copies detached.
- Update internal definition consumers and direct constructors coherently. Delete unreachable REST declaration-specific checks rather than simulate the removed form. Retain only runtime/registration/API machinery reserved for PR 28.3. Do not accidentally route executor leaves through the old REST handler or a model path; actual generation binding remains pending.

## Phase 2: Shared immutable namespace data and publication parsing

### Changes Required

- Add a small immutable internal namespace-indexed executor data value. Validate the section and namespace container structure through one factory; use existing namespace grammar/normalization and reject ambiguous normalized duplicate namespace keys. Preserve data-key spelling and literal dots inside each namespace.
- The section and namespace values are maps; nested values remain arbitrary YAML data, including null/scalars/lists/empty containers. Use shared recursive copying. Do not impose field-name/domain constraints below the ownership boundary.
- Expose this value through startup properties and `ExecutionConfigurationParser.Parsed` without introducing mutable duplicate state. Parsed properties may carry the same immutable value where needed for handoff.
- Extend publication allowlist with `executor-config`; extract it before existing Framework flattening. Validate only the publication target's namespace entries, rejecting foreign entries even if empty. Absence yields a new empty value and never consults startup, previous, Environment or another generation.
- Pass normalized target through all `SkillGenerationManager` parse calls. Preserve existing connection credential logic strictly within connection settings; `api-key-ref` and `${...}` in executor data remain literal content.
- Do not add annotation path parsing, foreign lookup, callback invocation or generation storage in this phase.

### Material implementation choices

- Definitions require an explicit `YamlSkillDefinition.Form`; internal callers were changed atomically. The catalog owns the authored form/presence matrix. Constructors check representation invariants, including model configuration presence and executor-reference presence, and do not repeat authoring rules.

There is no path resolver, domain schema, credential processing, validation callback or configuration lifecycle here.
- The ordered loader is discovered through production `spring.factories`. Its opaque raw transport prevents Binder from flattening or interpolating executor data, and the fixed early converter validates only the selected active source. Non-executor properties delegate to Boot with original origin-bearing values. Raw/delegated document association includes empty mapping documents; active/inactive profiles and imports are exercised through actual `SpringApplication` startup.
- REST declaration DTO/checks and absence-based inference were removed. Unreachable REST declaration branches were deleted from generation assembly, validation and metadata expectations; remaining runtime/API machinery is the PR 28.3 boundary. Executor generation preparation fails explicitly at that boundary rather than invoking REST or model execution.

No compatibility shim, bean override contract or Console protocol change was introduced.
