# Executor integration and consumer guidance testing plan

## Change summary and impacted areas

Add representative local HTTP/SQL-shaped application execution, real default reference-resolution composition, a complete runnable executor consumer example, and final architecture/removal evidence. Existing shared runtime contracts are preserved. Implementation follows `2026-11-01-pr-28.7-executor-integration-and-consumer-guidance.md` under the approved full pipeline.

Primary additions are `src/test/java/ai/loomspan/integration/ExecutorApplicationIntegrationTest.java`, temporary authored YAML fixtures, `docs/quickstart-executors.md` and targeted packaged guidance/index changes. Existing production owners are modified only for concrete in-scope defects found through verification; no new API, SPI, wire contract or resource lifecycle is planned.

## Risk assessment

- Mocking the resolver, raw Config Data path or standard tool manager would hide the integration being proved. Use actual owners and separate local servers for provider simulation and application HTTP.
- Raw Spring flattening must not alter executor-owned nested/null/case/dotted data. Read actual startup YAML through the existing Config Data initializer.
- The session-scoped `ref://` handle must resolve to a real Resource leaf without losing container semantics. Fixture setup may use internal session/VFS APIs, but consumer samples must use only allowlisted Loomspan API.
- A successful parent must not make a failed child a successful binding/result. Existing parameterized direct/standard/step suites cover this and all budgets/deadlines.
- Retaining executor namespaces must not grant unrelated callable authority or bind live replacement configuration. Existing dependency/generation tests cover these boundaries.
- Examples must execute and close application-owned clients/server/resources appropriately; compile-only verification cannot establish runnable guidance.
- No historical compatibility assertions, REST adapters, arbitrary failure-to-feedback conversion, sensitivity classification or masking are introduced. The existing journal exception remains unchanged.

## Tests to add/update

### 1. Local HTTP executor root

- **Type/location:** integration, `ExecutorApplicationIntegrationTest`.
- **Suggested name:** `httpExecutorCallsApplicationThroughStartupConfiguration` (ordinary naming may adapt).
- **Arrange:** temporary application.yml containing `loomspan.executor-config.default.http`, executor leaf YAML with declared business input, actual application executor bean using finite-timeout JDK HttpClient, local MockWebServer application endpoint. Boot Config Data initialization must parse the YAML; scalar property overrides must not substitute for the executor tree.
- **Act/assert:** facade root invocation reaches the local endpoint with expected method/path/body, selected skill/executor settings and caller input; response conversion is exact; public catalog says JAVA and excludes reference-only registration; observer reports terminal success. Invalid required/type input fails before HTTP, proven by request/call count.
- **Mocks:** only external application endpoint. No Framework invoker/resolver mock.
- **Surface/compatibility:** existing Application API and configuration/manifest contracts preserved; current diagnostics coherent.

### 2. Standard child HTTP with real session reference

- **Type/location:** integration, same class.
- **Suggested name:** `standardChildResolvesSessionResourceBeforeHttpExecution`.
- **Arrange:** deterministic model HTTP stub, model-backed standard parent with declared fixture-writer and HTTP children, actual default resolver/VFS. A fixture-only callable method writes known bytes under the current session directory and returns `ref://...`; its internal session access is test harness setup. Next model response selects the HTTP executor with that reference and schema-declared file attachment input.
- **Act/assert:** run through SkillTemplate and real standard tool manager; executor sees Resource (not the raw ref string), sends expected bytes to the local application endpoint, receives exact response and reports executing YAML leaf identity. Provider requests contain successful tool results; public observer includes child activity/completion. Unknown reference/invalid input produces failure and no application HTTP call. Use a distinct session/path and bounded counts/timeouts to prevent hangs or cross-test leakage.
- **Mocks:** provider/application servers only; do not replace manager, RefResolver or VFS.
- **Surface/compatibility:** public invocation and manifest contracts, shared Java execution and current observation semantics. Internal writer does not establish a supported VFS API.

### 3. General SQL-shaped data and invocation-only domain errors

- **Type/location:** integration, same class; reuse startup fixture where useful.
- **Suggested names:** `sqlShapedExecutorOwnsBothConfigurationMaps`, `domainChecksRunOnlyWhenExecutorIsInvoked`.
- **Arrange:** application executor accepts SkillExecutorInvocation; skill and executor maps both contain application domain values such as SQL/database selectors along with nested lists, null, empty containers and exact dotted/case-sensitive keys. Fixture records/returns interpretation without opening a database.
- **Act/assert:** actual invocation preserves exact separate maps, selected generation ID and business input. Deliberately invalid domain data passes Framework structural validation/preparation without executor calls, then fails during invocation with the application exception; it never becomes successful text. Do not assert a Framework SQL schema or configuration precedence.
- **Mocks:** none for executor behavior; no database.
- **Surface/compatibility:** existing uninterpreted configuration contracts preserved; domain errors stay application-owned invocation failures.

### 4. Exact runnable consumer example

- **Type/location:** manual automated-command verification from a uniquely named temporary consumer directory; committed source is the complete Markdown sample.
- **Arrange:** current starter installed locally; extract/copy exact pom, Java source and resource blocks from `docs/quickstart-executors.md`. Use allowed public Loomspan types, JDK HTTP server/client and Spring application beans. Default same-owner namespace requires no publication/provider credentials.
- **Act/assert:** compile and run the app, verify documented HTTP and SQL-shaped outputs and clean process exit. If the HTTP port is configurable, select a free local port through the documented mechanism. Close servers/streams; use bounded startup/run and capture command/exit/output evidence.
- **Mocks:** no Framework mocks; local application HTTP server is real application code.
- **Surface/compatibility:** supported consumer composition; no accidental internal imports or SPI.
- No permanent Markdown-snippet unit test is required. Sample execution is the meaningful verification.
