# Completed Trace File Publication Testing Plan

## Change Summary

The Framework writes `<sessionId>.<traceId>.execution-trace.ndjson.in-progress` until finalization. Retained traces are published with a same-directory atomic rename after the closed terminal append; immediate discard never exposes the completed name. Grace retention and download acquisition own the completed path after publication.

This is pipeline Step 3 under the Full 5-Step Pipeline, continuing directly from the implementation plan in this context. No test code was edited or tests executed during planning. Source inspection establishes the pre-fix behavior; the implementation stage must record the actual red/green run.

Implementation plan: `ai/thoughts/plans/2026-11-22-PR-36.1-publish-completed-trace-files.md`. Requirements/research: matching PR 36.1 ticket and research under `ai/thoughts/tickets/` and `ai/thoughts/research/`.

## Impacted Areas

- `src/main/java/ai/loomspan/internal/runtime/trace/`: handle paths/finalization, publication, immediate/scheduled retention, writer/reader interactions.
- `src/main/java/ai/loomspan/internal/observability/ObservabilityActivationCoordinator.java`: gated retention forwarding and disabled behavior.
- `LoomspanSession` journal projection and finalization error propagation; observation terminal availability, catalog and HTTP artifact delivery.
- Internal test constructors, custom writers/retention fakes and Java-produced Console corpus builders that use explicit output paths.
- Namespace/default-root/permission/configuration regressions and documentation storage claims.

## Risk Assessment

- Premature completed-name appearance, incomplete terminal/chunk bytes or writes after publication.
- Active readers/projector becoming disconnected by stale immutable-path assumptions.
- Expiry or scheduling rejection racing rename, deleting the wrong path, leaking registration/tasks, extending deadlines or incorrectly advertising retained artifacts.
- Repeat finalization appending a second terminal, republishing or hiding an earlier rename failure.
- Fixture helpers bypassing production lifecycle or continuing to read an active destination as completed.
- Downloads succeeding only for hand-built fixture descriptors rather than real renamed runtime artifacts.

Protected compatibility paths are the closed application API, unchanged host/configuration/manifest behavior, exact release marker, current writer/reader/projector and HTTP/Console semantics. There is no supported SPI. Early completed-name visibility and internal single-path retention signatures are intentionally replaced under the ticket; update their tests instead of maintaining both behaviors. Traces remain current-run diagnostics; no historical-schema or legacy-path tests are added. Access-control tests remain, and canonical content fidelity and the existing journal-projection exception remain unchanged.

## Bug Reproduction / Failing Test First

- **Name/type/location:** `activeTraceDoesNotExposeCompletedFilename`, unit test in `src/test/java/ai/loomspan/internal/runtime/trace/ExecutionTraceHandleTest.java`.
- **Arrange:** Real `@TempDir` root, captured `finance` namespace metadata, real handle with ALWAYS, fixed clock and deterministic session ID. Derive the completed name from the known session ID and handle trace ID rather than from a new production accessor.
- **Act:** Construct/initialize and append an ordinary record; leave the trace unfinalized.
- **Assert:** Completed destination absent; handle path equals its `.in-progress` sibling in `finance`; that sibling exists and `readRecords()` returns initialization and appended records. Project with the real `ExecutionJournalProjector` and check expected journal evidence while completed remains absent.
- **Expected pre-fix failure:** The completed file exists immediately after construction (`DefaultExecutionTraceHandle.java:89` and initialization). Run only this new test before editing production, retain the failure receipt, then implement.

## Tests to Add/Update

Paths below use `src/test/java/ai/loomspan/` as prefix unless fully qualified. Each case uses real temporary files unless noted. Use bounded timeouts/latches for concurrency and a controlled scheduler; do not use filesystem polling sleeps to establish ordering.

### 1) `publishesCompleteRetainedTraceOnce`

- **Type/location:** Parameterized unit; `internal/runtime/trace/ExecutionTraceHandleTest.java`.
- **Proves:** ALWAYS success/failure and ONERROR with `markErrored()` publish exactly once. Capture active bytes after each closed append and use a recording observation callback for `TRACE_COMPLETED` to assert active exists and completed is still absent. On the first completed-path read after finalization, all physical lines parse, expected records/chunks and Unicode content are present, exactly one terminal is last, active is absent and descriptor path/size match. The callback provides a deterministic before-publication boundary without new public test hooks.
- **Fixtures/data:** Real writer, ordinary records, a payload exceeding chunk size with Unicode, correct failure identity for failed completion, immutable expected sequence. Assert logical reconstruction as well as raw bytes.
- **Mocks:** Recording observer only; no filesystem mock. Repeat finalization with identical completion and assert identical optional descriptor, bytes and sequence; reject late append.
- **Affected surface/expectation:** Persisted or serialized behavior and Ephemeral diagnostics; new filename signal and current-run fidelity, with intentionally removed early visibility.

### 2) `liveReadsSnapshotsAndJournalFollowPublication`

- **Type/location:** Unit; `internal/runtime/trace/ExecutionTraceHandleTest.java`, plus `internal/core/LoomspanSessionTest.java` where session journal caching is involved.
- **Proves:** Before completion, readRecords/journal use active; after rename, readRecords/snapshot/tracePath use completed. `TRACE_STARTED.metadata.tracePath` remains its original active value; explicit metadata overrides stay exact. Session projects before publication and retains the journal on successful finalization.
- **Fixtures/data:** Real handle with ordinary journal-projectable records; explicit completed-path synthetic constructor; deterministic metadata override used by corpus builders.
- **Mocks:** Existing session collaborators only. Preserve existing journal exception tests without broadening rules.
- **Affected surface/expectation:** Ephemeral diagnostics and Internal implementation; coherent current path versus immutable recorded start path, atomic helper update without compatibility overloads.

### 3) `immediateDiscardNeverPublishesCompletedName`

- **Type/location:** Parameterized unit; handle and `ScheduledCompletionGraceRetentionTest.java`; disabled-observation branch in `internal/observability/ObservabilityActivationCoordinatorTest.java`.
- **Proves:** NEVER, nonerrored ONERROR, zero grace, elapsed grace, closed retention, disabled observability and rejected scheduling delete active without a rename. At decision boundaries assert completed absent; after return both paths absent, optional descriptor empty, no retained state and no AVAILABLE artifact. A scheduled executor rejection is deterministic. Distinguish failed outcome from the handle's existing errored predicate so tests do not silently redefine ONERROR.
- **Fixtures/data:** Active bytes and distinct completed sibling, fixed/mutable terminal time, ZERO/positive grace, already-closed retention.
- **Mocks:** Mockito executor rejecting schedule; recording observer. For direct immediate deletion assert no completed-path creation via a narrow internal publication spy only if such a seam already exists after implementation; do not add a production SPI for tests.
- **Affected surface/expectation:** Configuration and manifest contracts, Ephemeral diagnostics and Internal implementation; preserve discard decisions and remove obsolete completed-name transient exposure.

### 4) `gracePublicationTransfersExactPathOwnership`

- **Type/location:** Unit; `internal/runtime/trace/ScheduledCompletionGraceRetentionTest.java`, integrated with real handle where useful.
- **Proves:** Positive grace publishes completed; expiry stays terminal time plus original grace; returned size was captured before expiry. Acquiring that descriptor before deadline reads exact bytes; at deadline new acquire fails, an existing lease delays completed-path deletion until final release, repeated lease close is harmless and no active file reappears. Closing retention cancels tasks and preserves already published files. Nonexpiring artifact lease behavior remains unchanged.
- **Fixtures/data:** Mutable clock, real files, descriptor trace/session/expiry/size facts.
- **Mocks:** Capture scheduled Runnable and future. Advance clock and invoke task explicitly. Update the existing asynchronous-deletion fake to rename first, delete completed, then return captured size; handle must not call Files.size on an expired artifact.
- **Affected surface/expectation:** Ephemeral diagnostics and Internal implementation; existing deadlines, lease semantics and exact-path cleanup preserved through rename.

### 5) `expiryAndClosureCannotRacePublicationIntoStaleOwnership`

- **Type/location:** Deterministic unit; `internal/runtime/trace/ScheduledCompletionGraceRetentionTest.java`.
- **Proves:** (a) schedule invokes due task before returning: active discarded, completed absent, no state; (b) clock reaches deadline during scheduling without running task: no publication; (c) task begins concurrently with publication: it either wins and deletes active before publication or deletes completed afterward, never a stale active path; (d) close races pending reservation: no new publication once closed wins, while already published close preserves the file; (e) rejected schedule and failed move remove pending ownership and cancel future where one exists.
- **Fixtures/data:** Distinct sibling paths, mutable clock, barriers/latches and bounded futures; assert file existence, retained count, future cancellation, acquisition behavior and original deadlines at each controlled ordering.
- **Mocks:** Controlled executor, including inline execution and thread-coordinated captured task. Never await a blocked task while holding the lock it needs in the test harness. Test outcomes rather than prescribing private field layout.
- **Affected surface/expectation:** Internal implementation and Ephemeral diagnostics; synchronization correctness and preserved retention decisions.

### 6) `interruptionAndRenameFailureNeverAdvertiseArtifact`

- **Type/location:** Unit; handle test for never-finalized interruption and failed move; `internal/core/LoomspanSessionTest.java` or runner test plus observation test for disposition/catalog evidence.
- **Proves:** Leaving a handle unfinalized after real appends leaves only active (deterministic interruption model, no actual process crash required). Force rename IOException with an administrator-owned nonempty directory at completed destination; its marker remains untouched, active terminal bytes remain diagnostic evidence, finalized descriptor is absent and no republish occurs on a repeated call. Repeat rethrows cached failure with one terminal. Session wraps with its existing finalization error, observation reports CORE_FINALIZATION_FAILED and catalog has no AVAILABLE artifact.
- **Fixtures/data:** Temp directory blocker containing marker, ALWAYS and grace-retained paths, real terminal append. Assert no completed *regular file*, distinguishing the deliberate directory blocker.
- **Mocks:** Existing recording observation/catalog collaborators; real move failure. No permissions-based failure assumption, which varies by OS/user privilege. If an internal move seam is introduced, additionally inject AtomicMoveNotSupportedException and prove no copy/non-atomic fallback and the same error path.
- **Affected surface/expectation:** Ephemeral diagnostics and Internal implementation; visible failure, no artifact publication and idempotent terminal state.

### 7) `downloadsRealPublishedTraceByTraceId`

- **Type/location:** Integration; `internal/observability/web/ObservabilityArtifactIntegrationTest.java`.
- **Proves:** Use the enabled runtime's real observation/catalog collaborator and completion retention with a real handle. Before finalization, authenticated GET by trace ID cannot download the active trace. After finalization and normal observation close, GET is 200, bytes equal the renamed completed file, length and required NDJSON/cache/instance/content-disposition headers are correct, terminal is present, active is gone. Include positive-grace NEVER path so retention acquire actually follows the transferred completed path; exercise permanent retention too. Existing unauthorized-read and metadata path-omission tests remain passing. A failed rename has no downloadable catalog entry.
- **Fixtures/data:** Real temp-root handle, valid completion and canonical records; existing local Spring HTTP harness. No hosted model/provider call is needed. Use unique trace IDs per case.
- **Mocks:** No hand-built published fixture descriptor for the new end-to-end assertion; existing fixture-streaming tests remain useful separately.
- **Affected surface/expectation:** Ephemeral diagnostics/current authenticated HTTP consumer; unchanged wire schema, auth and compatibility marker.

### 8) `namespaceFixtureAndApiRegressions`

- **Type/location:** Existing Java unit/integration/corpus tests; existing Go client/acquisition suites.
- **Proves:** Default/configured roots and finance/shared captured ownership, permission preservation and unusable destination failure remain. Synthetic explicit destination consistently derives active and produces finalized corpus at the specified path. Release marker remains unchanged. Current Java corpus and Go consumers agree without any filename fallback. Architecture allowlist/public-signature tests remain clean and no supported API/SPI is introduced.
- **Fixtures/data:** Existing namespace/config fixtures and `loomspan-console-fixtures`; deterministic path metadata overrides. Preserve corpus bytes when only construction paths change; update an affected current fixture atomically only if it actually records the changed default path.
- **Mocks:** Existing conventions; no historical fixtures, supported internal constructor contract or dual old/new path behavior.
- **Affected surface/expectation:** Application API, Configuration and manifest contracts, Ephemeral diagnostic formats, Internal implementation; protected boundaries preserved and obsolete internal assumptions removed.

## How to Run

Use PowerShell from repository root, JDK 21 and the Maven wrapper. Go commands run with `loomspan-console` as working directory and its `go.mod` toolchain (`go1.26.5`). Existing local fixtures are required; no provider credentials or external model requests are needed. Retention tests inject clocks/schedulers rather than wall time.

1. Before production edits: `./mvnw.cmd '-Dtest=ExecutionTraceHandleTest#activeTraceDoesNotExposeCompletedFilename' test` — expect a failing completed-file-absence assertion, and record it.
2. Focused core: `./mvnw.cmd '-Dtest=ExecutionTraceHandleTest,NdjsonTraceRecordWriterTest,ScheduledCompletionGraceRetentionTest,LoomspanSessionTest,LoomspanSessionRunnerTest,ObservabilityActivationCoordinatorTest' test`.
3. Delivery/current consumers: `./mvnw.cmd '-Dtest=ObservabilityArtifactIntegrationTest,DefaultExecutionObservationHandleTest,InMemoryFinalizedTraceCatalogTest,NamespaceObservationIntegrationTest,ConsoleTraceFixtureCorpusTest,ConsoleRestFixtureCorpusTest,ConsoleSseFixtureCorpusTest,ConsoleArtifactFixtureCorpusTest' test`.
4. Required API classification: `./mvnw.cmd '-Dtest=LoomspanPublicSurfaceArchitectureTest' test`.
5. From `loomspan-console`: `go test ./internal/applicationclient ./internal/artifact`.
6. Final Java regression suite: `./mvnw.cmd test`.
7. Patch hygiene: `git diff --check`.

Record exact executed commands and actual outcomes. Do not label a toolchain/dependency failure a passing or failing behavioral test. If environment prevents a required check, report NOT RUN with cause and residual risk, resolve through the pipeline's environment/escalation rules, and do not substitute prose inspection for the completion gate. Broaden testing only for a new failure, changed consumer or implementation scope expansion; Console UI tests are not required for unchanged UI.
