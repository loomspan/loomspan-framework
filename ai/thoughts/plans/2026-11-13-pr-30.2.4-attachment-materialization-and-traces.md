# PR 30.2.4 attachment materialization and traces implementation plan

## Overview

Migrate the Framework attachment consumers to canonical standard schemas and implement the accepted Resource validation, bounded reads, descriptor recording and journal/observer behavior. This is Full 5-Step Pipeline Steps 2–3 following the developer's “proceed” at the profile gate. The checkout initially was clean; the research artifact is existing ticket work. No implementation or tests were executed during planning.

## Current State Analysis

The canonical compiler already admits and retains attachment annotations on INPUT string or nullable-string schema nodes, recursively including typed maps. `CanonicalSchema.tree()` returns a private copy; `providerTree()` strips only the known framework annotations at schema nodes. `SkillInputValidator` already checks actual reference strings against standard leaf assertions, strict reference syntax, JSON admission, requiredness, siblings, openness and array bounds. Its nonconsuming Resource admission is a first pass, not content validation.

Remaining owned consumers still name removed schema models: `DefaultMissionInputMaterializer.materialize:72` calls `fromManifest`; `ExecutionCoordinator.traceSafeNode:431` accepts the old manifest. Materialization lacks typed-map traversal and uses null-rejecting copies. It compares raw MIME strings, pre-reads `Resource.contentLength()`, and swallows digest IO failures. Descriptors reject missing filenames. Both engines materialize before planning but do not emit the existing `FRAME_METADATA_RECORDED` type. The journal currently projects each record independently, omitting attachments from finished events.

### Key discoveries

- `src/main/java/ai/loomspan/internal/runtime/input/SkillInputValidator.java:63`: runtime-handle admission is distinct from attachment content validation; preserve ordinary Java handle behavior.
- `src/main/java/ai/loomspan/internal/schema/StandardSchemaCompiler.java:93`: shared declaration checker is the place to add MIME syntax validation, rather than a second catalog checker.
- `src/main/java/ai/loomspan/internal/util/ImmutableContainers.java:12`: existing immutable deep copies preserve nulls and leaf identity.
- `src/main/java/ai/loomspan/internal/core/DefaultExecutionTraceRecorder.java:73`: captured mission frame ID, route and mission frame type establish the recording owner; current leaf/model frame is insufficient.
- `src/main/java/ai/loomspan/internal/runtime/DefaultMissionExecutionEngine.java:88` and `runtime/step/StepLoopMissionExecutionEngine.java:236`: emit metadata immediately after successful materialization.
- `src/main/java/ai/loomspan/internal/runtime/trace/ExecutionJournalProjector.java:31`: both list and streamed entry points need projection-local frame aggregation.

## Desired End State

Reference strings and repeatable Resources remain valid only at declared attachment leaves. Standard validation continues to preserve all ordinary structure and assertions. Null/missing states remain distinct; permitted nulls produce no media. Resources are resolved/read through existing boundaries, with filename detection or existing single-MIME fallback, parsed MIME comparisons, image signatures, repeatability and the existing byte limit. Descriptors contain accurate JSON Pointers, actual size/hash and original source associations, without Resource serialization or invented names/references.

Successful materialization is followed by descriptor-contract validation in a private JSON view, then exactly one nonempty attachment collection on the owning mission frame before planning/model/no-model work. Failed materialization emits no successful descriptor collection. A later failure retains successful metadata. Finished journal/observer details carry the owning collection under the existing journal exception. Canonical trace values remain faithful.

- Hosted calls, model downloads, external submissions, or implementation of the neighboring live/deployed suite. Those acceptance checks retain their downstream owners.
- Compatibility readers for the removed attachment dialect or internal schema types.

## Implementation Approach

Reuse canonical schema trees and the shared validator instead of rebuilding an internal schema hierarchy. Use a small internal attachment/schema helper only where it removes duplicated node selection, JSON Pointer construction or descriptor schema logic across the two walkers; do not create a new generic path engine. Traverse actual named properties first, otherwise object-valued `additionalProperties`, and homogeneous `items`. Do not inspect arbitrary data names as annotations.

Keep the existing nonconsuming admission pass. Materialization additionally invokes that real admission validator for its declared input before reading Resources so direct engine callers cannot bypass surrounding validation. Resolve/read only admitted attachment leaves. Build a private descriptor tree and a corresponding private schema copy; replace attachment leaves with the descriptor contract and retain parent constraints verbatim. Do not send the private schema or view to providers or return it as rewritten caller input. This is the explicitly agreed attachment adapter, separate from ordinary runtime-ref conversion.

Meaningful alternatives rejected: keeping old schema nodes duplicates the canonical authority; weakening leaves without post-materialization descriptor validation misses the accepted adapter; validating serialized Resources/fake reference strings violates the ticket. No new resource access policy is needed.

## Phase 1: Canonical traversal and attachment validation adapter

### Changes required

1. `internal/schema/StandardSchemaCompiler.java`: extend shared attachment checks to parse every allowed MIME entry using `MimeTypeUtils.parseMimeType`; catch malformed syntax with exact schema entry path and offending authored value. Catalog wrapping already adds source/skill context. Preserve authored entries and all existing shape checks.
2. `internal/runtime/attachment/DefaultMissionInputMaterializer.java`: remove old schema-node/fromManifest use; walk `definition.inputSchema().tree()`. Reuse named-before-additional selection and pointer escaping. Validate input through `SkillInputValidator`/resolved YAML contract before resource reads; preserve factual issue locations and causes.
3. Add a narrow internal attachment validation helper (or private materializer methods) for the descriptor schema/view. Replace only non-null materialized attachment leaves with existing descriptors. Replace only their schema leaves with a standard descriptor object schema, permitting null exactly where the authored leaf permits it. Validate through the shared compiler/validator, without adding general union support.
4. The descriptor schema requires `attachment` boolean true, `fieldPath` string, `name` string-or-null, `contentType`, `mediaType`, `source`; supports optional nonnegative `sizeBytes`, `sha256` string and JSON metadata object. Runtime-produced size/hash are present on success. Keep existing optional descriptor fields supported; no Resource field. Original string assertions/enum/format apply in admission to actual reference text, not descriptor fields or Resource names/bytes. Original null assertions apply before substitution. Parent requiredness, closure, bounds, sibling schemas and positions stay unchanged.
5. `ExecutionCoordinator.traceSafeNode/attachmentPlaceholder`: consume canonical nodes with the same selection/pointers. Null returns null before descriptor construction. Record pre-materialization descriptors only for actual reference/Resource values; invalid values remain original diagnostic values until validation rejects them. Do not claim size/hash before successful reads or invent source replacements. Preserve original keys and immutable containers.
6. `RenderedMissionInput` and `LoomspanAttachment`: use existing null-preserving immutable copies for rendered containers and descriptor maps, retaining absent name as null and preserving leaf/resource identity.

## Phase 2: Resource MIME, bounded read and failure behavior

### Changes required

1. Preserve extension MIME detection and single-allowed fallback. Compare parsed `MimeType` values using parser equality, retaining parameter semantics and authored declaration metadata. For image signatures select normalized parsed type/subtype only; do not lowercase arbitrary parameter values, introduce wildcard matching or infer provider support.
2. Remove the unconditional `contentLength()` call and its helper. One bounded digest pass returns actual count and SHA-256. Bound each stream read by remaining configured limit plus one overflow-detection byte (with overflow-safe arithmetic), capped by the normal buffer size. Reject as soon as count exceeds the captured per-materialization limit. Unknown length is acceptable when actual bounded read succeeds. Preserve the separate existing short image-signature read with closed stream; tests account for it explicitly.
3. Stream-opening and mid-read IOExceptions fail with JSON Pointer and original cause. No null digest fallback. Preserve repeatability check, resource resolution cause, image signatures and stream closure.
4. Remove only generic unsupported-media advice from `DefaultMissionExecutionEngine` wrapper; retain skill/model/connection/driver/media context, original cause and existing cancellation/designated-failure behavior.

### Success criteria

- [x] Counting resources demonstrate no contentLength pre-read and bounded overflow consumption, with exact at/below-limit size/hash.
- [ ] Reference/direct Resource MIME case, invalid signatures, unreadable/open/oversized/missing-reference cases behave consistently and fail before model work.
- [ ] Missing-name repeatable resources succeed without synthetic filenames; generic failure wrapper does not infer incompatibility.

## Performance Considerations

Projection-local state holds only attachment collections until frame close. No global cache, registry or duplicate materialization pass is added. Private schema compilation may initially be per invocation; do not add caching unless measurement or existing patterns justify it.
