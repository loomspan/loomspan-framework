# Catalog execution kind and declaration provenance testing plan

## Change Summary

Replace the current diagnostic `source` discriminator with `kind` and `declaration`, and add executorName for executor-backed YAML. Both Java forms are JAVA; YAML provenance and exact source bytes remain inspectable. Remove current REST skill support and obsolete fixture shapes, update all consumers directly, and preserve supported public APIs and current failure contracts.

Governing implementation plan: `ai/thoughts/plans/2026-11-01-pr-28.6-catalog-provenance-and-console.md`. Pipeline full, developer-approved. This document specifies verification; it does not claim checks already ran.

## Impacted Areas

- Java generation metadata, catalog entries and summaries, HTTP DTOs/mapping/codecs, namespace observation and Java-written HTTP fixture corpus.
- Go observability decoding/value validation, browser pass-through, MCP mapping/text, published JSON Schemas, discovery and skill goldens.
- TypeScript discriminated unions, React catalog/detail rendering, E2E mock response shapes and unchanged diagnostic-content/access behavior.
- Current Framework/Console docs and canonical agent skills, exact release marker checks, public-surface architecture and Java-to-Go trace corpus regression.

## Risk Assessment

| Risk | Required evidence |
| --- | --- |
| Executor still labeled YAML, or Java silently loses its YAML | Compare public and diagnostic catalogs; assert original YAML and all implementation fields together. |
| Reference-only executor becomes callable or same-name roles collide | Generation integration test with same qualified callable/executor identity and an additional executor-only registration; catalog counts/names exclude only registrations without a callable. |
| Foreign metadata introduces live lookup, retention, config or policy copying | Source review plus existing preparation/admission tests; new diagnostics copied only from checked registration strings. Retained catalogs remain immutable across publication/removal. |
| Go service accepts shape while raw decoder rejects it | Valid/invalid matrix through actual JSON Unmarshal and service entrypoints, including present-null/empty forbidden fields. |
| Browser works but MCP schema/text loses fields | Structured/text parity and validation against published schema for every form; discovery golden regeneration. |
| TypeSafe/SkillMethod regress | All four forms tested with their correct locations and nullable/effective outputSchema. |
| REST compatibility branch survives unnoticed | Negative REST-kind tests and scoped source/current fixture inventory. Keep unsupported manifest rest rejection tests and unrelated transport functionality. |
| Content or access boundary changes | Existing security/browser tests plus exact CRLF/comments/opaque-label fidelity; no rewriting of diagnostic strings. |
| PR 28.5 failure representation regresses | Full Java/Go checks and trace corpus parity; no second failure representation or classifier introduced. |

Application API remains supported and unchanged; `LoomspanPublicSurfaceArchitectureTest` is required for production type changes. No Supported SPI is added. Configuration and manifest contracts remain protected. Internal constructors and ephemeral diagnostic shapes change directly as authorized; no old-format expectation remains. Saved complete traces still use exact current marker policy, without historical readers.

## How to Run

Use PowerShell with explicit working directories. Quote Maven `-D` arguments. No secrets or external service credentials are needed for these tests.

Root focused verification after implementation:

```powershell
.\mvnw.cmd test '-Dtest=DefaultRegisteredSkillCatalogTest,DefaultSkillCatalogTest,ExecutorGenerationExecutionTest,ExecutorGenerationExecutionIntegrationTest,ExecutorDependencyResolutionTest,NamespaceObservationIntegrationTest,ObservabilityJsonCodecContractTest,ObservabilityDtoMapperTest,ObservabilityRestIntegrationTest,LoomspanPublicSurfaceArchitectureTest' '-DfailIfNoTests=false'
```

Confirm class names from checkout and do not treat silently skipped names as executed. Regenerate changed HTTP corpus, inspect fixture diff and remove only the stale renamed skill fixture, then verify without regeneration:

```powershell

.\mvnw.cmd test '-Dtest=ConsoleRestFixtureCorpusTest,ConsoleTraceFixtureCorpusTest' '-DfailIfNoTests=false'
```
