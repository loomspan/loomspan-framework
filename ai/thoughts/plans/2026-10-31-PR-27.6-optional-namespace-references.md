## Implementation Approach

Reuse `SkillIdentity` validation and constructor. Add one narrowly documented
internal boundary-resolution helper (for example `SkillIdentity.resolve` with
reference plus owning namespace). A reference containing a hyphen must go
through existing strict `parse`; a hyphen-free reference becomes
`new SkillIdentity(owner, reference)`. Null/blank/invalid component handling,
namespace normalization and combined limits remain authoritative. Do not infer
ownership from targets or catch parse failure and try another interpretation.

Use this helper only in root preparation and authored compilation. Keep strict
`parse` unchanged. Resolve raw validation comparisons against `YamlSkillCatalog`'s
known owner, then canonicalize the typed manifest's structured fields before
strict constraint/definition construction. Do not mutate source bytes, raw tree
diagnostic text or prose. Evidence is compiled separately from its original
string by resolving identifier tokens with owner context. This reuses existing
semantic records and avoids a second manifest model or runtime identity format.

Alternatives rejected: relaxing `parse` loses strict downstream invariants;
dispatch aliases/search violate fixed ownership; global YAML/expression rewriting
loses content/column fidelity. No unrelated dead-code removal was identified as
necessary; small removal of superseded boundary-only branches is in scope.
