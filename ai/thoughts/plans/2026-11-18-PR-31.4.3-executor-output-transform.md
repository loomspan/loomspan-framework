# Executor output transform implementation plan

## Overview

Add optional executor YAML `output_transform` so a skill can publish its own JSON vocabulary from an executor's successful result text. Compile JSLT with the leaf generation and apply it once where `ExecutionCoordinator` receives the ordinary executor String. Direct callers, tools, accepted task bindings and designated-child forwarding will receive that published String through their existing paths.

## Desired End State

An executor leaf accepts either transform independently or both. Model YAML rejects `output_transform` by presence. Declaration errors and compilation errors occur at startup/preparation, and failed preparation preserves active state. Retained admissions hold their original expression.

After successful executor work, an opted-in leaf parses exactly one complete JSON value, evaluates once with that value as `.`, checks that the resulting tree is JSON with finite numbers, and serializes the result as JSON text. All JSON roots are accepted. A missing lookup returns `null`, and a string retains JSON quoting and escaping. Constructed null members and empty containers survive.

Parse/evaluation failures fail the invocation after one executor call. Existing failure handling supplies the terminal failure and observer status. Canonical evidence distinguishes successful executor work from a later transform failure. Omission returns the ordinary executor text exactly, including empty and non-JSON Strings.

## Implementation Approach

Reuse the prepared JSLT engine and existing finite JSON conversion. Rename the internal `ExecutorInputTransform` to `ExecutorTransform`, keeping the existing map-input/object-output operation and adding a String-input/JSON-text-output operation with clear names. Reuse one `TransformDeclaration` record and raw declaration validator parameterized by field name for input and output. This avoids duplicating compiler settings and declaration rules while keeping input and output boundary methods explicit. Update all internal callers and test references atomically.

Strict output admission uses a private transform-local Jackson reader configured with `FAIL_ON_TRAILING_TOKENS`, big integers and big decimals. Reject null Java text and blank text explicitly and reject a missing tree, while accepting a real JSON `null` node. Do not alter shared mapper configuration or the binding decoder. Use existing recursive JSON conversion to reject constructed nonfinite values and serialize through the Framework JSON mapper. JSLT object construction retains the existing `withObjectFilter("true")` setting.

The output definition method returns the original String immediately when no transform is configured. When configured, wrap runtime failures with qualified skill identity and `output_transform failed`, preserving the cause and useful parse/evaluation detail. A parse failure must precede expression evaluation. The coordinator calls this method once after executor completion, within the existing mission worker and captured binding. Executor exceptions bypass it.
