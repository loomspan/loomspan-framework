# Standard planner inability testing plan

## Change summary

Verify one request-bound control for standard execution, one supported failure subtype, faithful model-message capture, and preservation of the existing authority, failure, result, and accounting contracts. Use deterministic evidence from the real tool advisor, runtime and provider adapters, supplemented by focused fixtures where adapters cannot construct the necessary Spring AI data.

## Impacted areas and existing coverage

| Area | Baseline evidence | Gap to close |
| --- | --- | --- |
| Supported Java surface | `LoomspanPublicSurfaceArchitectureTest`, `ApplicationApiValueTest`, `SupportedSurfaceIntegrationTest` | Exactly the documented subtype and its constructor, direct/admitted caller semantics, no internal type leaks |
| Model binding and dispatch | `CanonicalToolCallingManagerTest`, `SpringAiChatClientAssemblerIntegrationTest` | Tool-free standard turns, non-standard exclusion, complete selection validation and terminal rejection |
| Failure and lifecycle | `SkillFailurePolicyTest`, `LoomspanSessionTest`, `MissionLifecycleTest`, `MissionExecutionEngineTest`, `ExplicitJavaFailureHandlingIntegrationTest` | Model-origin first recording and propagation, attachment boundary, ordinary Java behavior, interruption and post-response quota precedence |
| Trace and usage | `ExecutionTraceContractTest`, `ExecutionJournalProjectionContractTest`, `ModelAttemptCallAdvisorIntegrationTest`, `TypeSafeSkillIntegrationTest` | Structured request and all generations, exact feedback and rejected-call evidence, bounded diagnostic with independent full reason, no phantom work |
| Provider adapters | `SpringAiProviderIntegrationTest`, `SpringAiChatClientAssemblerIntegrationTest`, `ConnectionProtocolTest` | Real four-driver control-only request, failure and success, plus supported native and Framework output schema behavior |

The highest-risk failures are executing part of a mixed batch, returning accompanying text as success, letting the child consume its own inability, treating terminal authority/lifecycle failures as recoverable, and first recording against an ancestor frame. Protect ordinary application tool identity, feedback, successful output, provider retries, Java facade and the exact compatibility marker. Intentionally replace the old Framework chat response `content` shape. Reader, Go DTO, and shared Console fixture changes belong to PR 29.3, so they remain outside this plan's local reader acceptance. Keep the existing journal exception and TypeSafe protocol.

## Tests to add or update

### 1. `plannerInabilityUsesTheSupportedRecoverableContract`

- **Type and location** — value and architecture tests in `src/test/java/ai/loomspan/api/ApplicationApiValueTest.java` and `src/test/java/ai/loomspan/architecture/LoomspanPublicSurfaceArchitectureTest.java`.
- **Fixture** — null, empty, whitespace-only, and a valid reason containing leading/trailing whitespace, Unicode, and mixed line endings.
- **Proof** — one public `String` constructor, no extra accessors, recoverable superclass assignability, exact inherited message, and existing rejection behavior for null/blank. Run the closed architecture checks after final production changes. No mocks.
- **Surface** — additive Application API, existing closed-surface protection.

### 2. `validatesBoundControlAcrossEveryGenerationBeforeDispatch`

- **Type and location** — focused parameterized unit cases in `src/test/java/ai/loomspan/internal/springai/CanonicalToolCallingManagerTest.java`.
- **Fixtures** — ordinary callable `loomspan-loomspan_cannot_complete`, case-normalized application selections where previously accepted, an actual control binding, an ordinary callback shaped with the exact control name but without the Framework marker, and assistant generations with controlled calls. Keep existing original-evidence and pre-side-effect assertions. For rejection, spy on the application delegate or callback count.
- **Cases** — null/missing argument, empty or invalid JSON, JSON null, scalar or array, absent/null/non-string/empty/whitespace reason, extra field, duplicate reason key, trailing second JSON value, two controls within or across generations, app/control in both orders and separate generations, and exact name without binding. Reject alias/case variants as unbound. Rejected cases never invoke the delegate, emit accepted-signal facts, or turn text into a result. Standard application-only dispatch and a legitimate application whose namespace/local name resembles the control still execute through the original delegate.
- **Surface** — internal dispatch and current-run diagnostic authority. Request binding is executable authority, including when no application tools are present.

### 3. `rootFailsExactlyAndNestedParentMayContinueWithoutReplay`

- **Type and location** — integration in `src/test/java/ai/loomspan/integration/StandardPlannerInabilityIntegrationTest.java` or the corresponding existing runtime fixture. Reuse `ExplicitJavaFailureHandlingIntegrationTest`'s actual `SkillTemplate`/admission, loopback response and trace helpers. No live credentials.
- **Root fixtures** — a model declaration with exact reason and accompanying text, both direct and admitted invocation; use an observer that throws for one path. Assert the exposed type, recoverable superclass catch, exact message, same primary failure with observer failure suppressed, failed model and mission and completion linkage. Test absence of result acceptance and a single provider turn. Ordinary text describing inability still follows the existing success/validation route.
- **Nested fixture** — parent calls a standard child, child optionally completes an earlier permitted call then declares inability, and parent receives a tool response and returns an ordinary success or invokes a permitted alternative. Assert provider order, no continuation in the declaring child, no automatic replay, preserved earlier completed work, exact association with original parent tool-call ID/name, and exactly the four fields in parsed feedback with the unmodified reason. The parent's system instructions supply continuation and effects guidance. Assert no successful child output or success credit. The successful root completion has no `terminalFailureId` even though the one child failure remains. A separate parent declaration after seeing child feedback has its own ID and no inferred cause link. Use existing step runtime coverage or a nested case for propagation through an explicit-step ancestor to a higher standard caller, with no new immediate-parent cutoff.
- **Accounting** — compare actual provider attempt/model/usage counters, child skill and application-tool invocations, and successful-result count. Valid control adds no tool, skill, or step work. Mixed or malformed dispatch adds no rejected application invocation, while the completed provider response is charged. Parent continuation shares the same counters and deadline. Assert no provider transport-failure or retry fact for dispatch rejections.
- **Surface** — public facade, configuration behavior, and current-run diagnostics. Protected observer and existing caller boundaries remain authoritative.

### 4. `recordsOnlyActualInabilityOriginAndPreservesTerminalGuards`

- **Type and location** — `LoomspanSessionTest`, `MissionLifecycleTest`, `MissionExecutionEngineTest`, `ModelAttemptCallAdvisorIntegrationTest`, and the runtime integration above. Extend existing fixture owners where possible.
- **Proof** — first-record a valid signal against the actual declaring `MODEL_CALL` frame before propagation. Assert one canonical `ERROR_RECORDED`, stable identity across recognized wrappers, `RECOVERABLE`, exact `exceptionMessage`, `kind` and stack-then-signal order. Check diagnostic content type and UTF-8 budget, absent ID serialized as JSON null, exact supplied name/argument string, and preserved decoded CR/LF. For oversize data, exercise the canonical capture path with a controlled multibyte reason, verify explicit `truncated` and valid UTF-8 at the boundary, and keep the full exception message and captured response arguments. Use a focused binding/session fixture instead of sending a large wire body if it reduces duplication.
- **Origins** — application-created subtype records Java origin with kind but no accepted-signal diagnostic. Test ordinary `RecoverableSkillException` without kind and unchanged feedback. A normal application wrapper around the subtype stays terminal without kind, preserving a link to any separately recorded underlying cause. Rejected/mixed/unbound signals have neither kind nor accepted-signal evidence.
- **Guard fixtures** — configure schema, linter and applicable evidence checking and use input attachments where supported. A valid declaration skips success validation/correction and preserves the exact failure with attachments. Verify the existing true provider/media error retains its contextual advice. Make post-response quota fail for a would-be valid signal and assert response capture but no signal acceptance or refund. Use existing bounded/latch-driven lifecycle fixtures for cutoff or interrupt before acceptance, with no accepted fact and the original primary outcome. Existing real callback authorization, shutdown and cancellation regression cases must still pass. Exercise a deadline/cancellation path with attachment context where it would otherwise change the primary outcome. Never rely on sleep-only races.
- **Surface** — diagnostic identity, runtime lifecycle, and protected authorization/limit behavior.

### 5. `capturesStructuredRequestAndAllReturnedGenerations`

- **Type and location** — `src/test/java/ai/loomspan/internal/runtime/trace/ExecutionTraceContractTest.java` and the existing model advisor/assembler tests. Prefer real recorder serialization with controlled `ChatModel` output and a `MockWebServer` route for genuine multi-generation dispatch if available. Use a narrowly mocked response only for a shape the SDK cannot construct.
- **Fixtures and assertions** — system/user `messageType` and exact text only. Assistant objects with null and empty text and ordered calls, including empty arrays and repeated/empty/null supplied IDs. Tool response messages carry ordered `toolResponses`, including empty array, and map response data exactly. Assert key sets and null versus empty for all fields, plus exact whitespace, CR/LF and quoting after canonical round-trip. On response, keep all assistant outputs in original order, null for missing output, and `generations: []` for missing response or no results. Assert old top-level `content` is absent and selected application result/usage remain unchanged. Keep invalid raw argument strings without trying to parse them in capture.
- **Rejected-turn proof** — send an app call in an early generation and a mixed, unbound or invalid selection in a later generation with no assistant text and no subsequent request. Verify every returned call survives the pre-dispatch canonical response record and no callback is executed. In the nested runtime case, assert the following actual request's tool response `content` equals the Spring AI supplied feedback string after decoding, without duplicating it into the failure record. Verify full ordinary payload capture through existing resource controls, including the current content retrieval path for a large payload when that fixture is already used.
- **Projectors** — migrate the direct legacy chat assertion and update Framework-local fixture shape where appropriate. Verify `ExecutionJournalProjectionContractTest` does not start projecting raw chats and retains the existing observer journal exception. Verify `TypeSafeSkillIntegrationTest` still records its separate evaluation protocol. Console fixture/browser/MCP changes remain in the series consumer work.
- **Surface** — current-run diagnostics and intentionally removed obsolete writer shape.

### 6. `standardControlWorksWithEachRealAdapter`

- **Type and location** — `src/test/java/ai/loomspan/internal/springai/SpringAiChatClientAssemblerIntegrationTest.java` with existing builders/fixtures from `SpringAiProviderIntegrationTest` and `src/test/java/ai/loomspan/internal/autoconfigure/ConnectionProtocolTest.java`. Use real pinned SDK adapters and controlled HTTP responses, extending the existing harness.
- **Every driver** — inspect a control-only request's tool name, description and supported native `reason` fields. Return a valid provider-native control call with an exact decoded reason and assert `PlannerInabilityException`, one attempted request, and diagnostic/trace call fields matching the Spring AI result. On a separate request return ordinary text and assert unchanged success while the control is exposed. OpenAI supplies the argument string and ID. Anthropic reserializes tool input and carries its supplied ID. Gemini reserializes args and supplies an empty ID. Ollama reserializes args and can supply a missing ID. Use the adapter-decoded values for assertions, with no dependency on object wire whitespace.
- **Native shape** — assert closure on the Framework definition and in OpenAI/Ollama serialization where supported by the existing SDK. Anthropic and Gemini retain the required `reason` schema fields supported by their adapters; local validation enforces closure for all drivers. Keep Gemini's loopback base URL override test-local and restore it in cleanup. No adapter changes solely to demand unsupported native schema features.
- **Across the matrix** — prove coexistence and actual ordinary callback invocation, initial planning and `STEP_EXECUTION` exclusions, terminal rejection for a supplied unbound control, Java and configured-executor routing, and configured output-schema success and inability. Use the existing Framework output-schema advisor for its ordinary supported configuration, rather than introduce a provider-native structured-output contract. Use focused matrix cases rather than repeat every runtime scenario on four providers.
- **Surface** — existing external provider protocols, internal request binding and configuration behavior.

## How to run

Use Java 21 and the local Maven command. Under PowerShell quote the complete `-Dtest=...` argument. Mock HTTP tests use loopback, no API credentials or live network. Run focused checks during implementation, then the complete framework suite. Record commands and actual results in the implementation/review handoff. The red method selector follows the chosen method name.

```powershell
mvn -q '-Dtest=SpringAiChatClientAssemblerIntegrationTest#exposesControlForToolFreeStandardExecution' test
mvn -q '-Dtest=ApplicationApiValueTest,LoomspanPublicSurfaceArchitectureTest,SupportedSurfaceIntegrationTest,SkillFailurePolicyTest,LoomspanSessionTest,MissionLifecycleTest' test
mvn -q '-Dtest=CanonicalToolCallingManagerTest,StandardPlannerInabilityIntegrationTest,ExplicitJavaFailureHandlingIntegrationTest,MissionExecutionEngineTest,ModelAttemptCallAdvisorIntegrationTest,NamespaceExecutionAuthorityIntegrationTest' test
mvn -q '-Dtest=SpringAiProviderIntegrationTest,SpringAiChatClientAssemblerIntegrationTest,ConnectionProtocolTest,ExecutionTraceContractTest,ExecutionJournalProjectionContractTest,TypeSafeSkillIntegrationTest' test
mvn --batch-mode --no-transfer-progress test
git diff --check
```

If a full-suite failure is attributable to the split, identify the exact failed check and show the causal mismatch with the owning PR 29.2 or PR 29.3 requirement. Verify all independently runnable local checks. Do not require old and new chat formats in the producer to satisfy a later reader. Independently review exclusions, documentation and single ownership. Integration in PR 29.3 includes the Console browser model view, Go failure analysis and browser/MCP contracts, exact marker rejection, and synchronized fixtures.
