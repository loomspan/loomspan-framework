## Risk Assessment

- A descriptive dynamic schema must not become a provider answer validator or static enum proof; test values that register but fail only at the receiver.
- Planner attempts and native child attempts must share accounting. Inspect counts and sends rather than asserting only the final exception.
- Supplied labels and original YAML must survive generation publication through actual routes; avoid manually constructing the Java DTO as sole producer evidence.
- Trace identity and native payloads must retain captured generation and same-session provenance; reader bounded/absent data must remain truthful.
- Protected surfaces: supported enum/descriptor/invocation/reload, manifest contracts and current-release consumer payloads. Internal classes are not compatibility promises. No obsolete path removal or dual behavior is planned.

## How to Run

Use PowerShell from repository root, quoting Maven property arguments containing punctuation:

```powershell
.\mvnw.cmd test "-Dtest=DefaultSkillCatalogTest,SkillGenerationManagerTest,YamlSkillCatalogTests,TypeSafeDeclarationTests,TypeSafeSkillIntegrationTest,DeclaredOutputBindingsPlanningIntegrationTest,DeclaredChildInputBindingsIntegrationTest,DesignatedChildResultIntegrationTest,*TypeSafeRegisteredInspectionIntegrationTest" "-DfailIfNoTests=false"
.\mvnw.cmd test "-Dtest=LoomspanPublicSurfaceArchitectureTest,SupportedSurfaceIntegrationTest,ConsoleRestFixtureCorpusTest,ConsoleTraceFixtureCorpusTest,ObservabilityRestIntegrationTest" "-DfailIfNoTests=false"
```

Adapt the wildcard only if the added actual inspection test has another name, and list that selected class explicitly in the implementation receipt. Focused suite includes ordinary output/forwarding and Java/REST/chat cases; no full Maven rerun is required after all relevant assertions pass unless failures or new production changes expand scope.

From `loomspan-console`:

```powershell
go test ./...
go run ./internal/buildtool verify
```

Standard verify includes strict toolchain validation, dependency install, TypeScript typecheck, UI coverage and web build. Run once; use selected failing checks during repair rather than repeating the entire suite without changed evidence. If pinned toolchains are absent, locate configured installations first; record any actual environment block and perform available component checks without claiming standard verification passed.

Only if concurrency implementation changes or verification reveals race risk, use the documented Windows race environment and `go test -race ./...` (`C:\msys64\mingw64\bin` on PATH, `CGO_ENABLED=1`). Assurance-only Java tests do not require unrelated Go race testing. Existing fixtures need no regeneration; if an actual in-scope wire/trace correction requires it, regenerate through the repository corpus command and inspect the intentional diff with LF preserved.

No real provider credentials, live accuracy experiment, e2e browser session or deployment is required for these contract assertions.
