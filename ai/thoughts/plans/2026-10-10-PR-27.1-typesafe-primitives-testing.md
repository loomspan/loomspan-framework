# PR 27.1 TypeSafe primitives testing plan

## Change Summary

New native leaf declarations compile scoped templates, validate one immutable resolved request, derive descriptive metadata, call System One on either configured account route, and return all named answers. Existing missions, input/access controls, retries, usage, captured generations, bindings, forwarding, catalogs and trace consumers integrate the leaf. This accompanies the implementation plan in pipeline profile `full`, scopes 27.2 → 27.3 → 27.4 → 27.5; no tests or production code are edited in this planning stage.

## Impacted Areas

- Java strict YAML catalog/manifest/definition copies, native request/schema owner, connection configuration/parser/runtime copies, Apache transport/registry, execution coordinator/generations/router, usage/retries/traces, public kind and catalogs.
- Go observability summaries/details and trace consumers, MCP source/output schemas and descriptions, current Java-produced REST/trace corpora.
- TypeScript contracts, catalog/detail and model-detail JSON/text rendering.
- Root README and routed skill-authoring/new TypeSafe topic, kind-related Java API guidance.

## Risk Assessment

- Premature provider reservation before request rejection, hidden HTTP retries/redirects, false cancellation from future interruption alone, late writes, leaked clients, or uncaptured reload resources.
- Content rewriting or primitive response DTOs dropping answers, accidental output repair/validation, result byte ceilings copied from diagnostics, or fake chat evidence.
- Schema mutation under dynamic concurrent criteria; new schema/binding rules beyond existing authority; account usage recorded twice or as estimates.
- Kind/source enums accepted inconsistently by Java, Go, MCP and TS; current inline/chunked native evidence not readable in model details.
- Protected paths: allowlisted String facade/descriptor API, sole RestSkillHandler SPI, existing chat configurations/semantics, ordinary versus exact inputs, binding/forwarding, exact same-release marker rejection and derived journal exception.
- Intentionally replace mandatory ChatModel native ownership restriction and chat-only native-detail assumptions. No tests must demand both obsolete and current internal signatures, legacy trace decoding, aliases, or shims.
