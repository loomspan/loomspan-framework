## Selected implementation approach

### Dependencies and ownership

Retain independent coordinates `ai.loomspan:loomspan-decisions:0.1.0-SNAPSHOT`.
Import Boot BOM `4.2.0-RC2` directly in the pack POM; do not make the aggregator
a shared release parent. Depend on the locally installed Framework starter
`1.0.0-beta.10-SNAPSHOT`, Boot auto-configuration, Apache HttpClient 5 and Jackson 3
databind explicitly. Boot BOM observations are HttpClient `5.6.5`, Jackson `3.1.8`,
JUnit `6.1.3`; record actual resolved versions during verification. Use JUnit,
AssertJ, Mockito (only final invocation/diagnostic test controls), Boot test support
and MockWebServer `4.12.0` as test dependencies. Pin Surefire `3.5.2` with module
path disabled; name all tests `*Test`, including local HTTP integration tests, so
`verify` always runs them without a separate Failsafe lifecycle.

Implementation lives under `ai.loomspan.decisions.internal.typesafe`; Spring
auto-configuration lives under `ai.loomspan.decisions.autoconfigure`. Register it
using `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.
One unconditional bean owns the client/pool and scheduler and closes them on
context shutdown. No authenticated cache, static singleton, per-publication pool,
generation callback or client default authorization exists.

### Settings and transport entry

Provide an internal reusable transport entry such as
`Object send(byte[] preparedJson, SkillExecutorInvocation invocation)`. It resolves
one immutable settings value from the invocation at entry, defensively copies the
prepared body once, and reuses those bytes for every attempt. Domain construction
and validation remain outside this helper and belong to 31.2.2.

Presence rules are fixed:

| Key | Resolution | Default |
| --- | --- | --- |
| `api_key` | Present skill key, otherwise present executor key | Missing fails |
| `base_url` | Present skill key, otherwise present executor key | `https://api.typesafe.ai` |

Present null/non-string/blank values fail with the selected configuration path;
never fall back from invalid presence. Preserve valid key strings verbatim; do
not trim credentials or interpolate `${...}`/`api-key-ref`. Reject characters
illegal in an HTTP header before any send, with a path-specific error; do not
repair them. Leading/trailing ordinary spaces in otherwise valid keys are retained
in the selected Authorization value rather than trimmed. Wire tests should choose
keys whose distinguishing spaces are inside the header value, because HTTP servers
may normalize trailing optional whitespace independently of credential selection.

Accept absolute HTTP/HTTPS base URIs with a host and optional path prefix, no
userinfo/query/fragment. Reject invalid URI syntax, invalid authority/port, other
schemes and surrounding whitespace rather than modifying configuration. Remove
only trailing slash separators when appending `/v1/systemone`; preserve encoded
path/prefix content. Set `Authorization: Bearer <selected exact key>` and JSON
content type on each fresh request. Endpoint and keys never become client defaults.

### Pool, deadlines, cancellation and shutdown

Use synchronous Apache classic HTTP on the calling invocation thread. This avoids
background I/O whose lifetime can outlive the executor unnoticed. Own one reusable
connection pool (max total 100, per route 20), one client and one scheduled watchdog
executor per transport bean. Pool acquisition limit is 5 seconds, connection limit
10 seconds, inactivity limit 30 seconds, and each physical attempt's total limit
60 seconds. These are fixed pack defaults in this delivery, not new YAML/property
keys. Package-private policy injection may shorten them in deterministic tests;
do not create a supported customization API.

Before every attempt and throughout retry waits, check current thread interruption,
invocation cancellation and live remaining time. Zero prevents send. Empty means
no Framework cap, while pack limits still apply. Preserve interruption both when
observed and when catching InterruptedException; stop retries immediately.

Each attempt starts one monotonic total deadline at the minimum of 60 seconds and
the current remaining execution budget. Pool wait, connect, headers and body reads
are within it. Per-request acquisition/response timeouts are capped to that budget;
never round a positive submillisecond duration to zero/infinite. Use saturating
duration/deadline arithmetic for extreme durations. The connect default is also
bounded by the attempt watchdog.

A pack-owned scheduled watchdog checks the attempt at most every 25 ms and cancels
its Apache request on total expiry, live cancellation, or a newly shortened
remaining execution budget. Schedule the first check no later than the initial
remaining deadline. The timer performs no I/O. Its lifecycle check cannot be blocked
by diagnostic capture or shared transport locks. Cancel/remove its task in finally;
check expiry again before returning the successful decoded result so scheduler
latency cannot turn an expired response into success. Do not reset Framework time
at entry or on retry. Distinguish elapsed pack request timeout (retryable while live
budget permits) from execution cancellation/interruption/exhaustion (never retry).

Closing the transport is idempotent, rejects new sends, closes the pool/client to
release active physical requests, terminates the watchdog and prevents pending
tasks from surviving close. Handle admission/close races and scheduler rejection
without orphaning a request. Remove canceled scheduled tasks rather than retaining
each completed request until its original deadline. Tests prove bounded cleanup.
Remote inference/billing cancellation is never promised. Framework remains owner
of mission timeout/cancellation, parent/shutdown budgets, fencing and retention;
no new Framework scheduler or lifecycle state machine is introduced.

### HTTP outcome, retry and JSON policy

Disable Apache automatic retries and redirects explicitly; no provider SDK is used,
so there is no independent SDK retry layer. Use at most **3 physical sends total**
(initial plus 2 retries). Retry transport IOException/request timeout and HTTP
408/429/500/502/503/504/529. Treat other statuses, all 3xx, local validation,
interruption/cancellation/expired execution and successful-response decoding failure
as terminal. TLS/endpoint/auth validation errors must not be silently repaired.

Backoff before retries is 250 ms then 500 ms. A valid nonnegative `Retry-After`
delta-seconds or RFC-1123 date supplies a delay capped at 5 seconds; invalid values
use ordinary backoff. Cap all waits to live execution budget and poll in slices
of at most 25 ms; after any wait recheck immediately before another physical send.
Use saturating parsing/arithmetic; huge headers cannot create an unbounded wait.
The retry count is per invocation, never a native Framework provider-attempt count.

Classify non-2xx status before reading its body. Capture at most 64 KiB plus a
sentinel, preserve a complete UTF-8 prefix, and expose explicit truncation/read-
unavailability information in pack failure evidence. Cancel the request before
closing truncated/unavailable error entities so Apache does not drain an unbounded
remainder. Malformed/HTML/error-body read faults cannot change status eligibility.
Do not require error JSON or parse it to select retries.

For successful HTTP, read the complete business body without the diagnostic error
ceiling and decode JSON exactly once using pack-owned immutable Jackson tooling.
Enable strict trailing-token failure and retain ordinary JSON structure/unknown
fields, including null, strings, arrays, usage and refusals. Generic Object decoding
can use BigInteger/BigDecimal for numeric fidelity and yields supported JDK maps/
lists for diagnostic use. No response schema, answer completeness, confidence check,
reshaping or answers extraction. Empty/malformed successful JSON fails once, outside
the transport retry branch. Json `null` is valid. 31.2.2 will serialize the whole
value into a representation preserving JSON across Framework's String/null boundary.

### Diagnostics

Report useful request, response, caught failure and retry evidence through the
invocation's existing info/warn/error methods. Request data may contain the prepared
UTF-8 JSON body as a string plus endpoint/attempt; response data may contain the
already decoded native value. Use only ordinary supported map/list/scalar values;
never hand diagnostic capture an Apache/Jackson/provider DTO. Avoid parsing a
second time solely to manufacture diagnostics. Never add native attempts or usage.

Contain ordinary new diagnostic-recording failures, including diagnostic-only
preparation helpers, so results/original failures remain unchanged. Safe wrappers
catch RuntimeException from recording; do not catch JVM Errors or execution work.
Business request/result preparation/serialization remains ordinary execution work;
caller argument evaluation before entry and existing automatic observation retain
their existing contract. Do not broaden Framework recording or add fallback logging
machinery. No content classification, masking or rewriting is permitted; error
capture limits and Framework diagnostic limits are explicit resource bounds.

## Testing strategy and performance

See `2026-11-16-PR-31.2.1-decisions-typesafe-transport-testing.md` for test cases.
Use real local sockets/client/transport; mock only the final invocation and diagnostics
for this helper-test boundary. Do not claim these replace actual annotated executor
consumer proof. Latches and bounded awaits coordinate cancellation and concurrency;
wall-clock assertions use generous upper bounds and demonstrate failure well before
full stub bodies finish. One pool and watchdog serve concurrent invocations without
shared credentials. Success bodies are complete business data; diagnostics stay
bounded independently. No live provider, benchmark, or manual observation is required.
