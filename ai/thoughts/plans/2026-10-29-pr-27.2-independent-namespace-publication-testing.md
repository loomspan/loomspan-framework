# PR 27.2 Independent Namespace Publication Testing Plan

## Change Summary and authority

Test complete namespace-targeted validation/preparation, coherent candidate overlay, target-only atomic publication, deterministic concurrent detached construction, Private startup, fixed Java ownership, expected-ID removal, and existing resource retirement. Governing inputs are the ticket, accepted namespace design, research artifact, and companion implementation plan `2026-10-29-pr-27.2-independent-namespace-publication.md`. This is Step 3 in the same approved full-profile planning context as Step 2. Tests are planned here, not implemented or run.

No test preserves deliberately removed public overloads, global replacement, serialized preparation, inherited configuration, or lazy recreation after removal. No compatibility bridge is required. Protect the sole `RestSkillHandler` SPI, Java binding/serialization/RBAC/security propagation, strict parser's exact supported nested fields, retained physical-work ownership, immutable catalogs and diagnostic fidelity.

## Impacted Areas

- API `SkillReloader`, new allowlisted `NamespaceVisibility`, candidate/catalog/result types and supported-only consumer composition.
- Manager registry/capture/publication/removal/startup and `DefaultSkillReloader` candidate/lifecycle synchronization.
- Factored dependency validator, input/output contracts, forwarding resolution, qualified edge visibility and effective schema storage.
- Fresh catalogs/manifests/properties/credentials, runtime/provider registry construction and one-shot close.
- Explicit early Spring startup wiring and namespace selection for direct Java entry; full reachable execution snapshots remain PR 27.3.
- README and bundled Java API/skill-authoring guidance identified in the implementation plan.

## Risk Assessment

The principal failure modes are stale-base refresh, treating null base as wildcard, inconsistent metadata capture, resolving a return path into old target content, skipping visibility edges because a skill was visited, sharing mutable catalogs/configuration, holding a registry lock during slow work, closing a winning/retained generation from a losing candidate, and reconstructing startup on lookup after removal. Test each positive contract together with its boundary failure.

Application API changes are intentional breaks authorized by the ticket. Configuration/manifest contracts preserve exact parser/schema behavior while eliminating inheritance and adding Public/Private target checks. Runtime publication is not persisted. Diagnostics are current-run values and retain source content fidelity; preserve existing journal-projection exception without extending it. Internal helpers/constructors/mocks are changed directly and do not establish compatibility promises. No planned Java-to-Go/trace-format change or compatibility-marker bump.

## Existing Test Coverage

- `SkillReloaderTest` already covers base/one-shot/foreign/closed/shutdown state, listener isolation, retained resources and publication during blocked preparation. Its `preparationsSerializeWithoutBlockingSnapshots` expressly asserts the behavior being removed and must be replaced.
- `SkillGenerationManagerTest` covers immutable generations, fixed declarations/handler reuse, no validation execution, binding graphs/paths/type compatibility, forwarding chains/cycles, derived schemas, runtime/configuration copies and cleanup.
- `ExecutionConfigurationParserTest` covers exact nested configuration fields/defaults, unsupported/direct credential/duplicate keys, timeout precision/range and both reference resolution paths.
- `NamespaceIdentityFoundationTest` covers canonical target ownership, target-local feedback, empty catalogs, 32/33 and 64/65 boundaries and raw diagnostic fidelity.
- `PublicSkillReloadIntegrationTest`, `SkillGenerationExecutionIntegrationTest`, supported surface and Java security integration tests provide deterministic Spring/MockWebServer execution/retirement evidence. Update their obsolete preparation API/fixtures directly.

## Bug Reproduction / Failing Test First

First demonstrate independent target behavior using real documents/configuration in `SkillReloaderTest` (or a focused new namespace publication test class in the same package). Start the existing default generation, prepare/publish an empty namespace `a`, then publish `b`; assert both `snapshot("a")` and `snapshot("b")` remain available and identify distinct generations. Current public signatures/registry cannot express this; record compilation failure for the new API as the initial red result, then, once API scaffolding compiles, record the behavioral red result before fixing registry semantics when feasible. Do not retain temporary scaffolding in the final API.

The deterministic concurrency red test is also required: gate one candidate in an injected internal runtime factory, wait for entry, start a second complete preparation, and require the second to finish before releasing the first. Current broad preparation serialization fails that bounded requirement. Use same-target and different-target variants. No sleep/thread-state/throughput-based proof.

## Fixtures and concurrency discipline

Use actual `ExecutionConfiguration` YAML, `YamlSkillCatalog`, contracts and definitions for behavioral tests. An empty supplied set can use a minimal valid complete configuration such as `loomspan: {}` when no model is required. Model-backed documents get explicit named model/connection settings; model driver/client fixtures must remain deterministic and send no real requests during preparation. Use existing MockWebServer infrastructure for execution integration.

Use internal runtime factory gates/counters or a focused validator collaborator gate to pause after base/metadata capture and before completion. These are test seams, not new production extension contracts. Every factory call creates a fresh mutable catalog/properties instance; do not return one shared mutable mock. Count runtime/registry closes by candidate ID or unique factory token. Reuse immutable fixed registration metadata only after discovery completes. Use latches/barriers and `Future.get`/`await` with existing five-second bounded waits, with `finally` releasing every gate and closing unpublished updates/managers/executors. A timeout signals a failed assertion, never success.

## Tests to Add/Update

### 1. `completeNamespaceReplacementHasNoInheritance`

- Type/location: manager/reloader unit tests in `src/test/java/ai/loomspan/internal/skill/SkillGenerationManagerTest.java` and `SkillReloaderTest.java`.
- Arrange: explicit startup limit distinct from built-in default; publish Public `a` with supplied skills and nondefault scalar (for example max depth 100 versus built-in 64); publish independent `b`; replace `a` omitting one supplied skill, visibility and scalar.
- Assert: only `a` changes; omitted supplied skill disappears; assigned fixed Java stays; default visibility becomes Private and omitted scalar becomes its built-in value, not startup/previous/b value. Host startup properties and `b` runtime/catalog remain unchanged. Test omission of models/connections required by supplied declarations rejects rather than inheriting. Empty no-Java target yields self-identifying empty catalog. Collision with assigned fixed Java fails.
- Inputs/mocks: real parser/catalog, counted independent runtimes, fixed metadata fake only; no providers invoked.
- Surface/compatibility: Application API and configuration/manifest behavior; intentional complete-input/default evolution.

### 2. `publicationUsesCapturedTargetBaseAndStrictAbsence`

- Type/location: reloader unit tests; parameterize creation/replacement where useful.
- Arrange/Assert: read generation 1, publish generation 2, then prepare generation 3; its publication succeeds replacing 2. Separately gate preparation after capture, replace target, complete preparation, and assert stale rejection without refresh. Candidate ID differs from base and becomes active on success.
- Prepare two same-base candidates and release publication tasks together: exactly one wins, loser throws stale and closes once, winner remains open. Do this for existing target replacement and absent target creation while target stays present. Different target candidates both publish successfully.
- Absence semantics: prepare absent `a`, publish then remove another incarnation, then publish first absence candidate successfully; no tombstone/history precondition. Present-base candidate rejected after removal, including removal/recreation; recreated ID differs from every prior/candidate ID.
- Dependency changes: after candidate preparation, update/delete/change Public-to-Private/recreate a referenced external namespace; target candidate still publishes if its own base matches. Confirm no dependency revalidation/provider invocation occurs during publication. Do not assert later admission succeeds; PR 27.3 owns that check.
- Inputs/mocks: complete configurations/documents, exact expected IDs, counted close owners, barriers.
- Surface/compatibility: Application API and internal concurrency; preserve candidate/opaque-ID semantics, intentional target granularity change.

### 3. `candidateStateAndLifecycleRejectWithoutClosingOtherOwners`

- Type/location: reloader/manager unit tests, existing lifecycle integration where physical ownership is needed.
- Assert foreign/fabricated, closed, twice-published and stale updates reject; cross-framework rejection never closes the foreign object; closing/rejecting an already-published update never closes its active generation. Abandoned candidate closes only itself once.
- Gate runtime construction, close admission, release construction: preparation throws, completed runtime closes once, peers/active/retained generations survive. Gate construction failure after partial client allocation: existing registry cleanup closes only its own partial resources. Close admission after preparation's final check but before publish: publish rejects/disposes of that candidate.
- Keep an existing generation owner/physical-work hold, replace or remove its namespace, verify no close until last physical owner releases. Existing unused generation retirement, callback failure isolation, registration close/no replay and shutdown omission tests remain applicable.
- Block a retirement close or callback and prove snapshot/unrelated publication can progress, demonstrating dispatch outside registry synchronization. Do not add a drainage/cancellation requirement to removal.
- Inputs/mocks: distinct counted runtime/client tokens, lifecycle admission gates, existing OwnerLease/physical-work fixtures.
- Surface/compatibility: Application API lifecycle and internal ownership; preserve established one-shot/physical-work semantics.

### 4. `coherentMetadataAndTargetOverlayValidateEveryOutgoingEdge`

- Type/location: focused internal dependency-validator tests plus `SkillGenerationManagerTest`; use real schemas and parser.
- Direct overlay: replace a local producer's contract, verify candidate binding/forwarded schema uses the new one. Omit a local old producer while another candidate skill still calls it: reject despite old active presence.
- Return path: Public candidate `a` calls Public `b`, whose contract/reference returns to `a`; change/remove the returned-to skill in candidate. Resolve against candidate and reject incompatibility/missing target. Candidate proposed Private rejects the foreign return edge even if old `a` is Public. Keep another unrelated skill in `b` with a broken dependency to prove preparation does not scan unrelated/incoming callers.
- Foreign references: missing namespace, missing skill, Private target including Java, incompatible input binding, invalid output producer/path/type and transitive missing/Private edge all produce errors and reject preparation before client construction. Feedback remains target-local and empty on errors.
- Coherent view: gate after one atomic metadata capture; publish/remove multiple external namespaces while validation is paused; release and verify validation consistently uses captured associations, never a mixture read from the live map. Also race capture with publication/removal repeatedly under a deterministic barrier and assert only valid whole associations, not live rereads. Use dependent schema pairs chosen so a mixed view would produce a distinct invalid result; old and new coherent captures have specified outcomes.
- Metadata retirement: capture external metadata, remove/retire external runtime while validation is gated, then resolve contracts successfully from immutable metadata; assert no invoker/provider/runtime reads and no unnecessary ownership retained through blocked candidate runtime construction or wait to publish. If implementation introduces a resource read, instead prove an existing temporary lease survives retirement and releases on valid/invalid/exception outcomes before provider initialization.
- Cycles: valid staged Public `a` (contains return target without b edge), then Public `b -> a`, then Public replacement `a -> b` works. Ordinary graph traversal terminates while still validating return-edge visibility/contract. A forwarding/schema cycle still rejects; no unresolved stubs or special transaction path.
- Inputs/mocks: real `YamlSkillDefinition`, input/output schemas, contracts and fixed Java metadata; gates only around deterministic validation capture/use, not replacing validators.
- Surface/compatibility: configuration/manifest and internal policy; reuse existing binding/forwarding rules with namespace scope, no schema compatibility engine.

### 5. `preparationsProgressConcurrentlyAndKeepStateIsolated`

- Type/location: replace `SkillReloaderTest.preparationsSerializeWithoutBlockingSnapshots` with separate same-target/different-target tests; supplementary manager isolation tests.
- Gate first candidate's expensive runtime construction. Before releasing it, require second candidate preparation to complete; snapshot reads must finish, and publish a ready candidate for an unrelated namespace successfully. For same-target preparations both may build, but later publication must respect captured base.
- Concurrent candidates use different documents, explicit configs, host maps, model aliases, timeouts/session settings, output schemas and source labels. Assert each candidate's catalog, frozen definitions, derived metadata and runtime properties match its own inputs, IDs differ globally, and copied input collections/maps remain detached from later caller mutation.
- Invalid/valid peer: barrier starts both, invalid document emits its own labeled errors, valid candidate completes/publishes with no contaminated errors/definitions/settings. Also fail provider construction for one peer while another remains usable.
- Fixed initialization: simultaneous REST candidates reuse exactly one safely completed handler instance; Java metadata discovery completes once, each generation includes only assigned registrations, and neither Java application method nor REST handle method is called by validation/preparation. Do not serialize the whole candidates around this initialization.
- Inputs/mocks: real catalogs/parser, minimal distinct documents, factory counters/gates, handler constructor versus invocation counters, mutable caller containers.
- Surface/compatibility: internal concurrency/configuration/diagnostics and Supported SPI binding; intentional removal of serialized preparation and inheritance.

### 6. `strictPublicationConfigurationPreservesExactBoundary`

- Type/location: extend `ExecutionConfigurationParserTest` and manager/reloader tests.
- Preserve all accepted nested fields: provider options, timeouts/retries, credential refs/headers/Vertex, quotas/depth/mission timeout/attachments and execution trace persistence. Verify startup/previous/other namespaces never fill missing models/connections/scalars.
- Reject omitted/null configuration, `loomspan.shutdown`, `loomspan.skills`, `loomspan.observability`, other application keys, unknown top/nested keys, duplicate keys and direct credential literals using current parser rules. Keep exact timeout whole-millisecond/range/driver tests.
- Environment references resolve only at prepare; validation has no resolution or clients. Explicit copied host map requires missing/blank/unused checks and no Environment fallback. Concurrent credential maps remain independent and mutation after entry does not alter candidate values. Do not add masking/sensitivity classification tests.
- Inputs/mocks: existing parser examples and Environment mock; actual parser; runtime creation counters.
- Surface/compatibility: configuration/manifest behavior; preserve exact supported parser contract, intentional required complete document.

### 7. `startupRemovalRecreationAndRestartPreserveFixedJavaLifecycle`

- Type/location: Spring integration in `PublicSkillReloadIntegrationTest` or a focused `NamespaceStartupIntegrationTest`, plus `SkillGenerationExecutionIntegrationTest` for retained owners.
- Embedded: configured default documents call qualified default Java/YAML children without publication; startup default is Private. Named Java namespace exists immediately with only its assigned methods, same startup values but separate runtime/registry; host-authorized direct Java entry works without activation publication. Reuse binding/result serialization/RBAC/security fixtures.
- Reject default startup declaration referencing a foreign Private namespace, including assigned Java capability; no defer/exception. Private same-namespace references remain valid. Java namespace discovery case normalizes.
- Managed no-local-files: start empty configured declarations with Java capability namespaces; publish complete Public shared namespace, then API-publish callers; demonstrate preparation/installation without adding readiness modes or bootstrap coordinator. Direct leaf invocation may be used; cross-namespace dispatch completion remains downstream.
- Departmental: API replacement retains assigned Java, removes omitted supplied content, rejects override/copy/relocation attempt. Host-owned Java bean state remains the same object and is not snapshotted/reconfigured by publication.
- Remove default and named Java namespace using exact IDs while holding existing ownership; snapshot/direct new entry fails, repeated lookups and startup callbacks do not recreate it, bean destruction count remains zero, retained bindings stay usable. Explicit absent-base recreation restores fixed methods with fresh ID. Missing/wrong ID removal leaves association unchanged.
- Restart via a fresh application context rebuilds original startup declarations/settings/Java namespaces Private, even after prior process publications/removals. IDs differ; no restoration store.
- Inputs/mocks: real Spring discovery, deterministic Java/REST implementations and optional MockWebServer, bean construction/destruction counters, explicit context close.
- Surface/compatibility: Application API, Supported SPI and configuration/startup contracts; preserve Java lifecycle/security while intentionally adding namespace withdrawal.

## How to Run

Use repository wrapper and Java 21+ (Maven wrapper enforces Maven >=3.9). Run from repository root in PowerShell. Quote comma-separated test selection so PowerShell passes one Maven argument.

```powershell
.\mvnw.cmd -q -DskipTests compile
.\mvnw.cmd -q '-Dtest=SkillReloaderTest,SkillGenerationManagerTest,ExecutionConfigurationParserTest,NamespaceIdentityFoundationTest' test
.\mvnw.cmd -q '-Dtest=LoomspanPublicSurfaceArchitectureTest,SupportedSurfaceIntegrationTest' test
.\mvnw.cmd -q '-Dtest=PublicSkillReloadIntegrationTest,SkillGenerationExecutionIntegrationTest,JavaSkillAuthorizationIntegrationTests,JavaSkillSecurityStartupTests,JavaSkillAuthenticationScopeIntegrationTests' test
.\mvnw.cmd -q test
git diff --check
```

Add any new focused validator/startup class to the relevant selection; report the exact command actually executed. Existing method/class names can be verified with `rg --files src/test` before invocation. No live credentials or external model calls are required. Run focused tests first, then required architecture/integration and full regression. Repeat only after changes or failures warrant it; no arbitrary stress/throughput run is required.

Maven test selection still compiles all tests, so old removed-API consumers must be updated directly. If an actual downstream-only semantic gap blocks full regression, record the exact class/test/command, failure, why it belongs to PR 27.3/27.4/27.5, and the narrower passing evidence in Step 4 durable results. Do not preserve old production APIs or disable required PR 27.2 checks. Full-suite green must not be claimed when blocked. Step 5 independently determines whether verification is sufficient under the ticket's explicit sequential-slice allowance.
