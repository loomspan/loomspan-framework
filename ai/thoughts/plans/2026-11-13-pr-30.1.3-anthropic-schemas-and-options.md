## Implementation Approach and Decisions

1. Reuse the existing internal contributor and Spring AI builder/SDK option extension facilities. Match only the exact accepted fixture `claude-sonnet-5-5`; this is an explicit known identity, not a version/prefix/endpoint heuristic. Apply native LOW/MEDIUM/HIGH effort for the already accepted level vocabulary and adaptive thinking. Reject unsupported levels before any send. Leave omitted thinking omitted. All other IDs retain current legacy mapping; no claim is made about unlisted future IDs.
2. Keep native option assembly in the existing contributor or a small package-private helper in the same package. The helper accepts existing Anthropic options plus a raw schema map/native format and returns a new options object. Copy the existing output config (`toBuilder`), replace `format`, and mutate the option copy. Preserve unknown native config fields, effort, model, max tokens, sampling settings and tool options. Do not use RC2 convenience `outputSchema`, which strips schema entries. Do not introduce validation or schema normalization here.
3. Native schema helper calls in deterministic adapter/factory tests establish its contract now. Later consumer wiring must reuse it rather than reconstructing a fresh output config. A helper without current consumer wiring must remain internal and explicitly limited; do not claim standard mission/planner integration is complete.
4. Root correction strategy: retain official RC2 until a suitable upstream artifact is established. Do not substitute the unverified latest/main source. A focused upstream correction means changing the actual upstream mapper and consuming a reproducibly identified artifact, not copying the class into Loomspan. If implementation establishes such an artifact within authorized scope, record exact coordinates/commit/checksum and run all request cases. Otherwise record an owned dependency blocker and continue independent work. No open design choice is being deferred: the required action under the current evidence is a blocker, not a speculative workaround.
