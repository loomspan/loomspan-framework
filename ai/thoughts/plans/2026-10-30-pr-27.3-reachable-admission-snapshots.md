# PR 27.3 Reachable Admission Snapshots Implementation Plan

## Overview

Admit a root against the immutable generations reached by its declared child graph. Capture that association and leases atomically with publication/removal, validate contracts outside the registry lock, and carry the association through existing root execution machinery. Validation uses the same checks with temporary ownership and no admission reservation.

Selected profile: **full**, approved by the developer after Step 0. Initial checkout was clean; the research artifact is the only preceding pipeline change. Leave all work uncommitted and do not sync. No developer decision remains unresolved.

## Current State Analysis

- `SkillGenerationManager#capture` currently leases only one namespace under `generationMonitor`; publication/removal already use that boundary. `OwnerLease` and retirement dispatch provide idempotent release and callbacks outside the monitor.
- `SkillDependencyValidator#check` validates complete candidates and their transitive declarations using immutable metadata. It already owns visibility, input-contract resolution, child input binding checks, effective output forwarding, and output binding compatibility. `visit` checks each source edge before recursion and tracks skill names separately from namespace selection.
- `CapabilityMetadata.inputContract` and `toolDescriptor` input/output schema strings are the prepared representations. `YamlSkillDefinition` retains parsed child constraints, forwarding, input/output bindings and execution/planning declarations. No dependency-history subsystem is needed.
- `DefaultSkillTemplate#prepareObject` captures before conversion; `prepareMap` validates input. `rootNamespace` currently parses only for namespace selection, leaving the original string in skill lookup. `validatePrepared` checks current entry RBAC and releases its lease; invoke/handoff do not yet precheck entry RBAC before lifecycle admission.
- `PreparedInput`, `LoomspanSessionRunner`, and `ExecutionBinding` carry only the entry generation. `FrameworkExecutionLifecycle.AdmittedRoot` already accepts `AutoCloseable` ownership and defers release until physical mission work completes.
- `DefaultSkillInvocationHandoff` stores authentication and an entry generation ID outside its consumable payload. ID reads remain valid and do not extend ownership.

## Desired End State

Every root overload parses one qualified identity and captures exactly the reached namespace generations. Optional and role-restricted declared children participate. Multiple reached skills in one namespace are traversed independently. Ordinary namespace cycles terminate; forwarding cycles and existing contract rules still fail. Missing reached targets, foreign Private edges, invalid constraints and changed prepared derived contracts reject before skill/provider execution. An unrelated broken skill never blocks an entry.

One immutable internal association supplies entry generation, selected generation lookup and captured visibility. One aggregate owner retains all selected generations. An admitted handle and every branch binding carry that snapshot. Future namespace resolution never attaches live generations. Entry RBAC is checked with each operation's existing authentication boundary; reachable child roles are not eagerly checked.

Temporary validation creates no root/session/provider work, releases ownership on all paths, and cannot reserve the view for invocation. Catalogs continue to describe prepared contracts and own no execution lease. Fresh descriptor-driven operations always capture current state.

## Implementation Approach

Use an internal immutable execution snapshot over existing SkillGeneration objects and an aggregate over existing leases. Capture performs only graph selection/metadata existence work plus lease acquisition under `generationMonitor`; expensive policy and schema checks run after leaving it. Extract shared validation internals in SkillDependencyValidator so candidate preparation still starts from all candidate definitions while admission starts from the entry only. Recompute with captured targets, compare schema trees with existing Jackson representations, and retain original published metadata for execution/catalogs.

Alternatives rejected: capturing all namespaces couples unrelated broken graphs and resources; complete-candidate validation at admission incorrectly blocks unrelated entries; generation-ID equality rejects harmless updates; raw string equality rejects equivalent formatting/order; a second validator or historical dependency schema copies duplicates policy. Making no change cannot stabilize declared dependency generations or implement temporary reachable validation.
