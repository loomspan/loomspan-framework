## Overview and desired end state

Reject explicitly refused or incomplete provider generations at the physical provider-attempt boundary, before semantic validation, planning parsing or tool dispatch. Retain original response evidence and actual usage once, record one failed outcome for the same physical attempt, and preserve normal tool continuation and existing transport retry policy. Reuse the same internal classifier at the canonical tool manager; it does not own usage.

## Current state and verified discoveries

- `ProviderAttemptCallAdvisor#adviseCall` catches only the downstream physical call, then unconditionally records success before extracting and accounting returned usage. Its existing response payload already preserves rich parts, generation metadata and response metadata.
- `CanonicalToolCallingManager#executeToolCalls` validates every bound selection before delegating, but does not inspect explicit response completeness.
- `DefaultSessionUsageService#recordModelResponse` mutates usage before enforcing quotas. Cancellation/write fencing belongs to the current execution binding. Moving accounting into the transport retry catch would change that policy.
- `ModelUsageExtractor#hasExactUsage` tests positive counts. Explicit native zero usage therefore needs a distinct exact-zero control without treating adapter-synthesized missing-usage zeros as exact.
- `SpringAiProviderIntegration#inspectResponsesBody` already sees original HTTP-200 failed envelopes and retains bounded diagnostics, but `ProviderCallException` has no actual-response usage carrier. This existing interceptor can retain available failed-envelope evidence without another transport.
- `loomspan-console/internal/traceanalysis/attempts.go#lifecycleAccepts` currently permits only SENT -> RECEIVED or SENT -> FAILED. Required receipt-plus-rejection semantics need coordinated Java/Go reader and fixture updates.
- `OutputSchemaCallAdvisor`, `LinterCallAdvisor` and `EvidenceContractCallAdvisor` obtain downstream responses before validating candidates; a terminal inner exception escapes before correction. `DefaultPlanningService#requestPlanAttempt` calls the interaction before parsing its normalized plan tree. Those existing seams support executable pre-consumption checks.

## Implementation approach and finite status mappings

Use one internal driver-aware classifier over the actual pinned metadata, returning an explicit rejection decision and faithful evidence. Wire the same classifier/driver into the provider advisor and canonical manager before any delegation. Do not infer from prose, missing text, absence of candidates or unknown statuses.

| Driver | Reject from explicit evidence | Preserve normal controls |
| --- | --- | --- |
| Responses | Native response/generation status `incomplete`, explicit `refusal`, retained `openai.responses.incomplete_reason`; mapped LENGTH/CONTENT_FILTER/INCOMPLETE when they represent those explicit mapper outcomes; explicit incomplete item status within the containing response | completed STOP/TOOL_CALLS; complete tool turns without final text; unknown status has no new policy |
| Anthropic | `max_tokens`, `model_context_window_exceeded` and `pause_turn` are explicitly unfinished generation; `refusal` is explicit refusal. Retain native `anthropic-response` and supplied stop details | `end_turn`, `stop_sequence`, `tool_use`; no vendor continuation/fallback policy is adopted |
| Gemini | `MAX_TOKENS` is incomplete. Explicit text filtering/blocking reasons `SAFETY`, `RECITATION`, `LANGUAGE`, `BLOCKLIST`, `PROHIBITED_CONTENT` and `SPII` are rejection signals. Retain details actually exposed by the adapter | `STOP`, normal function-call turn; OTHER/unspecified/unknown values and malformed-function/unexpected-tool values get no new status policy. No empty-output inference. Missing promptFeedback/details are the bounded B05 deferral; native generated attachments remain excluded |

The finite Gemini table is grounded in pinned SDK `google-genai:1.73.0` source `com/google/genai/types/FinishReason.java`, whose comments explicitly name token exhaustion and safety/recitation/language/blocklist/prohibited-content/SPII cutoffs, together with `https://ai.google.dev/api/generate-content`. Add explicit tests for each handled value. Native generated attachments remain outside this ticket's classification scope. Anthropic meaning is grounded in `https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons`. Vendor advice to continue or fall back does not override the ticket's terminal rejection policy. No unlisted or undocumented status gains new handling.

## Implementation decisions

- Gemini finite text-status mapping additionally includes RECITATION, LANGUAGE,
  BLOCKLIST, PROHIBITED_CONTENT and SPII. The pinned google-genai 1.73.0
  `FinishReason.Known` source explicitly documents these as content-triggered
  generation cutoffs, consistent with the [official GenerateContent reference](https://aistudio.google.com/api-reference/generate-content).
  OTHER/unspecified and malformed-function/tool statuses get no new policy;
  generated-image attachments remain excluded. Unit and real-adapter fixtures
  cover each added value; no prose/sensitivity classification is introduced.
- The canonical manager derives the same driver from its typed prompt options;
  production assembly already binds official driver-specific options. It reuses
  the sole classifier and never owns usage.
- Internal response evidence is shared across integration/advisor packages via
  an internal carrier; technically public types have explicit architecture
  allowlist reasons and add no application API or supported SPI.
- Failed-envelope token counts are accepted as exact only when present values
  are nonnegative representable integers and satisfy the existing usage-record
  constraints. Missing totals use an exact checked component sum. Invalid or
  unrepresentable counts leave usage unavailable; the complete original envelope,
  including native usage, remains evidence and the provider error retains its
  existing classification. Do not narrow, estimate or replace its native counts.
