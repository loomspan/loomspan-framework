# PR 37.1 declaration identity implementation plan

## Overview

Register every callable and reference-only executor using the exact ordered pair of its namespace and local name. Enforce the portable component grammar and pair length at declaration, retain the existing owner assignment rules, and provide actionable Java declaration errors. This is pipeline Steps 2 and 3 under the Full 5-Step Pipeline, approved by the developer.

## Current state analysis

`SkillIdentity` already owns component validation and is carried by `CapabilityMetadata`, `YamlSkillDefinition` and `SkillExecutorRegistration`. Its constructor currently folds namespace case, permits uppercase and underscores, and counts one separator character. `parse`, `resolve` and `toString` use a single hyphen. Registration maps use `toString()` as their key. Allowing hyphens inside both components while retaining that encoding would make distinct pairs collide, such as `(a-b, c)` and `(a, b-c)`.

`YamlSkillCatalog#checkedConfigured` assigns `default` before discovery. `checkedSupplied` assigns the supplied namespace. The shared `SkillMethodBeanPostProcessor#identity` already selects an explicit nonempty annotation name or the canonical method name verbatim. Its error identifies the bean and method, and needs a corrective instruction. The processor has separate callable and executor maps. `SkillDependencyValidator#check` merges fixed Java callables with YAML definitions in the candidate owner and reports collisions. These mechanisms can be reused.

Source anchors are `src/main/java/ai/loomspan/internal/core/SkillIdentity.java:6`, `SkillMethodBeanPostProcessor.java:182`, `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:140`, `YamlSkillCatalog.java:170`, `YamlSkillCatalog.java:264` and `SkillDependencyValidator.java:55`. Existing evidence includes `SkillIdentityTest`, `SkillMethodBeanPostProcessorTest`, `NamespaceIdentityFoundationTest`, `NamespaceStartupIntegrationTest` and `ExecutorDependencyResolutionTest`.

## Desired end state

- Every component matches the entire ASCII pattern `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`, contains 1–64 characters, and excludes substrings `anthropic` and `claude`.
- Every registered pair satisfies `namespace.length() + 2 + localName.length() <= 64`, including executor registrations.
- Supplied spelling is validated as written. `lookup-3pl` works in either component. Invalid names fail at their declaration boundary.
- Nested startup YAML belongs to `default`. Supplied YAML belongs to its reloader namespace. Both Java roles use their declared owner or `default` and the explicit nonempty annotation name or exact method name.
- Callable uniqueness spans YAML and Java within one owner. Executor uniqueness is independent. Equal local names under different owners and one callable plus one executor with the same pair work.
- Registration keys encode the ordered pair unambiguously with a colon. Both hyphen-bearing pairs in the collision example remain distinct.
- Declaration documentation, packaged examples and focused fixtures teach the enforced rules and have executable evidence.

## Implementation approach

Reuse `SkillIdentity` as the single authority for component validation and pair length, and retain the existing separate role indexes. Its colon representation is sufficient for unambiguous map keys, so introducing another identity type or parallel registration-key abstraction would add redundant state. Change the internal namespace helper to an exact-validation name such as `requireNamespace` and update all production/test call sites. Return the supplied namespace after successful validation, with no transformation or alias helper.

## Phase 1 — Exact identity foundation

Change `src/main/java/ai/loomspan/internal/core/SkillIdentity.java`.

- Replace the component regex, per-component length rules and reserved-substring checks. Use whole-string matching. Reject null, empty and all invalid spellings with field-specific diagnostics.
- Validate and retain the namespace verbatim. Count two separator characters in the pair limit and report the failing pair/length clearly.
- Render and parse exactly `namespace:local-name`. The parser accepts exactly one colon with two nonempty components. `resolve` delegates qualified colon input to `parse` and creates an owner-relative pair for a bare local name.
- Update namespace validation call sites, including `ExecutorConfiguration`, `DefaultSkillReloader`, `YamlSkillCatalog`, `SkillGenerationManager`, `SkillGeneration`, `DefaultSkillCatalog`, `CapturedNamespaceMetadata`, `ExecutionFrame` and `EvidenceExpressionParser`. Remove obsolete normalization wording and redundant comparisons that existed only to reject noncanonical normalized case. Preserve each caller's existing null/optional semantics and access checks.
- Update `SkillIdentityTest` to prove the grammar matrix, reserved substrings, exact rejection, component/pair boundaries and the ambiguous-hyphen pair round trip. Update namespace-key configuration tests so valid owner keys are lowercase, invalid uppercase keys fail, and arbitrary nested domain keys remain exact.
