# PR 30.3.2 Planning and Step Contracts Implementation Plan

## Overview

Migrate planning to its own framework-owned canonical/native output contract and JSON-only acceptance. Restore canonical-schema consumers in step input guidance. Make step-action decimal decoding independent of an injected mapper's floating-point defaults and reject explicit null argument roots before dispatch. Preserve existing planning semantics, correction budgets, assignment ownership, option routing and diagnostic fidelity.

Pipeline mode: Full 5-Step Pipeline, approved by the developer after Step 0 on November 13, 2026. Initial checkout was clean; the research artifact is the only earlier pipeline addition. This plan and its companion testing plan govern implementation. No implementation or tests were performed while planning.

## Current State Analysis

- `DefaultPlanningService.java:300–426` owns one total correction across structure, task counts, evidence and binding checks. Its request at lines 505–550 sends `planning=true` with no output contract. Parsing at lines 799–986 accepts JSON/YAML, unwraps fences and aliases statuses; runtime replaces model plan IDs.
- `ExecutionPlan.java:18` requires identity and timestamp, defaults null status to VALID and tasks to empty. `PlanTask.java:22` requires task ID/title/status, defaults lists, and normalizes nullable text. `PlanStructureValidator` additionally requires task capability and dependency arrays and enforces ordering/grouping.
- `ModelInteractionRequest.outputContract`, `NativeOutputContract`, `ProviderAttemptCallAdvisor` and the PLANNING role of `StandardSchemaCompiler` provide the shared native path. OpenAI native mapping requires closed objects with every declared property required. It does not rewrite user schemas to fit.
- `StepLoopMissionExecutionEngine.java:1205` binds action arguments and final-response trees with its injected mapper. Default `schemaTree()` already enables BigDecimal, but the engine does not enforce local decoding precision for other injected mappers. Explicit null and omitted toolArguments both become null and normalize to an empty map later.
- `StepPromptBuilder.java:243–341` and `SkillInputPromptRenderer` still consume old `SkillInputSchemaNode` accessors although `SkillInputContract.schema()` returns CanonicalSchema. Planning and engine fixtures still instantiate removed output-manifest types.
- Root-build failures reported by PR 30.3.1 concern TypeSafeDeclaration and YamlSkillCatalog. These are historical observations to recheck, not current verification results. PR 30.3.4 owns those remaining consumers; PR 30.4.3 owns integrated reconciliation.

## Desired End State

Every initial and corrected planning request carries the same dedicated canonical plan contract through the existing native schema path. Local JSON, schema and semantic checks share the existing single correction allowance. Invalid candidates are never stored or executed. Provider/operational failures escape their existing owners and are not mistaken for invalid candidates. Step dispatch and final output preserve exact model numbers, explicit null tool argument roots correct or fail before effects, and omitted/nested-null controls continue working.

### Framework-owned generated plan contract

Compile once with `StandardSchemaCompiler.Role.PLANNING` and `Origin.GENERATED`; reuse the immutable contract. Use only approved v1 keywords. Both root and task objects are closed. Every declared property is required **by an explicit choice for this framework-owned generation format**, allowing the existing OpenAI strict mapping without changing arbitrary user contracts. Omission of previously defaultable fields in model-generated plans is intentionally replaced by explicit null or an explicit empty list as described below; update the prompt and all owned fixtures atomically.

| Location/field | Contract and conversion |
| --- | --- |
| Root | Object; exactly capabilityName, createdAt, status, tasks; no model-owned planId |
| capabilityName | Nonempty string; exact executing identity checked by PlanStructureValidator |
| createdAt | String, date-time; existing Instant conversion remains authoritative |
| status | Nullable string enum VALID/null; null retains ExecutionPlan's VALID default; no other initial status or alias |
| tasks | Non-null array of task objects; structural validator already requires an array; empty allowed unless task/evidence constraints disallow it |
| Task taskId/title | Nonempty strings; existing nonblank typed/semantic checks remain |
| Task status | String enum PENDING only; null invalid because PlanTask requires it |
| Task capabilityName | Nonempty string; exact authorized visible binding remains a semantic requirement |
| Task dependsOn | Non-null array of strings; structural validator retains nonblank/existence/order/group checks |
| Task expectedOutputs | Nullable array of strings; null retains existing empty-list default |
| Task intent/note | Nullable strings; retain existing blank normalization |
| Task parallelGroup | Nullable string; retain exact existing semantic grammar, width and contiguity checks; no schema pattern keyword |

Do not add dynamic capability enums, historical task-ID patterns, execution-state enums, generated defaults, or a second schema implementation. Generate planId after canonical/structure acceptance and before typed conversion; never treat it as model authority. A model-supplied planId is an unknown field and invalid under the new contract. No historical plan reader is required.

- No ordinary advisor repair (PR 30.3.3), TypeSafe/catalog restoration (PR 30.3.4), upstream SDK blocker repair, hosted-provider certification or suite implementation.
- No live model calls, downloads, paid sends, issue/PR submissions, transport-budget changes, or sensitivity classification/content rewriting. Preserve the existing journal projection exception unchanged.

## Implementation Approach

Reuse CanonicalSchema and the existing request field. Keep planner acceptance in DefaultPlanningService and step acceptance in StepLoopMissionExecutionEngine. Treat parse, completed schema violations and typed candidate-conversion failures as bounded invalid-candidate outcomes while keeping provider exceptions and incomplete/operational validation outside that classification. Use a private lossless action reader/tree before binding, retaining existing inability strictness and envelope handling.
