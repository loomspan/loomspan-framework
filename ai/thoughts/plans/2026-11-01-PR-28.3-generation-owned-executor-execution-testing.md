# Generation-owned configured Java executor execution — testing plan

## Change Summary

Enable executor-backed YAML through generation-owned registrations/configuration and one retained admission. Share callable/executor dependency semantics and one Java route; remove REST support and redundant CapabilityKind. This is Step 3 in the same planning context as Step 2, pipeline profile **full**, approved by the developer. Governing implementation plan: `2026-11-01-PR-28.3-generation-owned-executor-execution.md`.

No tests were run and no test code was edited during planning. Commands below are required implementation/review checks, not reported results.

## Impacted Areas

- Shared discovery and immutable ExecutorConfiguration/SkillExecutorInvocation.
- SkillGeneration, SkillGenerationManager startup/prepare/publish/capture/retirement and SkillDependencyValidator.
- SkillAdmissionSnapshot, DefaultSkillTemplate, admitted handoff, ExecutionBinding and ExecutionCoordinator.
- Public catalog/validation, diagnostic definition lookup, Spring wiring, supported API allowlists and testkit.
- Existing REST-backed integration scenarios and live authoring/API guidance.

## Risk Assessment

- Selecting a foreign executor generation/configuration at preparation instead of admission; late live lookup during retained execution.
- Capturing callable and executor namespaces at different times, omitting leases, or leaking owners when validation fails.
- Enqueuing an executor as a callable, checking unrelated declarations, or treating namespace retention as callable authority.
- Dropping executor-only namespaces or fixed registrations during replacement/recreation; destroying Spring beans during namespace withdrawal.
- Rebinding path rules independently at lifecycle boundaries; silently accepting missing/null/scalar/list subtrees or trimming malformed paths.
- Conflating JAVA execution with Java method declaration and losing YAML bytes/config/identity.
- Bypassing the shared Java work executor, references, proxy advice, authentication restoration, observations or cancellation.
- Deleting REST tests that actually establish binding/planning/namespace behavior rather than converting their fixtures.

Protected paths: existing SkillMethod input/proxy/result semantics, five-component invocation construction/copying, strict PR 28.2 manifest/configuration data, target-base publication and captured ownership, existing authorization hooks and exact declared callable authority. Intentionally removed: REST handler/invocation/kind and one-to-one internal CapabilityKind; no legacy compatibility tests for these removals. Composed declarative authorization and complete diagnostic wire/Console provenance remain separately assigned work. No new masking/redaction test requirement is selected; preserve existing derived-journal coverage.

## Tests to Add/Update

Names below define observable cases; related cases may be parameterized or kept in existing suites rather than adding one file per row. Use real immutable registrations/generations for resolution tests, mocks only for provider/resource accounting or the router seam. Real application contexts are required where discovery/proxy/Spring lifetime matters. Do not mock the resolver in tests intended to prove binding.

### 1) Binding and reference role matrix

- **Type/location**: unit, SkillDependencyValidatorTest plus focused new ExecutorDependencyResolutionTest if separation improves readability.
- **Names/proofs**:
  - `resolvesLocalExecutorInDeclaringNamespaceAndQualifiedWithoutFallback`: local lookup uses the YAML owner; qualified lookup never searches another namespace or same-name callable index.
  - `allowsSameNamespaceAndPublicForeignButRejectsPrivateAndDefaultForeignExecutor`: candidate/local Private succeeds, foreign Public succeeds, foreign Private fails; default is not implicitly Public.
  - `separateRolesPermitSameQualifiedNameWithoutExecutorCallability`: callable and executor with one identity coexist; a missing executor cannot resolve to its callable counterpart, and an executor alone cannot satisfy allowed_skills.
  - `validatesExactDotPathsAndMapSelections`: parameterized omitted/explicit empty string => empty map; whitespace-only, surrounding whitespace and `.x`, `x.`, `x..y` fail; explicit missing, null, scalar, list and non-map intermediate fail; `{}` succeeds. Keys are case-sensitive, `a.b` chooses nested keys rather than literal dotted-key fallback; preserve literal dotted keys inside a selected map.
  - `checksCompleteCandidateIncludingTransitiveReturnPaths`: candidate replaces old target callables/executors/config/visibility even when a foreign child returns into it; same-name role indexes remain distinct.
- **Fixtures**: small SkillDocument builders, fixed annotated registration snapshots, candidate ExecutorConfiguration and immutable foreign generations. No domain executor validation or resource callbacks.
- **Surface**: configuration/manifest and internal resolution. Preserve strict behavior; no old/new fallback.

### 2) Preparation and executor-only startup

- **Type/location**: unit/integration, ExecutorConfigurationManagerTests, NamespaceStartupIntegrationTest and ExecutorConfigurationStartupTests.
- **Names/proofs**:
  - `initializesNamespaceContainingOnlyExecutors`: real executor-only bean in non-default namespace yields an active Private generation with no callable executor entry.
  - `candidateOwnsFixedExecutorsAndOnlyItsConfiguration`: replacement carries assigned registrations and newly supplied target map, omission does not inherit startup/previous data; config persists even when runtimeFactory is absent.
  - `validatesFixedExecutorPathsInCompleteCandidate`: malformed annotation path/explicit missing own map fails binding even in executor-only namespace; empty omission works.
  - `preparationIsMetadataOnlyAndDoesNotRetainForeignResources`: counters prove validate/prepare do not invoke methods/domain code; prepare caller against foreign metadata, then remove/replace foreign and assert its runtime retires immediately when no admission owns it. Caller preparation must not pin foreign resource lease or settings/policy.
  - `startupAndPublicationDeliverEquivalentSelectedMap`: real Config Data resource vs equivalent published YAML preserves nested maps/lists, nulls, empty containers, scalar types, case, literal dots and literal `${...}`/ordinary domain keys into the selected invocation map. Existing ingress tests provide broad raw-data matrix; add end-to-end selected-map evidence without duplicating every parser test.
- **Fixtures/mocks**: actual Boot startup for discovery/ingress, application counters, close-counting runtime factory for ownership. Keep resources application-owned; no executor setup/cleanup hook.
- **Surface**: configuration/manifest, internal lifecycle. Explicit strict binding and complete replacement, no compatibility shim.

### 3) Captured bindings across replacement, removal and recreation

- **Type/location**: unit/integration, SkillAdmissionSnapshotTest/SkillReachableAdmissionTest and new ExecutorGenerationExecutionTest or ExecutorGenerationExecutionIntegrationTest.
- **Name**: `retainedExecutorUsesCapturedRegistrationConfigAndGenerationAcrossLifecycle`.
- **Arrange**: Public executor namespace I1, caller namespace S with leaf; obtain real admitted handoff before replacing I with I2 and different configuration. Register close-counting provider runtime and retirement listener. Fixed Java bean tracks invocations/destruction.
- **Assert**: retained invocation reports I1 ID/map, fresh invocation reports I2; skillName is S-leaf and skill config stays S-owned. Remove executor namespace: fresh validate/invoke/handoff fail while retained work completes. Explicit recreation restores fixed assigned registration with I3 configuration; fresh execution uses I3, never old/startup config. No config annotation still reports the executor namespace generation ID. Release retained owner and assert exactly-once deferred retirement; withdrawal never destroys Spring bean. Shutdown uses normal Spring ownership.
- **Additional name**: `failedAdmissionReleasesEveryCapturedNamespaceOwner`: path/visibility failure after capture releases all leases and allows retirement; invalid business input likewise releases capture. Exercise relevant map/object overloads using the same existing helper patterns.
- **Mocks**: provider runtime close probes only; actual executor registration/invocation and handoff for retained evidence.
- **Surface**: configuration behavior/internal concurrency plus existing supported handoff semantics.

### 4) Preparation/publication concurrency and capture coherence

- **Type/location**: unit/integration, SkillDependencyValidatorTest, SkillReloaderTest, SkillReachableAdmissionTest.
- **Names/proofs**:
  - `foreignChangeAfterPreparationDoesNotRevalidateAtPublication`: prepare caller against Public I1, retain an admission, replace I with Private I2 (or remove/recreate); caller candidate still publishes when its own base matches. Fresh admission checks selected I2 and fails, retained work uses I1. Also keep target-base conflict test proving actual target changes reject publication.
  - `captureSelectsOneGenerationWhenBothRolesReachNamespace`: callable and executor dependencies overlap; force replacement around capture with latches/barriers and assert exactly one ID per namespace with matching binding data. Never mix old registration/config with new ID.
  - `bindingValidationDoesNotHoldRegistryMonitor`: block controlled expensive schema/validation work outside capture and show concurrent publication/removal/retirement progresses before releasing validation. Use existing concurrency fixtures, no timing-dependent sleep assertion.
- **Fixtures/mocks**: deterministic CountDownLatch/barrier arrangement and close counters; real shared resolver/leases. Assert both test threads finish with bounded joins and propagate thread failures.
- **Surface**: internal lifecycle/concurrency and explicit public replacement behavior.

### 5) Root-reachable traversal and callable authority

- **Type/location**: unit/integration, SkillReachableAdmissionTest and NamespaceExecutionAuthorityIntegrationTest.
- **Names/proofs**:
  - `executorRetentionIgnoresUnrelatedBrokenCallableDependencies`: executor namespace also contains unrelated callable requiring a now-removed third namespace. Caller leaf admission succeeds and captures only caller/executor namespaces, not the removed third namespace. Variant: unrelated malformed foreign executor binding used only by an unreachable callable must not become an admission root.
  - `executorNamespaceRetentionGrantsNoCallableAuthority`: shared namespace contains another skill; root/child dispatch without exact allowed_skills remains denied even though namespace is retained. Executor registration itself is never a template root or visible tool.
  - `unreachableExecutorDependencyDoesNotBlockIndependentRoot`: namespace has safe and broken-after-foreign-removal leaves; safe root works while dependent root fails. Reuse root-reachability facade overload coverage.
- **Fixtures**: Public executor namespace with multiple definitions, deliberately broken third dependency after valid publication; real access guard for authority assertions.
- **Surface**: existing authorization boundary/internal graph. Preserve declared callable authority; do not implement PR 28.4 composition as a temporary test workaround.

### 6) Shared Java execution and invocation fidelity

- **Type/location**: integration, new `src/test/java/ai/loomspan/integration/ExecutorGenerationExecutionIntegrationTest.java`, existing Java lifecycle/authentication/cutoff suites.
- **Names/proofs**:

  - `javaExecutorLeafRetainsYamlDefinitionInGenerationAndCatalog`: public validation/catalog returns SkillKind.JAVA, definition/source/config lookup succeeds, diagnostic catalog construction does not throw solely because declaration is YAML and execution JAVA.
- **Fixtures/mocks**: real Spring proxy/advice where tested; fake deterministic model/provider, existing reference/session fixtures and latches for cutoff. Do not use the public invocation constructor directly as substitute for proving Framework construction.
- **Surface**: supported invocation/config behavior, current diagnostics and internal shared routing. No extra public fields or executor engine.
