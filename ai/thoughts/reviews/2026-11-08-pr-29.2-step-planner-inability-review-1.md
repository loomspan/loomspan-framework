# PR 29.2 Explicit-Step Planner Inability Review 1

## Code Review Findings

### [P2] Reject an inability value before duplicate action binding can overwrite it

- **Location** `StepLoopMissionExecutionEngine.java:1249`.
- **Evidence** The initial scanner matched only the exact string `CANNOT_COMPLETE`. The ordinary Jackson mapper reads the padded string `" CANNOT_COMPLETE "`, numeric `2`, and numeric string `"2"` as that enum value. The same mapper accepts duplicate action fields in a typed action and retains the last value. A standalone probe with the configured schema mapper reproduced that binding behavior.
- **Trigger** A response supplies one of those malformed `stepAction` values followed by a duplicate `"stepAction":"FINAL_RESPONSE"` and a final result. In an assigned worker, the duplicate can instead supply `CALL_TOOL` with valid assignment and tool arguments.
- **Impact** The engine can accept a malformed inability envelope as successful output or dispatch a tool without taking the existing action-correction path. The exact-spelling check on the final typed action cannot see the overwritten declaration.
- **Recommendation** Inspect each top-level action value using the same enum binding rules for detection. Keep acceptance on the strict raw JSON path, including exact spelling, exact field count, and duplicate-key rejection.

## Findings Resolved in This Context

- **P2 resolved.** The engine detects every top-level action value the ordinary mapper can bind to inability, before ordinary action binding. It validates the original candidate with the scoped strict reader and requires the exact textual value. The existing malformed-action matrix covers the padded, numeric, and numeric-string duplicate variants in assigned work and synthesis. The post-fix focused selection passed 339 tests.
