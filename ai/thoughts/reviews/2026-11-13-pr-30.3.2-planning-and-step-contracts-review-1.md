### [P2] Preserve required names that are not declared in properties

- **Location:** `src/main/java/ai/loomspan/internal/runtime/input/SkillInputPromptRenderer.java:210`.
- **Evidence and trigger:** The migrated `required` helper filtered names through the declared `properties` map. Standard schemas may require an undeclared name in an open object. For `{"type":"object","required":["unlisted"],"additionalProperties":true}`, canonical validation rejects `{}`, but compact and verbose guidance said `Required fields: []`. Nested typed maps had the same problem. The closed-empty shortcut could additionally advise an empty object despite undeclared required names.
- **Impact:** Model guidance contradicts canonical admission, encouraging invalid actions and exhausting bounded correction.
- **Fix:** Filter only generated false ownership reservations, retaining undeclared required names. Require an empty visible required list before the closed-empty shortcut. Added `retainsRequiredNamesOutsidePropertiesAtEachOpenObjectScope`, with compact/verbose, nested optional-parent, real validator and closed-empty controls. Existing false-reservation tests remain intact.
- **Verification:** Before edits, a disposable test against actual sources failed the required-name assertion.
