## Correctness and boundary assessment

The materializer runs actual nonconsuming admission before resource reads, which
retains original reference string assertions and ordinary parent/sibling
constraints. Direct Resources pass only at marked attachment leaves. A fresh
canonical tree is walked with named-property precedence, otherwise typed-map
schemas, and homogeneous array items. Null returns unchanged; requiredness and
nullability are enforced by admission, not by invented descriptors. The private
descriptor schema changes only declared attachment leaves and retains parent
constraints. Canonical and provider trees remain unchanged.

The streamed digest computes actual byte count and SHA-256 without invoking
`contentLength()`. Each read is limited by remaining budget plus one detection
byte; arithmetic checks overflow before adding the read. Streams close on
success/failure. Opening and mid-read IOExceptions retain pointer and cause.
The existing image-signature pass remains separately bounded. Parsed MIME
equality handles type/subtype case without rewriting authored metadata or
arbitrary parameter values. Missing filenames remain null in immutable copies.

Both engines record one nonempty collection immediately after successful
materialization and before planning/early completion. The state service retains
writable-binding checks. The recorder uses the owning mission ID, route and
mission frame type, independently of an active model/planning frame. Its
payload is descriptor maps, not Resources. Successful metadata remains when
later work fails; failed materialization never reaches recording. The generic
wrapper preserves original cause/context and no longer infers media
incompatibility. Cancellation exclusions remain unchanged.

The journal's state is local to each projection invocation and keyed by exact
frame ID; a close consumes that frame's attachment collection. List and streamed
paths share the same algorithm. Existing recursive journal rules are applied
only to the derived collection, without mutating canonical data. The existing
observer mapper retains the collection. No additional masking, classification,
resource access, external calls, provider fallback or endpoint was introduced.

Application API signatures and their closed allowlist remain unchanged. The
only classification correction concerns internal cross-package collaboration.
Current diagnostic paths intentionally become JSON Pointer as required by the
ticket. The trace data extension uses the existing record type and transport;
Console detail rendering remains separately owned.
