## Code Review Findings

### [P2] Preserve the exact JSON reason through typed failure responses

- **Location** `loomspan-console/internal/traceanalysis/failures.go:73`, `loomspan-console/internal/mcpadapter/output_schemas.go:30`
- **Evidence** Java's `escapedReasonCodeUnitSurvivesCanonicalFailureRecording` accepts a nonblank reason containing an isolated UTF-16 code unit and emits it as an escape. Console's former Go string decode replaced the escaped value before either response was produced. Preserving the value through Go then exposed a second replacement when the MCP SDK decoded and reserialized the structured result. The HTTP regression reproduced both conversions and checked the original escape in the browser response, MCP text fallback, and MCP structured output.
- **Trigger and impact** An accepted standard or step declaration or a Java-thrown inability carries such a code unit in its reason. The failure view loses fidelity even though the original trace value is available.
- **Correction** Decode the nullable value for validation and retain its original JSON representation for projection. Publish the existing MCP record tool's encoded result after complete and advertised schema validation, with the SDK still handling typed input validation.

### [P3] Reject ambiguous failure kind and classification

- **Location** `loomspan-console/internal/traceanalysis/failures.go:73`
- **Evidence** JSON map decoding selected the last `kind` member. A null `kind` followed by `planner_inability` was accepted. Go struct matching could also read uppercase `Classification` after canonical `classification` and validate a kind against the noncanonical field.
- **Trigger and impact** Import a trace with duplicate kind members or an apparent recoverable classification supplied through the uppercase member while the canonical value is terminal. The failure fact can validate despite an invalid or contradictory declaration.
- **Correction** Read the failure object through the existing unique-member decoder. Use the exact canonical classification member. Exercise both inline and reconstructed `ERROR_RECORDED` data.

### [P3] Reject a model range from the wrong evidence source

- **Location** `loomspan-console/web/src/observability/TraceExplorer.tsx:127`
- **Evidence** The model-range reader passed responses to the explorer verifier before decoding. The verifier cleared selection when the response source disagreed but returned the response in the imported case and in a target response with a matching target ID. Browser tests for both source choices showed the model detail rendered the mismatched payload.
- **Trigger and impact** A model-range response presents a different source from the selected one. The UI presents the returned bytes as evidence for the selected source.
- **Correction** Reject the mismatched response before model parsing, retaining the existing mismatch state, selection reset, and stale-target refresh behavior. Server-side authorization and artifact scoping remain the authority.
