# PR 30.2.3 Independent Review 1

## Code Review Findings

### [P2] Keep admitted runtime handles out of marked-leaf serialization

- **Location:** `src/main/java/ai/loomspan/internal/runtime/input/SkillInputValidator.java:79` and `:123`.
- **Evidence:** Before this review's fix, map/list admission constructed a private view with accepted runtime descendants replaced by null, but then passed the original container to `leafCheck`. That method converted the original container to a JSON tree.
- **Trigger:** A valid GENERATED string schema with the runtime marker can also carry standard `properties` or `items` keywords. Those keywords do not make a container satisfy its string type, but admission can encounter a marked runtime descendant in such an invalid container. A generated marked string with a marked `properties.nested` child and input `{value: {nested: Resource}}` reproduced a Jackson `DatabindException` through `Resource.getURI()` before the standard type rejection.
- **Impact:** Invalid inputs can inspect/serialize runtime-object internals or fail operationally instead of returning an ordinary invalid-input result. This violates the ticket's non-consuming pre-conversion and original-diagnostic requirements.
- **Recommendation:** Run leaf assertions against the already admitted private view while retaining the original value solely for diagnostic lookup.

## Findings Resolved in This Context

- Fixed the P2 above by giving `leafCheck` separate view/original arguments. Maps/lists pass their recursively admitted view; scalar JSON values pass themselves. `standardIssues` still looks up rejected values from the original container. The canonical string type rejects invalid containers; no broadened runtime permission or weakened successful contract is introduced.
- Added `SkillInputValidatorTest#invalidMarkedContainersNeverSerializeAdmittedNestedRuntimeHandles` for both map and list inputs, with Resource metadata/content sentinels, original rejected-value identity and canonical-schema preservation assertions.
- Post-fix complete internal re-review found no further actionable findings. A fresh independent context must review this fix.
