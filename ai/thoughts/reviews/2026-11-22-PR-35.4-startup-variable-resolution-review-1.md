### [P2] Mixed nested and dotted YAML loses effective connection fields — resolved

The original `StartupVariableResolution.read` returned the retained root slice immediately when a YAML document contained `loomspan.connections`. The loader also retained dotted fields from that same document as separate slices. Consequently, a document with a nested connection and a dotted API-key or header setting silently ignored the dotted settings. It could select the earlier API key and omit a configured header despite successful startup. The original candidate passed 461 focused tests, which contained separate nested and dotted examples but no mixed-document case.

The added `StartupVariableResolutionIntegrationTest#mixedNestedAndDottedYamlFieldsKeepEffectiveValuesAndAuthoredMarkers` first reproduced the defect with an expected `demo-key` and actual `nested-key`. The final regression uses competing literal API keys to protect native document ordering and a distinct dotted marker header to protect authored marker retention. It runs both declaration orders and observes the inherited driver, winning key, both headers and one lookup of `app.region`.
