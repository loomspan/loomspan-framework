### [P2] Count short JSON control escapes accurately before rejecting capture

- **Location:** `src/main/java/ai/loomspan/internal/core/BoundedExecutorDiagnosticCapture.java:139`
- **Evidence:** The string/key precheck charged every control character six bytes.
  The configured Jackson generator writes backspace, tab, newline, formfeed and
  carriage return using two-byte short escapes. The capped sink already enforces
  the actual serialized limit independently.
- **Trigger:** A supported String of 16,383 newlines serializes to exactly 32,768
  JSON bytes, including quotes, but was rejected with DATA_LIMIT. Supported map
  keys containing these characters were similarly overcharged. A regression
  reproduced the failure before the production edit.
- **Impact:** Diagnostics discarded supported JSON below the documented byte
  limit and emitted an inaccurate capture-limit state/notice. Multiline textual
  evidence and keys could lose content unnecessarily.
- **Recommendation:** Count the five short control escapes as two bytes, retaining
  six bytes for other escaped controls, the existing bounded scan, and the capped
  output sink. Applied in this context.

## Findings Resolved in This Context

- **P2: Short control escapes overcharged.** Added
  `shortControlEscapesUseTheirActualJsonByteBudgetForValuesAndKeys`, exercising all

  keys. It failed with DATA_LIMIT before the fix. The bounded string scan now uses
