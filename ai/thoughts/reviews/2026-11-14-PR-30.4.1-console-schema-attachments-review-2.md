## Findings Resolved in This Context

### [P2] Include attachment records in the ordinary Records query

The new action is rendered only for `FRAME_METADATA_RECORDED`, but
`TraceExplorer.tsx` omitted that type from `defaultRecordTypes`. Opening the
finalized trace's Records tab therefore excluded every attachment-bearing record
at the server query, hiding the new action. The changed debugging guidance
described selecting Attachments directly in Records. The existing Show all
checkbox provided a workaround, but component-only attachment tests never
exercised this actual explorer query boundary.

Added a filter-aware explorer regression that returns an attachment metadata
record only when the requested type filter permits it. It failed on the initial
candidate because no Attachments button existed (76 other explorer tests passed).
Including `FRAME_METADATA_RECORDED` in the existing developer-relevant defaults
makes the same test pass, loads the inert inline descriptor through the actual
explorer, and leaves Show all unchecked. No new filter system or data contract
was introduced. Final focused verification passes all 156 tests.
