## Findings Resolved in This Context

### [P2] Retain markers under Spring's relaxed YAML prefixes

`ExecutorYamlPropertySourceLoader.retain` used case-sensitive string prefix comparison when descending toward the selected settings. A YAML root spelled `Loomspan` or `LOOMSPAN` is accepted by native Spring binding, but that comparison skipped retention of its authored connection and executor nodes. A connection API-key marker consequently reached terminal binding as an ordinary map and startup failed with `loomspan.connections.primary.api-key has an invalid value`.

An isolated ConfigData boot probe reproduced the marker failure and a literal control with the same capitalized root passed. The committed regression `StartupVariableResolutionIntegrationTest#relaxedYamlPrefixesRetainAuthoredMarkers` then failed before the production fix. It checks lowercase, titlecase and uppercase roots with a capitalized `Connections` section and camelCase `executorConfig` section, observing actual bound provider and namespace settings.

The fix uses the loader's existing `ConfigurationPropertyName` selection helper for ancestor traversal. Both selected-root recognition and parent traversal now use Spring's native name matching. The final forced compilation and 463-test run passed, including the new regression. This context changed only that loader condition, the regression and this review document.
