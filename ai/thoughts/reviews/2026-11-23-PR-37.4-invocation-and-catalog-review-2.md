## Independent reconstruction

The six `SkillTemplate` methods and two `SkillInvocationHandoff` methods require namespace and local name separately. `DefaultSkillTemplate.captureRoot` constructs `SkillIdentity` directly from that pair. Its grammar and combined length checks run before generation capture. No root path invokes owner-relative resolution or decodes an encoded target. A missing namespace or callable fails through the existing `SkillException` boundary.

Preparation retains the existing capture-before-conversion ordering. The captured snapshot entry is used to require the matching capability. Object conversion, map validation, dependency revalidation, entry authorization, session creation and final observer handling continue to operate on the prepared capability and captured generations. Exception and fatal-error paths still release preparation ownership. Handoff captures the same prepared metadata and calling authentication. Its payload is claimed once, and retained execution receives the captured capability, association and authentication. Canonical diagnostic identity now comes from that metadata. The removal of a redundant caller target string does not create another execution lookup.

`DefaultSkillCatalog` validates its namespace, builds descriptors from the registered typed identities and retains immutable sorted metadata. Its `skill(localName)` constructs exactly one pair from the catalog namespace and caller local name, then makes one map lookup. This validates qualified local arguments, grammar and the pair length even on a miss. It has no foreign namespace or alternate spelling lookup. The public records store namespace and local name, validate them with the existing shared validator and derive `qualifiedName()` from those immutable strings. Other required field checks and nullable output schema behavior are preserved. `SkillGenerationManager` produces the same components directly and sorts successful validation metadata by qualified name.
