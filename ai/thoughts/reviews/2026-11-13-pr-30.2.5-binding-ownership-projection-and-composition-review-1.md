## Findings Resolved in This Context

### [P2] Preserve invalid-JSON classification in binding composition

- **Location:** `src/main/java/ai/loomspan/internal/outputschema/OutputBindingComposition.java`, private `validate` adapter.
- **Evidence:** The new adapter classified blank/null text and Jackson parse exceptions as `SCHEMA_VALIDATION_FAILED`. The replaced validator returns `INVALID_JSON` for these cases. `OutputSchemaCallAdvisor` carries the enum into schema outcomes, retry/exhaustion diagnostics and the terminal validation exception.
- **Trigger:** A bound-output model returns no text, whitespace, or malformed JSON.
- **Impact:** The migration misclassifies malformed transport content as a valid JSON instance that violates its schema, regressing the retained diagnostic contract.
- **Correction:** Use `INVALID_JSON` in the two parsing-failure branches. Ordinary well-formed instance failures retain `SCHEMA_VALIDATION_FAILED`.
- **Verification:** Added `OutputBindingCompositionTest.malformedAndBlankContributionsRetainInvalidJsonFailureClassification`. A fresh restricted run failed before the correction (54 tests, one failure, expected INVALID_JSON versus actual SCHEMA_VALIDATION_FAILED). After the two-line fix, all 54 binding tests pass, including null, empty, whitespace, malformed text and a well-formed nonobject control.
