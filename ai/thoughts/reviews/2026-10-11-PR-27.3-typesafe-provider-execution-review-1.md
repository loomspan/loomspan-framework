## Independent Review Evidence

The production delta is confined to `NamedAiConnectionRegistry`. Retry-policy
construction now precedes native allocation. A local client reference owns the
acquired resource until runtime assignment; cleanup chooses the runtime resource
or that local client, preventing duplicate closure. Both safe and generic failure
paths close the unregistered resource and previously registered resources. Generic
failures retain their original cause, safe failures retain their original instance,
and suppressed cleanup failures remain visible while later resources still close.
Normal destroy remains idempotent. Tests observe an actual closed Apache pool,
rather than relying only on mocked close calls.

The surrounding runtime, transport, Spring wiring, usage services, configuration,
and consumer paths were inspected independently before plan conformance. Native
attempts reserve and trace before one physical send; retry bodies remain unchanged.
Response extraction preserves complete object-valued answers. Successful HTTP
usage is recorded before terminal extraction failure, while error-body usage is
excluded. Real-client cancellation aborts blocked I/O without worker cancellation,
and mission gates prevent late response accounting. Success body acceptance is
independent of bounded error capture and trace chunking.

Security review found no changed authentication, authorization, or endpoint/header
boundary. Retaining exception causes is intentional diagnostic fidelity, not a
new content-rewriting path. No automatic masking or sensitivity classification
was introduced. Canonical native evidence and the existing derived-journal
exception remain separate and their regression tests passed.

Java-generated native malformed/provider-error fixtures, Go logical/range/attempt
and terminal-failure views, and TypeScript model/diagnostic rendering agree.
Unavailable and failed continuation cases do not fabricate content. The small
64-byte corpus diagnostic is a reader-state fixture; real invocation tests verify
the actual 1 MiB transport limit. Missing/unequal compatibility marker rejection
and exact release acceptance remain exercised by Go processor tests.
