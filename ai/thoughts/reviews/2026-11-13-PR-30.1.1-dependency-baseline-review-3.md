## Code Review Findings

### [P2] Preserve an explicitly authored Anthropic Authorization header (resolved)

- **Location:** `src/main/java/ai/loomspan/internal/springai/SpringAiProviderIntegration.java:157`.
- **Evidence:** The candidate injected `x-api-key` whenever the custom header map lacked X-Api-Key. `LoomspanProperties.validateHeaders` accepts Anthropic Authorization headers. Both the prior SDK 2.40.1 `StaticAuthHeaders.kt:15-25` and selected SDK 3.4.0 `StaticAuthHeaders.kt:16-23` leave requests unchanged when either auth header already exists. The adapter's injection bypassed that precedence.
- **Trigger:** An Anthropic-compatible connection configured with an API key plus a custom Authorization header, including mixed-case header spelling.
- **Impact:** The request newly sends the API key alongside the explicitly selected bearer credential, changing gateway authentication and potentially routing a previously working connection under another credential.
- **Recommendation:** Add the configured API key only when neither X-Api-Key nor Authorization is authored, with case-insensitive comparison.
