# Research — PR 35.2 provider literals

## Research question and scope

Map current startup and publication provider configuration, authentication validation, Gemini credential consumption, resource loading, tests and documentation for `ai/thoughts/tickets/loomspan-pr-35.2-provider-literals.md`.

The selected profile is Full 5-Step Pipeline. The user authorized confirming the recommended process and continuing through PR 35.4 with one local commit per completed ticket. The checkout was clean at the revision above. This research changes only this artifact.

## Summary

Startup properties already expose literal API keys, headers and Gemini JSON contents. Published configuration accepts the older provider-specific reference fields and excludes their literal counterparts. Both routes bind to `LoomspanProperties`, which owns driver applicability, authentication-mode and header validation. `SpringAiProviderIntegration` constructs provider clients, including explicit service-account credentials from JSON contents. It also has a separate Spring resource loader for credentials by URI.

PR 35.1 added internal authored-node discovery/substitution and portable fixtures, without connecting them to these usable configuration entry points. PR 35.3 owns complete-candidate variable resolution and retirement of published API-key/header/JSON reference fields. PR 35.4 owns effective Spring precedence and literal placeholder delivery. This ticket separately retires the URI fields and loader, while introducing literal published provider settings.

## Current production paths

### Published execution configuration

`ExecutionConfigurationParser` is the strict YAML-to-runtime boundary (`src/main/java/ai/loomspan/internal/skill/ExecutionConfigurationParser.java:19`). Its connection allowlist currently includes `api-key-ref` and `header-refs`, excluding literal `api-key` and `headers` (`:23`). It turns each referenced value into an ordinary flattened property for a Spring `Binder` (`:64`). Header keys are currently authored strings, and reference resolution applies only to their values.

The Gemini nested allowlist contains `vertex-ai`, `project-id`, `location`, `credentials-ref` and `credentials-json-ref` (`:76`). `credentials-ref` becomes the bound `credentials-uri` property, and `credentials-json-ref` becomes `credentials-json`. The two authored reference fields are mutually exclusive. Literal credential JSON is absent from the published allowlist.

The parser accepts only root `loomspan` and publishable `connections`, `models`, `session`, `execution-trace` and `executor-config`. It checks executor target namespace and explicitly flattens typed provider/model/session settings. `scalar` converts a non-null scalar with `String.valueOf` and rejects maps/lists. It binds the flattened map through `MapConfigurationPropertySource`, calls `afterPropertiesSet`, validates session quotas, and returns properties plus captured executor configuration (`:125`). Reference validation uses `unresolved-reference` as a placeholder before resolution. Unused explicit-map entries fail after current provider-only accounting (`:123`).

`DefaultSkillReloader` no-map overloads select the Environment path with an internal null map. Explicit-map overloads reject null and copy the map (`src/main/java/ai/loomspan/internal/skill/DefaultSkillReloader.java:51`). An explicit empty map is already distinguishable from the no-map route. Public `SkillReloader` remains the supported entry point.

`SkillGenerationManager.prepare` first parses without resolution and checks the supplied skills/dependencies. It then parses again using either the Environment or the supplied map and builds an independent runtime (`src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java:162`). Its `validate` path parses without values and builds no provider client (`:175`). The all-literal acceptance therefore spans parser support and the actual public preparation route, not only direct adapter construction.

### Startup configuration and validation

`LoomspanProperties` uses strict configuration binding with `ignoreUnknownFields=false` (`src/main/java/ai/loomspan/autoconfigure/LoomspanProperties.java:26`). `ConnectionProperties` contains `apiKey`, `Map<String,String> headers`, common transport settings and driver-specific option blocks (`:451`). `GeminiOptions` currently has both `credentialsUri` and `credentialsJson` getters/setters (`:529`).

Validation is shared by startup and parsed candidates. OpenAI and Anthropic require a nonblank API key. Gemini requires exactly one of API-key mode or `gemini.vertex-ai=true`. API-key mode rejects a Gemini options block. Vertex mode requires project and location, permits absent explicit credentials, and rejects simultaneous nonblank URI and JSON (`:216`, `:225`). Driver-specific option blocks must match the driver (`:200`). Headers apply only to OpenAI and Anthropic, require HTTP-token names and reject null values (`:247`). Request timeouts retain whole-millisecond conversion and bounded validation (`:187`).

Startup YAML currently delegates ordinary connection values to Boot flattening and binding. `ExecutorYamlPropertySourceLoader` specially transports only executor configuration as an opaque raw value, and `ExecutorConfigurationBinding` converts it. Effective marker resolution and preventing another placeholder pass are assigned to PR 35.4 by its explicit acceptance criteria.

### Provider adapters and URI loading

`SpringAiProviderIntegration.openAi` passes the API key to official Responses options and copies custom headers, including configured OpenAI project (`src/main/java/ai/loomspan/internal/springai/SpringAiProviderIntegration.java:114`). `anthropic` passes its API key and headers, supplying `x-api-key` when neither that header nor Authorization was authored (`:137`).

Gemini builds the existing Google GenAI client with one-attempt HTTP options (`:153`). API-key mode supplies `builder.apiKey`. Vertex mode sets vertex/project/location, then prefers a nonblank credential URI over nonblank JSON. With neither supplied it leaves the builder's existing credential behavior in place. The service-account JSON path uses UTF-8 bytes in a `ByteArrayInputStream` and `ServiceAccountCredentials.fromStream`, so its input is JSON contents and can include multiline contents (`:473`). Its local error currently mentions the older published `credentials-json-ref` name.

The URI path uses `resourceLoader.getResource(uri).getInputStream()` and `GoogleCredentials.fromStream` (`:460`). The `ResourceLoader` field and constructor parameter exist for that path. All production construction is in `LoomspanAutoConfiguration.skillGenerationManager` (`src/main/java/ai/loomspan/autoconfigure/LoomspanAutoConfiguration.java:169`), which injects a ResourceLoader and passes it to this internal integration. Tests instantiate the integration with DefaultResourceLoader or mocks. These constructors are internal implementation, including their public Java declarations.

`NamedAiConnectionRegistry` and `ProviderFailureGuidance` currently name `gemini.credentials-uri` among applicable diagnostic settings (`src/main/java/ai/loomspan/internal/autoconfigure/NamedAiConnectionRegistry.java:65`, `src/main/java/ai/loomspan/internal/provider/ProviderFailureGuidance.java:73`).
