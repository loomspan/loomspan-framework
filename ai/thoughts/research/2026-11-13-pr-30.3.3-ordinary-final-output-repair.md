## Summary

Ordinary interaction requests are built by SpringAiModelInteraction and executed
through Spring's ToolCallingAdvisor, the canonical manager, and the physical
ProviderAttemptCallAdvisor. The three ordinary validators currently re-enter
their downstream advisor chains with independently built correction prompts.
There is no existing completed-history/raw-candidate/terminal-repair holder in
SpringAiModelInteraction. Tool history is available at the canonical manager's
delegate-return boundary; raw provider output is available before the schema
advisor's optional output composition.

The agreed ticket approach is narrowly specified in the ticket and retained
TBD-11 mechanism probe. That historical probe uses synthetic correction components;
it is not evidence that the current Framework's real three-advisor path satisfies
the ticket. Existing real loopback tests and actual-source local build scripts
provide the current executable integration seams.

The clean-checkout root Maven attempt failed at production compilation before
any requested tests could execute. Its eight errors are surviving legacy
TypeSafe/catalog references owned by PR 30.3.4. This ticket does not own their
restoration. Root/public-surface verification remains blocked, and the ticket
requires its own behavior to have deterministic local executable evidence rather
than treating that baseline failure as permission to defer ordinary repair.

## Current flow and ownership

### Interaction and advisor wiring

- `src/main/java/ai/loomspan/internal/springai/SpringAiModelInteraction.java:41`
  builds each call independently from system/user input, renders attachments as
  user media, adapts capabilities into callbacks, and exposes PlannerInabilityTool
  only for non-planning STANDARD interaction. Advisor parameters carry trace,
  output contract, and planning-call marker. No call-local repair state is
  allocated or passed to tool context today.
- `SpringAiModelInteractionFactory.java:36` chooses the ordinary or step client.
  `SpringAiChatClientAssembler.java:53` configures the real Spring
  ToolCallingAdvisor with CanonicalToolCallingManager and the Spring delegate.
  Unlimited Spring tool-call caps leave Loomspan's own budgets authoritative.
  The assembler's recoverableFeedback processor preserves existing ordinary
  argument/capability feedback handling; this is separate from final repair.
- `SpringAiChatClientAssembler.java:124` starts from typed model-default options
  and combines execution configuration. This is the point at which typed
  options and callback defaults enter the request surface. It cannot be assumed
  that a generic options object or prompt instruction clears defaults.
- `SpringAiChatClientAssembler.java:144` removes all three final validators from
  STEP_EXECUTION clients and always adds physical-attempt instrumentation.
  Schema and linter advisors also explicitly bypass planning requests.
- `DefaultSkillAdvisorResolver.java:100` constructs schema, evidence, and linter
  advisors from the captured definition. Schema binding composition changes
  advisor order deliberately: default ordering is linter (-100), schema (-90),
  evidence (-80); bound schema uses -70 so other validators see composed output.
  Preserve that ordering and its differing raw-versus-assembled boundaries.

### Ordinary schema correction

`src/main/java/ai/loomspan/internal/outputschema/OutputSchemaCallAdvisor.java:86`
augments the baseline prompt with schema guidance, stores the generation contract
in context, and calls the downstream chain. It validates returned text; with
output bindings it composes and validates a complete result using
OutputBindingComposition. When successful, lines 125–149 replace text parts once,
retain non-text parts and original metadata, and return application-facing text.

At lines 186–189 correction is built from baselineRequest, not the previous
retry. `buildRetryPrompt` at line 259 adds a newly constructed text-only
AssistantMessage(candidate) plus a UserMessage correction. It preserves baseline
options. Thus current unit behavior explicitly excludes previous rejected
candidates while keeping the latest candidate in full; that unit behavior is
not a completed-history capture. Exhaustion throws
LoomspanOutputSchemaValidationException and records its existing outcome.

Binding composition is created under the owning MissionContext and verifies the
same mission on reuse (`invocationComposition`, line 198). It uses the captured
definition and mission snapshot; repair does not own binding-source recapture.

### Linter and evidence correction

- `src/main/java/ai/loomspan/internal/linter/LinterCallAdvisor.java:73` retains
  currentRequest across retries; line 116 appends feedback via system-message
  augmentation. It does not add candidate/history messages. Exhaustion returns
  the last response and failed LinterOutcome rather than throwing.
- `src/main/java/ai/loomspan/internal/runtime/evidence/EvidenceContractCallAdvisor.java:50`
  follows the same request-retention pattern. It validates against the owning
  mission's successfulDirectSkills, records failures, and throws
  LoomspanEvidenceValidationException at exhaustion. `appendHint` at line 115
  uses OutputValidationFeedback.ordinaryEvidenceHint and existing system text.
- Feedback, correction counts, recorder behavior, and differing exhaustion
  policies are independent of carrying completed exchanges forward. These are
  explicit preservation controls in the ticket.

### Canonical dispatch, histories, and raw provider output

- `src/main/java/ai/loomspan/internal/springai/CanonicalToolCallingManager.java:36`
  first applies the shared provider response-status guard. It checks a bound
  callback surface, validates every selection before any dispatch, normalizes
  canonical names, rejects blank argument roots, and handles planner-inability
  control separately. The final delegate call returns ToolExecutionResult
  directly at line 99; its conversationHistory is not retained separately.
- Name correction currently preserves every other MessagePart object, payload,
  attributes, and message metadata. CanonicalToolCallingManagerTest includes
  rich parts and unchanged-name identity assertions. The old text/tools/media
  reconstruction noted in historical research is already replaced in this
  checkout; do not duplicate that earlier migration.
- `src/main/java/ai/loomspan/internal/chat/ProviderAttemptCallAdvisor.java:62`
  prepares native output contracts, requires the trace context and execution
  binding, reserves each physical attempt, records the request, calls downstream,
  accounts response receipt once, checks status, and returns linkedResponse at
  line 152. The AssistantMessage here precedes upstream output composition.
  There is currently no raw-output handoff to ordinary correction state.
- Provider transport retries use chain.copy(this) on the same request, separate
  from semantic retry budgets. Cancellation is checked before reservation and
  during backoff. The ticket does not authorize changing that retry/accounting
  ownership.
- `NativeOutputContract.java:43` makes typed per-request copies for Responses,
  Anthropic, and Gemini. It retains generation contract and existing request
  options and records prepared schema separately. Repair option copies interact
  with this code; both native output settings and removal of executable tools
  must reach actual serialization.
