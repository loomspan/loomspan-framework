# Research — PR 37.1 declarations

## Research question

Map the existing YAML and Java declaration paths, owner assignment, identity validation, registration indexes, focused evidence and authoring documentation for `loomspan-pr-37.1-declarations.md`.

## Summary

The implementation already carries an ordered `SkillIdentity(namespace, localName)` and keeps callable and reference-only executor registrations separate. Configured YAML receives owner `default`; application-supplied documents receive the namespace passed through `SkillReloader`. Both Java annotations default to `default`, and their shared processor selects an explicitly nonempty name or the Java method name verbatim. Existing component validation permits uppercase and underscores, normalizes namespace case, and encodes qualified identities with one hyphen. These rules are shared by declarations and downstream lookup, planning and dispatch consumers.

This research describes the checked-out implementation. The controlling ticket and design explicitly authorize replacement of these rules across the eight-ticket series. The developer authorized breaking changes without compatibility shims, current-state consumer documentation, local commits after each completed ticket and an uncommitted Sidecar handoff edit at the end of the series.

## Detailed findings

### Identity representation and validation

- `src/main/java/ai/loomspan/internal/core/SkillIdentity.java:6` defines the internal record. Its compact constructor normalizes the namespace, validates the local name and checks the combined length with one separator character.
- `SkillIdentity#component` accepts `[A-Za-z_][A-Za-z0-9_]*`. Namespace length is capped at 32, local length at 64, and combined length at 64. Reserved substrings are currently accepted.
- `SkillIdentity#normalizeNamespace` validates then calls `toLowerCase(Locale.ROOT)`. Local names retain case. `parse` requires exactly one hyphen, and `resolve` treats any hyphen-bearing reference as qualified. `toString()` returns `namespace-localName`.
- The constructor is shared by YAML declarations and both Java annotation roles. `CapabilityMetadata` stores the record and derives `name()` from it. Its string constructors parse encoded identities, and its tool descriptor must have the same name.
- Namespace validation also feeds `ExecutorConfiguration`, retained execution metadata, generation ownership, catalog acquisition, publication and removal. `SkillIdentity.parse/resolve` feed authored fields, dependency traversal, model tool dispatch, plans and worker actions. A change to this shared class reaches those later-ticket consumers even when declaration registration is the immediate entry point.

### YAML startup and supplied publication

- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:140` resets configured loading to namespace `default`. Discovery records each configured location pattern and resource in `DiscoveredYamlSkillResource`, then reads resource bytes. Its directory hierarchy contributes no owner assignment.
- `YamlSkillCatalog#checkedSupplied(String, List, boolean)` validates/normalizes the supplied namespace. The default overload delegates with `default`.
- Supplied YAML is wrapped in a `ByteArrayResource` and `YamlSkillSource` with its exact `SkillDocument.sourceName` label. Null/blank labels, duplicate labels and null YAML are reported before loading. Labels are diagnostic content.
- `YamlSkillCatalog#loadDefinition` reads raw `name`, validates it using `new SkillIdentity(namespace, skillName)` in `validatePublicSkillName`, and constructs `YamlSkillDefinition` with that owner. `YamlSkillDefinition` retains the identity alongside the manifest and source bytes.
- `YamlSkillCatalog#addDefinition` uses `putIfAbsent(definition.identity().toString(), definition)` and reports duplicate identities with source locations.
- `src/main/java/ai/loomspan/internal/skill/DefaultSkillReloader.java:42` validates the namespace before obtaining a preparation view. `prepareInternal` does the same before preparing the candidate. The manager then supplies the namespace to a new YAML catalog and dependency validator.
- `SkillGenerationManager#initializeStartup` builds a Private default generation from configured YAML, then additional Private generations for fixed Java owners. Java-only and executor-only owners are included. `SkillGeneration` verifies that keys and stored identities match the containing namespace.

### Java annotation discovery and indexes

- `src/main/java/ai/loomspan/api/SkillMethod.java:15` declares the supported annotation with `name() default ""`, `namespace() default "default"` and required `description()`. `SkillExecutor` has the same name/namespace defaults plus `config() default ""`.
- `src/main/java/ai/loomspan/internal/core/SkillMethodBeanPostProcessor.java:182` has one `identity` method for both roles. `localName.isEmpty() ? method.getName() : localName` selects the name verbatim. Invalid identity exceptions identify the annotation role, bean and generic method signature. The current diagnostic includes the underlying grammar error.
- Discovery canonicalizes bridge/interface methods, resolves annotation metadata and detects conflicting roles. The processor retains invocation against the final managed bean/proxy. These discovery mechanics also have focused target-discovery and shared invocation tests.
- `registerSkillMethod` constructs `CapabilityMetadata` and uses a callable `capabilitiesByName` map. `registerExecutor` requires exactly one `SkillExecutorInvocation` parameter, creates `SkillExecutorRegistration` and uses a distinct `executorsByName` map. Each uses `putIfAbsent` and reports both conflicting declaration locations.
- A callable and executor can therefore have the same identity. They remain different registrations. An executor registration alone contributes no callable schema or catalog skill.
- `src/main/java/ai/loomspan/internal/skill/SkillDependencyValidator.java:55` first indexes fixed Java callables for the candidate owner, then reports a duplicate when a YAML definition has an existing callable identity. It separately indexes fixed executors in the candidate namespace view. Same local names in different owner generations are distinct.

## Architecture and series context

Registration is already owner-aware. Canonical string keys connect separate registration maps to generation metadata and downstream runtime consumers. The shared record is therefore both the declaration validator and the codec used by lookup/runtime collaborators. The proposal assigns colon-qualified Loomspan references and double-hyphen provider spellings to distinct boundaries. PR 37.2 owns discovery path spelling, PR 37.3 authored references, PR 37.4 public invocation/catalog accessors, PR 37.5 model/worker dispatch, and PR 37.6 Console identities. PR 37.7 audits documentation and PR 37.8 closes integration and deferred checks.

Historical context comes from `ai/thoughts/future/portable-skill-naming.md` and the eight PR 37 tickets. The current file-under-directory startup implementation assigns `default` directly. Supplied source labels are arbitrary diagnostics. No location-derived namespace logic was found in these declaration paths.
