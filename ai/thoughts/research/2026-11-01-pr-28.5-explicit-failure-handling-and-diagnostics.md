# Research: explicit Java failure handling and diagnostics

## Research question and execution context

Map the current implementation and verification boundaries for
`ai/thoughts/tickets/loomspan-pr-28.5-explicit-failure-handling-and-diagnostics.md`.
This is pipeline Step 1, selected profile **full**, approved by the developer
after Step 0. Step 0 and this research began against a clean checkout. No
production changes or tests were performed during research. Metadata came from
`bash ai/scripts/spec_metadata.sh`; the displayed client date is November 1,
2026, America/Los_Angeles.

The controlling context is the ticket, `AGENTS.md`, `loomspan-console/AGENTS.md`,
the accepted configured-Java-executor design, the feature design lens, and the
pipeline's shared protocols. The ticket deliberately authorizes changes to the
current diagnostic contract and broad feedback behavior, with no historical
reader or compatibility path. Step recovery is a separate effort.

## Summary

Both Java roles already use one managed-bean invocation and result conversion
path. Their Java-boundary failure policy recognizes the designated public
`RecoverableSkillException` after reflection/proxy unwrapping. That policy is
currently package-private and does not own tool feedback or canonical failure
recording. Standard tool execution uses Spring AI 2.0.0's default exception
processor behind the existing canonical-selection manager.

Failed child calls are recorded and rethrown before the Spring AI adapter sees
them. Success credit and completed-result binding have separate success paths.
The canonical failure recorder currently aliases any recorded exception found
in an arbitrary cause chain; provider correlation uses a separate cause-chain
map. Console stores terminal-completion linkage, exception type, contextual
message, and stack descriptors, but no explicit recoverability fact. Its failure
diagnostic heading calls a nonterminal failure “Recovered failure.”

## Detailed findings

### Shared Java invocation and direct reporting

- `src/main/java/ai/loomspan/internal/core/JavaSkillInvoker.java:20` invokes the
  final managed bean through reflection and resolves JDK/CGLIB-compatible
  invocable methods. An `InvocationTargetException` passes through
  `SkillFailurePolicy.propagate`. Null becomes empty text, strings remain exact,
  and other successful values use the configured Jackson mapper. Serialization
  failure throws `IllegalStateException` with its Jackson cause.
- `src/main/java/ai/loomspan/internal/core/SkillFailurePolicy.java:13` unwraps
  only `InvocationTargetException` and `UndeclaredThrowableException`; it does
  not search arbitrary causes. `recoverable` tests the normalized top-level
  object against `RecoverableSkillException`. Runtime failures propagate;
  checked failures receive `UndeclaredThrowableException`; `Error` is thrown.
- `src/test/java/ai/loomspan/internal/core/SharedJavaDiscoveryInvocationTest.java:48`
  parameterizes callable/executor invocation, exercises a real proxy, exact
  successful text, recoverable message/cause propagation, ordinary application
  wrappers, `SkillException` wrappers, cancellation, access denial, fatal errors,
  and serialization failures. Other methods cover actual JDK/CGLIB and method
  security dispatch. This supplies an existing common test seam for the two
  forms rather than independent discovery implementations.
- `src/main/java/ai/loomspan/internal/core/ExecutionCoordinator.java:170`
  invokes executor-backed YAML leaves using captured binding/configuration and
  `SkillExecutorInvocation`; callable Java roots invoke their captured callable.
  Model-backed YAML selects standard or explicit-step execution separately.
  Its catch at line 198 records failures unless primary lifecycle cancellation
  supplies the controlling identity, then rethrows.
- `src/main/java/ai/loomspan/internal/skillapi/DefaultSkillTemplate.java`
  preserves `AccessDeniedException` and existing `SkillException` subtypes;
  ordinary runtime failures receive the facade's contextual `SkillException`
  with original cause. `RecoverableSkillException` is already a supported
  `SkillException` subtype. Existing observer/finalization logic preserves the
  primary execution failure if later observation also fails.

- The successful return branch at lines 207-228 alone records task completion,
  unplanned successful-skill credit, success outcome, and `TOOL_CALL_COMPLETED`.
  Spring feedback happens outside this invocation, after the throw has traversed
  that recording path.
- Bound result assembly requires a completed producer task and an accepted

  The invoker's `ChildInputBindingAssembler` path makes those checks explicitly.
- `src/main/java/ai/loomspan/internal/runtime/usage/DefaultSessionUsageService.java:47`
  increments/enforces skill invocations; lines 59-86 meter model responses,

  Outcomes are metrics, not counter refunds. The existing snapshot belongs to
  the session; normal continuation uses these same owners.
- `src/main/java/ai/loomspan/internal/runtime/MissionWorkExecutor.java:45`
  submits one bounded mission and waits using the captured timeout. A standard
  model/tool continuation is inside that submitted work, rather than a new
  parent mission wait. The catch at line 112 first considers primary lifecycle
  cancellation, then unwraps `ExecutionException` to runtime/error or a
  contextual checked-failure wrapper. Timeout/interruption/cancellation follow

- Existing `JavaSkillMissionCutoffTest`, `JavaSkillLifecycleIntegrationTest`,

### Explicit steps terminate and keep success results separate

### Canonical failure identity and bounded diagnostics

- `src/main/java/ai/loomspan/internal/core/LoomspanSession.java:147` is the
  canonical `ERROR_RECORDED` boundary. Under the session lock it walks up to 64
  arbitrary causes, collects provider correlation, and returns an already
  recorded failure identity for any recorded cause. It maps the incoming
  wrapper to that earlier record. A fresh record stores one failure ID, origin
  frame, optional attempt/retry IDs, context payload, exception type, and stack.
- `TraceFailureMetadata.java:18` currently writes the throwable class and the
  caller's nonblank contextual message. It does not emit recoverability or an
  independent exact application-message field. Callers use summaries such as
  “Tool execution failed” and “Assigned task execution failed.”
- `LoomspanSession.java:204` separately registers provider attempt links by
  throwable/cause identity. This correlation has a different purpose from
  deciding whether two failures are one failure; both maps currently participate
  in the recorder loop.
- `BoundedStackTraceCapture.java:15` captures 1 MiB of valid UTF-8 stack text,
  including Java's cause/suppressed diagnostics. Head/tail retention and an
  explicit omission marker support bounded capture. Diagnostic descriptors
  carry truncation and limit facts. Canonical content is not field-redacted.
- `LoomspanSessionTest` covers recording/deduplication and bounded diagnostics;
  `ExecutionTraceContractTest`, `LoomspanSessionRunnerTest`, and
  `ExecutionCoordinatorTest` exercise recording and finalization consumers.

## Contract inventory and feature-lens assessment

| Surface | Current classification and evidence |
| --- | --- |
| `RecoverableSkillException`, SkillMethod/SkillExecutor declarations, facade | Application API: closed architecture allowlist and README; exact exception text and public behavior are consumer-visible. No new public API is prescribed by this ticket. |
| Policy, invokers, manager assembler, coordinator, lifecycle classes | Internal or accidentally exposed implementation, including Java-public internal classes. No supported SPI or bean replacement contract exists. |
| Spring AI processor interface | Dependency integration seam used internally, not a new Loomspan supported SPI. |
| Planning/limits configuration | Configuration and manifest contracts; this ticket retains quotas, deadlines, slot semantics and explicit-step termination. |
| Canonical error records and current Console query DTOs | Ephemeral diagnostic formats with deliberate exact-release consumers, not historical analysis contracts. Current Java/Go/web/MCP fixtures establish observable current behavior. |
| Saved complete trace artifact | Narrow same-exact-marker import/export behavior; no general historical reader or migration promise. |
| Derived journal and SkillExecutionEvent details | Current-version diagnostic projection; retains the established journal-only field-name redaction exception. Public value constructors remain supported API. |

The framework owns failure disposition and records its authoritative meaning;
Console currently derives terminal linkage but does not own Java recoverability.
The requested work affects skill authors' failure choice, callers' reporting,
and developers' diagnostic interpretation. It does not add business state,
executor lifecycle, or a recovery engine. Existing shared Java invocation,
tool processor hook, failed-call recording, session usage, and canonical failure
recording are the relevant existing owners.

The ticket explicitly selects an atomic current-contract change without shims.
There are no deployed consumers requiring adapters. The compatibility marker
comes from `src/main/resources-filtered/META-INF/loomspan-release.properties:1`
using Maven `${project.version}`; current project version is
`1.0.0-beta.9-SNAPSHOT`. `ConsoleTraceFixtureCorpusTest:273` asserts that exact
value. The marker decision must therefore address release identity, rather
than invent an independent schema counter.

## Documentation routing and drift

Consulted the checkout's `agent-skills/loomspan-docs/SKILL.md` as required by
the shared docs protocol after inventorying source and tests. Its declared
`1.0.0-beta.9-SNAPSHOT` matches this checkout's pom. Relevant routed sets are
`java-api` and `skill-authoring`; entrypoints, Java declarations, observation and
errors, and the failure/debugging portions of traces-and-debugging were read.

- **Aligned**: Java-boundary designated exception construction, exact message,
  reflection/proxy wrapper treatment, direct failure propagation, and lack of
  automatic step recovery match the current code.
- **Aligned baseline changing intentionally**: traces-and-debugging says normal
  wrappers around recorded causes reuse the failure ID, matching today's
  recorder. PR 28.5 expressly changes this rule to distinct application-wrapper
  identity with recorded-cause linkage; that prose needs coordinated revision.
- **Documentation coverage gap within ticket scope**: current declaration/error
  guidance only promises the Java-boundary designation. Standard designated
  feedback, explicit canonical classification, and the distinction between
  classification and observed correction are not yet documented contracts.
  This is the ticket's requested change, not an unexplained source defect.
- Observability/debugging and observation guidance are affected because readers
  must distinguish classification, contextual summary, exact application
  message, terminal completion linkage, and actual continuation.
