## Summary

The independently versioned Decisions JAR exists as a Maven scaffold and contains
no Java implementation, transport, auto-configuration or tests. Framework's exact
v1 invocation and bounded diagnostics are implemented. They supply captured maps
and live lifecycle observations, without a public invocation constructor, physical
HTTP cancellation registration, native provider registry, or usage-reporting API.

Native code is evidence only: it owns Apache connections per native connection,
disables redirects and implicit retries, bounds error capture, and distinguishes
status/transport failures before JSON parsing. Its response timeout is explicitly
an inactivity limit. Pack-owned total deadlines and lifecycle/retry cooperation
remain this ticket's work. No Framework change is required by existing evidence.

Fresh primary provider documentation was retrieved on **2026-11-16 PST**, without
inference or authenticated account access. It describes the TypeSafe System One
wire protocol and an OpenRouter-compatible prefix. Representative synthetic wire
examples below establish fixture material; the implementation stage owns their
test-resource files and release-aligned pack documentation.

### Existing native HTTP behavior and tests

`internal/typesafe/TypeSafeClient.java:39` captures native connection URL/key/header
properties. It strips trailing slashes and appends `/v1/systemone`. Its Apache
pool and client are constructed per native connection. Configuration at lines
49–71 sets response/socket timeouts, disables automatic retries and redirects.

`send()` at line 78 sets request auth and body and registers an internal lifecycle
physical future whose cancellation calls `request.cancel()`. This is unsupported
internal machinery and is not an available pack API. Success reads the entire
body; error capture reads at most 1 MiB plus a truncation sentinel, preserves
complete UTF-8 characters and cancels truncated requests to avoid draining an
unbounded remainder. `translate()` at line 146 classifies HTTP statuses independently
of body decoding, with transient statuses 408/429/500/502/503/504/529. This list and
capture ceiling are native evidence, not preselected pack defaults.

deterministic local-stub anchors:

### Diagnostics and containment

`api/extensions/v1/ExecutorDiagnostics.java:37` defines exactly `info`, `warn` and
`error`, each with message-only and `(String, Object)` overloads. The documented
closed JSON capture set includes ordinary scalar numbers/strings/booleans/null,
exact supported JDK maps/lists and arrays; DTOs, custom collections and JsonNode
objects are not the diagnostic object contract. Actual supported maps/lists from
business decoding can be supplied without provider DTOs or implicit conversion.

Per-call limits are 8 KiB message, 32 KiB JSON data, 48 KiB envelope, depth 32 and
4,096 values/keys. Per invocation: 128 attempts and 256 KiB developer envelopes,
four ordinary notices plus one reserved limit notice, four warning attempts.
Calls after return/failure/cutoff are ignored before inspecting data.

`internal/core/DefaultExecutorDiagnostics.java:54` serializes calls, captures and
appends within RuntimeException containment, independently bounds fallback notices
and logging, and suppresses reentry. Existing records are
`EXECUTOR_DIAGNOSTIC_RECORDED` and
`EXECUTOR_DIAGNOSTIC_SYSTEM_NOTICE_RECORDED`, within existing frames/content paths.
Ordinary diagnostic faults after method entry do not change business results or
replace original failures. Caller expression evaluation, business preparation/
serialization, JVM-wide failures and pre-existing automatic observation are outside
this new guarantee. `DefaultExecutorDiagnosticsTest`,
`BoundedExecutorDiagnosticCaptureTest` and `ExecutorDiagnosticsIntegrationTest`
already exercise these paths. 31.1.3's execution notes record restored Console
reader/corpus support and generic usage tests; no outstanding debt is handed here.
