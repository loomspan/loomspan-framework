## Summary

The current manager has independent active namespace generations and target-only publication revision checks. Its root `capture(namespace)` acquires one lease for the entry generation under `generationMonitor`. Root input preparation uses that capture, while execution bindings carry one generation. The immutable generation already stores visibility, definitions, prepared input contracts, and derived tool output schemas.

`SkillDependencyValidator` is the metadata-only policy owner used by preparation. It walks transitive outgoing declarations, checks source-to-target visibility, resolves YAML input contracts, validates child input bindings, computes effective output schemas through forwarding, rejects forwarding cycles, and validates output bindings. Its current entry point starts from every candidate definition, overlays candidate declarations over external namespace metadata, and returns contracts/effective schemas separately from immutable published capability metadata. It does not compare recomputed contracts to published prepared contracts during root admission because root admission currently does not call it.

The existing lifecycle already accepts `AutoCloseable` generation ownership and delays release until root execution and all registered physical mission work are complete. Handoff payloads preserve generation IDs independently of ownership and retain captured authentication. Validation currently checks input/root RBAC and closes its lease without creating a root or session. Root boundary normalization currently extracts the parsed namespace but still looks up the original argument string.

## Detailed findings

### Namespace publication, immutable generations, and capture

- `src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java:57` stores `active` namespaces; `generationMonitor` protects publication/removal, preparation metadata capture, owner counts, and retirement selection. Startup initialization is separately one-shot and initializes fixed Java/REST registrations.
- `capturePreparation` at line 146 returns `PreparationView(namespace, baseId, Map.copyOf(active))`. This is metadata-only and acquires no executable leases. `SkillDependencyValidatorTest#capturedMetadataSurvivesPublicationRemovalAndResourceRetirement` demonstrates that preparation can still read retained immutable metadata after the provider registry has retired.
- `publish` at line 279 checks only target namespace base ID and lifecycle state, then atomically selects the candidate. `remove` checks the requested exact current generation, removes the association, and marks the old state superseded. Incoming dependents are not scanned. `SkillReloaderTest#dependencyChangesNeverInvalidateTargetPublication` covers replacement, visibility change, removal, and recreation between preparation and caller publication.
- `capture` at line 306 normalizes the namespace, reads its active generation, increments that generation's owner count, and returns `Capture(generation, OwnerLease)` within `generationMonitor`. It does not receive an entry skill identity or traverse children. A missing namespace fails with `SkillReloadException`; no namespace is created.
- `OwnerLease` at line 383 is idempotent using an atomic closed flag. Closing decrements owner count under the monitor and dispatches selected retirement after leaving it. Retirement requires superseded state and zero owners; dispatch closes the runtime and invokes captured listeners with isolated failures. Shutdown clears active associations, marks every published state superseded, and retires owner-free states.
- `SkillGeneration.java:45` copies capability and definition maps, checks namespace/key/kind consistency, and builds eager immutable catalogs. It holds final namespace, ID, visibility, runtime, definitions, and capabilities. `visibility()` is captured on the generation itself. `owns(capability)` uses exact object identity in the generation map.
- `prepareCatalog` in the manager constructs capabilities from the validator's resolved input contracts and output schemas, then invokes the runtime factory exactly once for that candidate. No runtime construction occurs in `capture` or the dependency validator. IDs combine an instance UUID and monotonic counter, independently of namespace creation history.

### Root API and argument handling

- `api/SkillTemplate.java` exposes exactly two validate and four invoke signatures, including both Object and Map inputs and optional observers. `api/SkillInvocationHandoff.java` has Object and Map handoff signatures. `api/AdmittedSkillInvocation.java` exposes entry `generationId`, two invoke signatures, and release; there is no dependency-map accessor.
- `internal/core/SkillIdentity.java:6` is the shared structured parser/formatter. Exactly one hyphen separates namespace and local name; components use ASCII letters/digits/underscores, namespace is lowercased with `Locale.ROOT`, local name case is preserved, namespace limit is 32, and combined identity limit is 64. Invalid/unqualified input is rejected without alternate encodings.
- `DefaultSkillTemplate.java:115` captures before Object conversion and rejects null Object input. It converts through the application mapper into Map, then follows the shared preparation path. Map input follows capture directly; null Map becomes empty only when the prepared input contract allows it. Every failure path closes the lease, including Error.
- `rootNamespace` at line 146 parses the supplied argument but returns only its namespace. `prepareMap` and `requireSkill` retain the original supplied string. Canonical descriptor names therefore work, while uppercase namespace normalization is not yet applied to capability lookup. `DefaultSkillCatalog` already normalizes lookup independently and catalogs do not own resource leases.
- `PreparedInput` at line 324 currently contains entry generation, capability, normalized input validation, and a concrete manager `OwnerLease`. It contains no reachable association.
- Input values are passed only as business input to validation/execution; the root namespace comes from the host argument. There is no input-driven namespace override or namespace view API in the inspected root implementation.

### Authentication, validation, and handoff

- `validatePrepared` at `DefaultSkillTemplate.java:189` reads current authentication, checks the requested capability's policy through `SkillRoleEvaluator`, and always closes its temporary lease. It does not call `FrameworkExecutionLifecycle.admitRoot`, create sessions, bind execution identity, invoke observers, or run the router.
- Direct invoke reads authentication after input preparation and passes it to `LoomspanSessionRunner`. Router execution checks entry authorization via `DefaultAccessGuard`. Current preparation does not pre-check root RBAC for direct invocation or handoff.
- `DefaultSkillInvocationHandoff.java:41` prepares input, captures authentication, and creates a lifecycle root with the same lease. It does not call the root role evaluator in the current admission path. Errors close ownership.
- Its admitted handle stores generation ID and skill name as final fields outside the atomic payload. Claiming takes the payload once, invokes with its captured authentication, and uses the reserved root. Explicit release drops payload and closes the pending root. Framework pending termination drops payload. Generation-ID reads are side-effect-free after any terminal state.
- `DefaultAccessGuard` uses explicit invocation authentication when supplied, otherwise the immutable session authentication. It delegates only role evaluation currently; namespace call authorization is PR 27.4 scope. Existing role evaluator semantics and scoped Java/REST security contexts remain authoritative.

### Dependency metadata inventory and validators

- `SkillDependencyValidator.java:21` is package-private and explicitly metadata-only. `check` takes target namespace, checked supplied documents, candidate visibility, and external generation map. Fixed Java capability metadata and discovered REST bean names are constructor inputs.
- `check` builds names/definitions for the complete candidate plus all foreign generations; references returning to the candidate namespace cannot fall back to its old active generation. It traverses every candidate definition, tracks visited qualified skill names separately from namespace association, and records a reachable definition list. Java skills have metadata but no YAML definition and terminate traversal.
- `visit` at line 297 iterates every `allowedSkills()` reference without role/task-choice pruning. Each outgoing edge checks existence and source namespace versus target visibility before recursion. Repeated target visits terminate recursion without suppressing the current source edge check. REST/TypeSafe leaves have empty allowed constraints from parsing.
- `YamlSkillDefinition.java:18` stores a copied manifest, immutable typed allowed constraints, structured identity, parsed forwarding identity, compiled output bindings, effective execution configuration, and evidence contract. Accessors copy mutable manifest fragments. `allowedSkills()` derives canonical references from constraints. No dependency revision history or schema-assumption registry exists.
- `CapabilityMetadata` stores the prepared input contract and `CapabilityToolDescriptor`, whose output schema is the resolved effective schema computed at preparation. These existing published representations carry caller-derived contracts; catalogs are eagerly mapped from this metadata. The validator returns recomputed structures without editing these representations.
- `SkillInputContractResolver.java:39` resolves explicit YAML inputs or generic object inputs; Java contracts resolve from reflected schemas. `toJsonSchema` and typed `SkillInputSchemaNode` already supply input schema representations. There is no admission-specific schema substitution.
- `ChildInputBindingDeclarations.java:14` validates receiver destination paths, parent-input paths, declared child producers, producer task-count feasibility, self-dependencies, overlaps, and child-result dependency cycles. Unknown/open schema branches remain runtime obligations. Its current checks do not compare all historical child schemas or guarantee value transfer compatibility across arbitrary schemas.
- `SkillDependencyValidator#resolveOutputSchema` at line 240 recursively follows `outputFromSkill`, rejects forwarding cycles, and derives ordinary/TypeSafe model output metadata from declared schema. Java/REST/unspecified outputs remain absent. Evidence-specific annotations are excluded by `outputSchemaMetadata`.
- `validateOutputBindings` at line 105 checks selected source/destination paths, direct producer existence and feasible counts, type/nullability/enum compatibility, object constraints, and arrays. It uses the recomputed effective child schemas. `applyOutputDefaultOpenness` treats output objects as closed by default for these checks. There is no generic schema normalizer.
- Forwarding declaration requirements are enforced by `YamlSkillCatalog#validateRawOutputFrom` at line 489: explicit planning, only a skill selector, no conflicting parent output schema/linter/retry declarations, and a direct required child with max_tasks 1. Other declaration-only planning and schema validations execute while documents are loaded.
- Generated-plan validators `PlanInputBindingDependencyValidator` and `PlanOutputBindingProducerValidator` operate on an actual generated execution plan, not the registry capture. `ExecutionCoordinator` applies live execution limits/mission behavior. These are distinct from metadata-only admission checks.

### Execution binding and physical-work ownership

- `ExecutionBinding.java:11` carries session, optional mission, physical branch, and one generation. `withMission` and `forkBranch` preserve that generation. `ExecutionBindingScope.java:67` rejects binding a different session inside an existing scope and restores the old binding in finally.
- `LoomspanSessionRunner.java:252` registers a root with any passed `AutoCloseable` generation owner. Failure before admission closes ownership. `executeAdmittedRoot` claims a reserved root, constructs a fresh UUID session using entry generation runtime/settings/ID, installs `ExecutionBinding.sessionOnly`, completes session/observer handling, and completes root execution in finally.
- Nested direct root execution and admitted-root execution reach the same fresh-session binding rejection. Validation and handoff preparation do not install a session, so the binding restriction does not prohibit them. Cleanup must account for failure after a root was claimed but before action execution.
- `FrameworkExecutionLifecycle.java:307` owns `AdmittedRoot`, whose generation owner is already an `AutoCloseable`. Registered `MissionLifecycle` objects notify physical completion. `releaseGenerationIfSafe` at line 339 does not release while pending/executing or while any mission is physically incomplete. Thus a logical timeout/response alone does not establish safe retirement. No separate snapshot lifecycle engine exists.
- `DefaultSkillVisibilityResolver.java:26` resolves allowed child metadata only in `binding.generation()`. `CapabilityExecutionRouter.java:75` and `ExecutionCoordinator.java:91` require ownership by the current generation. Coordinator definition/capability lookup also uses the current binding generation. These are the existing seams for the ticket's snapshot propagation and PR 27.4's namespace switching; membership alone currently supplies no new permission.
