### 2. Existing runtime wiring and mechanical API boundaries

- `SpringAiProviderIntegration.create()` (`src/main/java/ai/loomspan/internal/springai/SpringAiProviderIntegration.java:128`) selects OpenAI, Anthropic, Gemini or Ollama. TypeSafe cannot construct a ChatModel. OpenAI/Anthropic options set SDK retries to zero and preserve timeout, headers and endpoint settings. Gemini uses its native client with one-attempt HTTP options plus Spring retry template; Ollama uses Spring RestClient and its native adapter (`:142–224`).
- `SpringAiChatOptionsContributor.createOptions()` (`src/main/java/ai/loomspan/internal/springai/SpringAiChatOptionsContributor.java:16`) constructs per-skill options. Anthropic uses numeric thinking budgets and doubled max tokens; Gemini currently uses numeric thinking budget. Native effort/level behavior is owned by the next provider tickets.
- `SpringAiChatClientAssembler` constructs ChatClient with **one Spring AI ToolCallingAdvisor** around a canonical ToolCallingManager (`src/main/java/ai/loomspan/internal/springai/SpringAiChatClientAssembler.java:54–61`). It installs per-skill options and advisors; step execution filters semantic validators without introducing another tool loop (`:116–166`).
- `CanonicalToolCallingManager` validates the complete selected callback surface before delegating execution, handles the planner-inability control, then reconstructs each assistant message using text, metadata, media and tool calls (`src/main/java/ai/loomspan/internal/springai/CanonicalToolCallingManager.java:37–72`). `OutputSchemaCallAdvisor.java:125` also reconstructs messages when composing final output. The precise ordered-parts preservation changes at both sites are already specified in 30.1.2, lines 245–271.
- `SpringAiModelInteraction` exposes the neutral internal boundary, creates text/media requests and calls ChatClient (`src/main/java/ai/loomspan/internal/springai/SpringAiModelInteraction.java:41–101`). Its result remains the content string plus context map.
- `ProviderAttemptCallAdvisor` owns physical attempt reservation/retry outcomes and successful model-response accounting (`src/main/java/ai/loomspan/internal/chat/ProviderAttemptCallAdvisor.java:69–114`). Its diagnostic prompt payload currently uses text/tool views (`:160–177`).
- `ModelUsageExtractor` reads standard `Usage`, preserves native usage and uses text estimation when exact positive token counts are absent (`src/main/java/ai/loomspan/internal/runtime/usage/ModelUsageExtractor.java:15–74`). Zero/missing-usage status semantics are explicitly owned by 30.1.5.
