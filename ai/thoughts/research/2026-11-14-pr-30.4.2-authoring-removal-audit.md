## Current executable schema architecture

### Compiler and immutable representation

`src/main/java/ai/loomspan/internal/schema/StandardSchemaCompiler.java:13` owns the
only supported declaration profile. Its roles are INPUT, OUTPUT and PLANNING, with
AUTHORED and GENERATED origins. It accepts object roots, six ordinary types,
two-element nullable type arrays, scalar enums, homogeneous nested arrays,
descriptions, standard formats and the six approved numeric/string/array bounds.
INPUT additionally accepts typed `additionalProperties` and nested unconstrained or
description-only schemas. Generated false property schemas protect ownership.

The keyword allowlist excludes legacy `nullable`, schema-node `evidence`,
`type: attachment`, references, general unions/composition and other unapproved
assertions. Recognized extensions are `x-loomspan-attachment`,
`x-loomspan-evidence` and generated-input-only `x-loomspan-runtime-ref-capable`.
Placement and shape are checked at actual schema nodes; arbitrary property names
are not interpreted as keywords. Bundled meta-schemas are used without remote
retrieval. Local validation enables format assertions and does not coerce or
insert values.

`CanonicalSchema.java:10` retains defensive tree snapshots, initialized validation,
and detached structural/provider trees. Its annotation stripping traverses schema
nodes under `properties`, `items` and schema-valued `additionalProperties`, retaining
ordinary data properties named after annotations. Canonical schemas and original
YAML retain their annotations.

`StandardSchemaCompilerTest` covers exact names, required presence versus null,
omitted/false openness, nullable type arrays, no coercion, exact numeric boundaries,
scalar enums, nested arrays, unsupported old dialect and schema locations.
`CanonicalSchemaTest` covers defensive views and annotation/property-name separation.
`StandardSchemaFormatsTest` covers standard formats. These are located test anchors,
not newly executed evidence.

### YAML, Java, TypeSafe and runtime consumers

`YamlSkillManifest.java:53` caches compiled INPUT and OUTPUT canonical contracts and
defensively stores raw declaration trees. `YamlSkillCatalog.java:829` compiles the
appropriate role and reports schema source paths. Its evidence extraction at line
841 reads immediate output properties and compiles the exact annotation expression
against direct allowed children. `YamlSkillDefinition.java:109` supplies TypeSafe
descriptive output or compiled ordinary output, and line 141 supplies input schema.

`LoomspanMethodInputSchemaGenerator.java:40` emits a standard closed object contract
using binding introspection, typed map values, arrays, DTOs, exact effective property
names, parameter requiredness and generated runtime-reference markers. Resource,
InputStream and byte[] are marked leaves, not recursively exposed bean schemas.
`Object` emits an unconstrained nested schema. This generator directly invokes the
shared compiler with GENERATED INPUT origin; it does not emit a legacy dialect.
`LoomspanMethodInputSchemaGeneratorTest` and `JavaInputDeclarationTest` cover those
boundaries, including retained map-key/JsonUnwrapped/UUID corrections.

`TypeSafeDeclaration.java:31` compiles its derived schema as GENERATED OUTPUT.
Native answer extraction remains distinct from ordinary chat output validation.
`TypeSafeDeclarationTests` and `TypeSafeSkillIntegrationTest` include exact input
types, descriptive metadata, dynamic criteria, native request fidelity and published
documentation examples. The named published-example test is
`publishedTypeSafeExamplesExecuteDirectAndFullyBoundForwardingParent`.

The binding, runtime input, output and planning packages reference `CanonicalSchema`.
`SchemaDeclarationFixturesTest` compiles actual authored fixtures and distinguishes
shared-compiler placement checks from evidence grammar/child-resolution checks.
Its migrated-standard fixture tests intentionally accept case-distinct names,
required undeclared properties and nested arrays. Invalid fixture directories can
contain schemas that pass compiler shape checks but fail later catalog rules; their
directory name alone does not establish compiler validity.

creates a detached provider tree, applies usage-specific preparation, and sets the

explicit false openness before sending. Anthropic requires closed objects and omits
the documented assertion set only at schema nodes in OUTPUT/PLANNING requests.
Gemini uses the current Spring AI output-schema option; documented SDK narrowing
remains an actual integration limitation.

`OutputSchemaPromptAugmentor.java:19` still renders canonical contract guidance for
the model. Its `nullable` word is explanatory prose, derived from type arrays; it
does not read or generate the old `nullable` schema keyword. The search found no
active BeanOutputConverter/StructuredOutputConverter or old fixed schema-node
implementation alongside the canonical compiler. Runtime guidance, native request
formatting and local validation are distinct responsibilities in this checkout.

`SharedResponsesProtocolIntegrationTest`, `AnthropicProtocolIntegrationTest` and
`GeminiProtocolIntegrationTest` retain opt-in blocker assertions. The current
