## Summary

`SkillMethodBeanPostProcessor` currently owns discovery, canonicalization, interface contract selection, callable metadata construction, parameter schemas/binding, proxy selection, invocation, JSON result conversion, and exception-to-text transformation. `SkillGenerationManager` consumes its fixed callable registrations and installs them in namespace-owned `SkillGeneration` instances. There is currently no executor annotation, invocation record, registration index, or recoverability policy.

The existing security resolver and JSR-250 verifier are independent internal collaborators used by discovery. Runtime advice is preserved by fetching the current Spring bean by name and selecting a method invocable on that bean. Container copying lives privately inside `RestSkillInvocation`; it recursively copies maps/lists while preserving arbitrary other leaves. The public-surface architecture test, API value tests, supported-surface integration tests, README and bundled documentation are explicit contract evidence.

PR 28.1 adds the shared Java foundation. PR 28.2 owns manifest/configuration ingress, PR 28.3 owns generation integration and removal of REST API/runtime, PR 28.4 owns composed authorization, and PR 28.5 owns outer tool disposition and canonical failure classification. The accepted series intentionally allows intermediate breaks and forbids compatibility scaffolding.

## Detailed findings

### Discovery and declaration contracts

- `src/main/java/ai/loomspan/internal/core/SkillMethodBeanPostProcessor.java:43` implements `BeanPostProcessor` and `BeanFactoryAware`. It keeps a linked callable-name map, a processed bean-name set, declaration records and a discovery-complete flag.
- `completeDiscovery()` at line 59 scans configurable bean definitions, skips `scopedTarget.*`, locates `@SkillMethod`, instantiates relevant beans (including lazy declarations), repeats postprocessing safely, then verifies proxyability and security advice on the final beans. `capabilities()` at line 96 closes discovery and returns an immutable list.
- `discoverAndRegisterSkills()` at line 180 uses `AopUtils.getTargetClass`, `MethodIntrospector.selectMethods` and merged annotations. Bridge methods are mapped with `BridgeMethodResolver.findBridgedMethod`; synthetic/bridge canonical results are excluded and repeated canonical methods deduplicated.
- `resolveContractMethod()` at line 252 collects annotated interface methods mapped to the canonical implementation, sorts by generic signature, compares annotations and parameter names/`@SkillParam`, and selects the interface parameter contract when present. A directly annotated implementation with no interface parameter metadata currently returns before comparing multiple interface contracts. This is the exact existing branch; the ticket explicitly requires deterministic incompatible-contract rejection and cross-declaration role conflict handling.
- `mapsToCanonicalMethod()` at line 324 finds an implementation matching the erased interface signature, then resolves its bridge. This is also used for fallback proxy method selection.
- `registerSkillMethod()` at line 202 validates optional primitive parameters, generates a callable schema, applies description/name fallbacks, constructs `SkillIdentity`, resolves policy, and stores `CapabilityMetadata`. Duplicate callable identities raise `CapabilityCollisionException` naming both declaration locations. Explicitly named overloads are supported; default-named overloads collide.

### Identity and registration ownership

- `SkillIdentity.java:6` is the existing internal identity record. Namespace is lowercased with `Locale.ROOT`; local case is retained. Components use ASCII identifier grammar. Namespace limit is 32 and total qualified identity limit is 64. `resolve` handles owner-relative references; `parse` accepts qualified `namespace-localName` identities.
- `CapabilityMetadata.java:10` is callable metadata: identity, description, execution descriptor, policy, invoker, kind, tool schema, input contract and diagnostic source. It requires a description and enforces that tool name matches identity. `CapabilityInvoker.java:6` accepts a map and returns Object.
- `SkillGenerationManager.java:443` freezes discovery using `javaSkills.capabilities()` once and separately discovers REST handler beans. Startup at line 99 creates default and non-default namespaces from fixed callable Java identities. `prepareCatalog()` at line 229 reinserts matching fixed Java capabilities for every replacement/recreation.
- `SkillGeneration.java:20` owns immutable callable and YAML-definition maps plus catalogs and execution runtime. Its constructors validate matching namespace/map keys and YAML-kind associations. Its catalog is built exclusively from callable capabilities. There is no executor index in today's generation.
- The PR 28.1 ticket requires separate callable/executor identity indexes within existing registration/generation design, but explicitly defers end-to-end executor binding to PR 28.3. PR 28.3 explicitly owns generation storage, executor-only namespace startup, retained admission and execution routing. These are sequencing facts, not permission for a separate executor lifecycle in PR 28.1.

### Parameter contracts, resource handling and copying

- `SkillMethodBeanPostProcessor.java:334` generates schemas using the separate `LoomspanMethodInputSchemaGenerator`, remaps implementation parameter names to contract names, and applies descriptions/requiredness. Nested runtime reference-capable Resource, byte-array and stream fields are represented as ref-friendly strings. Executor record schema generation is absent today and expressly forbidden by this ticket.
- Argument binding at line 567 uses contract parameter names and Jackson JavaType conversion. Optional null values remain null. Typed nested map/list/DTO values materialize resources according to destination type. Resource handles pass through for Resource destinations; String/byte-array/stream destinations read content. Opened input streams are tracked and closed in a finally block.
- `RestSkillInvocation.java:18` is a public three-component record; required values are non-null and generation ID is nonblank. Private copy helpers at lines 29–54 copy top-level map values, recursively copy nested map keys/values and lists, use unmodifiable wrappers, preserve nulls, insertion order and non-container leaves. They do not copy arrays, sets, arbitrary objects, or resource bytes. This is the baseline specifically named for extraction.
- `ApplicationApiValueTest.java:78` onward tests REST invocation copy behavior, null/resource preservation, immutable containers, required fields and record components. `SkillExecutorInvocation` will have a different settled five-component public constructor; no compatibility adapter is selected.

### Spring proxy invocation and supported security

- `SkillMethodBeanPostProcessor.java:483` resolves the bean from BeanFactory for each invocation; no target unwrapping is used for application execution. `selectRuntimeInvocableMethod()` at line 532 first uses AopUtils, then a compatible annotated interface contract, then deterministically sorted equivalent interface candidates.
- `completeDiscovery()` rejects private/final/static methods on CGLIB proxies before invocation. `Jsr250EnforcementVerifier.java:22` checks annotated declarations against actual `Advised` beans, the standard named JSR-250 interceptor/configuration, proxyability and matching advisor pointcuts. Unannotated plain beans need no JSR-250 advice.
- `SkillAccessPolicyResolver.java:13` uses Spring's unique security annotation scanner for `RolesAllowed`, `PermitAll` and `DenyAll`; conflicting Spring security contracts follow that scanner's semantics. It is already separate from Java parameter schema code.
- `ExecutionCoordinator.java:154` dispatches Java and REST through `MissionWorkExecutor`. It resolves caller authentication, opens the existing scoped authentication context, resolves input references, then invokes callable metadata. Its `String.valueOf` wraps the already converted Java result; it does not currently perform JSON conversion itself.
- `MissionWorkExecutor.java:36` owns bounded worker submission, timeout/interruption, primary cancellation precedence, cleanup and future handling. `ExecutionException` is unwrapped one level; runtime exceptions and Errors rethrow, checked failures become IllegalStateException. This control owner is distinct from Java method conversion.
- `DefaultCapabilityInvoker.java:80` records tool attempts, binds validated arguments and dispatches via `CapabilityExecutionRouter`, with success and failure bookkeeping at that boundary. PR 28.5 owns changed outer tool feedback and failure-record semantics.

### Results, exceptions and infrastructure wrappers

- Current `invokeSkillMethod()` at line 503 JSON-serializes every result, including strings and null. Jackson failures become an IllegalStateException. Other RuntimeExceptions are intercepted: an arbitrary cause-chain search rethrows security/authentication exceptions, IllegalArgumentException is rethrown, and other failures are logged and passed to `LoomspanExceptionTransformer` as successful text.
- `DefaultLoomspanExceptionTransformer.java:5` walks to the deepest cause and returns `ERROR: <class>. HINT: <message>`, using fallback text for a missing message. It has one focused test and is wired as an infrastructure bean in `LoomspanAutoConfiguration.java:83`. Processor constructors/factories accept it. Architecture and autoconfiguration tests mention it.
- `SkillException.java:3` is a RuntimeException with message-only and message/cause constructors. It imposes no message validation. There is no designated recoverable subclass at baseline.
- `ReflectionUtils.invokeMethod` is the actual reflective boundary. Cached Spring core 7.0.8 bytecode was inspected with local JDK 25 `javap`: InvocationTargetException is handled through `getTargetException`; runtime exceptions/Errors rethrow directly; checked target exceptions are represented by `UndeclaredThrowableException`. Reflection failures have their own IllegalStateException handling. This dependency inspection is supporting evidence, not a substitute for focused tests through the actual configured proxy/reflective path.
- JDK proxies can expose UndeclaredThrowableException for undeclared checked throwables. Spring's interception adds its own target reflection before the outer reflective call. Which wrapper combinations reach a newly shared invoker remains an implementation verification topic; ordinary IllegalStateException with a recoverable cause is explicitly terminal under the accepted contract.
- `SpringAiModelInteraction.java:30` unwraps one ToolExecutionException with a runtime cause. `MissionWorkExecutor` handles ExecutionException as above. Worker/tool wrapper integration is explicitly PR 28.5; PR 28.1 establishes the single narrow policy and actual Java invocation wrapper coverage without arbitrary cause searching.
- `DefaultSkillTemplate` preparation/facade boundaries preserve SkillException subtypes and AccessDeniedException, wrapping other runtime failures with facade context. Thus identical exception object propagation across every outer boundary is not the existing public guarantee.
