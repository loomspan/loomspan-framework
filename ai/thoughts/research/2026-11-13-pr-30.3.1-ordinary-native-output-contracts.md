## Summary

The source graph is partway through canonical-schema migration. Declaration and
binding ownership already use `CanonicalSchema`; ordinary validator, renderer and
advisor signatures still name the removed `YamlSkillManifest.OutputSchemaManifest`.
`ModelInteractionRequest` currently carries prompts, materialized input, tracing,
capabilities and a planning flag, with no output contract. The ordinary Spring AI
interaction builds a ChatClient request without per-call native output options.

Phase 1 supplies official adapter construction, option/default controls, request
captures, native Anthropic format assembly and response/retry ownership. It does
not establish complete raw schema fidelity: prior developer-approved dependency
blockers B01–B05 remain recorded with complete opt-in correctness assertions.
Those existing deferrals are distinct from ordinary consumer wiring and local
acceptance. No live provider acceptance or enforcement was established here.

  defensive-copy `JsonNode` output declaration as OUTPUT/AUTHORED.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillDefinition.java:109` returns

  migrated. `outputSchemaMaxRetries()` preserves the manifest's configured value.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:793` validates
  output declaration/retry bounds and invokes `compileSchema`; compiler declaration
  errors become the existing resource/field-path skill-loading error. This path
  performs local compilation, not provider probing.
- `src/main/java/ai/loomspan/internal/schema/StandardSchemaCompiler.java:18` owns
  the exact v1 vocabulary, OUTPUT/INPUT/PLANNING roles and GENERATED ownership
  exceptions. It initializes Draft 2020-12 NetworkNT validators with remote
  loading disabled. Root type must be exactly object. Nested nullable type pairs,
  scalar enums, bounds and enumerated standard formats are supported; general
  composition/references/defaults/patterns are outside the accepted profile.
- `src/main/java/ai/loomspan/internal/schema/CanonicalSchema.java:13` returns
  detached tree copies. `providerTree()` strips only recognized Loomspan
  annotations at schema nodes, traversing properties/items/additionalProperties.
  It does not currently implement provider-specific assertion omissions.
- `CanonicalSchema.validate` (`:25`) runs format assertions and returns only a
  completed verdict; operational exceptions propagate. The retained validator is
  immutable and no coercion/default insertion authority exists here.
- `pom.xml:50` pins Java 21, Boot `4.2.0-RC2`, Spring AI `2.1.0-RC2` and NetworkNT
  `3.0.9`; these are the current checkout dependencies, not a new version decision.

### 2. Ordinary execution, request and advisor flow

`DefaultMissionExecutionEngine.executeMission` materializes input and optionally
initializes planning, then captures output composition (`:97`). Complete binding
assembly without model contribution calls `composeEmpty`, validates bound
policies, records output outcome and result assembly, and returns without a final
model request (`:100–108`). Mixed/ordinary generation opens its model frame and
calls `ModelInteractionRequest` (`:134`). Planning is separately invoked before
that ordinary request.

`src/main/java/ai/loomspan/internal/model/ModelInteractionRequest.java:10` is an
internal record with five components: system prompt, rendered input, trace context,
bound capabilities and planning. Call sites are the ordinary engine,
`DefaultPlanningService:525` and `StepLoopMissionExecutionEngine:1119`; adding a
record component affects these internal callers and direct test constructors.

`SpringAiModelInteraction.doCall` (`:41`) adds the control tool only for STANDARD
non-planning calls, adds supplied capability callbacks/media, passes trace context
and the planning bypass advisor parameter, then returns text plus response context.
It currently does not apply output-schema options.

`SpringAiChatClientAssembler.create` (`:123`) resolves the effective captured
connection, creates target defaults through `SpringAiChatOptionsContributor`,
and installs advisors including `ProviderAttemptCallAdvisor`. The official
Spring AI `ToolCallingAdvisor` owns continuations and the existing canonical tool
manager owns tool argument enforcement. Step execution filters final schema,
evidence and linter advisors; it is a distinct consumer.

`DefaultSkillAdvisorResolver:100` installs `OutputSchemaCallAdvisor` when the
definition has an output contract. Its binding variant receives the definition;
unbound validation remains outside composition. The advisor (`:85`) bypasses
planning calls, augments the first prompt using the canonical or binding-projected
contract (`:97`), then validates each downstream result (`:112`). It uses
`OutputValidationPolicy.exhausted` and preserves the configured retry count. The
retry request is rebuilt from baseline plus the complete latest candidate and a
bounded correction (`buildRetryPrompt`, `:235`); it retains baseline options.
Changing completed tool history/repair enforcement belongs to PR 30.3.3.

The advisor's field and constructors still name the removed manifest type, while
the resolver and binding projection now supply `CanonicalSchema`. This is a
current source mismatch, not a claim that the ordinary runtime presently builds.

### 3. Current parsing and rendering seams

`OutputSchemaValidator:45` accepts the removed manifest type, reads the response
through its supplied mapper and hand-walks the old schema semantics. Its object
walker folds names through Locale.ROOT, treats omitted additionalProperties as
closed, checks string enums, and treats format as guidance. These are the old
implementation semantics; the accepted ticket explicitly migrates them to
standard exact-name/open/format semantics. Parser failure facts remain in
`OutputSchemaValidationIssue` and the existing correction/error/outcome records.

The historical ticket precision anchor is no longer a complete description of
the default codec: `LoomspanJacksonCodecs:39` now builds `schemaTree()` with
`USE_BIG_DECIMAL_FOR_FLOATS`. However the validator constructor still accepts an
arbitrary supplied mapper and parses through it. A local lossless output reader
is a separate requirement from whether today's default mapper happens to retain
decimals. `AcceptedResultDecoder` independently reads Object values with big
integer/decimal handling and FAIL_ON_TRAILING_TOKENS and returns detached values.
It retains malformed/plain text as text; it does not certify schema acceptance.

`OutputSchemaPromptAugmentor:13` renders the removed manifest tree. Its blanket
unknown-field instruction and `Boolean.TRUE` object-openness rendering are the
legacy closed-by-default behavior identified by the ticket. It recursively emits
descriptions, required/optional, nullable/non-null, enums and formats in declaration
order. `StepPromptBuilder:218` reuses this renderer only in final-response guidance;
its own removed-type parameters are assigned to PR 30.3.2, while this ticket asks
for focused step-final openness assertions for the shared renderer behavior.

### 4. Binding composition and application-facing response delivery

`OutputBindingProjection` already preserves canonical contracts and standard
omitted openness. It removes bound destinations from the model contribution,
updates ancestor requiredness, computes whether model space remains and checks
exact destination ownership independently of provider output schemas.

`OutputBindingComposition:40` snapshots selected input/accepted-child values,
validates each bound destination before generation, and retains provenance.
`compose` (`:66`) checks mission/plan fences, decodes losslessly, rejects bound
overrides, validates the projected contribution (`:79`), inserts detached bound
values and validates the complete original output (`:95`). Its private validation
helper (`:97`) currently duplicates the JSON-parse/NetworkNT-error conversion path
instead of calling `OutputSchemaValidator`, whose current signature is still old.
The supplied mapper serializes assembled output; the canonical schemaTree codec
parses that validation text. Operational validation failures propagate.

When composed output passes, `OutputSchemaCallAdvisor:125` constructs a replacement
AssistantMessage from assembled text, metadata, tool calls and media. It constructs
a new ChatResponse containing only that replacement generation. The current code
does not preserve the original ordered parts as a collection; Phase 1 response
diagnostics already know part-aware messages. The ticket owns preserving untouched
ordered parts/attributes when replacing application-facing text and keeping raw
provider evidence distinct.

### 6. Failure, retry and diagnostic ownership

- `ProviderAttemptCallAdvisor:54` owns physical sends and transport retry around
  the existing official model advisor; SDK auto-retries are disabled by
  `SpringAiProviderIntegration` and Gemini is configured for one physical attempt.
- `SpringAiProviderIntegration:401` treats HTTP statuses 408, 429, 500, 502, 503,
  and 504 as transient and ordinary invalid requests as
  permanent; original provider details are retained. The code does not infer schema
  capability from incidental error prose. `ProviderRetryDecider:10` retries only
  TRANSIENT failures within the existing policy.
- Explicit refusal/incomplete evidence is classified before normal schema/linter/
  evidence correction by ProviderAttemptCallAdvisor, retaining receipt/usage.
- Generated invalid output returns an existing OutputSchemaValidationResult; the
  ordinary advisor exhausts with `LoomspanOutputSchemaValidationException`, original
  candidate text and existing outcome/trace facts. Composition source/lifecycle
  failures use current IllegalArgumentException/IllegalStateException mechanisms.
- `ProviderAttemptCallAdvisor.requestPayload` (`:221`) currently records messages,
  not output contract/native schema options. Its part-aware `messagePayload` and
  `responsePayload` record text, metadata, ordered parts, part payload/attributes,
  tools, generations and provider metadata before outer composition. These are
  the existing diagnostic seams relevant to distinguishing canonical/transmitted
  schemas and raw/composed output; no new observability subsystem is present.
- Existing authentication/authorization failure classification remains separate.
  No rollback/compensation machinery is present or promised for earlier tool work.

## Surface classification and documentation comparison

- **Application API:** the closed `ai.loomspan.api` allowlist in
  `LoomspanPublicSurfaceArchitectureTest`; no new application surface is requested.
- **Supported SPI:** none. Internal constructors/interfaces and publicly accessible
  Spring integration machinery do not establish one.
- **Configuration and manifest contracts:** canonical output_schema vocabulary,
  standard required/null/openness/format semantics, unchanged retry configuration
  and ordinary text mode are author-facing concerns. The approved migration
  deliberately replaces the legacy dialect and case aliases.
- **Persisted or serialized contracts:** actual three-provider request schema
  fields/options are external serialized contracts subject to native mapping
  evidence. No Console REST/SSE/NDJSON wire format change is established here.
- **Ephemeral diagnostic formats:** provider attempt messages/parts/schema copies,
  output validation outcomes and assembly provenance. Fidelity and correct raw/
  composed distinction remain current-run goals.
- **Internal or accidentally exposed implementation:** ModelInteractionRequest,
  option mapper/helper, advisor/validator/renderer and binding composition. They
  are technically public in places for cross-package collaboration, already
  described as internal by the architecture inventory; no compatibility shim is
  indicated by that modifier alone. New technically public internal types would
  also need deliberate architecture inventory treatment.

The repository `agent-skills/loomspan-docs/SKILL.md` was used as the documentation
router after source/test inventory; its version `1.0.0-beta.10-SNAPSHOT` matches
the root POM. Relevant routed topics are `standard-schemas.md`,
`output-contracts.md`, `source-verification.md` and the authoring README coverage
table. **Drift classification: aligned** for documented canonical declaration/
binding behavior and the explicitly incomplete full integration boundary.
Legacy ordinary renderer/validator behavior differs from the new accepted
standard contract, but this discrepancy is explicitly the ticket's authorized
migration, not a newly inferred product defect. Documentation impact exists:
the ordinary acceptance/native-copy guarantees and remaining integration limits
will change with this ticket; the existing topics currently state them incomplete.
