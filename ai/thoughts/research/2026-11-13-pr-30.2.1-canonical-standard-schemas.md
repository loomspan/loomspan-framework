## Summary

The root POM already pins NetworkNT 3.0.9, Java 21, Spring Boot 4.2.0-RC2 and Spring AI 2.1.0-RC2. Production schema declarations still use separate nested input/output DTOs in `YamlSkillManifest`, catalog-owned recursive declaration checks, a reduced input tree and handwritten input/output instance validators. The retained standalone NetworkNT probe contains working API examples but is not a production compiler.

Skill documents pass through SnakeYAML raw values and then Jackson tree conversion. Executor `config` is removed before that conversion and restored through its separate immutable configuration path. Configuration property loading also uses `YamlValues`; it delegates ordinary properties to Boot and retains executor configuration as raw values. The existing distinction is visible in production and tests.

The ticket deliberately separates this foundational declaration/compiler migration from Java generation, runtime input adaptation, attachments, binding composition, native output/planning and TypeSafe/evidence integration. Its build allowance explicitly permits the downstream DTO callers to stop compiling when obsolete structures are removed. This research records those callers and owners rather than treating their legacy behavior as required new-schema semantics.

### YAML ingestion and configuration separation

- `src/main/java/ai/loomspan/internal/serialization/YamlValues.java:14-30` constructs a `CoreSchema` loader. Explicit timestamp tags remain strings, duplicate keys are disallowed, and code points/collection aliases are explicitly set to `Integer.MAX_VALUE`.
- `YamlValues.java:33-66` rejects recursive map/list containers and bounds expanded logical values at 1,000,000. Its DAG memoization retains shared aliases while counting logical expansions. It does not enforce string map keys or finite numbers.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:304-323` reads resource bytes before calling `readManifest`; supplied documents reach the same manifest path. `readManifest` at `:400-418` decodes raw YAML, removes top-level `config`, and invokes `yamlObjectMapper.valueToTree` on the remaining document. The placeholder config tree carries only shape/presence for form checks.
- `YamlSkillCatalog.java:440-463` binds the remaining tree to `YamlSkillManifest`, checks top-level config keys are textual and restores the original config values. `:476-505` owns declaration-form applicability, including executor-only config and TypeSafe/model restrictions.
- `src/main/java/ai/loomspan/internal/autoconfigure/ExecutorYamlPropertySourceLoader.java:24-53` loads all raw YAML documents, associates them with Boot's delegated property sources and replaces only `loomspan.executor-config` with an opaque raw holder. Ordinary Boot decoding remains delegated. `ExecutionConfigurationParser` and `ExecutorConfiguration` are the separate configuration consumers.
- `LoomspanJacksonCodecs.java:35-46` builds the skill YAML mapper with unknown-property rejection and duplicate detection, and builds the schema JSON mapper without explicit decimal parsing options. `applicationConversion` remains an independently supplied application mapper.

The ticket's literal fractional/exponent precision, non-string key collision, and non-finite number cases concern the boundary before JSON tree conversion. Existing TypeSafe scalar coverage at `TypeSafeDeclarationTests.java:93` supplies a BigDecimal programmatically; that is distinct from literal YAML construction. `ExecutorConfigurationTests.java:29-47` establishes shared-alias identity and expansion-bound behavior; `:57-69` checks domain values remain uninterpreted.

### Declaration representation and catalog ownership

- `YamlSkillManifest.java:109,128,353-385` stores separate output/input schemas. `:505-630` defines `InputSchemaManifest`; `:632` begins `OutputSchemaManifest`. Both have scalar type strings, nested properties/items and string-only enums. Inputs have format and legacy attachment metadata; outputs have legacy nullable and evidence fields.
- DTO setters normalize type text and selected descriptions/formats; the evidence setter preserves its original string. Typed manifest binding rejects unknown fields but is not standard JSON Schema meta-schema checking.
- `YamlSkillCatalog.java:323-345` validates inputs for every form, returns executor definitions early, checks TypeSafe inputs/model compatibility, and validates ordinary model output schemas before compiling evidence.
- `:801-837` manages output correction defaults/range and invokes declaration validation. `:921-1255` recursively checks the legacy schemas, including root object type, string enums, required-declaration consistency, case-folded property uniqueness, array restrictions and attachment rules. Output object validation supplies omitted closure through the legacy path.
- `:841-919` compiles old property-level evidence into `EvidenceContract`, parses namespace-aware direct-child expressions and creates case-normalized claim lookup. This is structural declaration code adjacent to execution metadata compilation, whose migrated owner is 30.3.4.
- `YamlSkillDefinition.java:43-76` copies the manifest on construction; `:109-111` and `:159-161` return defensive schema copies; `:189-193` returns a defensive manifest. Its output binding destination canonicalization at `:136-151` currently uses the case-insensitive output matcher.
- `SkillGeneration.java:17-80` owns immutable capability/definition maps and captured execution runtime. `SkillAdmissionSnapshot.java:8-36` associates a root with immutable generations and captured executor bindings. These are the existing ownership boundaries referenced by the ticket, not a request for a new registry or lifecycle.
