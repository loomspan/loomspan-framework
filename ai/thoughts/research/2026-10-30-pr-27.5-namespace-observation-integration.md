## Summary

Canonical identity and namespace execution are already implemented in the generation, admission, binding, authority, and root APIs. `SkillAdmissionSnapshot` is the authoritative namespace-to-generation association. `ExecutionBinding` carries both entry and current contexts, and the session runner starts one session using entry settings. Observation currently receives only the entry generation ID: canonical trace initialization, active snapshots, finalized artifacts, Java HTTP DTOs, Go DTOs/artifact metadata, and TypeScript contracts lack a retained captured namespace-generation mapping.

The existing HTTP registered-skill supplier selects only the current `default` generation. Skill names generally flow as strings through record correlations and UI. Metrics currently lowercase the entire supplied skill name, including its case-sensitive local component. Existing semantic fixture inputs still include old dotted/local skill identities. Prior PR 27.4 verification records 465 individually attributed baseline failing cases, mostly old fixture references, plus explicit observation closure work assigned to this ticket; those results do not establish this checkout's full-suite status.

The release marker already derives from Maven `${project.version}` and is consumed by live connection and saved-trace paths. No namespace-specific compatibility mechanism exists or is requested. Existing observation access controls and the derived journal exception are independent of skill-call visibility.

## Current executable architecture

### Identity, publication, admission, and binding

- `src/main/java/ai/loomspan/internal/core/SkillIdentity.java` owns canonical grammar, namespace case normalization, local-case preservation, namespace length and combined length. Runtime references use `namespace-skillName`; declaration components remain local names.
- `src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java:49` owns the active namespace map, the generation monitor, published generations/retirement, and fixed registrations. Startup is explicitly one-shot (`initializeStartup`, line 107): Private default combines configured declarations and assigned Java methods; other assigned Java namespaces get independent Private generations/runtimes.
- `SkillGenerationManager.java:137` selects `active(namespace)` without recreating absent namespaces. `capturePreparation` at line 151 takes a coherent immutable map plus target base under the same monitor. Existing preparation builds detached runtimes and uses target-only publication checks.
- `src/main/java/ai/loomspan/internal/skill/SkillAdmissionSnapshot.java:8` is an immutable record of structured entry identity and `Map<String, SkillGeneration> generations`. It validates map ownership and entry presence. `resolve` selects a namespace's retained generation and canonical capability. This already contains the identities needed after replacement/removal/recreation; current registry lookup is a separate operation.
- `src/main/java/ai/loomspan/internal/core/ExecutionBinding.java:48` exposes `entryNamespace()` and `currentNamespace()`. Bindings validate generation membership in the snapshot and choose child generations from that captured association. `ExecutionBindingScope` propagates/restores bindings through managed work.
- `src/main/java/ai/loomspan/internal/core/LoomspanSessionRunner.java:285` starts an admitted root from `snapshot.entryGeneration()`. It selects entry depth, persistence and quota snapshot; lines 308–329 construct one `LoomspanSession` with only entry skill and entry generation ID, then install a session binding containing the full snapshot. The trace starts during session construction, before the binding scope is installed.
- Root validation, handoff and invocation use the existing reachable capture implementation in `SkillGenerationManager`, `DefaultSkillTemplate`, and `DefaultSkillInvocationHandoff`. `AdmittedSkillInvocation.generationId()` is entry-scoped; `RestSkillInvocation.generationId()` is the target's retained generation. No public snapshot-map API is present.

### Canonical trace and observer path

- `src/main/java/ai/loomspan/internal/runtime/trace/DefaultExecutionTraceHandle.java:395` initializes `TRACE_STARTED` with tracePath, release marker, entrySkill, entry `generationId`, and optional entry configured quota limits. There is currently no entryNamespace or captured namespace-generation map in that metadata.
- The handle serializes appends and owns one trace ID and monotonically sequenced record stream. Its overloads accept a frame or session record; frame routes are copied without reinterpretation (`append`, lines 423–446). Finalized artifacts retain only entrySkill and generationId (`FinalizedTraceArtifact.java:10`; artifact construction near handle line 512).
- `LoomspanSession.java:864` funnels trace appends through its lock and preserves supplied metadata/payload. Frame-less and frame-bound records share the same trace handle. Session failure recording, completion and journal projection reuse this flow.
- `DefaultExecutionTraceRecorder.java:28` records frames. Result assembly/forwarding check owning mission/frame identity; model records use `ModelTraceContext` and tool records use `ToolTraceContext`. `ModelTraceContext.java:83` stores skillName with provider/attempt metadata; `ToolTraceContext.java:20` stores capabilityName. These current types do not carry a target generation association.
- Not every route names a skill: planning, step, model and other operation frames have their existing route meanings. `TraceRecord.java:14` and `TraceDiagnostic` permit optional fields; unknown-origin failures already have nullable/unavailable information. There is no basis to manufacture a skill identity from an arbitrary route.
- `ExecutionJournalProjector.java:44` projects the canonical trace into a derived journal. Only root/skill frames become skill lifecycle events; tool/model/plan/error types use their existing summaries. Its existing field-name redaction is deliberately retained for journal/observer output only. Canonical trace content is not rewritten by that exception.
- Supported `SkillExecutionView`/`SkillExecutionEvent`, mapped by `SkillExecutionViewMapper`, expose one session and ordered event history. `DefaultSkillTemplateTest`, `ApplicationApiValueTest`, `ExecutionTraceContractTest`, and `SkillExecutionViewMapperTest` establish synchronous at-most-once callback and error/history semantics. Callback behavior does not require Console storage.

### Live observation and finalized HTTP metadata

- `runtime/observation/DefaultExecutionObservationHandle.java:54` sends each canonical record through one projector/state, updates one active registry entry, and appends activity to the existing replay stream. Terminal publication is held until canonical finalization, then the finalized artifact is cataloged. Failure handling preserves existing observation availability behavior.
- `runtime/observation/ExecutionProjectionState.java:25` stores entrySkill and a single generationId. `LiveActivityProjector.java:90` reads generationId from TRACE_STARTED; active branches are complete frame paths. Its detail-key allowlist currently includes skill/capability identity and attempt/task facts, not namespace-generation metadata.
- `ActiveExecutionSnapshot.java:16`, `FinalizedTraceArtifact.java:10`, `ObservabilityDtos.java:105`, and `ObservabilityDtoMapper.java:36` form the active/finalized metadata path. Finalized catalog entries keep their artifact, and DTO mapping gets generation ID from it. These are current internal/same-release representations.
- `observability/web/ObservabilityRouteRegistrar.java:133` supplies registered skills through `generations.active("default").registeredSkillCatalog()`. Each selected generation's `DefaultRegisteredSkillCatalog.java:29` builds sorted canonical-name entries with Java or original manifest metadata. The current supplier therefore excludes other active namespaces and depends on default being present.
- `ObservabilityRestController.java:56` uses that supplier for instance counts and existing list/detail routes. Lists paginate by registeredName; detail lookup is exact. There is no namespace query/filter/enumeration endpoint.
- `ObservabilityAccessService`, the route security chain, and host security integration tests own existing observation authorization. They are separate from `NamespaceAccessGuard` execution visibility. Public skill-call visibility has no observation grant.

### Metrics

`runtime/usage/MicrometerUsageMetricsRecorder.java:23` receives skillName for skill/model/tool/guardrail counters. Its shared `normalize` at line 111 returns `unknown` for null/blank and otherwise lowercases the entire string. Thus present tags can merge `a-search` with `a-Search`, although structured runtime identity preserves local case. Other tags such as driver/outcome share this normalization. `MicrometerUsageMetricsRecorderTest` and `SessionUsageServiceTest` are the existing coverage anchors; unknown-skill behavior is distinct from a known canonical skill string.
