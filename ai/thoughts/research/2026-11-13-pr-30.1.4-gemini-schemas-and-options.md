## Summary

Framework constructs the official Spring AI Google GenAI model. Its pinned
`org.springframework.ai:spring-ai-google-genai:2.1.0-RC2` still converts output
schemas into SDK `Schema` and tool schemas through both OpenAPI narrowing and SDK
`Schema`. The constructor wraps supplied tool managers in its provider-specific
converter. The final schema conversion and request-building methods are private;
there is no evidenced raw-schema options-only extension for both paths.

Fresh Maven Central metadata reports RC2 as latest/release. Fresh upstream main
inspection at `0393acb10aea3363054beee408442129d55c7204` still shows all three narrowing
operations. No acceptable fixed artifact was identified. This is a concrete owned
schema dependency blocker under the ticket's artifact rules, not permission to
copy an adapter, replace a loop or rewrite HTTP bodies. Independent thinking-option
work is available: RC2 already supports native `GoogleGenAiThinkingLevel.MEDIUM`,
while Framework currently chooses a numeric budget for every Gemini model.

### Actual schema path in RC2

Matching dependency source locations:

1. `GoogleGenAiChatModel.java:264–269` accepts a Google-specific manager directly,
   otherwise wraps the supplied manager in `GoogleGenAiToolCallingManager`.
2. `schema/GoogleGenAiToolCallingManager.java:72–86` delegates definition resolution,
   parses each canonical JSON schema, calls
   `JsonSchemaConverter.convertToOpenApiSchema`, uppercases types and returns
   replacement `DefaultToolDefinition` objects. Tool execution delegates unchanged
   (`:95–97`). Bypassing only the final SDK setter cannot restore lost content.
3. `GoogleGenAiChatModel.java:581–587` privately deserializes schema JSON into SDK
   `Schema`, whose finite representation is the second narrowing boundary.
4. Output mapping at `:937–938` calls
   `responseJsonSchema(jsonToSchema(requestOptions.getResponseSchema()))`.
5. Tool mapping at `:982–988` resolves definitions through the wrapped manager and
   calls `.parameters(jsonToSchema(toolDefinition.inputSchema()))`.

The SDK raw setters `parametersJsonSchema(Object)` and
`responseJsonSchema(Object)` are exercised by the retained direct-SDK test. Those
SDK capabilities do not establish Spring AI integration support. Fixed
`HttpOptions.extraBody` cannot express changing per-request contracts or repair
pre-HTTP tool failures; no production extraBody workaround exists here.

### Framework wiring and option combination

- `SpringAiProviderIntegration.java:155–168` builds API-key or Vertex SDK clients
  and the official Google model, supplies observation registry and one-attempt
  Spring retry template. `oneAttemptGoogleHttpOptions` disables SDK retry with
  attempts=1 and maps configured request timeout exactly in milliseconds.
- `SpringAiChatClientAssembler.java:52–63` creates the Spring AI tool advisor with
  `CanonicalToolCallingManager`. `:101–123` resolves captured connection runtime,
  creates the ChatClient and applies contributor-produced default options. There
  is one Spring AI ChatClient/tool-loop owner.
- `CanonicalToolCallingManager.java:28–39` checks canonical bound names while
  delegating schema definition resolution; `:42` onward checks all selected tool
  names before delegating execution. It is not a schema mapper.
- `SpringAiChatOptionsContributor.java:61–69` builds fresh Gemini options from
  effective model identity and applies `includeThoughts(true)` plus numeric
  budget to every non-null thinking level. `:72–81` maps low/medium/high to
  1024/4096/8192, rejecting other strings locally.
- RC2 options `mutate()` carries thinkingBudget, includeThoughts and thinkingLevel
  (`GoogleGenAiChatOptions.java:448–450`). Its combine routine independently
  assigns each non-null budget/level (`:642–649`); a null level/budget does not
  clear an inherited value. Explicitly avoid retaining a numeric legacy budget
  alongside a selected native level when composing changed-model options.
- RC2 `GoogleGenAiChatModel.java:1256–1262` uses model options only when prompt
  options are absent. Typed direct prompt options are used as supplied. ChatClient
  combines defaults through provider builders; direct-model calls do not prove
  that same combination behavior.

### Native thinking and selected fixture

RC2 `GoogleGenAiChatModel.java:948–964` independently maps budget, includeThoughts
and thinkingLevel into SDK ThinkingConfig. `:1096–1102` maps native enum MEDIUM.
Its exact-model support table at `:1124–1145` does not contain
`gemini-3.8-flash`; unknown IDs are left to the server (`:1163–1165`). That permits
an offline serialization fixture, not a hosted acceptance claim.

Framework currently has no selected-model native-level branch. Existing focused
`SpringAiChatOptionsContributorTest.providerOptionContributorsApplyImmutableTargetOptions`
asserts legacy `gemini-2.5-pro` low means budget 1024 and includeThoughts=true.
The accepted fixture is exactly `gemini-3.8-flash`; native low/medium/high mappings
and null/unsupported-level behavior can be verified locally without expanding
model-family or endpoint inference. The contributor currently sets no Gemini cap;
request builders expose maxOutputTokens. Caps 1024/4096/2048 can therefore be
checked unchanged through ChatClient combination, including changed schemas.
Schema failures and option evidence need separate assertions: nullable output may
fail before any request even when options themselves are correctly composed.
