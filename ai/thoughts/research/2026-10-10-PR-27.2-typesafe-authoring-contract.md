## Detailed findings

### Strict manifest parsing and leaf selection

`LoomspanJacksonCodecs` configures `skillYaml` with strict duplicate detection and
failure on unknown properties (`src/main/java/ai/loomspan/internal/serialization/LoomspanJacksonCodecs.java:32`).
`YamlSkillCatalog.readManifest` reads bytes into a tree, verifies the root and
required identity fields, then applies raw field checks before binding to the
manifest (`src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:408`).

`validateRawTypeSafe` checks presence of `typesafe`, rejects the twelve incompatible
fields using `root.has`, and calls declaration compilation. Consequently null,
false, and empty incompatible values are rejected before their setters or coercion
can obscure presence (`YamlSkillCatalog.java:460`). The block itself must be an
object. Unknown block/question fields are rejected by declaration validation;
unknown manifest fields remain the YAML codec's responsibility.

`loadDefinition` validates name/description and the common input schema. A TypeSafe
leaf additionally requires object-root input schema, recursively excludes attachment
nodes, requires a configured model, and selects a TypeSafe connection
(`YamlSkillCatalog.java:336`, `YamlSkillCatalog.java:470`). Existing RBAC roles remain
available. `YamlSkillManifest` stores a defensive declaration tree and immutable
compiled declaration reference (`YamlSkillManifest.java:66`). `YamlSkillDefinition`
retains that compiled reference even when callers obtain mutable manifest copies.

### Bounded grammar and JSON Pointer resolution

`TypeSafeDeclaration` deep-copies the tree, compiles string templates, validates
literal constraints, and derives the schema during construction
(`src/main/java/ai/loomspan/internal/typesafe/TypeSafeDeclaration.java:26`).
Compilation scans only state, instructions, and criteria values; it never scans
keys or question types (`TypeSafeDeclaration.java:202`). Compiled token lists are
immutable and indexed by original parsed string text.

The scanner recognizes `$${`, `${/input}`, and `/input/` descendants, uses the
first closing brace, rejects nested expressions and malformed tilde escapes,
and compiles pointers through Jackson `JsonPointer`
(`TypeSafeDeclaration.java:246`). It preserves other literal characters. No
schema analysis, defaults, environment/configuration expansion, or function
evaluation occurs. The template path grammar remains separate from parent binding
syntax.

Whole-reference nodes deep-copy the selected JSON value. Embedded references
accept strings, numbers, and booleans, using the existing JSON codec for numeric
and Boolean serialization (`TypeSafeDeclaration.java:292`). Input values are never
rescanned. Leading/trailing text, including whitespace, changes a whole reference
into interpolation. Recursive substitution preserves array order, literal object
keys, omitted fields, explicit nulls, and YAML-parsed Unicode/newlines.

Lookup uses JsonPointer's decoded object tokens and exact object access. It checks
array tokens against `0|[1-9][0-9]*` and rejects missing/out-of-range indexes and
scalar/null traversal (`TypeSafeDeclaration.java:335`). Empty object keys and
numeric object keys retain exact lookup semantics.

### Registration and invocation share primitive shape rules

`validate` requires string/object/array state and a nonempty question object. Types
are literal `choice`, `noul`, or `score`; instructions are optional and accept
string/object/array/null (`TypeSafeDeclaration.java:80`). Whole-reference criteria
defer input-dependent criteria checks during registration. All literal portions
remain subject to validation.

Choice criteria contain 1–255 entries and descriptions accept
string/object/array/null. Score contains 1–10 ordered descriptions with the same
types, including nulls and singleton arrays. Noul accepts omitted/null criteria or
an object limited to independently optional `true`/`false`; absent/null
instructions require at least one non-null outcome description. There is no
fabricated description, universal instructions rule, or second request coercion.

`names` checks question siblings and Choice candidate siblings using
`toLowerCase(Locale.ROOT)` and reports both names plus the containing location
(`TypeSafeDeclaration.java:359`). It preserves spelling and does not check arbitrary
description/state objects or provider responses.

`resolve` validates normalized input as JSON-compatible before tree conversion,
substitutes a private request, runs complete validation, and returns an immutable
serialized `ResolvedRequest` (`TypeSafeDeclaration.java:41`, `TypeSafeDeclaration.java:74`).
Each `json()` read returns a new tree. The JSON checks reject unsupported objects,
non-string map keys, and non-finite Float/Double values
(`TypeSafeDeclaration.java:410`, `TypeSafeDeclaration.java:429`).

### Input ownership and retry timing

`CapabilityExecutionRouter` checks access, validates through
`SkillInputValidator.validateExact`, obtains normalized input, and dispatches it
inside the captured generation (`src/main/java/ai/loomspan/internal/core/CapabilityExecutionRouter.java:55`).
An empty exact-path set retains ordinary coercion. Author-bound subtree paths
receive exact validation. `SkillInputValidator` owns this distinction and ordinary
number validation can accept non-finite numeric values; TypeSafe's request check
rejects those after normalization
(`src/main/java/ai/loomspan/internal/runtime/input/SkillInputValidator.java:25`, `SkillInputValidator.java:253`).

`ExecutionCoordinator` routes TYPESAFE_SKILL through the existing mission executor
(`src/main/java/ai/loomspan/internal/core/ExecutionCoordinator.java:153`).
`TypeSafeExecutor.execute` resolves once, adds the captured configured model,
serializes once, and only then enters the retry loop and reserves an attempt
(`src/main/java/ai/loomspan/internal/typesafe/TypeSafeExecutor.java:36`). Every retry
sends the same body. This is pre-existing provider integration; PR 27.2's contract
does not require creating another execution or input-validation path.

### Derived schemas and generation consumers

`deriveSchema` creates the existing `OutputSchemaManifest` vocabulary: closed root
with all question properties required; open answer objects; singleton primitive
type enums; Noul numeric noul; Choice value/confidence/probabilities; and Score
value/confidence/probabilities/legend (`TypeSafeDeclaration.java:471`). Fixed
Choice criteria add exact candidate enums and closed required probability keys.
Fixed Score criteria add closed zero-based probability keys and a range
description. Whole-reference criteria leave probability maps open and describe
the dynamic range. Score legend always remains an open object. No new numeric
bound keywords or answer validator are present.

`outputSchema()` returns a defensive converted copy
(`TypeSafeDeclaration.java:37`). `YamlSkillDefinition.outputSchema` delegates to
that schema for TypeSafe definitions (`YamlSkillDefinition.java:95`), and
`SkillGenerationManager.resolveOutputSchema` publishes it through the existing
effective schema map, including inherited forwarding schemas
(`SkillGenerationManager.java:442`). Catalogs, tools, binding checks, and forwarding
consume that existing map. Invocation does not specialize or mutate the schema.

## Architecture documentation

The implementation has one bounded declaration authority, immutable compiled
templates/declaration, per-call resolved request, and existing schema DTOs and
runtime/generation integration. Request checks and descriptive output metadata
are separate from returned-answer validation. Shared bindings retain existing
partial schema compatibility and runtime destination validation. Public consumers
invoke registered skills rather than internal TypeSafe classes.
