## Summary

Framework already compiles executor-only JSLT and evaluates it after validating
ordinary receiving input. It hands the resulting object to the supported v1
invocation while keeping skill and executor configuration in separate accessors.
The Decisions executor currently ignores that input as a complete request. It
copies `skillConfig.request`, applies its own `skillConfig.bindings`, validates,
serializes once and sends the bytes through its existing transport.

The installed-JAR support-triage consumer already exercises real pack discovery,
HTTP requests, complete native responses, explicit parent input/result bindings,
publication, lifecycle, diagnostics and accounting. Its fixtures and helpers encode
the existing configuration contract. Local pinned JSLT artifacts exist, but the
installed Framework snapshot POM predates that dependency. A fresh Framework local
installation is needed before consumer verification can exercise the prerequisite.

## Framework input and configuration boundary

`YamlSkillCatalog` reads `input_transform` separately from executor `config`,
accepts only `language: jslt` and a nonblank `expression`, and compiles it during
catalog preparation. It rejects this declaration on model-backed leaves
(`src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:416`, `:489`, `:496`).

`ExecutorInputTransform` uses the pinned Jackson 3 JSLT implementation. Its object
filter preserves authored null members. It admits JSON values with finite numbers,
rejects runtime handles for transformed input and requires an object result
(`src/main/java/ai/loomspan/internal/skill/ExecutorInputTransform.java:25`).

`YamlSkillDefinition#executorInput` returns the resolved ordinary input when no
transform is present and applies the captured compiled transform otherwise
(`src/main/java/ai/loomspan/internal/skill/YamlSkillDefinition.java:35`).
`ExecutionCoordinator` performs ordinary input validation/reference resolution,
prepares the executor input, checks lifecycle and constructs the v1 invocation
with that input, the leaf config and the captured executor binding config
(`src/main/java/ai/loomspan/internal/core/ExecutionCoordinator.java:175`).

`SkillExecutorInvocation` copies business containers and exposes `input()`,
`skillConfig()`, `executorConfig()`, captured identities, diagnostics and live
cancellation/deadline observations. It is deliberately supported Application API
under the exact v1 allowlist. The transform changes no v1 signatures
(`src/main/java/ai/loomspan/api/extensions/v1/SkillExecutorInvocation.java:29`).

`ExecutorInputTransformIntegrationTest#directAndPlannedChildDeliverTheSameNativeObjectAndRetainBusinessDiagnostics`
exercises direct and bound-child transformation, pre-dispatch input rejection,
configuration separation and original business diagnostics. Other tests in that
class cover captured expression generations and failed preparation.
`ExecutorInputTransformTest`, `ExecutorDeclarationTests`,
`SharedDeclarativeAuthorizationIntegrationTest` and
`ExecutorInvocationLifecycleIntegrationTest` establish the narrower transform,
declaration, authorization and lifecycle boundaries.

## Decisions request and settings ownership

Paths in this section are relative to `../loomspan-extensions/`.

`TypeSafeExecutor#execute` is reference-only `@SkillExecutor(name = "typesafe",
config = "typesafe")`. It calls `TypeSafeRequest.prepare(skillConfig,
executorConfig, input)` and returns serialization of the complete transport result
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeExecutor.java:14`).

`TypeSafeRequest.prepare` admits only `request`, `bindings`, `api_key` and
`base_url` in leaf config and only `api_key` and `base_url` in executor config.
It copies the request template, applies RFC 6901 target/source bindings, validates
the resolved request and serializes it once. Missing binding sources remove object
members, while missing array values fail. The pointer parser, lookup, overlap and
assignment logic are private to this old pack construction path
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeRequest.java:16`, `:128`).

Validation permits native `model`, `state`, and nonempty `questions`, with Choice,
Noul and Score forms. It rejects unknown provider fields and unsupported question
types. Copying preserves finite numbers and JSON content, checks cycles/depth,
and materializes permitted local Spring Resources as UTF-8 text. The serialized
body limit is 32 MiB. Plain URL strings stay text
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeRequest.java:41`, `:96`).

`TypeSafeSettings.capture` currently prefers a present leaf `api_key` or
`base_url` over the captured executor value, validates the selected values and
appends `/v1/systemone` to the selected base path. Absent base URL defaults to
`https://api.typesafe.ai`. Credentials are required and remain exact
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeSettings.java:8`).

`TypeSafeTransport.send` checks live lifecycle, captures settings once, clones the
prepared body and reuses it for at most three attempts. Authorization is request
local. Redirects and Apache automatic retries are disabled. It preserves the full
successful JSON value, including unknown fields and scalar/null values. Empty or
malformed successful content fails outside the IOException retry classification
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeTransport.java:69`, `:108`).
The default policy has 60-second total, 30-second inactivity, 5-second acquisition,
10-second connect limits, 250/500-ms backoffs and a 5-second Retry-After cap
(`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TransportPolicy.java:9`).

Transport request, response, caught failure and retry diagnostics use the v1
facility. Existing cancellation checks and request watchdog remain pack-owned.
Framework-accounted usage excludes pack sends/retries. `DecisionsAutoConfiguration`
constructs the executor and shared closeable transport. Its public classes and
internal classes serve construction, with no supported Java replacement SPI.
The pack POM declares Framework, Boot, HttpClient and Jackson dependencies and has
no direct JSLT dependency.

## Runnable recipe and installed consumer

`extensions/decisions/examples/support-triage/pom.xml` is an independent Maven
consumer of `ai.loomspan:loomspan-decisions:0.1.0-SNAPSHOT`. Framework arrives
transitively as `1.0.0-beta.10-SNAPSHOT`. Consumer Java imports use supported
Framework APIs. `TypeSafeConsumerTest#ordinaryDependencyDiscoveryIsReferenceOnlyAndPackaged`
asserts the dependency loads from a JAR and creates reference-only registration.

`triage.yaml` currently accepts a closed object containing `ticket`, declares
`SUPPORT_TRIAGE` and puts `jev-latest` plus team/repeat/impact questions in
`config.request`. Its pack mapping puts `/ticket` into request `/state`.
`assess.yaml` accepts numeric `probability` and binds its entire ordinary input
into the follow-up request's state using the pack mapping.

`parent.yaml` already uses Framework `input_bindings` to pass parent `/ticket`
to triage and select triage `/answers/repeat/noul` into assess `/probability`.
It forwards the complete assess result using `output_from`. The receiving child
schemas are closed and wholly bound. `CompositionConsumerTest` sends a real
two-task mocked plan, verifies the follow-up state probability and complete
forwarded response, and rejects missing/type-invalid answers before assess sends.

`ConsumerHarness` starts real Boot discovery and two local HTTP stubs, publishes
ordinary SkillDocuments and captured namespace settings through supported APIs,
invokes the public facade, and reads captured HTTP and canonical trace files
(`extensions/decisions/examples/support-triage/src/test/java/ai/loomspan/examples/triage/ConsumerHarness.java:54`).
Its `leaf` helper currently emits supplied maps under YAML `config`.

`TypeSafeConsumerTest` covers primitives, mixed questions, fidelity, local resource
handling, precise input, complete results, validation-before-send, retries,
redirects, canonical diagnostics and leaf connection overrides.
`PublicationConsumerTest` currently tests both leaf-owned and executor-owned
settings across concurrent replacement. `AccountingConsumerTest`,
`LifecycleConsumerTest`, `DiagnosticFaultConsumerTest`, and `ConsoleConsumerTest`
also construct fixtures through the old helper. Unit ownership resides in
`TypeSafeRequestTest`, `TypeSafeSettingsTest`, transport suites and auto-config tests.

`TriageApplication` publishes the recipe with application-resolved namespace settings
and prints captured request, native result and illustrative policy. Its default
JDK stub uses local test credentials. Optional arguments enable live use, which
existing deterministic verification does not exercise.
