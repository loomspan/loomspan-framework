## Summary

Executor YAML and model YAML are the two current manifest forms. The catalog
validates form applicability against the raw tree before binding the typed
manifest. An executor definition currently carries its original source, input
schema and immutable skill config, without model configuration. No
`input_transform` field or JSLT dependency exists in this checkout.

Direct and child calls converge at `CapabilityExecutionRouter`, which checks
access and validates the complete ordinary input contract. Child bindings have
already assembled business arguments at this boundary. `ExecutionCoordinator`
selects the captured definition, checks access again and resolves input refs on
the mission worker before constructing the supported v1 invocation. Its one
executor invocation construction is the common Java handoff.

The exact requested JSLT build is installed locally. A matching upstream source
checkout exists at the pinned commit with no tracked modifications. That commit
already uses Jackson 3. Its parser exposes an object-value filter, and its
compiled expression accepts/returns Jackson 3 `JsonNode` values.

## Detailed findings

### Manifest ingress, validation and immutable definitions

- `src/main/java/ai/loomspan/internal/serialization/SkillDocumentValues.java:44`
  decodes authored YAML to JSON-bound data while extracting only the actual
  top-level `config` subtree into ordinary YAML domain data. `checkJson` at line
  65 rejects non-JSON document values and nontextual keys before tree conversion.
  Arbitrary strings, including placeholder syntax, receive no expression meaning.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:386` reads the
  manifest. `validateDeclarationForm` at line 466 owns applicability and presence
  rules. An `executor` field selects executor form, rejects model-only fields
  even when null/empty, and validates the executor reference. Model form rejects
  executor-only `config`. Unknown properties fail typed binding.
- `YamlSkillCatalog#loadDefinition` at line 317 validates the ordinary input
  schema before constructing an executor definition. Executor definitions skip
  model resolution, output contracts, evidence/linter configuration and allowed
  child processing. `collect` catches authoring exceptions into structured
  `SkillValidationIssue` records. This is shared by startup and supplied-document
  validation/preparation, including namespace qualification.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillManifest.java:18` has an
  internal field-presence enum and typed getters/setters. Input/output schemas
  retain authored JSON plus immutable compiled canonical schemas. The current
  manifest contains no transform declaration.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillDefinition.java:42` detaches
  the manifest in its constructor. `copyManifest` at line 202 explicitly copies
  ordinary fields, preserves declared fields and separately shares immutable
  compiled schemas. `manifest()` returns another defensive copy. Definition
  input metadata continues to come from the ordinary `input_schema`.
- `YamlSkillSource` retains exact original YAML bytes. Prepared catalogs expose
  YAML source even when runtime references have been namespace-qualified.

### Argument assembly, validation and executor handoff

- `src/main/java/ai/loomspan/internal/runtime/input/ChildInputBindingAssembler.java:17`
  assembles a detached argument object from model-owned arguments, the exact
  owning parent's input and accepted direct-child results. Its pointers traverse
  object fields and preserve selected whole values. It rejects supplied bound
  destinations and records source provenance.
- `src/main/java/ai/loomspan/internal/runtime/tool/DefaultCapabilityInvoker.java:111`
  invokes the assembler and validates the complete receiving contract. At lines
  172–173 both ordinary and assembled calls enter the capability router.
- `src/main/java/ai/loomspan/internal/core/CapabilityExecutionRouter.java:54`
  checks authorization, validates exact caller/assembled input, checks captured
  capability ownership and calls `ExecutionCoordinator`. Validation returns
  detached input values and preserves the caller's contract.
- `src/main/java/ai/loomspan/internal/runtime/input/SkillInputValidator.java:21`
  walks Java values before standard-schema validation. Declared ordinary JSON
  scalars include finite floats/doubles and arbitrary-precision numbers. Runtime
  refs/attachments may accept Resources, streams or bytes under explicit schema
  markers. Generic contracts accept other runtime values. `jsonScalar` at line
  142 is private, and the validator does not expose a standalone JSON-only
  admission/conversion method for executor transforms.
- `src/main/java/ai/loomspan/internal/core/ExecutionCoordinator.java:98` obtains
  the definition from the captured target generation and checks access again.
  It records original mission input before worker execution. At line 169 its
  JAVA branch resolves schema-selected refs. At line 178 the sole production
  `ExecutorInvocations.create` call receives resolved input, separate skill
  config and captured executor config. Both root and child executor invocations
  reach this branch, inside `MissionWorkExecutor` and scoped authentication.
- `src/main/java/ai/loomspan/internal/vfs/InputReferenceTraversal.java:13` recurses
  through map/list input and resolves only generic or schema-marked leaves.
  Ordinary literal JSON strings in a declared contract retain their text.
  Resolved handles can therefore exist immediately before Java handoff.
- `src/main/java/ai/loomspan/api/extensions/v1/SkillExecutorInvocation.java:17`
  has a private constructor and existing `input()`, `skillConfig()`,
  `executorConfig()`, identity, diagnostics and live lifecycle accessors.
  `ExecutorInvocations` is its internal construction bridge. The supported
  invocation recursively freezes map/list containers through
  `ImmutableContainers`, retaining nulls and arbitrary non-container leaf identity.

### Generation capture and failure isolation

- `src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java:152`
  parses candidate execution configuration, loads/checks supplied documents and
  requires a valid checked set before constructing a candidate runtime/catalog.
  Preparation and publication are separate operations. `publish` at line 286
  checks the expected target base ID, then replaces active state atomically.
- `SkillGenerationManager#prepareCatalog` at line 224 stores each YAML
  definition in the generation's definition map and builds callable metadata
  from its original contract. Executor registrations/configuration are also
  captured in generation-owned state.
- `SkillGenerationManager#capture` at line 315 walks reachable callable edges
  and their executor namespace dependencies under the generation lock. Retained
  snapshots hold the selected generations through replacement/removal.
- `src/main/java/ai/loomspan/internal/skill/SkillAdmissionSnapshot.java:8`
  keeps immutable generation and resolved executor-binding maps. The target
  definition and selected executor configuration have separate captured owners.
  Thus a transform belongs to the executing leaf generation even when its
  executor registration comes from a different namespace.

## Surface inventory and classification

| Design-lens category | Current evidence and relevance |
| --- | --- |
| Application API | Exact v1 invocation and diagnostics types are deliberately allowlisted. Their current signatures already represent an arbitrary object input. `SkillTemplate` and reload APIs are existing public entry points. |
| Supported SPI | Repository policy declares none. Annotation-based executor declarations do not create a bean-replacement or Java SPI contract. |
| Configuration and manifest contracts | Root executor YAML syntax, caller `input_schema`, child `input_bindings`, config separation and exact field validation are author-visible. This ticket adds root syntax in that category. |
| Persisted or serialized contracts | No new durable format is identified. Existing authored YAML remains source data. |
| Ephemeral diagnostic formats | Catalogs retain exact YAML and source, execution frames retain business input and generation facts. Current REST/SSE/NDJSON and Console DTO shapes have no transform-specific field. |
| Internal or accidentally exposed implementation | Manifest/definition/catalog, generation managers, invocation bridge, mappers, constructors and runtime Spring wiring are internal despite public Java declarations. JSLT is required to remain internal by the ticket. |

guidance owns complete receiving input and projected model input. README currently
routes to both topics. The ticket requires updating authoring guidance to explain
the additional executor-side object without changing the caller/parent contracts.
