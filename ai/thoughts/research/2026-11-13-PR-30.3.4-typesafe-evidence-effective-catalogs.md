## Summary

The standard schema foundation already exists: `YamlSkillManifest` stores detached
Jackson trees, lazily compiles canonical input/output contracts, and no longer
defines the legacy InputSchemaManifest or OutputSchemaManifest nested classes.
TypeSafe derivation and two catalog consumers still use the removed types. A fresh
compile currently stops at eight compiler diagnostics in TypeSafeDeclaration and
YamlSkillCatalog; tests cannot execute through the root Maven build at this state.

Evidence grammar, namespace resolution and execution-history truth sets remain
separate from structural validation. Shared compilation already validates the
`x-loomspan-evidence` placement/shape and retains its exact text. Catalog extraction
still uses the old accessors and diagnostic vocabulary, and EvidenceContract still
trims and folds claim keys. Effective output metadata now serializes a canonical
provider copy instead of the historical fixed-field reconstruction cited by the
ticket. That copy retains constraints today, but it is explicitly named and owned
as a provider view.

Both TypeSafe request reparsing and response parsing currently use the shared
schema-tree mapper, which already enables USE_BIG_DECIMAL_FOR_FLOATS. The historical
rounding probes in the ticket do not establish a current rounding defect. Exact
request/response/trace decimal regression coverage is still an acceptance requirement.

## Current production paths

### Standard declarations and immutable snapshots

- `src/main/java/ai/loomspan/internal/skill/YamlSkillManifest.java:50` stores
  compiled canonical schemas; `compiledInputSchema()` and `compiledOutputSchema()`
  use INPUT/OUTPUT roles with AUTHORED origin. Getters/setters deep-copy raw trees.
- `src/main/java/ai/loomspan/internal/schema/StandardSchemaCompiler.java:16`
  defines the bounded Draft 2020-12 profile with NetworkNT 3.0.9. It rejects
  unsupported keywords, validates meta-schema shapes, initializes validators and
  blocks external schema fetching. Exact names, explicit nullable type arrays,
  ordinary-input typed maps/unconstrained leaves, standard bounds/formats and
  generated false property ownership are represented in the current compiler.
- `StandardSchemaCompiler.java:91` checks evidence annotation role, immediate root
  property placement, string type and nonblank content. It does not parse evidence
  grammar or resolve child names. Legacy schema-node `evidence` is unknown syntax.
  Ordinary property names under `properties` are traversed as names, not keywords.
- `src/main/java/ai/loomspan/internal/schema/CanonicalSchema.java:10` retains an
  immutable tree and initialized validator. `tree()` detaches a canonical copy.
  `providerTree()` detaches a copy and strips exactly recognized Loomspan
  annotations at schema-node positions, following properties, items and
  schema-valued additionalProperties. Similarly named data properties survive.
  Local validation does not mutate or coerce input and enables format assertions.
- `src/main/java/ai/loomspan/internal/serialization/LoomspanJacksonCodecs.java:36`
  builds `schemaTree` with USE_BIG_DECIMAL_FOR_FLOATS. `applicationConversion` is
  separately supplied and remains ordinary application conversion. This is current
  code, not the historical codec state described by the ticket's probe.

### TypeSafe declaration, metadata and admission

- `src/main/java/ai/loomspan/internal/typesafe/TypeSafeDeclaration.java:20` captures
  a detached native declaration, compiles substitution tokens, validates literal
  structure and derives descriptive output metadata once. `outputSchema()` at
  line 37 still returns the deleted OutputSchemaManifest type.
- `TypeSafeDeclaration.java:471` derives the existing result table: a closed root
  requiring all question names; open answer objects requiring their named fields;
  singleton primitive `type` enums; noul number; choice string and fixed candidate
  enum; score number; descriptive confidence/probability ranges; closed named
  probability fields for fixed criteria; open probability objects for dynamic
  criteria; open score legends. Numeric assertions and typed probability-map
  schemas are absent. These schemas are descriptive metadata.
- `TypeSafeDeclaration.java:41` checks JSON-compatible input before conversion,
  substitutes only state/instructions/criteria, validates the fully resolved
  native request, and captures JSON text. Literal/reference handling and native
  case-insensitive question/candidate collision checks are distinct from evidence
  claim-name semantics. `ResolvedRequest.json()` at line 74 reparses a detached
  tree using the schema-tree codec; returned copies may be mutated independently.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:324` validates
  authored input first. TypeSafe requires input_schema, rejects attachments,
  requires a TypeSafe-backed model alias and returns an empty local evidence
  contract. Its declaration-form check at line 477 rejects chat execution and
  authored output fields even when present with null/false/empty values.
- `YamlSkillCatalog.java:500` still declares attachment traversal using the deleted
  InputSchemaManifest and old `type: attachment` representation. It traverses
  properties/items, but the method currently has no map-value branch.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillDefinition.java:109` already
  declares a CanonicalSchema output accessor and delegates TypeSafe metadata to
  TypeSafeDeclaration. This exposes the remaining representation mismatch.
- `src/main/java/ai/loomspan/internal/runtime/input/SkillInputValidator.java:21`
  applies JSON-compatible Java-value admission and shared canonical validation.
  Open or unconstrained input does not admit unmarked Resource/InputStream/byte[]
  handles. Generic inputs are an explicit separate contract mode.

### Native evaluator and decimal evidence

- `src/main/java/ai/loomspan/internal/typesafe/TypeSafeExecutor.java:26` resolves
  one private request, adds the configured model verbatim, serializes one body
  before retry iteration, and records native request evidence. Model/connection,
  mission lifecycle and physical attempt quotas come from the captured binding.
- At line 89 it parses successful HTTP bodies with the schema-tree codec. It
  records the parsed envelope (or raw malformed body), available served model,
  endpoint and requested model. Successful HTTP usage is recorded once before
  answer extraction. Only an object-valued `answers` is required; empty/extended
  objects and descriptive-schema mismatches are returned without validation or
  schema repair. Transport failures use the existing retry decider; extraction
  failures occur after the transport catch and are terminal.
- `src/main/java/ai/loomspan/internal/runtime/input/AcceptedResultDecoder.java:12`
  is the existing private arbitrary-precision decoder for accepted business
  results. It additionally enables big integers and trailing-token rejection.
  It returns immutable JSON-compatible values, retaining malformed/plain text.
- Research did not run an exact native HTTP decimal fixture. Mapper configuration
  is source evidence, not a passing end-to-end numeric assertion. The trace path
  must be exercised with precision-preserving comparisons rather than default
  floating-point tree equality.

### Evidence extraction, identity and runtime behavior

- `YamlSkillCatalog.java:835` compiles only immediate output properties, parses
  expressions with the owner namespace and verifies references against direct
  allowed children. It retains wrong-case suggestions and original token columns.
  Its loop at line 849 still uses deleted OutputSchemaManifest/getEvidence;
  diagnostics currently end in `.evidence`. Line 895 creates a lowercase claim
  index.
- `src/main/java/ai/loomspan/internal/runtime/evidence/EvidenceContract.java:12`
  stores expression and normalized-claim maps. `expressionForClaim()` and
  `presentClaims()` trim/lowercase keys. `presentClaims` uses property presence,
  so explicit null is present, while absent optional fields are absent.
- `EvidenceExpressionParser.java:23` parses original text directly, uses 1-based
  original token positions, case-insensitive whole-token and/or operators,
  and-before-or precedence and parentheses. Identifier leaves use SkillIdentity
  owner-relative resolution. The compiled AST renders canonical expressions;
  authored expression text remains in canonical declaration/source snapshots.
- `EvidenceCoverageValidator.java:16` checks every annotated claim for planning,
  using a set of nonblank exact PlanTask capability names. Final validation checks
  only present claims against a set of successfully executed direct children.
- `EvidenceBackedOutputValidator.java:46` determines present annotated claims from
  the structurally accepted candidate. `DefaultMissionExecutionEngine.java:186`
  invokes evidence checks on assembled bound outputs. Existing evidence advisor
  and ordinary final-output repair paths own correction/replay/no-tool behavior.
- Successful-call credit is recorded by DefaultCapabilityInvoker after successful
  invocation, DefaultPlanningService and StepLoopMissionExecutionEngine for
  assigned work, and DefaultExecutionStateService into the current mission's set.
  Failure/cancellation paths do not execute the success recording point. Nested
  missions have their own successfulDirectSkills state.

## Contract classification and public surface

- **Application API:** existing allowlisted SkillCatalog/SkillDescriptor and
  SkillTemplate signatures; descriptor schema strings are the consumer-facing
  path. The ticket explicitly preserves descriptor signatures. The architecture
  test is required after production changes.
- **Supported SPI:** none. Public internal declarations, constructors, Spring
  wiring or mock seams do not create a replacement/extension promise.
- **Configuration and manifest contracts:** standard input/output syntax,
  x-loomspan-evidence, exact claim keys, TypeSafe declaration restrictions and
  existing connection/model configuration are author-visible. The ticket
  explicitly authorizes removal of superseded vocabulary without aliases.
- **Persisted or serialized contracts:** catalog/inspection JSON carries schema
  text; native System One request/response protocol stays intact. No new durable
  compatibility promise or trace interchange format is introduced by this work.
- **Ephemeral diagnostic formats:** expression paths/columns, original source,
  native request/envelope/raw body, usage and effective inspection metadata.
  Existing REST/Go/TypeScript consumers pass existing fields; the ticket changes
  schema content rather than DTO signatures or transport event shapes.
- **Internal or accidentally exposed implementation:** CanonicalSchema,
  TypeSafeDeclaration, EvidenceContract, catalog preparation, internal constructors
  and Spring bean mechanics. No internal compatibility shim is established.

Existing canonical trace fidelity and the narrow ExecutionJournalProjector derived
journal/observer exception remain exactly as described by repository AGENTS.
