## Summary

The independently versioned Extensions artifact already implements the complete
31.2.1 transport, captured settings, bounded retries/deadlines, JSON decoding,
request/response/retry diagnostics and Spring shutdown cleanup. Its Boot imports
currently register only that transport. There is no annotated TypeSafe executor,
request builder or runnable consumer. The support-triage directory is a README
placeholder. The next work is owned by Extensions; Framework supplies the already
implemented v1 API, generic executor/YAML behavior and observation.

Framework's ordinary Java return conversion has an important concrete boundary:
Java null becomes empty text and Java String passes through without JSON quoting.
The transport returns decoded Java Object values, including null and String.
The pack's actual executor therefore needs a representation preserving those native
JSON shapes through existing conversion; no Framework conversion change is authorized.

31.2.1 already refreshed primary provider documentation and checked in synthetic
mixed text/JSON request and complete response fixtures on 2026-11-16. No concrete
remaining provider-contract uncertainty was found requiring a repeat refresh.
No external source was fetched for this stage.

### Transport handoff already implemented

`extensions/decisions/src/main/java/ai/loomspan/decisions/internal/typesafe/TypeSafeTransport.java:37`
contains an implementation-detail reusable transport. Its public constructor and
`send(byte[], SkillExecutorInvocation): Object` are not supported application APIs.
The complete selected policies are recorded in 31.2.1 ticket Execution notes and
`extensions/decisions/docs/transport.md`:

- `send` checks live lifecycle, captures settings once, clones prepared bytes once,
  and reuses them through at most three sends. It does not construct requests from
  application input or select a model.
- One synchronous HttpClient/pool and one watchdog are Spring-owned. Pool capacity
  is 100 total / 20 per route. Apache automatic retries and redirects are disabled.
- Per-attempt total budget 60s, inactivity 30s, pool acquisition 5s, connect 10s;
  total is capped by live remaining execution time, with polling/wait slices at
  most 25ms. Previously observed deadlines cannot be extended.
- Retryable statuses are 408/429/500/502/503/504/529, plus IO/request timeouts while
  live. Backoffs are 250/500ms; valid Retry-After overrides cap at 5s. Local request
  construction is outside this retry loop.
- Non-success status classification precedes error-body handling. Error evidence
  is a bounded 64KiB UTF-8 prefix with explicit truncation/unavailability.
- Success bytes decode once to native maps/lists/scalars with BigInteger and
  BigDecimal numbers and strict trailing-token rejection. Malformed/empty success
  raises failure outside IO retry classification. There is no answer schema,
  confidence validation, envelope extraction or usage aggregation.
- Request body string/endpoint/attempt, complete decoded response, caught HTTP/IO
  failure and retry delay are supplied through existing info/warn diagnostics.
  Diagnostic preparation/recording RuntimeExceptions are contained. Business
  preparation, result serialization, JVM-wide Errors and pre-existing automatic
  recording retain their separate existing semantics.
- Physical IO executes on the calling invocation; the watchdog only polls/cancels.
  Closing cancels the client and terminates the timer. No generation resource
  callback, authenticated-client cache or separate background IO worker exists.

`TypeSafeSettings.java:8` applies presence-based `api_key` and `base_url` selection:
skill map first, executor map second, provider base default last. Present invalid
values fail with their selected config path. Credentials are required, nonblank,
ASCII HTTP-header-safe, and otherwise remain unchanged. URLs must be HTTP(S) with
host and optional prefix, without user info/query/fragment. Trailing slashes are
removed before appending `/v1/systemone`; prefixes are preserved. No environment,
`${...}`, native connection or credential-reference resolution exists.

### Configuration, binding and resource behavior

`src/main/java/ai/loomspan/internal/serialization/SkillDocumentValues.java:44`
decodes the overall skill through the lossless document path, then separately
reads actual executor `config` using ordinary `YamlValues.read`. Thus exact decimal
source digits may already have rounded before reaching the pack. The ticket
accepts that boundary and forbids precision modes or added conversion/rounding.

`SkillDependencyValidator.java:244` excludes executor definitions from generated
output schema resolution. Executor YAML rejects `output_schema`, native `model`
and native TypeSafe fields. Its generic `config` is pack domain data. Application
request binding and model selection therefore belong within the pack config/input
contract selected during planning, rather than native model registry reuse.

`agent-skills/loomspan-docs/references/skill-authoring/input-bindings.md` describes
parent input and successful child-result object JSON Pointers, with existing runtime
validation when producer schemas are unknown. Native complete pack results require
application paths under `/answers/...`. No generated output metadata or new
Framework binding enforcement is in scope.

Framework already resolves ordinary input references to Resource handles; see
`ExecutorApplicationIntegrationTest` and `docs/quickstart-executors.md`. Resource
handles do not freeze bytes. A pack supporting local text/JSON content must
materialize it during request construction, before retry. No existing transport
request builder traverses Resource leaves or fetches remote URLs.

### Consumer and diagnostic evidence paths

`SkillTemplate.java:15` supplies supported validate/invoke overloads, including an
observer accepting `SkillExecutionView`. Results are text. `SkillReloader.java:9`
supplies complete namespace validate/prepare/publish/snapshot operations, using
`SkillDocument`, `ExecutionConfiguration` and normal visibility rules. These are
supported consumer paths; internal context runner bean replacement is not.

`SupportedSurfaceIntegrationTest` demonstrates public-facade executor and YAML
composition against a local protocol-compatible model endpoint.
`ExecutorGenerationExecutionIntegrationTest` demonstrates real YAML/config loading,
publication, direct invocation and ordinary observation. The latter test imports
Framework auto-configuration because it is a Framework test; that convenience is
not a supported external-consumer import.

`ExecutorDiagnosticsIntegrationTest` checks real canonical diagnostics but uses
internal trace helpers. A pack consumer can observe public views and inspect
persisted canonical JSON evidence as files without importing those helpers.
The derived journal/observer retains the known ExecutionJournalProjector field-name
redaction exception; canonical traces and business results preserve source content.
This ticket's normal fidelity proof must distinguish those existing paths.

Diagnostics are records within existing execution frames, never new frames or a
separate stream. Existing spellings are `EXECUTOR_DIAGNOSTIC_RECORDED` and
`EXECUTOR_DIAGNOSTIC_SYSTEM_NOTICE_RECORDED`. Framework controls timestamps,
association and sequence. Existing `data` content envelopes carry severity,
message/data state and supplied JSON. System notices have no developer severity.
The established MCP tools are `LOOMSPAN_query_trace_records` and
`LOOMSPAN_read_trace_content`; no new tools/content protocol/indexes/filters are
introduced here. Advanced Console/MCP qualification belongs to 31.3.2.
