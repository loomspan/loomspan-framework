## Summary

The checkout contains PR 28.1's shared callable/executor discovery and final managed-proxy invocation, and PR 28.2's explicit executor declarations and immutable namespace-indexed configuration. Generation assembly currently stops executor-backed YAML with `Executor generation binding is not implemented yet`. Executor registrations remain in discovery's separate reference-only index; generation storage and reachable capture currently contain callable capabilities and YAML definitions only.

`SkillDependencyValidator` already owns candidate overlay, transitive callable namespace checks, input bindings and prepared output-contract checks at preparation and admission. `SkillGenerationManager` owns atomic capture, namespace installation, resource leases and retirement. `ExecutionCoordinator` already has a single Java/REST direct-work branch through bounded mission execution, reference resolution and scoped authentication. Its definition lookup and diagnostic catalog currently infer declaration provenance from execution kind. Internal `CapabilityKind` has exactly four values mapping one-to-one to public `SkillKind` and no independent behavior beyond `publicKind()`.

The ticket explicitly authorizes removing REST API/runtime/kind support and compatibility breaks. The remaining feature tickets assign composed declarative authorization to PR 28.4 and diagnostic wire/UI provenance to PR 28.6; those are scope boundaries, not reasons to retain obsolete execution paths.

## Detailed findings

### 1. Existing Java declarations and invocation

- `src/main/java/ai/loomspan/internal/core/SkillMethodBeanPostProcessor.java:44` is the one discovery component. `capabilities()` at line 97 returns callable registrations; `executors()` at line 104 returns reference-only registrations from a distinct index.
- `registerExecutor` at line 198 constructs `SkillExecutorRegistration` with canonical identity, the raw annotation config path, resolved declarative access policy, Java source and an invocation function. It requires exactly one invocation-record parameter and uses the same canonical method/proxy validation as callable declarations. The registration's function passes a single invocation argument to `JavaSkillInvoker`.
- `registerSkillMethod` at line 216 constructs callable metadata, reflected input contracts and typed argument binding. Both forms converge on `JavaSkillInvoker.invoke`, which obtains the final bean by name, selects its runtime-invocable method, invokes the managed proxy, normalizes null/void to empty text, preserves strings, and JSON-serializes other values.
- `SkillExecutorRegistration.java:8` is an internal record, not a callable capability. Its config path is not currently parsed/bound. `JavaSkillInvoker.java:17` and `SkillFailurePolicy` are the shared execution and transparent-wrapper/failure owners delivered by the prior ticket.
- `src/main/java/ai/loomspan/api/SkillExecutorInvocation.java:13` already defines the exact five-component record: input, skillConfig, executorConfig, skillName and executorConfigGenerationId. Required-field validation and recursive map/list copying preserve nulls and arbitrary leaf identity, including Spring Resource handles. It exposes no authentication, snapshot, runtime or full configuration object.
- `SharedJavaDiscoveryInvocationTest` covers separate role indexes with same-name coexistence, lazy executor discovery, canonical interface bridges, split-role rejection, proxyability, actual method-security advice, result conversion and transparent infrastructure wrappers. These tests invoke executor registrations directly as discovery tests; they do not establish generation-backed execution.

### 2. Manifest and configuration ingress

- `YamlSkillDefinition.java:18` declares `Form.MODEL`, `TYPESAFE`, `EXECUTOR`. Executor definitions retain original YAML/source, a canonical identity, optional immutable skill config and no model execution configuration. Accessors `executor()` and `config()` exist separately from `allowedSkills()`.
- `YamlSkillCatalog.java:457` resolves executor references through its identity helper; line 748 calls `SkillIdentity.resolve(reference, namespace)`. Local references are owner-relative, qualified references explicit. `SkillIdentity.java:13` owns normalization and strict grammar; canonical references have one hyphen and no fallback lookup.
- `YamlSkillCatalog.validateDeclarationForm` at line 486 owns authored field-presence/type/form restrictions. Executor leaves reject model/planning/children/output schema combinations; old `rest` syntax fails ordinary unknown-field validation. Definition construction protects representation invariants rather than selecting forms by missing execution configuration.
- `ExecutorConfiguration.java:10` stores immutable namespace-to-map data, copied using `ImmutableContainers`. `from` validates section/namespace map structure and namespace names; `requireTarget` rejects foreign entries for publication. It deliberately has no path resolver or domain semantics.
- `ExecutionConfigurationParser.java:23,54,122,132` accepts executor-config, validates the target namespace, and returns the same immutable value through `Parsed.executorConfig()` and parsed properties. Omission constructs an empty value; no previous or startup inheritance occurs.
- `LoomspanProperties.java:32` holds this immutable representation at startup. `ExecutorYamlPropertySourceLoader`, production spring.factories registration and `ExecutorConfigurationBinding` preserve raw map/list/null/scalar/case/dotted-key data across real Boot Config Data loading, avoiding ordinary Binder flattening/interpolation for this subtree.
- `ExecutorDeclarationTests`, `ExecutorConfigurationTests`, `ExecutorConfigurationStartupTests` and `ExecutorConfigurationManagerTests` exercise structural validation, actual startup equivalence, publication-target handling, defensive copies and no application invocation. Configuration path syntax/binding remains absent, as stated by the bundled docs.

### 3. Namespace preparation, publication and ownership

- `SkillGenerationManager.java:69` stores a completed fixed callable snapshot plus obsolete fixed REST handler names/handler. `initializeFixedDependencies` at line 439 reads `javaSkills.capabilities()` and REST bean names, but not `javaSkills.executors()`.
- Startup at line 99 builds default plus non-default namespaces discovered from fixed callable capabilities. Startup namespaces are Private. The namespace enumeration currently has no executor-only source. Default YAML startup checks use an empty foreign view.
- `capturePreparation` at line 151 snapshots the active namespace map and target base ID under `generationMonitor`. It does not increment ownership or retain foreign provider resources. `PreparationView` contains generation objects, but metadata checks read declarations/capabilities/visibility, not live invokers or runtime clients.
- `prepare` at line 160 parses structural configuration, checks documents against the captured metadata view, then parses credential-backed provider settings and assembles a detached target generation. `validate` at line 173 follows the metadata-only path and does not build runtime resources.
- `prepareCatalog` at line 229 re-adds fixed callable registrations for its target namespace, computes YAML metadata from checked contracts, then constructs target provider runtime. Line 246 explicitly rejects executor definitions before metadata construction. No executor configuration is currently passed to `SkillGeneration`.
- `SkillGeneration.java:20` owns namespace/ID, visibility, immutable callable and definition indexes, public/diagnostic catalogs, and optional `ExecutionRuntime`. Definition checks at lines 70–79 expect only YAML or TypeSafe kinds; executor-backed JAVA definitions do not satisfy that assumption. `owns` checks capability object identity.
- `ExecutionRuntime.java:11` owns prepared provider clients/settings and closes its registry once. Its property-copy code does not copy executor configuration; executor configuration is currently not used for execution. This runtime is not an executor resource owner.
- `publish` at line 279 checks only the target's expected base ID and installs atomically. Foreign dependency changes do not revalidate publication. `remove` at line 289 withdraws the namespace and marks its prior generation superseded; it does not destroy application beans.
- `PublishedGeneration` tracks owners. `selectIfRetired`, `dispatch` and `OwnerLease.close` at lines 374–434 select retirement after supersession and zero owners, close provider runtime outside the monitor, and deliver existing listeners. Never-published candidate cleanup and public one-shot update behavior are handled by `DefaultSkillReloader`/`DefaultPreparedSkillUpdate` with the framework lifecycle owner.

### 4. Shared dependency checks and root-reachable admission

- `SkillDependencyValidator.java:21` permits same namespace or a Public foreign target. Default has no special Public status.
- `check` at line 40 seeds target fixed callables and all proposed target definitions, then overlays only foreign generations. Thus references returning to the candidate see its complete replacement rather than old target declarations.
- `checkGraph` at line 87 starts from the supplied candidate roots. `visit` at line 314 traverses only allowedSkills, checks existence/visibility and follows YAML children. Shared graph checks resolve input contracts, binding contracts and effective output schemas. Executor references are currently not included.
- `checkAdmission` at line 64 builds lookup indexes from retained namespaces but seeds graph traversal with only the entry definition. It validates the root-reachable graph and compares recomputed output contracts with prepared metadata. It does not make all definitions in a captured namespace validation roots.
- `SkillGenerationManager.capture` at line 305 walks a queue of reachable callable identities under `generationMonitor`, selects exactly one active generation per namespace, fails missing namespaces/callables, follows only allowedSkills and increments ownership for the selected set. `validateAdmission` at line 337 performs expensive checks outside the monitor.
- `SkillAdmissionSnapshot.java:8` is the immutable authoritative association. `resolve` and `generation` use only selected generations. It currently has no executor-registration/configuration binding result.
- `DefaultSkillTemplate.java:148–189` captures once, normalizes/validates input, then validates admission outside the monitor. Failure closes the lease. The same prepared snapshot feeds direct execution and `DefaultSkillInvocationHandoff` so queued retained work does not recapture at invocation.
- `ExecutionBinding.java:12` carries that snapshot through session, target switching and physical branches. Root-target and exact declared-child authority remain separate from namespace retention. `DefaultAccessGuard.java:62` requires captured ownership, the actual entry for root calls, or the current source's allowedSkills plus captured visibility for child calls. Retaining a foreign namespace alone does not authorize calling its other capabilities.

### 5. Execution routing, references and provenance

- `CapabilityExecutionRouter.java:59` checks access and exact input validation, requires the current session binding and captured capability ownership, then delegates to `ExecutionCoordinator`.
- `ExecutionCoordinator.java:105` selects the captured target generation, rechecks access, and currently retrieves a YAML definition only when kind is YAML_SKILL/TYPESAFE_SKILL. A JAVA-classified YAML declaration therefore needs declaration lookup independent of that assumption.
- The shared direct-work branch at line 160 accepts JAVA_SKILL or REST_SKILL. It resolves reference inputs through the current session/input contract inside `MissionWorkExecutor`, installs/restores caller authentication, then invokes the capability function. Mission frames, failure recording, parent restoration, cancellation and limits surround the branch. Existing Java lifecycle and cutoff tests establish this path.
- `DefaultCapabilityInvoker` adds normal child tool frames, input binding, usage, task outcomes and success/failure evidence. `DefaultToolSurfaceService` delegates visible child selection to `SkillVisibilityResolver`; existing access guard preserves callable authority. The executor registration itself is absent from these callable catalogs/tools.
- `DefaultRegisteredSkillCatalog.java:34` currently treats YAML/REST/TypeSafe kind as manifest provenance and JAVA as bean/method provenance. Public `DefaultSkillCatalog.java:37` obtains kind through `CapabilityKind.publicKind()`. These are separate consumer assumptions: retaining a definition for a JAVA executor leaf is needed in Framework, while the ticket explicitly assigns diagnostic wire/UI provenance completion to PR 28.6.
- `CapabilityKind.java:5` contains only YAML_SKILL→YAML, REST_SKILL→REST, JAVA_SKILL→JAVA, TYPESAFE_SKILL→TYPESAFE and a getter. No distinct required execution responsibility exists in that enum in the inspected source. Production uses occur in discovery, metadata, generation assembly/checks, coordinator, public catalog conversion and diagnostic catalog selection. Tests/testkit also construct it extensively.
