## Research question and execution context

Map the current implementation, integration evidence, consumer guidance and verification boundaries for `ai/thoughts/tickets/loomspan-pr-28.7-executor-integration-and-consumer-guidance.md`. The developer selected the Full 5-Step Pipeline after Step 0. This is Step 1, with no implementation changes or tests run. The checkout was clean at initial triage and research. The only new artifact from this stage is this document.

The ticket, accepted `configured-java-skill-executors.md` design, feature design lens, root guidance and Console guidance govern the work. Historical wording describing executors as unimplemented in the phase document describes its design-time baseline; current production source and focused tests below implement the preceding tickets. Sidecar HTTP migration and Planner Failure Recovery are separate efforts. Content fidelity and the existing derived-journal/observer-only redaction exception remain explicit boundaries.

## Summary

Production already has a shared Java scanner/invoker, an explicit executor YAML form, immutable namespace executor data, captured dependency bindings, composed authorization, actual standard-tool feedback limited to designated recoverable exceptions, and separate Console execution-kind/declaration provenance. Existing tests cover substantial portions of the requested integration, including real Spring proxies, retained foreign generations, cancellation, the three failure routes, quotas and original deadlines. These are executable test definitions, not claims that this research executed them.

The inspected integration tests use synthetic executor behavior. Existing HTTP mock servers primarily simulate model-provider requests; no application executor making an HTTP request was located in the inspected source/test/docs inventory. SQL-shaped data exists in a startup-binding fixture, but that fixture does not invoke a SQL-shaped executor. Reference resolution into an executor is covered with a custom resolver in a coordinator-level test; the actual `DefaultRefResolver` and session filesystem are separately tested. Current documentation already covers most settled contracts, while resource retirement is described generically rather than linked concretely to executor configuration-owner IDs. The only complete runnable application guide located is `docs/quickstart-java.md`, whose example uses an annotated callable method.

## Detailed findings

### 1. Public declarations and the Java execution owner

- `src/main/java/ai/loomspan/api/SkillExecutorInvocation.java:14` defines the five-component public record: input, skillConfig, executorConfig, skillName, executorConfigGenerationId. Its constructor requires all values, rejects blank metadata, and recursively copies map/list containers through `ImmutableContainers`; arbitrary leaves retain identity. No authentication/context/runtime component is present.
- `SkillExecutor` supplies name/namespace/config; `RecoverableSkillException` is the designated failure contract. The exact closed 25-type API allowlist is in `src/test/java/ai/loomspan/architecture/LoomspanPublicSurfaceArchitectureTest.java:30`. `SkillKind` is the shared execution classification, including JAVA for executor-backed YAML.
- `src/main/java/ai/loomspan/internal/core/SkillMethodBeanPostProcessor.java:50` owns separate callable and reference-only executor indexes in one discovery flow. `:176` determines the role; `:199` constructs an executor registration, validates the single invocation parameter, and uses the shared identity/security infrastructure. `:277` rejects conflicting callable/executor declarations across canonical and interface methods. `:90` validates actual proxy invocability.
- `src/main/java/ai/loomspan/internal/core/JavaSkillInvoker.java:22` obtains the final managed bean and selects an invocable method. It preserves null/void as empty text, Strings exactly, and serializes other results with the application mapper. Reflection failures pass through `SkillFailurePolicy`. Runtime method selection and interface bridge mapping are shared by both roles.
- `src/main/java/ai/loomspan/internal/core/SkillExecutorRegistration.java:8` is an internal immutable registration carrying identity, config path, access policy, source and invocation function. Public Java visibility supports cross-package implementation, not an SPI.

The role differences visible in source match the design's table: callable methods derive input schema and bind typed parameters; executors accept the invocation record, use YAML input metadata, and select configuration through namespace bindings. Both converge on managed-proxy invocation and result/failure conversion. Executors have a reference-only index; their callable surface belongs to a YAML declaration.

### 2. Authoritative manifests and raw configuration ingestion

- `src/main/java/ai/loomspan/internal/skill/YamlSkillDefinition.java:18` has explicit MODEL/TYPESAFE/EXECUTOR forms. Executor definitions require absent model execution configuration (`:55`). Definition ownership is distinct from execution kind.
- `src/main/java/ai/loomspan/internal/skill/YamlSkillCatalog.java:405` removes raw executor configuration before typed manifest decoding, preserves its data, then installs the copied map. `:486` selects explicit form and validates field presence, including forbidden fields on executor declarations; `rest` is unsupported syntax.
- `src/main/java/ai/loomspan/internal/skill/ExecutorConfiguration.java:17` requires map shape at section and namespace roots, normalizes namespaces, preserves data keys, rejects duplicate normalized namespaces and enforces target-only publication (`:38`).
- `src/main/java/ai/loomspan/internal/autoconfigure/ExecutorYamlPropertySourceLoader.java:18` captures raw `loomspan.executor-config` before normal Boot flattening. `ExecutorConfigurationBinding` supplies fixed early conversion. `ExecutionConfigurationParser` uses the same immutable configuration model for publication. Ordinary provider credential references remain a separate Framework-owned contract.
- `src/test/java/ai/loomspan/autoconfigure/ExecutorConfigurationStartupTests.java:17` loads real Spring Config Data with nulls, empty containers, exact case/dotted keys, lists and scalar distinctions, compares publication parsing, and includes `infrastructure.databases.inventory: {database: arbitrary, sql: "select :input"}`. Its later tests cover imports, profiles, empty documents, duplicate keys, null spellings and aliased containers. This is configuration-ingestion evidence, without executor domain execution.

### 3. One generation system, shared dependency rules, captured execution

- `src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java:238` creates metadata with JAVA execution kind for executor YAML while retaining definitions. `:264` records implementation provenance from the resolved registration. `:284` publication checks only target base/absence. `:317` captures callable reachability and executor namespace dependencies under one registry monitor; admission validation happens separately. Executor references retain a namespace without traversing its unrelated callable graph.
- `src/main/java/ai/loomspan/internal/core/ExecutionCoordinator.java:158` has one JAVA dispatch branch. It installs scoped caller authentication on mission work, resolves inputs with the declared contract, then either constructs `SkillExecutorInvocation` from the captured binding/definition or invokes ordinary typed Java binding. It uses the existing `MissionWorkExecutor`, execution frame and failure recording lifecycle.
- `src/test/java/ai/loomspan/internal/skill/ExecutorDependencyResolutionTest.java:55,80,103,142,169,193,220` covers exact malformed/missing/null/scalar/list path rules, local/qualified references, private namespace rejection, retained config and policy, foreign changes between preparation/publication, no authority expansion, mixed reference-role coherence, and expensive validation outside the registry lock.
- `src/test/java/ai/loomspan/integration/ExecutorGenerationExecutionIntegrationTest.java:23,46,108,130,162` covers startup/publication selected data, retained handoffs across foreign replacement/removal/recreation, preparation not retaining foreign runtime, actual cancellation fencing, and secured retained work restoring ambient caller context. ### 4. Security, reference resolution, lifecycle and observations

- `src/main/java/ai/loomspan/internal/security/SkillRoleEvaluator.java:35` composes YAML access and captured Java executor policy with logical conjunction against one Authentication. Role-prefix/hierarchy handling is shared. It does not execute application advice during discovery/validation.

Its other tests cover lazy executor-only discovery, role conflicts, unsafe proxy dispatch, path and identity rules.
- `src/main/java/ai/loomspan/internal/vfs/DefaultRefResolver.java:21` resolves only an exact `ref://` String. - `JavaSkillLifecycleIntegrationTest`, `JavaSkillMissionCutoffTest`, `ExecutorGenerationExecutionIntegrationTest` and existing mission/usage tests own completion, observer history, timeout, interruption and late-completion fencing. `SupportedSurfaceIntegrationTest.java:108` drives an actual model-backed explicit-step parent with callable and executor children via supported facade APIs; it verifies public kind, handoff, input validation, caller and completed observations.

### 5. Failure orchestration and diagnostic identity

- `src/main/java/ai/loomspan/internal/core/SkillFailurePolicy.java:12` unwraps only transparent reflection/proxy, worker ExecutionException and Spring AI ToolExecutionException wrappers with bounded/cycle-safe traversal. It recognizes only an effective RecoverableSkillException, never arbitrary application causes. It preserves RuntimeExceptions/Errors and transparently represents checked application failures.
- `src/main/java/ai/loomspan/internal/springai/SpringAiChatClientAssembler.java:49` constructs the production standard ToolCallingManager. Its exception processor uses that shared policy, emits JSON with `status: failed`, `correctionPermitted: true` and exact application message only for designated failures, and propagates all others. `CanonicalToolCallingManager` owns canonical tool selection.
- `LoomspanSession.java:153` owns canonical failure identity and cause linkage through the shared unwrapping policy. `TraceFailureMetadata.java:24` records classification and exact exception message. Transparent propagation reuses identity; a distinct application wrapper can link to an already recorded cause without inheriting recoverability.
- `src/test/java/ai/loomspan/integration/ExplicitJavaFailureHandlingIntegrationTest.java:28` parameterizes callable/executor forms through direct, actual standard-tool and explicit-step routes. It tests designated/transparent/terminal/application wrappers, exact Unicode/whitespace messages, one invocation, observer failures, and failure recording before the next provider turn.
- The same class covers terminal authorization/cancellation/shutdown, model-selected reattempt versus alternate selection, successful-result binding exclusion, all existing quota meters and original parent deadline. It checks provider/model/tool/skill/usage-unit accounting and no successful completion for failed calls. These tests already provide the requested three-route integration; they are not standalone simulated manager callbacks.

## Architecture and removal inventory

The current ownership map has one Java discovery processor and managed invoker; one SkillRoleEvaluator for declarative access; one immutable executor configuration representation shared by raw startup/publication ingress; one dependency validator with two explicit reference roles; one shared Java failure classifier; one generation capture/retirement system. Role-specific argument construction and callable-schema ownership are explicit and required by the accepted contract. Provider retry classification remains a different domain from Java application failure feedback.

An exact search for `RestSkillHandler`, `RestSkillInvocation`, `SkillKind.REST`, `CapabilityKind`, `RestTool`, `RestSkill`, and `transformer` in current src/main, src/test, README, agent-skills, docs and Console returned no matches. Negative tests/documentation mentioning unsupported `rest:` are current rejection guidance, not production implementations. Historical `ai/thoughts` are intentionally outside that removal search. `ai/thoughts/plans/2026-11-01-PR-28.3-generation-owned-executor-execution.md` records the CapabilityKind assessment: it was a one-to-one SkillKind translation with no independent execution meaning, and its removal was part of that implementation.
