## Summary

`DefaultExecutionTraceHandle` owns one immutable path today. It selects `<root>/<entryNamespace>/<sessionId>.<traceId>.execution-trace.ndjson`, initializes records immediately, and uses that same path for active reads, snapshots, finalization, deletion and finalized descriptors. There is no separate active filename or rename in the checked-out implementation.

Each NDJSON append opens and closes its own output stream. Finalization appends `TRACE_COMPLETED`, marks the handle completed, then either builds an ordinary retained descriptor or delegates to completion-grace retention. The retention collaborator currently receives and owns one exact path. Journal projection runs before handle finalization, and downstream artifact publication runs after it returns successfully.

Console downloads by trace ID through Framework's catalog. Framework opens the exact finalized descriptor path; Console obtains bytes over HTTP and installs its own process-local evidence bundle. The inspected download path does not reconstruct the Framework filename. The ticket's authorized change concerns the filesystem publication lifecycle, with existing configuration, retention decisions, canonical contents, access controls and compatibility marker values retained.

## Detailed findings

### Path selection, initialization and writing

- `src/main/java/ai/loomspan/internal/runtime/trace/DefaultExecutionTraceHandle.java:64` is the package-private full constructor. A non-null explicit path is used as supplied; otherwise lines 89–91 resolve the entry namespace under the configured root and append the session/trace filename. The writer and reader are initialized at lines 100–101.
- Public constructors beginning at lines 113, 129, 146 and 165 create a UUID trace ID, delegate, reset the selected file and initialize records. These are internal subsystem construction paths, not supported application extension points.
- `initialize()` at line 182 emits `TRACE_STARTED` and `TRACE_CAPTURE_POLICY_RECORDED` once. Trace-start metadata includes `tracePath`, release-owned `consoleCompatibilityVersion`, entry skill and captured namespace/generation facts. `tracePathMetadata` defaults to the actual path, with explicit overrides used by deterministic tests.
- `src/main/java/ai/loomspan/internal/runtime/trace/NdjsonTraceRecordWriter.java:31` creates parent directories and opens CREATE/WRITE/APPEND inside try-with-resources. It writes one canonical JSON record and newline, then closes the stream before returning. There is no long-lived writer stream or separate close operation in `TraceRecordWriter`.
- `appendInternal()` at handle line 344 refuses writes after `completed`. A logical chunked record writes its envelope and every physical chunk before observation publication. Normal record publication likewise follows successful file append. Observation exceptions are contained by `publish()`.
- `resetTraceFile()` at line 333 deletes the current path if present. Initialization/reset IOException is wrapped with existing session-specific IllegalStateException messages. Normal append and finalization declare IOException.

### Current finalization and repeated calls

`DefaultExecutionTraceHandle.finalizeTrace()` at line 264 is synchronized, as are appends and `readRecords()`:

1. Validate completion; return the cached optional descriptor if `completed` is already true.
2. Ensure initialization, combine completion metadata with `errored` and persistence policy, and append `TRACE_COMPLETED`.
3. Set `completed = true` immediately after the append returns.
4. For policy-driven discard candidates, call `completionGraceRetention.retainOrDelete(tracePath, terminalTimestamp, traceId, sessionId)`. Empty means no finalized artifact. A retained result supplies expiry and captured size.
5. Otherwise measure `Files.size(tracePath)` and build a nonexpiring descriptor.

`descriptor()` at line 305 includes the same path, terminal outcome/time, entry namespace/generation, persistence and optional expiry. `FinalizedTraceArtifact` normalizes that path to an absolute normalized path in its canonical constructor (`src/main/java/ai/loomspan/internal/core/FinalizedTraceArtifact.java:25`). No rename or publication state exists today. `completed` is already true if a later retention/size operation throws, while `finalizedArtifact` remains empty until assigned. This is the current state ordering relevant to repeated finalization after file-operation failures.

The deletion predicate at handle line 537 uses `errored`, independently of the completion outcome: NEVER is a discard candidate; ONERROR is a discard candidate only when not errored; ALWAYS persists. Failed ONERROR retention tests explicitly mark the handle errored.

### Live reads, snapshots and journal projection

- `tracePath()` at handle line 252 returns the single current field; `snapshot()` at line 246 builds `ExecutionTrace` with `visibleTracePath()`.
- `visibleTracePath()` at line 548 returns null only for completed discard-policy traces whose path is absent. Otherwise snapshots report that path, including during execution and completion grace.
- `readRecords()` at line 327 passes the same path to `NdjsonExecutionTraceReader`. The reader (`NdjsonExecutionTraceReader.java:35`) returns without records for null/missing paths, parses the file through a closed-on-return BufferedReader and reconstructs logical chunked content.
- `ExecutionJournalProjector.project(handle)` (`ExecutionJournalProjector.java:45`) uses `handle.readRecords`. The established derived-journal field-name redaction remains confined to that projector and is outside this filename change.
- `LoomspanSession.finalizeTrace()` (`src/main/java/ai/loomspan/internal/core/LoomspanSession.java:616`) holds the session lock, projects the journal at line 642, then finalizes the handle at line 661. Successful projection is saved only when handle finalization also succeeds. A projection IOException can first record a canonical failure and change completion to FAILED.
- The session catches finalization IOException and closes observation with `CORE_FINALIZATION_FAILED`, passing no descriptor. It then throws `IllegalStateException("Failed to finalize execution trace for session ...", cause)` at line 707. Unchecked failures and Errors similarly produce failed observation and propagate. On success, observation receives the finalized optional descriptor.
- A session-level repeat returns early if the handle is completed and its finalized journal is already cached (lines 636–639). The handle independently caches its finalization result.

### Completion retention owns an exact path

`CompletionGraceRetention` (`src/main/java/ai/loomspan/internal/runtime/trace/CompletionGraceRetention.java:11`) currently has one retention entry point, `retainOrDelete(Path, Instant, String, String)`, plus `acquire(FinalizedTraceArtifact)` and `close()`. The retained result contains expiry and size, without a path. It has no separate decision, publication or path-transfer method.

- `ImmediateCompletionRetention.java:16` deletes the supplied path immediately and returns empty.
- `ScheduledCompletionGraceRetention.java:57` calculates `expiresAt = finalizedAt + grace`, normalizes the supplied path and deletes it if grace is zero/already expired or retention has closed. Otherwise it captures size and registers a `RetentionState` keyed by that exact path.
- Scheduling begins inside that method. The scheduled task can run before it returns; the return is empty if the state has already disappeared. Scheduling rejection removes state, deletes the file and returns empty.
- `acquire()` at line 142 looks up expiring artifacts by the descriptor's exact normalized path, checks identity/expiry/size facts and increments reader accounting, then opens that path. Nonexpiring artifacts are opened without transferring deletion ownership.
- Expiry marks a state expired and deletes its exact path when there are no readers. A lease acquired before the deadline defers deletion until release. `close()` cancels tasks and clears states without deleting retained files.
- `ObservabilityActivationCoordinator.GatedCompletionRetention` (`src/main/java/ai/loomspan/internal/observability/ObservabilityActivationCoordinator.java:73`) forwards retention/acquisition to the enabled runtime; otherwise it delegates discard to immediate retention. This wrapper is another in-repository caller if the internal retention interface changes.
- `ObservabilityRouteRegistrar.java:144` creates scheduled retention using configured completion-grace TTL. `LoomspanSessionRunner.java:204` and the admitted-root factory at line 315 carry the retention collaborator and host trace directory into the handle. The requested lifecycle behavior does not change root selection or entry-namespace ownership.

### Descriptor publication and downloads

- `DefaultExecutionObservationHandle.recordAppended()` holds a projected completion instead of publishing terminal availability immediately. `close()` only publishes normal terminal availability for successful core finalization (`src/main/java/ai/loomspan/internal/runtime/observation/DefaultExecutionObservationHandle.java:98`).
- `publishSuccessfulTerminal()` at line 141 publishes a nonempty descriptor to the finalized catalog, then emits AVAILABLE with effective expiry. Empty yields UNAVAILABLE/NOT_RETAINED. Catalog publication failure yields UNAVAILABLE/CATALOG_PUBLICATION_FAILED. Core finalization failure discards held normal completion and emits UNAVAILABLE/CORE_FINALIZATION_FAILED.
- `InMemoryFinalizedTraceCatalog.publish()` (`src/main/java/ai/loomspan/internal/runtime/observation/catalog/InMemoryFinalizedTraceCatalog.java:66`) checks the exact descriptor path is a readable regular file, preserves it in the catalog, and bounds effective expiry by metadata TTL and artifact expiry.
- `acquire(traceId)` at catalog line 137 delegates to retention using the stored descriptor. `ObservabilityRestController.artifact()` (`src/main/java/ai/loomspan/internal/observability/web/ObservabilityRestController.java:256`) checks TRACE_ARTIFACT_READ authorization, finds/acquires by trace ID and streams the obtained lease. It does not select a path from the filename. HTTP attachment naming is based on trace ID.
- `loomspan-console/internal/applicationclient/artifact.go:129` constructs an authenticated `ArtifactEndpoint(traceId)` GET, validates the response and streams its body. `loomspan-console/internal/artifact/acquire.go:47` loads authoritative metadata, opens this upstream stream, validates/installs its own staging bundle, then publishes installed evidence. Neither selects the Framework active file.
- Current REST trace metadata deliberately omits filesystem `artifactPath` (`ObservabilityRestIntegrationTest.java:253`). The source-level download assessment is therefore that a correct finalized descriptor automatically supplies the renamed artifact through the existing endpoint; verification of an actually finalized renamed handle remains future implementation work.

## Architecture documentation and historical context

The current architecture places canonical trace ownership in one session/handle, live projection downstream of successful record writes, derived journal projection before finalization, and artifact catalog publication downstream of successful core finalization. Retention owns exact filesystem paths and leases independently of catalog metadata lifetime. ## Open questions for planning

No product decision blocks planning. The following bounded internal choices remain for the planning stage:

- How the active path, completed path and reader/snapshot path state are represented, including explicit-path fixture construction and the immutable trace-start path metadata. The current ticket requires finalized descriptors/downloads/cleanup to use the published path and live reads to keep working.
- How the retention decision and exact-path ownership handoff surround publication. Current retention both decides and schedules deletion in one call, can expire before return, and can choose immediate discard due to zero/elapsed grace, closure or scheduling rejection. These are existing behaviors to account for alongside the ticket's rule that immediate discard never exposes a completed filename.
- How same-directory rename failures and repeated finalization map onto the existing completion flag/cached descriptor and core-finalization error path. Current completion marking occurs before retention filesystem work; the new terminal record must remain single and a failed rename must advertise no artifact.
- Which deterministic filesystem/observer test setup verifies interruption, first completed-name read, rename failure and retention races without relying on timing. Existing custom writers, retention fakes, mutable clocks and controlled scheduler tests provide current test seams.

These are ordinary implementation/verification details within the approved ticket. No additional compatibility break, Console production change or external decision was established by research.
