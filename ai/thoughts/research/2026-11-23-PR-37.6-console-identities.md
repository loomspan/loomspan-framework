# Research — Console identities

## Research question

Map callable identities through Framework observation producers, Console Go consumers, browser and MCP contracts, UI navigation and filtering, canonical trace evidence, stored samples and documentation for `loomspan-pr-37.6-console-identities.md`.

## Summary

The current Framework runtime uses the exact colon-qualified `SkillIdentity` established by PR 37.1–37.5. The registered observation catalog keys entries by `CapabilityMetadata.name()`, while its serialized summaries and details expose only `registeredName`. The same single string travels through Go observability, browser, MCP and TypeScript contracts. Both exact detail lookup and UI navigation already use that string directly.

The shared Go `skillidentity` package still validates the pre-series namespace and single-hyphen capture grammar. Its consumers include active execution and finalized trace validation, canonical trace processing, and ephemeral manifest reopening. Current colon-qualified Framework captures therefore encounter a different grammar in Console. Java REST/SSE/canonical trace fixture producers and their Go/UI consumers also retain old identity-bearing samples. Their generation paths and exact fixture checks are identified below.

Raw provider names and resolved skill facts already occupy distinct fields. Model content readers display recorded `toolCalls.name` and tool-response names. Tool lifecycle metadata, plan capability names, `skillName` facts and frame routes carry the resolved identity. Current raw-content and diagnostic tests deliberately include arbitrary text, hostile-looking strings, Unicode, whitespace and identity-like business content. Those values have their own meaning and fidelity assertions.

No tests were run during research. Planning questions concern coordinated DTO shape, the version decision record, fixture provenance and practical verification toolchains. No developer decision is required to continue planning.

## Go consumers and output contracts

### Shared consumed identity validator

`loomspan-console/internal/skillidentity/identity.go` is the existing shared authority used by these consumers.

- `namespacePattern` is `^[a-z_][a-z0-9_]{0,31}$`.
- `skillPattern` is `^[a-z_][a-z0-9_]*-[A-Za-z_][A-Za-z0-9_]*$`.
- `ValidCapture` checks a 64-character encoded string, namespace membership by `namespace + "-"`, nonblank generation IDs and the captured map.
- `ValidOwner` checks the namespace and matching generation in that map.
- It has no colon pair validation, combined two-character provider limit or reserved-substring rule.

The current callers are `observability/dto.go` for namespace publication, `observability/service.go` for active and trace DTOs, `traceanalysis/processor.go` for canonical trace capture and executing-owner facts, and `traceanalysis/service.go` for ephemeral analysis manifests. The namespace map may contain captured owners without a currently running skill, so standalone namespace validation is independently used.

- `observability/service.go:282` checks registeredName only for nonblank content. Detail validation near line 314 compares it with the requested name using exact equality. There is no namespace parsing or retry.
- `Service.GetSkill` near line 77 rejects an empty argument, obtains the one escaped application endpoint and validates its returned exact resource identity.
- `applicationclient/address.go:131` constructs `/skills/` plus `url.PathEscape(registeredName)`.
- `observability/service.go:338` and near line 559 call `ValidCapture` for active executions and traces. This is an affected normal entry path for current colon-qualified producers.
