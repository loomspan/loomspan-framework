## Summary

Declarations and input validation now use `CanonicalSchema`, but binding consumers retain legacy `SkillInputSchemaNode` and removed manifest-schema APIs. Output projection and composition still depend on the removed `OutputSchemaManifest`; the existing output validator is also legacy and belongs to the next ordinary-output ticket. A genuine fresh production compile currently fails. The ticket explicitly authorizes this intermediate build state and divides later ordinary, step/planning and effective-catalog integration among PRs 30.3.1, 30.3.2 and 30.3.4.

The existing algorithms separate the complete receiving/output contract from the model contribution, preserve accepted-source snapshots, reject model overrides, compose detached exact values and validate the complete result. The specific accepted migration changes are exact property-name matching, standard omitted openness and numeric enum value equality. Their current implementations and retained tests are identified below; inspected tests are not newly passing evidence.

## Detailed findings

### Canonical schema foundation and ingress

- `src/main/java/ai/loomspan/internal/schema/CanonicalSchema.java:13` retains a defensive tree snapshot and initialized NetworkNT validator. `tree()` copies the canonical tree; `providerTree()` strips recognized annotations only at schema nodes. `validate()` enables format assertions, returns completed verdicts and propagates operational failures.
- `StandardSchemaCompiler.java:14` defines INPUT/OUTPUT/PLANNING and AUTHORED/GENERATED roles. Compilation validates profile and meta-schema and requires exact root `type: object`. Nested false property schemas are accepted only for GENERATED contracts. INPUT alone admits nested unconstrained/description-only leaves and schema-valued additionalProperties. Nullable nested types are two-element arrays. Bounds, scalar enums, formats and descriptions are retained.
- `SkillInputContract.java:7` now stores `CanonicalSchema`; genericObject builds an explicitly open canonical object. `SkillInputContractResolver.java:31` compiles generated tool schemas instead of permissively interpreting arbitrary keywords. Consequently, old projection-test expectations that malformed/unsupported schemas silently become conservative proof exclusions no longer describe declaration admission. Invalid declaration rejection is separately exercised by compiler tests.
- `SkillInputValidator.java:20` performs Java-value admission followed by shared standard validation. `validateExact()` retains its assembly call boundary and delegates to ordinary exact validation; there is no coercion. Runtime Resource/InputStream/byte[] handling is restricted to marked input leaves; this behavior is owned by prior ingress/attachment work.
- `YamlSkillManifest.java:56` compiles/caches input and output canonical schemas. `YamlSkillDefinition.java:109` exposes canonical output schemas, including the TypeSafe branch whose declaration producer is still unmigrated.

### Child model projection and dispatch proof

- `project` at line 86 removes whole bound properties and their required names, recursively projects partial ancestors, and makes an ancestor required exactly when required unbound siblings remain. Open/unknown branches receive an object scaffold. - `inputSchema()` at line 47 serializes the projected contract and inserts `false` at each framework-owned property, including nested open/generic paths. Ownership checks at line 62 reject a present final key regardless of value and reject nonobject ancestors, using exact Map key lookup already.
- `proveDispatch` at line 26 requires supported, nongeneric, closed receiving shape, root-level bindings, no projected possible fields/requiredness and acceptance of empty arguments. Nested destinations remain conservative model dispatch. Whole object/array destinations can qualify.
- `runtime/tool/BoundCapability.java:33` constructs the projection and exposes its argument contract, eligibility, schema and ownership checks to both callback and assigned-action callers. `runtime/step/StepActionValidator.java:162` checks ownership before effective argument validation; `StepPromptBuilder.java:242` consumes the effective contract but remains a later step-schema migration consumer.

### Output projection and exact composition

- `OutputBindingProjection.java:12` computes a legacy-schema copy and modelContributionRequired. `hasSpace` at line 43 regards only explicit true as open; omitted additionalProperties therefore follows legacy closure. Recursive partial ancestors use the same rule. Whole-subtree bindings bypass any interior model space.
- `project` at line 53 removes bound properties and adjusts required ancestors and nullable flags. Unknown open destinations get object scaffolds. `copy` at line 74 copies only legacy fields. No boolean false output property is currently emitted; explicit override checking is a separate ownership authority.
- `validateModelContribution` at line 23 uses `OutputSchemaValidator.propertyNamesMatch`, currently Locale.ROOT lowercasing. Thus current output ownership/path behavior differs from the accepted exact-name migration. Child input checks are already exact.
- `OutputBindingComposition.java:16` checks definition/mission identity, captures the accepted plan and verifies selected evidence. For child-result bindings it requires a captured plan, every accepted task completed with matching result producer, and no results outside that plan.
- The lower-level constructor at line 38 copies the complete schema, constructs projection, assembles a detached source snapshot and validates each known destination subschema before any output model call. Open unknown destination branches currently have no static subschema.
- `compose` at line 61 fences changed plans and closed lifecycle, decodes the contribution, rejects overrides, validates projected contribution, constructs bound ancestors, inserts exact selected values and validates the assembled complete canonical-intent schema. It currently uses the legacy OutputSchemaValidator throughout. Its legacy ancestor case canonicalization at line 82 is another exact-name migration seam.
- `OutputSchemaValidator.java:39` matches names case-insensitively, assumes omitted output openness closed, implements a custom legacy structural validator and accepts removed manifest types. Its general migration is owned by PR 30.3.1. Binding-owned validation must use the shared standard validator without claiming that the advisor/general generation migration is complete.
- `StandardSchemaCompiler` accepts object roots only; existing input leaf checks demonstrate a private object wrapper for internal subschema validation (`SkillInputValidator.java:114`). Internal destination array/scalar checks remain part of this ticket's accepted contract.
