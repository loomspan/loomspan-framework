## Summary

`SkillTemplate` exposes six root operations with one target string, and `SkillInvocationHandoff` exposes two more. Their common preparation calls `SkillIdentity.resolve(skillName, "default")`. Current production therefore accepts a bare local target in `default` or an exact colon-qualified target. PR 37.1 already made identity components strict, preserved case verbatim and changed canonical keys to a colon. The public JavaDoc and several tests still describe the earlier single-hyphen encoding and namespace normalization.

After preparation, the entry is already an immutable `SkillIdentity` in `SkillAdmissionSnapshot`. Generation capture, reachable dependency validation, authorization, retained admission and actual execution use the selected metadata and captured generations. Root execution does not search other namespaces after capture. The handoff payload also keeps the original caller target string for facade diagnostics while its `PreparedInput` retains authoritative resolved metadata.

`SkillReloader.snapshot(namespace)` already selects and validates one explicit namespace. Candidate snapshots have the same namespace-scoped `SkillCatalog` contract. `DefaultSkillCatalog.skill(name)` currently parses a qualified identity and performs an exact lookup in that snapshot's qualified-key map. Public `SkillDescriptor` and `ValidatedSkill` are records with one `name` component. They have no namespace/local-name accessors today. Their only production construction sites are `DefaultSkillCatalog` and `SkillGenerationManager.validationResult`.

The closed API architecture test classifies the affected facade, handoff, catalog and record types as Application API. `ApplicationApiValueTest` separately locks their exact signatures and constructor components. Existing unit and integration tests cover all root overloads, capture timing, retention, authorization, input fidelity and observer behavior, but multiple families carry stale pre-series target strings. The previous ticket records these consumer obligations explicitly.

## Production identity flow

### Boundary validation and preparation

`DefaultSkillTemplate.captureRoot` at line 150 wraps `generationManager.capture(SkillIdentity.resolve(skillName, "default"))`. `SkillIdentity.resolve` at `internal/core/SkillIdentity.java:25` parses any target with a colon, otherwise constructs a pair with the supplied owner. This shared helper is also used by authored reference compilation, where owner-relative behavior belongs to PR 37.3.

`SkillIdentity` validates both components against the exact ASCII lowercase grammar, reserved substrings and combined provider limit in its compact constructor at line 6. Qualified parsing requires exactly one colon. Its canonical `toString()` is `namespace + ":" + localName`. There is no case folding, trim or owner search in these paths.

Object preparation captures the complete reachable association before checking null or calling Jackson conversion at `DefaultSkillTemplate.java:116`. It then forwards the captured canonical entry string into map preparation. Map preparation captures first at line 144, selects the exact capability from the captured entry generation at lines 160–165, validates input, validates captured reachable dependency contracts and builds `PreparedInput(snapshot, capability, validation, lease)` at line 344.

`requireSkill` at line 302 performs both an exact map lookup and an equality guard between the requested canonical name and returned metadata. Unknown targets produce `SkillException`. Invalid root identity construction failures are wrapped by `captureRoot` in the facade's `SkillException` boundary. Map and Object null rules remain distinct. Preparation closes the captured lease on all handled exceptional outcomes. Fatal `Error` values are rethrown after release.

### Capture and admission

`SkillGenerationManager.capture(SkillIdentity entry)` at `internal/skill/SkillGenerationManager.java:334` runs under the generation monitor. It selects active generations by each reached identity's namespace and checks the exact canonical capability key. It traverses allowed children and retains executor owner generations. Each reachable identity is visited once and each selected generation receives one owner count for the capture. Missing namespaces and skills terminate that capture. Unrelated declarations are not traversed.

`SkillAdmissionSnapshot.java:8` stores the typed entry, immutable namespace-to-generation association and admitted executor bindings. `entryGeneration()` selects `entry.namespace()`. `resolve(identity)` performs exact canonical lookup in that identity's captured generation. Constructor checks ensure the entry namespace exists and each map key matches the generation namespace.

`SkillDependencyValidator.checkAdmission` at line 85 rebuilds dependency facts from retained immutable metadata, checks the entry graph, verifies effective output contracts and returns a new snapshot retaining the same entry and generations with selected executor bindings. It does not re-resolve a root string. These expensive checks occur outside the registry monitor.

`DefaultSkillTemplate.validatePrepared` at line 196 checks calling authentication and entry authorization, then always releases temporary ownership. It creates no execution session or admission. Direct invocation authorizes the prepared entry before passing the exact metadata to the session runner.

`DefaultSkillInvocationHandoff.admit` at line 41 captures authentication, authorizes the prepared entry, and transfers its lease to `FrameworkExecutionLifecycle.admitRoot`. The admitted implementation stores a single-use `AtomicReference<Payload>` and generation ID from `prepared.snapshot().entryGeneration().id()` at lines 74–85. `Payload` contains the original target string, prepared input and authentication. `invoke` consumes the payload once and executes that prepared input with captured authentication. It never performs another registry lookup. Pending termination clears the payload, release closes admission ownership, and losing execution attempts fail without executing.

### Execution, access and observations

`DefaultSkillTemplate.invokePrepared` at lines 245–265 supplies the selected metadata name, snapshot, authentication and retained owner/admission to `LoomspanSessionRunner`. The action executes the same `CapabilityMetadata` through `CapabilityExecutionRouter` at lines 294–299.

`LoomspanSessionRunner.java:297` obtains the runtime from `snapshot.entryGeneration()`, claims admitted execution, creates a fresh session with the canonical entry string and `CapturedNamespaceMetadata.from(snapshot)`, and installs `ExecutionBinding.sessionOnly(session, snapshot)` at line 340. Replacement while input conversion or queuing occurs does not redirect the prepared entry.

`ExecutionBinding.java:47` identifies root authority using both `target.identity().equals(snapshot.entry())` and the session entry string. `DefaultAccessGuard.java:51` additionally requires the target metadata to be owned by the captured selected generation. A root without a mission may execute only its entry target. A child requires membership in the source's declared allowed list and existing namespace visibility. `SkillRoleEvaluator.java:35` evaluates the selected callable's roles and, for executor-backed YAML, the selected admitted executor's roles. Private visibility allows direct host entry under applicable role checks while foreign child access requires Public visibility.

The observer receives the existing completed public execution view after execution/session completion. Exception and observer mapping use the canonical capability identity in actual execution data. The caller's original target string remains in some facade failure messages. Input, tool arguments, provider evidence and result text follow their existing fidelity rules. The approved derived-journal projector behavior remains outside this naming boundary.

## Catalog and validation producers

`SkillGeneration.java:114` builds `DefaultSkillCatalog` from capability metadata sorted by canonical name. It verifies the catalog's namespace/generation ID match the generation. `DefaultSkillCatalog.java:24` validates namespace, generation ID, input list, ownership of every capability and duplicate canonical names. It stores an unmodifiable navigable map keyed by `metadata.name()` and an immutable values list.

The sole production descriptor constructor is `DefaultSkillCatalog.java:36`. It copies canonical name, description, kind and the exact registered input/effective output schema strings. `skill(String name)` at line 61 calls `SkillIdentity.parse(name)` and looks up the canonical key. Local unqualified input currently fails parsing. A valid qualified reference owned elsewhere finds no entry in this snapshot. The catalog does not query the global active registry or grant authorization.

The sole production `ValidatedSkill` constructors are `SkillGenerationManager.validationResult` at lines 237–240. Successful checked sets include fixed Java callables assigned to the checked namespace and YAML definitions, mapped to YAML or JAVA kind. Entries are sorted by `ValidatedSkill::name`. An error produces no skills. `SkillValidationResult.java:10` detaches both lists and enforces that errors and a nonempty successful skill list cannot coexist.

`SkillReloader.snapshot` and candidate snapshot therefore converge on the same descriptor implementation. Proposed validation and prepared/active catalogs contain caller-reusable identity only as encoded strings today. Namespace snapshot metadata exists separately even for an empty catalog.
