## Summary

The checked-out Framework already produces standard structural effective schemas and attachment descriptor records. Console already displays schema JSON and original YAML as inert text, and its Java/Go/TypeScript contracts carry schema text without rebuilding the schema. The missing attachment-specific UI is bounded by the existing `TraceRecords` detail/action system and the logical record content descriptor: ordinary records expose their `data`, while chunked envelopes expose reconstructed semantic payloads. Raw record reads and semantic content reads are separate mechanisms.

The current shared trace corpus has generic chunked JSON/text fixtures and native TypeSafe semantic-content fixtures, but no named attachment corpus fixture. Console has no attachment detail parser/action/component in `TraceRecords.tsx`. Existing schema tests already cover rich standard metadata and inert source display, so the ticket's two producer dependencies are preservation/integration boundaries rather than a second implementation assignment.

- `loomspan-console/internal/traceanalysis/query_records.go:215-243` attaches a reconstructed content descriptor to a logical envelope using its stored payload descriptor, or a DATA content descriptor for ordinary record data. `ReadContentRange` in `query_ranges.go` validates opaque content references against evidence/handle scope before serving ordinary record data or envelope bytes. It preserves existing evidence lifetime, range, and access rules.
- `loomspan-console/web/src/observability/TraceRecords.tsx:198-226` distinguishes `readCompleteRecord` (physical raw envelope, using `getRawRecordRange`) from `readCompleteContent` (semantic content, using `getContentRange`). This matters for a Unicode descriptor split across byte ranges.

- The record-detail union at approximately lines 174-177 and handler at 1060-1090 currently cover tool input/result, structured output, evidence, completion and step results. Record action selection around 1100-1165 has no attachment-specific case. Generic `Read raw record` and `Read content` remain available according to the current descriptor.
- `loomspan-console/web/src/observability/TraceRecords.raw.test.tsx` establishes raw continuation gathering, action order, inert envelope rendering, load errors and action coexistence. These tests do not exercise attachment-specific rendering or reconstructed attachment payloads.
- `TraceRange` in `web/src/api/contracts.ts:330` carries TEXT/BASE64 content, continuation cursor, total/actual byte ranges and evidence scope. Existing generic Java/Go/TS DTOs support the selected data channel. No public application descriptor signature change is selected by the ticket.
